# Minecraft 25w03a 变更分析

- 上一个版本：25w02a
- 当前版本：25w03a

## 常规自然生成恢复，刷怪场重新产出生物

在已加载区块内，生物种类由当前生物群系或结构的生成列表选定；生成前还会检查这个种类是否允许出现在具体落点。

### 差异出现的场景

玩家附近存在满足距离、亮度、空间、生物数量上限等条件的自然生成位置，包括普通刷怪场和依靠结构生成列表的刷怪场。

### 版本变化

- 25w02a：检查时把生物生成条目与带权重的包装对象比较，结果始终不匹配，常规区块自然生成在此处被拒绝。
- 25w03a：改为比较包装对象内部的生物生成条目，满足其余条件时可以正常生成。

### 实际影响

通过常规自然生成运行的刷怪场恢复产出，周围世界也重新补充这一路径生成的生物。区块首次生成时放置动物、刷怪笼和独立的特殊生成器采用其他调用路径，不属于这次恢复的范围。

## 跌落伤害改为向下取整

生物的跌落距离改用双精度累计，最终伤害也从向上取整改为向下取整，影响摔落削血装置和带有减伤倍率的落点。

### 差异出现的场景

生物落地，累计跌落距离超过其安全跌落距离；没有其他免伤效果。计算示例中的“距离”指实体实际累计的跌落距离。

### 版本变化

- 25w02a：将“超出安全距离的部分 × 落点倍率 × 跌落伤害倍率”向上取整。
- 25w03a：先给距离加上 `0.000001` 的浮点误差补偿，再将同一乘积向下取整。例如默认安全距离为 3、伤害倍率为 1 时，累计下落 3.5 格从 1 点伤害变为 0 点，4.5 格从 2 点变为 1 点。

对干草捆、蜂蜜块等有伤害倍率的落点，结果同样改为向下取整。朝上的滴水石锥尖端给距离额外添加的数值由 2 改为 2.5，再乘 2；这一补偿与新的取整方式共同决定最终伤害。落地粒子的出现门槛和数量也改用取整后的超额距离。

### 实际影响

依赖精确剩余生命值的摔落装置，尤其是落点位于半格高度或使用减伤方块的装置，会得到不同的削血量。此次取整变化针对生物承受的跌落伤害；下落中的铁砧、滴水石锥等砸中其他实体时，仍采用其自身的下落方块伤害公式。

## 移除潜影盒不再散落其中的物品

潜影盒应把内容物保存在掉落的盒子里。新版取消了普通容器的移除散落处理，修复空盒掉落和创造模式复制内容物的问题。

### 差异出现的场景

玩家打破装有物品的潜影盒，或通过其他方式移除、替换该方块。

### 版本变化

- 25w02a：生存模式挖掘时先散落并取空盒内物品，再计算盒子掉落，得到空盒和散落物品；创造模式先生成保留内容物的盒子，移除时又散落原内容物，额外复制一份。
- 25w03a：生存模式和创造模式均不再执行这一步散落，打破非空盒子时保留带原内容物的潜影盒掉落。

直接替换方块时，新版也不再通过普通容器移除回调散落内容物；是否留下潜影盒物品，取决于该替换方式本身是否执行掉落。

## 用桶重新捕获美西螈会丢失颜色

美西螈桶需要保存被捕获个体的变种。新版将变种迁移到物品组件时读取了错误的来源，导致普通捕获所得桶丢失颜色。

### 差异出现的场景

用普通水桶捕获一只非粉红色美西螈，再把它放回世界，包括稀有的蓝色美西螈。

### 版本变化

- 25w02a：捕获时把美西螈的变种写进桶，放出后保持原来的颜色。
- 25w03a：变种改存为物品组件，但捕获代码错误地从新生成的桶自身读取该组件，没有读取被捕获的美西螈。普通捕获所得桶不含变种，放出时美西螈保留初始化的 `lucy` 变种，即粉红色。

已有旧版美西螈桶在世界升级时会把原变种转换为新组件，因此可以保持首次放出时的颜色；在新版再次用桶捕获后，仍会遇到上述丢失。年龄、生命值等其他桶数据没有因这一处错误被一起删除。

## 骨粉先补满花簇，再产生掉落物

粉红色花簇和野花簇在同一格最多堆叠四簇。新版恢复用骨粉增加地面花簇数量的行为。

### 差异出现的场景

对少于四簇的粉红色花簇或野花簇使用骨粉。

### 版本变化

- 25w02a：立即掉落一个对应物品，地面花簇数量不变。
- 25w03a：每次先增加一簇，达到四簇后再使用骨粉才掉落物品。

使用低密度花簇直接生产掉落物的装置，前几次骨粉会用于补满地面花簇。

## 草方块骨粉生成随机选择花卉配置

草方块施用骨粉时，会从所在生物群系的花卉生成配置中决定生成内容。新版允许选中列表中的其他配置。

### 差异出现的场景

对草方块使用骨粉，所在生物群系具有多项花卉生成配置，例如同时包含野花簇和其他花卉配置的桦木森林。

### 版本变化

- 25w02a：每次进入花卉生成分支都固定使用列表第一项。
- 25w03a：每次进入该分支都随机选择一项配置，骨粉花场可得到的花卉及其比例随之改变。

随机选择在配置之间等概率进行；各配置内部的生成规则仍然生效，因此不表示所有花卉物品等概率产出。

## 水、熔岩和细雪按实际接触处理燃烧

实体移动过程中接触的方块与流体，用于决定点燃、熄灭及熔岩伤害。新版将流体判定与方块判定分开。

### 差异出现的场景

燃烧实体快速穿过含水方块，或只擦过浅层水、熔岩所在方块的上部空间；也包括一段移动同时经过火焰和灭火介质的情况。

### 版本变化

- 25w02a：移动路径的燃烧处理按方块种类识别普通水、气泡柱和熔岩；流体所在方块的整个范围参与判断，含水的其他方块不会在这一轮按水处理。
- 25w03a：水和熔岩按流体实际高度形成的体积检测，含水方块里的水也可以参与灭火。实体只经过流体上方空隙时，不再因为经过其所在方块而被这一判定熄灭或受到熔岩处理。

新版把水和细雪的熄火集中到移动路径处理，删除了早先基于水状态直接清火和生物细雪状态的重复熄火处理。旧版基础实体更新中额外的一次熔岩伤害调用也被删除，实际接触熔岩时仍由移动接触处理施加伤害；矿车自己的熔岩处理仍然保留。

熄灭声音改为在处理前后确实从燃烧变为未燃烧时播放，避免按中间接触状态播放；服务器直接广播该声音，带有静音标记的实体也不再通过通用实体声音入口抑制它。

## 鞍成为真正的装备槽

鞍从猪、炽足兽的布尔状态和马类的独立物品栏，统一迁移到 `saddle` 装备槽。

### 差异出现的场景

给猪、炽足兽或马类装备带有自定义名称、附魔等组件的鞍，使用发射器装鞍，或用命令读取、替换鞍。

### 版本变化

- 25w02a：猪和炽足兽只记录“已装鞍”，死亡时生成一件普通鞍，原鞍的名称等组件丢失；马类的鞍另存于独立物品栏，命令槽名为 `horse.saddle`。
- 25w03a：这些实体保留实际装备的鞍物品及其组件，死亡时走通用装备掉落处理。猪和炽足兽因此可以返还原本带组件的鞍；带有消失诅咒等禁止装备掉落效果的鞍也受这一通用规则约束。命令槽名改为 `saddle`，可以统一操作猪、炽足兽和马类。

发射器装鞍改用通用装备逻辑，会给成功装备的生物标记持久存在，防止其因距离消失。普通手动装鞍只保证鞍的掉落，不附带这一持久标记。成年、存活、马类需要驯服等装鞍条件仍由目标检查。

实体装备 NBT 也统一改为 `equipment`，例如 `equipment.saddle`、`equipment.mainhand` 和 `equipment.head`。旧世界的装备和鞍有数据转换；实时执行的 `/summon`、`/data` 以及检查旧 `ArmorItems`、`HandItems`、`SaddleItem`、`Saddle` 路径的函数，需要采用新结构。

## 装备目标限制约束穿戴、交互和拾取

物品的 `equippable` 组件可以限制允许装备的实体。新版在更多装备入口执行这一限制，并增加右键生物直接装备的能力。

### 差异出现的场景

使用自定义了 `equippable.allowed_entities` 的装备，或为物品启用新增的 `equip_on_interact`；也包括马类物品栏内的鞍槽操作。

### 版本变化

- 25w02a：玩家右键穿戴、手动放入护甲栏以及生物拾取装备，没有统一检查允许的实体类型；没有 `equip_on_interact` 这一通用交互装备入口。
- 25w03a：上述入口均检查目标类型，不在允许列表时不能通过这些方式装备。启用 `equip_on_interact` 的物品可以在右键目标、对应槽位为空且符合限制时装备到目标身上；普通鞍使用这一能力。

普通鞍的目标限制也使僵尸不再将它作为普通手持物拾起。马类鞍槽改用通用装备槽后，带有绑定诅咒效果的自定义鞍，非创造模式玩家不能从该槽取出。

新版还存在自定义装备的边界问题：玩家的槽可用性检查接受 `body`、`saddle`，但物品栏没有对应存储槽。把允许玩家使用的物品配置为这两种槽并右键穿戴时，旧版拒绝穿戴，新版会消耗手中物品而不保存装备。原版鞍的允许目标不含玩家，不触发此问题。

## 正常游戏中开放 GameTest 和方块测试

GameTest 可以运行结构内的测试，并设置测试环境。新版在正常游戏中开放测试命令及两种管理员测试方块。

### 差异出现的场景

管理员在正常游戏环境中运行 `/test`，或放置、编辑 Test Block 和 Test Instance Block。

### 版本变化

- 25w02a：`/test` 和测试更新只在开发环境注册、执行，正常游戏不能通过该命令运行测试。
- 25w03a：正常游戏注册 `/test`，要求权限等级 2，可运行、重复运行、定位、重置或清除测试，并通过数据包的 `test_instance`、`test_environment` 定义测试结构及环境。新增两种测试方块进入管理员物品栏，放置和编辑受管理员方块权限约束。

Test Instance Block 可以保存、加载并运行关联结构。方块式测试用 Test Block 的 START 模式输出强度 15 的信号，ACCEPT、FAIL 和 LOG 模式在收到红石上升沿时分别参与成功、失败和日志判定。本版 START 触发代码没有安排复位计划刻，输出不会据此自动形成固定长度脉冲。

### 实际影响

测试环境设置会直接作用于运行世界：可以修改游戏规则、时间、天气并执行设置和清理函数。清理时，游戏规则恢复默认值，时间没有自动恢复步骤，天气清理重置天气周期；这些操作不恢复运行前全部环境状态。

重置或清理测试会重新放置、清空测试结构区域。加载 Test Instance Block 的结构前，还会直接移除范围内的非旁观实体，包括普通玩家，并不执行正常死亡处理。

测试批次完成或验证遇错停止时，运行器清除所在维度的全部强制加载区块记录，其中包括测试前由 `/forceload` 设置的区块。

## 物品可通过组件指定生成实体的变种

新版为猫、狼、狐狸、青蛙、猪、马、羊驼、美西螈、鹦鹉、兔子、哞菇、鲑鱼、热带鱼、绵羊、潜影贝、村民和画增加对应的变种组件。生成实体时会读取其支持的组件。

### 差异出现的场景

通过刷怪蛋、桶等物品生成实体，物品上带有对应实体支持的变种组件，例如绵羊刷怪蛋上的 `sheep/color="red"`。

### 版本变化

- 25w02a：主要通过 `entity_data` 或桶内的变种 NBT 指定外观；不读取这些新增变种组件。

组件只对具体实体实现的字段生效。本版村民实现了 `villager/variant`，僵尸村民没有对应读写实现，该组件并非所有村民类实体通用的变种入口。

## 实体变种谓词迁移到组件，旧颜色条件不再生效

新版实体谓词新增 `components`，按实体提供的组件值精确匹配，并移除多种旧变种专用条件。

### 差异出现的场景

数据包用实体谓词筛选猫、狼、青蛙等变种，或使用绵羊的旧 `color` 条件。

- 25w02a：可通过相应 `type_specific` 谓词筛选变种；部分谓词支持变种标签或变种集合，绵羊谓词可限制颜色。
