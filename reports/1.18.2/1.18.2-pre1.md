# Minecraft 1.18.2-pre1 变更分析

- 上一个版本：22w07a
- 当前版本：1.18.2-pre1

## 实体斜撞墙角时同时清除两个方向的速度

实体移动时，碰撞处理会移除受阻方向上的速度。本版修正了同时沿 X、Z 两个方向撞上方块时的处理。

### 差异出现的场景

实体斜向移动到墙角，本次移动在 X、Z 两轴都受到阻挡。以下差异发生在通用实体移动处理阶段，适用于继续沿用其计算结果的实体。

### 版本变化

- 22w07a：先清零 X 速度，再处理 Z 速度；第二次写入使用碰撞前缓存的速度，把 X 速度恢复了。因此同时撞上两个方向时，最终只清除了 Z 速度。
- 1.18.2-pre1：一次写入两个方向的结果，X、Z 速度同时清零，墙角不再保留上述 X 方向动量。

此外，新版统一以水平碰撞判定使用的容差决定是否清零速度。当请求位移与实际位移仅相差小于约 `0.00001` 格时，旧版仍可能清零该轴速度，新版保留它。

代码出处：[22w07a · 旧版碰撞判定与两次速度写入](https://github.com/TISUnion/guardian/blob/ae6549048dc3698324e1f95efdb61be8b14e5734/src/main/java/net/minecraft/world/entity/Entity.java#L583)；[1.18.2-pre1 · 新版按轴判定并同时写入速度](https://github.com/TISUnion/guardian/blob/83c2231553928c88df10cfe4885f0b500d0a574c/src/main/java/net/minecraft/world/entity/Entity.java#L583)；[1.18.2-pre1 · 位移比较容差](https://github.com/TISUnion/guardian/blob/83c2231553928c88df10cfe4885f0b500d0a574c/src/main/java/net/minecraft/util/Mth.java#L194)。

## generator-settings 留空会阻止专用服务器启动

本版读取服务器属性时，会立即把 `generator-settings` 解析为 JSON 对象，导致旧配置中的常见空值出现回归。

### 差异出现的场景

已有 `server.properties` 包含 `generator-settings=`，等号后为空或只有空白。无论世界类型是否为超平坦、是否已经存在世界存档，启动时都会读取该配置。

### 版本变化

- 22w07a：非超平坦世界忽略该字段；超平坦分支也会把空字符串转换为空 JSON 对象，因此空值本身不会造成解析失败。
- 1.18.2-pre1：直接解析空字符串，抛出文件结束解析异常，服务器无法正常启动。若整个属性不存在，才会直接使用空对象默认值；明确填写 `generator-settings={}` 也能正常通过这一步。

新版还会同样拒绝其他无效 JSON 或非对象 JSON；这些内容在旧版非超平坦服务器中可以一直被忽略。

代码出处：[22w07a · 旧版仅在 flat 分支解析并单独处理空串](https://github.com/TISUnion/guardian/blob/ae6549048dc3698324e1f95efdb61be8b14e5734/src/main/java/net/minecraft/world/level/levelgen/WorldGenSettings.java#L221)；[1.18.2-pre1 · 新版读取属性时统一解析](https://github.com/TISUnion/guardian/blob/83c2231553928c88df10cfe4885f0b500d0a574c/src/main/java/net/minecraft/server/dedicated/DedicatedServerProperties.java#L71)；[1.18.2-pre1 · 只有属性不存在或解析返回空值时才采用默认值](https://github.com/TISUnion/guardian/blob/83c2231553928c88df10cfe4885f0b500d0a574c/src/main/java/net/minecraft/server/dedicated/Settings.java#L84)；[1.18.2-pre1 · 直接调用 JSON 对象适配器并向外抛出解析异常](https://github.com/TISUnion/guardian/blob/83c2231553928c88df10cfe4885f0b500d0a574c/src/main/java/net/minecraft/util/GsonHelper.java#L421)。

## 下界要塞整体范围内的普通底板也能使用要塞刷怪列表

本版把结构专属刷怪规则移入结构配置，其中下界要塞的适用范围发生了变化。

### 差异出现的场景

刷怪位置在下界要塞的整体包围盒内，但不在任何桥梁、走廊等结构部件的包围盒内，脚下是满足刷怪条件的普通方块，而非下界砖块。

### 版本变化

- 22w07a：要塞部件内使用要塞刷怪列表；部件外只有脚下是下界砖块时，才能在整体包围盒内使用该列表。上述普通底板位置使用所在生物群系的刷怪列表。
- 1.18.2-pre1：要塞配置直接在整个结构包围盒内覆盖怪物刷怪列表。上述位置也能尝试生成凋灵骷髅、烈焰人等要塞生物，仍须满足光照、空间和相应生物的其他条件。

### 实际影响

要塞整体包围盒内、各部件之间的空隙可以用其他合格方块铺设要塞刷怪平台。依靠非下界砖块底板让这些位置使用原生物群系刷怪列表的布局，其生成种类也会改变。已有要塞加载后同样适用此规则。

代码出处：[22w07a · 旧版按要塞部件选择生物](https://github.com/TISUnion/guardian/blob/ae6549048dc3698324e1f95efdb61be8b14e5734/src/main/java/net/minecraft/world/level/levelgen/NoiseBasedChunkGenerator.java#L482)；[22w07a · 旧版下界砖块上的整体范围补充判定](https://github.com/TISUnion/guardian/blob/ae6549048dc3698324e1f95efdb61be8b14e5734/src/main/java/net/minecraft/world/level/NaturalSpawner.java#L311)；[1.18.2-pre1 · 新版要塞使用整体包围盒覆盖怪物列表](https://github.com/TISUnion/guardian/blob/83c2231553928c88df10cfe4885f0b500d0a574c/src/main/java/net/minecraft/data/worldgen/StructureFeatures.java#L123)；[1.18.2-pre1 · 新版结构刷怪范围判定](https://github.com/TISUnion/guardian/blob/83c2231553928c88df10cfe4885f0b500d0a574c/src/main/java/net/minecraft/world/level/chunk/ChunkGenerator.java#L528)。

## 超平坦世界开始使用结构专属刷怪规则

在超平坦世界已经存在、或随后生成的海底神殿、女巫小屋和掠夺者前哨站中，结构专属自然刷怪现在生效。

- 22w07a：这些专属规则仅由噪声地形生成器提供。超平坦生成器按生物群系选择自然生成的生物，例如“水世界”中的海底神殿没有正常地形中的守卫者专属刷怪区。
- 1.18.2-pre1：超平坦也会读取结构配置。海底神殿整体范围使用守卫者列表，并排除地下水生生物和美西螈；女巫小屋部件内使用女巫、猫列表；掠夺者前哨站整体范围使用掠夺者列表。各生物的其余生成条件仍然需要满足。

若不同结构的专属刷怪区域重叠，新版也不再保留旧版先女巫小屋、再前哨站、再海底神殿等固定检查顺序；最终使用的覆盖列表可能改变。

## 玄武岩三角洲增加下界要塞生成机会

下界要塞与堡垒遗迹改为在同一组候选位置中按权重竞争；先选中的结构无法生成时，新版会继续尝试组内剩余结构。

### 差异出现的场景

在尚未生成结构的区块中，一个下界建筑候选位置原本被随机选为堡垒遗迹，但该结构在对应位置不能生成。例如堡垒遗迹不允许生成在玄武岩三角洲。

### 版本变化

- 22w07a：要塞和堡垒遗迹分别执行互斥的随机检查，约 40% 候选选要塞、60% 选堡垒遗迹。选中堡垒遗迹却不满足条件时，该候选位置不会改生成要塞。
- 1.18.2-pre1：首先仍按要塞 2、堡垒遗迹 3 的权重选择。堡垒遗迹尝试失败后，继续尝试要塞；只要要塞自己的生成条件成立，就可以补上原本空缺的位置。

### 实际影响

玄武岩三角洲中更多候选位置能够生成要塞。候选网格的间距和盐值保持原值；已有区块中的建筑不重建，新增要塞来自后续结构生成。

## 下界废弃传送门改用主世界的分布间距

在默认下界的新区块中，废弃传送门的位置网格从间距 25 区块、最小分隔参数 10，改为间距 40 区块、最小分隔参数 15，与主世界共用同一套分布。

相同种子下，新生成传送门的位置会改变，候选位置也更稀疏。旧版每个 `25×25` 区块区域一个候选位置，新版为每个 `40×40` 区块区域一个；这是候选密度变化，实际生成仍取决于地形和群系条件。

## 湖泊生成取消对村庄所在区块的排除

当湖泊生成尝试落在具有村庄结构引用的区块时，22w07a 会直接放弃这次生成；1.18.2-pre1 继续执行湖泊形状和周围方块检查，条件成立就会生成。

默认世界主要受影响的是熔岩湖。它们现在可以出现在旧版会因村庄引用而跳过的位置，包括村庄附近或村庄下方；允许生成并不代表每次尝试都会成功。数据包使用同一种湖泊功能生成的其他湖泊也受到这一变化影响。

## 旧世界结构记录升级时出现识别丢失与变种误判

本版将结构记录从“村庄”“沉船”等结构种类，细分为沙漠村庄、海滩沉船等具体配置。升级时根据各区块保存的生物群系猜测变种，存在以下实际差异。

### 差异出现的场景

加载 22w07a 或更早版本生成的结构区块，或使用定位功能检查尚未完整加载升级的旧区块。

### 版本变化

- 22w07a：起始记录与相邻区块引用都使用同一个结构种类，不依赖各区块群系来区分变种。
- 1.18.2-pre1：起始记录和引用分别使用它们所在区块的群系进行转换。含有多种可映射群系时，按这些群系在各区段调色板中的出现次数选择，并不直接读取原建筑的真实变种。

这会造成三种具体结果：

- 旧废弃传送门所在区块没有命中沙漠、丛林、山地或海洋映射时，转换结果是未注册的 `minecraft:ruined_portal_standard`。例如纯平原、沼泽和下界群系的区块会落入此情况；实际标准配置的 ID 是 `minecraft:ruined_portal`。加载器因此丢弃相应的结构起始记录或引用，定位和结构位置条件可能不再识别该处传送门。已生成的黑曜石、箱子等方块仍保留。
- 横跨不同群系区块的旧村庄、沉船、矿井等，起始区块与引用区块可能被转换成不同变种。例如起始记录被转换为沙漠村庄，而相邻平原区块把引用转换为平原村庄；从后者查询时找不到对应起始记录，结构位置条件会在该处失效。
- 定位功能扫描未加载的旧区块时，只读取版本号和结构起始摘要，不读取用于判别变种的群系。转换会先落到默认变种，例如把旧沙漠村庄视为平原村庄。因此直接定位 `minecraft:village_desert` 可能跳过尚未完整加载升级的旧沙漠村庄；定位 `#minecraft:village` 仍可以命中这个被归为平原变种的村庄。完整加载区块后，起始记录才按实际保存的群系转换。

## 升级已有超平坦世界后，原结构白名单不再限制新区块

超平坦生成设置把旧的 `structures` 改为 `structure_overrides`。前者没有在本版转换为后者；新字段缺省时会启用注册表中的全部结构组，再由群系和各结构自身条件筛选。

### 差异出现的场景

升级一个在旧版明确只允许部分结构、或不允许任何结构的超平坦世界，并继续生成新区块。世界总设置仍允许生成结构。

### 版本变化

- 22w07a：使用存档内 `structures` 指定的名单和分布参数。例如“红石就绪”预设的空结构名单会阻止所有结构生成。
- 1.18.2-pre1：旧字段被忽略，缺少 `structure_overrides` 的旧设置采用全部结构组。上述世界的后续区块可能生成符合群系与地形条件的村庄、沙漠神殿、废弃传送门等，旧版的单独禁用和自定义间距也不再生效。

本版新建并通过界面选择内置超平坦预设时，会写入新的结构组名单；显式填写空的 `structure_overrides` 仍能禁止结构。世界总开关关闭结构生成时，仍不会创建结构起始记录。

## 同一种子中新生成的部分结构箱子改变战利品种子

结构放置阶段改为按具体配置分配随机序号，导致部分结构即使位置和建筑布局不变，箱子的战利品种子也会改变。例如埋藏的宝藏在旧版地下结构放置顺序中排在普通矿井之后，本版增加恶地矿井的独立位置后，它的序号向后移动；普通沉船的放置序号也发生变化。

因此，在同一种子、同一坐标重新生成这些结构，箱内物资可能与 22w07a 不同。变化影响本版才放置的箱子；已生成箱子保存的战利品种子不会因此重新抽取。

## 结构分布、专属刷怪和地形适配可由数据包分别控制

旧版数据包提供同一结构种类的多个配置时，共用该种类在生成设置中的分布，生成时按注册顺序尝试。新版增加 `worldgen/structure_set`，可以为具体结构配置安排独立的分布，或把多个配置放在一组按权重选择；一个候选失败时继续尝试组内剩余候选。同一区块也能够分别保存不同结构配置的起始记录。

结构配置还增加 `spawn_overrides`，可以按生物类别替换自然刷怪列表，并选择仅在部件范围还是整体结构范围生效；`adapt_noise` 控制是否让地形在结构周围适配，缺省为 `false`。

这些修改也影响已有自定义世界与数据包的兼容性：

- 旧噪声生成设置内的 `structures` 不再决定分布，需要把配置移到结构组。旧格式的自定义噪声设置还缺少新版必需的 `noise_router`，不能原样继续使用。
- 旧的自定义结构配置需要补上 `spawn_overrides` 字段。原来依靠结构种类自动获得的女巫、守卫者等专属刷怪，现在需要在具体配置里明确提供；自定义村庄等若要保留周围地形适配，也需要相应设置 `adapt_noise`。
- 新增 `worldgen/density_function` 注册表与噪声路由配置，可以分别替换用于地形、洞穴、含水层、气候取样和矿脉的密度函数。旧的噪声洞穴、面条洞穴布尔开关从噪声设置中移除，相关取舍改由密度函数组合表达。数据包格式号从 8 升为 9。

## 定位命令、结构位置条件和探险地图改用具体结构配置

- `/locate` 现在接收具体结构配置 ID 或结构标签。旧的 `/locate village`、`/locate ocean_ruin` 等种类名不再有效，应使用 `#minecraft:village`、`#minecraft:ocean_ruin` 搜索整类，或用 `minecraft:village_desert` 等只搜索指定变种。`minecraft:shipwreck`、`minecraft:mineshaft`、`minecraft:ruined_portal` 现在分别只包含普通沉船、普通矿井、标准废弃传送门；要覆盖全部变种需使用对应同名标签。末地城的配置 ID 为 `minecraft:end_city`，替代旧的 `endcity`。
- `/locatebiome` 同样支持 `#` 开头的群系标签，可以一次搜索标签包含的多个群系。通过标签定位时，两条命令的成功结果都会注明实际命中的配置或群系。
- 进度及其他位置谓词的 `feature` 从结构种类改为具体配置 ID，仍要求位置在该结构部件内。旧的 `village` 不再匹配所有村庄；`shipwreck` 只匹配普通沉船。该字段没有同时增加标签语法，原来按整类结构检测的数据包需要把各变种条件分别列出。
- `exploration_map` 战利品函数的 `destination` 从结构种类改为结构标签名，字符串本身不带 `#`。例如原来显式写 `buried_treasure` 的自定义战利品表，现在需要改为 `minecraft:on_treasure_maps` 等有效标签；不存在的目标标签会使函数保留原空地图。省略目标时，默认使用埋藏的宝藏标签。制图师的两种探险地图也分别由 `on_ocean_explorer_maps`、`on_woodland_explorer_maps` 标签决定目标。
