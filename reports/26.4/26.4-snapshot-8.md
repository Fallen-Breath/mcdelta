# Minecraft 26.4 Snapshot 8 变更分析

- 上一个版本：`26.4-snapshot-7`
- 当前版本：`26.4-snapshot-8`

## 矿车改用记录位置累计落距，普通矿车恢复坠落结算

矿车结算坠落时改为读取当前位置与上次记录位置的高度差。普通矿车因此恢复落距累计；启用“矿车改进”实验时，同一刻内从斜轨驶出后的落距计算也会改变。

### 差异出现的场景

未启用“矿车改进”实验的世界中，矿车脱离铁轨后下落并落在会处理坠落的方块上；包括载有生物或玩家的矿车，以及 TNT 矿车。

启用该实验时，另一处差异出现在矿车同一刻先沿下降斜轨移动、随后驶离轨道继续下落，且这两个移动步骤之间没有落地的情况。

### 版本变化

普通矿车下落：

- Snapshot 7：普通矿车处理接触方块的效果时，把移动起点和终点都设为当前位置，传入坠落结算的高度变化为 0。正常下落不能由这一路径累计落距，依赖落距的乘客摔伤和 TNT 矿车落地爆炸不会据此触发。
- Snapshot 8：矿车使用当前位置与上次记录位置的高度差累计落距，再进行落地结算。普通乘客会按落距及其自身减伤、免伤条件承受摔落伤害；TNT 矿车的累计落距达到 3 格时，会进入落地爆炸处理。

实验性运动中，同一刻从下降斜轨驶出并继续下落：

- Snapshot 7：第一次处理离轨步骤的方块效果时，按这一离轨步骤记录的位移累计落距。
- Snapshot 8：改用当前位置与最后一次在轨步骤起点的高度差；因此，这次结算额外包含最后一个在轨步骤的下降量。实验性矿车原有的逐步处理及每步两次检查仍然存在，主要变化是第一次离轨结算采用的起点。

### 实际影响

利用普通矿车把玩家或生物直接送下高处、落在普通地面上的运输结构，现在需要考虑乘客摔伤。利用 TNT 矿车从高处落地的装置，也重新受到落距爆炸条件控制。

启用矿车改进实验时，从下降斜轨末端高速驶出后落地的矿车，累计落距可能比旧版更大，处于摔伤或 TNT 矿车爆炸阈值附近的装置也会改变结果。

## 骑乘时的爆炸推动改为作用于载具，玩家攻击也会同步受控载具的速度

新版把爆炸造成的速度增量直接发给负责移动的玩家客户端，并排除仍在乘坐其他实体的乘客。玩家攻击受控载具时，也会把击退后的速度直接发给控制它的玩家。

### 差异出现的场景

玩家骑马、划船等，由玩家客户端控制载具运动时，载具或乘客处于爆炸范围内；或者另一名玩家攻击这类载具，且攻击使载具需要同步速度。爆炸推动的乘客排除条件，以处理推动时是否仍保持骑乘关系为准。

### 版本变化

- Snapshot 7：爆炸会给乘客和载具分别添加速度；符合条件的玩家还会从爆炸效果消息中取得自身冲量。对客户端控制的载具，服务端添加的冲量没有采用直接发给控制者的专门路径。玩家攻击后的即时速度同步也只专门处理被攻击者本身是玩家的情况。
- Snapshot 8：仍在骑乘其他实体的乘客不再单独获得爆炸冲量。载具若由玩家控制，爆炸冲量发给该控制者，由客户端加到载具当前速度上；其他实体继续在服务端获得冲量。玩家攻击后需要同步速度时，检查范围扩展到被攻击实体的控制者，因此受控载具也会立即收到更新后的速度。

### 实际影响

骑乘中的移动结果主要由载具受到的爆炸推动决定，乘客不再另外积累一份爆炸速度。利用爆炸或近战推动有人驾驶的载具时，新版会把对应速度更新直接交给驾驶者；乘客自身不再额外取得一份爆炸推动。爆炸伤害仍在是否推动的检查之前处理；若爆炸已破坏载具并解除骑乘关系，乘客可能按独立实体继续结算推动。

## 冻结免疫扩展至所有亡灵生物

冻结免疫名单从单独列出的部分亡灵生物改为引用整个 `minecraft:undead` 实体类型标签。

### 差异出现的场景

原本未列入冻结免疫名单的亡灵生物接触细雪，或受到能够累积冻结程度的“冰冻”效果。

### 版本变化

- Snapshot 7：免疫名单包含流浪者、凋灵、冻尸、僵尸、溺尸和尸壳，以及北极熊和雪傀儡；其他亡灵生物仍可能累积冻结程度并承受冻结伤害。
- Snapshot 8：整个亡灵标签中的生物都不能继续累积冻结程度，也不会承受完全冻结后的周期伤害。新增覆盖包括骷髅、凋灵骷髅、沼骸、焦骸、骷髅马、僵尸马、僵尸村民、僵尸猪灵、僵尸疣猪兽、骆驼尸壳、僵尸鹦鹉螺和幻翼。

### 实际影响

利用细雪或冰冻效果伤害上述新增免疫生物的处理装置失去这条伤害来源。数据包对亡灵标签的增删，也会连带改变冻结免疫范围。

## 填充蓝冰的硫方怪取消上浮，只把水源变为霜冰

默认数据中，蓝冰使硫方怪获得冷型特性。新版同时调整这一特性的液体运动与结冰条件。

### 差异出现的场景

硫方怪填充蓝冰后进入水或熔岩；或者它站在地面上、未骑乘其他实体，附近存在可被其结冰效果选中的水方块。结冰仍要求水上方为空气，并通过放置碰撞检查。

### 版本变化

- Snapshot 7：冷型特性会额外提供液体中的向上推力。结冰检查接受水方块中的水源和流水。
- Snapshot 8：冷型特性不再提供这份额外上浮推力；没有其他支撑或向上作用时，不再靠该特性维持上浮。结冰检查额外要求水处于水源状态，流水会保留。

### 实际影响

用蓝冰硫方怪浮在液体中运输的结构，其高度与运动过程会改变。围绕蓝冰硫方怪布置流水槽时，流水不再被转为霜冰，结冰位置会集中在符合条件的水源上。

## 洞穴雕刻范围限制到地形生成高度，下界顶部洞道会改变

新版使用地形生成范围与区块高度范围的交集限制洞穴雕刻，再保留顶部 7 格。此前顶部保护仅相对于区块的完整高度计算。

### 差异出现的场景

生成尚未存在的噪声地形区块，地形生成高度小于维度可用高度。默认下界符合这一条件：维度高度为 256 格，噪声地形只生成至 Y=127。

### 版本变化

- Snapshot 7：默认下界的雕刻上界按维度顶端计算，顶部 7 格保护落在远高于下界实际地形的位置；雕刻洞道可以延伸到 Y=121–127。
- Snapshot 8：默认下界普通新生成区块的雕刻上界为 Y=120，因此不会再由雕刻器挖通 Y=121–127 的方块。自定义维度也按生成范围和区块范围共同限制雕刻的上下边界。

### 实际影响

相同种子下，新生成下界区块靠近顶部的洞道结果会改变，已生成区块不会重算。旧地形升级区块原有的“不保留顶部 7 格”分支仍适用，因此不能把 Y=120 这一上限直接套用到该分支。这里限制的是雕刻器挖出的洞道，地形噪声自身形成的空腔仍按原有噪声规则决定。

## 末影龙更快地向飞行目标升降

末影龙根据当前阶段的飞行目标修正垂直速度，新版将每次修正的系数提高到原来的 10 倍。

### 差异出现的场景

末影龙正常运行 AI，当前阶段提供飞行目标，且目标高度与末影龙不同；例如巡航、接近返回传送门或向目标位置移动时。

### 版本变化

- Snapshot 7：目标的高度差经水平距离及阶段速度限制换算后，以 `0.01` 为系数加入垂直速度，升降调整较缓。
- Snapshot 8：相同换算结果以 `0.1` 为系数加入垂直速度，向高处或低处目标调整得更快。

### 实际影响

已有屠龙方案中，依据末影龙升降轨迹、接近位置和到达时间安排的攻击窗口会改变。提高的是逐刻垂直加速度修正，不能直接理解成所有飞行速度或到达时间都变为原来的 10 倍。

## 树木生成结束时补上遗漏的树冠边界更新

树木生成后会统一更新生成区域的外表面。新版把所有实际生成的树冠方块加入这一范围，补上仅靠树干距离遍历未能覆盖的位置。

### 差异出现的场景

树木自然生成、树苗长大，或通过命令放置树木地物；生成的部分树冠没有被树干距离更新遍历到。自定义树木使用不带树叶距离属性的方块作为树冠时，也会触发这一差异。

### 版本变化

- Snapshot 7：最终更新范围来自树干、根、装饰，以及树叶距离遍历覆盖到的位置。遗漏的树冠表面不会参加最终的相邻形状更新。
- Snapshot 8：所有生成的树冠位置都会并入最终更新范围，树冠外表面及其相邻方块会重新计算连接、支撑等状态。

例如数据包用实心方块作为树冠，生成后紧邻已有的墙：旧版可能留下尚未连接的墙形状，直到其他方块更新到来；新版会在树木生成结束时更新连接。这里的变化发生在树冠外表面，具体结果取决于相邻方块如何响应形状更新。

## 负时间参数现在可以通过部分命令解析

不带显式下限的时间参数由“至少 0”改为允许整个整数范围，使 `/time set`、`/schedule function` 和 `/title ... times` 的负数输入产生实际行为。

### 差异出现的场景

输入这些命令时使用转换后仍为负数的时间，例如 `-1t`，并具备执行命令的权限。

### 版本变化

- Snapshot 7：上述位置的负时间会在参数解析阶段被拒绝。
- Snapshot 8：`/time set -1t` 可以把对应时钟的总刻数直接设为 -1；`/schedule function <函数> -1t` 会把事件安排到当前游戏时间之前；`/title <目标> times -1 40 -1` 会只更新停留时间，客户端保留原有的淡入和淡出时间。

定时队列每次处理所有触发时间不晚于当前游戏刻的事件。因此，负延时事件会在下一次处理队列时到期；若正在执行定时回调，它新增的负延时事件也能在同一次队列处理中继续执行。标题的负时间则被客户端当作“保留这一项”的条件，不会成为负的显示时长。

### 实际影响

依赖“负延时必定报错”的函数分支现在会真的安排回调。若定时函数反复以负延时并使用 `replace`（含省略模式时的默认行为）安排自身，队列会在当前游戏刻持续处理新的到期事件，可能使世界停留在这一刻。

## 战利品数据缺少必需上下文时，会阻止数据包重载

新版将无法提供必需参数的战利品数据从警告提升为错误，同时允许校验器识别在特定上下文中必定不成立的条件。

### 差异出现的场景

数据包的战利品表、物品修饰器等，在实际声明的上下文中使用了无法取得的参数。例如箱子类型的战利品表无条件使用依赖工具的 `minecraft:apply_bonus`。

### 版本变化

- Snapshot 7：缺少上下文参数通常记录警告，数据包重载仍可成功。以上例子中，修饰器运行时找不到工具，会保留原数量而不应用工具附魔加成。

### 实际影响

## 命令资源提前校验，错误参数可能使整份函数无法加载

新版把部分资源存在性检查和战利品上下文检查提前到命令解析或函数编译阶段，改变了错误发生的时间和波及范围。

### 差异出现的场景

命令引用不存在的进度、配方、结构或模板池，或使用无法在该命令上下文运行的战利品资源。尤其是将这类命令放进 `.mcfunction`，并指望外层 `execute` 条件让它不被执行。

### 版本变化

- Snapshot 7：进度、配方等部分资源参数先解析为名称，运行命令时才查找实际资源。即使函数中含有不存在的这类名称，函数也可以编译加载，直到对应命令真正运行时才报错。命令使用战利品资源时，也没有统一按调用处上下文提前校验。
- Snapshot 8：这类资源名称在解析时就查找，找不到会成为解析错误。战利品表、修饰器、数值提供器和槽位来源也按调用处能够提供的参数校验；例如 `/loot ... loot` 使用箱子上下文，`/loot ... fish` 使用钓鱼上下文。

### 实际影响

普通函数中只要有一行出现这类解析或校验错误，整份函数就无法加载，其他正确的行也不会执行；即使该行原本位于不会通过的 `execute` 条件后面也一样。宏替换后的命令按同样规则解析和校验，错误会使这次宏实例化失败。

## 调试世界的实体展示网格收紧边界

调试世界会按网格生成实体展示。新版修正了网格最外沿的坐标限制。

### 差异出现的场景

调试世界生成新的实体展示区域，位置换算后的网格坐标恰好等于网格宽度或高度，且旧版继续算出的索引仍对应有效实体。

### 版本变化

- Snapshot 7：允许网格坐标等于宽度或高度，部分越界位置仍会额外生成实体展示。
- Snapshot 8：只允许坐标小于宽度和高度，上述最外沿越界位置不再额外生成实体。已经生成的实体不会因此删除。
