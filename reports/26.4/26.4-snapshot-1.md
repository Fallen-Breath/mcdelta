# Minecraft 26.4 Snapshot 1 变更分析

- 上一个版本：`26.3`
- 当前版本：`26.4-snapshot-1`

## 蘑菇可以在强光下放置，但自然扩散出现异常

红色蘑菇和棕色蘑菇的存活检查与自然扩散检查在新版分开。手动放置取消了光照限制，自然扩散则改变了光照、支撑方块和目标是否为空气的判断。

### 差异出现的场景

在普通完整、不透光方块上放置蘑菇，或让蘑菇在附近自然扩散。扩散仍受随机刻及附近同种蘑菇数量限制；下述目标均指扩散过程选中的候选位置。

### 版本变化

- 26.3：普通支撑方块上要求蘑菇所在位置的亮度低于 13；菌丝体、灰化土、绯红菌岩和诡异菌岩豁免光照限制。自然扩散还要求目标为空气。
- 26.4-snapshot-1：放置和存活只检查下方是否为完整、不透光方块，不再检查亮度。自然扩散拒绝普通完整方块上方的空气，即使那里足够暗；菌丝体、灰化土和两种菌岩上方的目标则直接通过检查，即使已经有方块占据。

新版还有另一种可通过扩散检查的情况：下方不满足普通支撑要求、目标亮度至少为 13，且目标原来不是空气。上述非空气目标会被新蘑菇替换；缺乏支撑的新蘑菇可能在后续方块更新时消失，但原有方块已经被替换。

### 实际影响

依靠普通地板繁殖蘑菇的暗室失去原有扩散条件。菌丝体等材料上方的已有方块又可能被扩散覆盖，因而手动种植成功的位置与适合自然繁殖的位置不再一致。

## 含水铜格栅不再把内部水源视为下落水流

含水铜格栅内部保存的是水源，但旧版还为其设置了下落标记。新版移除该标记，改变满足特定邻接条件时的水流方向。

### 差异出现的场景

实体接触含水铜格栅内部的水、能够受到水流推动，且格栅水平方向的邻位或该邻位上方满足水流的固体侧面判断。所有氧化程度和涂蜡状态的铜格栅都适用。

### 版本变化

- 26.3：内部水源带有下落标记，在上述邻接条件下，水流计算会加入向下分量。
- 26.4-snapshot-1：内部水源不再带有下落标记，因此不再由这一标记产生向下水流；接触该含水区域的实体可能获得不同的竖直推动。

## 在水或熔岩中靠墙上浮需要跳跃或游泳状态

通常的液体移动会在撞墙时检查前上方空间，帮助实体越过岸边。新版为这次辅助上浮增加了动作条件。

### 差异出现的场景

使用通常液体移动方式的玩家或生物横向撞到墙壁，且其上方有足够空间，满足原有的出水空间检查。

### 版本变化

- 26.3：碰撞和空间条件满足时，会直接把向上速度设为 0.3，即使实体没有跳跃，也没有处于游泳状态。
- 26.4-snapshot-1：只有正在跳跃或处于游泳状态时，才执行这一步向上推动。

因此，玩家仅向岸边移动时不再必然获得这次上浮；保持跳跃或游泳仍可触发。依靠实体在水边、熔岩边碰墙自动抬升的运输或困住实体的布局，也会受到同一条件约束。采用独立游动逻辑的实体应以各自移动实现为准。

代码出处：[26.3：旧碰墙推动](https://github.com/TISUnion/guardian/blob/d5822ca2a1bd154ee42b8610f8b169b5c601b619/src/main/java/net/minecraft/world/entity/LivingEntity.java#L2558)；[26.4-snapshot-1：新增跳跃或游泳条件](https://github.com/TISUnion/guardian/blob/b9de237a46a3ec9a8a970c768b2b973573d4a2d4/src/main/java/net/minecraft/world/entity/LivingEntity.java#L2558)；[26.4-snapshot-1：水中调用](https://github.com/TISUnion/guardian/blob/b9de237a46a3ec9a8a970c768b2b973573d4a2d4/src/main/java/net/minecraft/world/entity/LivingEntity.java#L2507)；[26.4-snapshot-1：熔岩中调用](https://github.com/TISUnion/guardian/blob/b9de237a46a3ec9a8a970c768b2b973573d4a2d4/src/main/java/net/minecraft/world/entity/LivingEntity.java#L2540)。

## 朝下的物品展示框把掉落物生成在更低位置

物品展示框生成掉落物时，新版为朝下的展示框增加了竖直偏移，改变掉落物最初出现的位置。

### 差异出现的场景

破坏安装在方块底面、朝下的物品展示框或荧光物品展示框，或者只打掉框内物品，并且满足原有的物品掉落条件。

### 版本变化

- 26.3：展示框和内容物使用默认的掉落高度。
- 26.4-snapshot-1：两者的生成位置都比旧版低 0.25 格。只打掉框内物品时也采用这个偏移，因此紧贴天花板布置的收集区域会面对更低的初始掉落位置。

代码出处：[26.3：旧掉落位置](https://github.com/TISUnion/guardian/blob/d5822ca2a1bd154ee42b8610f8b169b5c601b619/src/main/java/net/minecraft/world/entity/decoration/ItemFrame.java#L232)；[26.4-snapshot-1：朝下展示框的偏移](https://github.com/TISUnion/guardian/blob/b9de237a46a3ec9a8a970c768b2b973573d4a2d4/src/main/java/net/minecraft/world/entity/decoration/ItemFrame.java#L222)。

## 生物重复请求同一路径时不再不断重置卡住检查

生物沿路径移动时，会约每 100 个寻路刻检查一次实际位移，移动距离不足便停止当前导航。新版收紧了这项检查的重置条件。

### 差异出现的场景

生物 AI 持续重复请求同一条路径，但生物停滞或移动缓慢，没有推进到下一个路径节点。

### 版本变化

- 26.3：每次接受移动请求都会重置检查的计时和起点，即使请求的路径没有改变。持续重复请求可以一直推迟这项卡住检查。
- 26.4-snapshot-1：只有路径改变，或导航前进到下一个路径节点时，才重置检查。在上述场景中，检查计时可以继续累积，位移不足时会停止导航。

针对单个节点的超时判断仍独立存在。本次改变的是重复导航请求对位移检查的影响，是否停止导航仍取决于路径推进和实际位移。

代码出处：[26.3：旧请求重置检查](https://github.com/TISUnion/guardian/blob/d5822ca2a1bd154ee42b8610f8b169b5c601b619/src/main/java/net/minecraft/world/entity/ai/navigation/PathNavigation.java#L213)；[26.4-snapshot-1：按路径是否改变决定重置](https://github.com/TISUnion/guardian/blob/b9de237a46a3ec9a8a970c768b2b973573d4a2d4/src/main/java/net/minecraft/world/entity/ai/navigation/PathNavigation.java#L198)；[26.4-snapshot-1：推进节点时重置](https://github.com/TISUnion/guardian/blob/b9de237a46a3ec9a8a970c768b2b973573d4a2d4/src/main/java/net/minecraft/world/entity/ai/navigation/PathNavigation.java#L352)；[26.4-snapshot-1：位移与节点超时检查](https://github.com/TISUnion/guardian/blob/b9de237a46a3ec9a8a970c768b2b973573d4a2d4/src/main/java/net/minecraft/world/entity/ai/navigation/PathNavigation.java#L300)。

## 旁观者进入末地不再重建黑曜石平台

通过末地传送门进入末地时，平台生成会重建出生黑曜石平台并清理其上方空间。新版让旁观者跳过这一步。

### 差异出现的场景

旁观者通过末地传送门进入末地，出生平台或其上方空间已经被玩家改动。

### 版本变化

- 26.3：旁观者进入末地同样会触发平台生成，重置平台并清理上方空间。
- 26.4-snapshot-1：旁观者不会触发这次平台生成，已有平台及清理范围内的建筑得以保留。其他会执行平台生成的实体仍按原有方式处理。

代码出处：[26.3：旧平台生成](https://github.com/TISUnion/guardian/blob/d5822ca2a1bd154ee42b8610f8b169b5c601b619/src/main/java/net/minecraft/world/level/block/EndPortalBlock.java#L88)；[26.4-snapshot-1：旁观者豁免](https://github.com/TISUnion/guardian/blob/b9de237a46a3ec9a8a970c768b2b973573d4a2d4/src/main/java/net/minecraft/world/level/block/EndPortalBlock.java#L88)。

## 生物群系按单个方块保存，环境规则与精细修改使用同一边界

新版按单个方块保存细化后的生物群系，而旧版每 4×4×4 格保存一个采样值，再在查询时生成不规则边界。这同时改变了 `/fillbiome` 的实际修改范围，以及一部分环境属性在边界附近的取值。

### 差异出现的场景

使用 `/fillbiome` 修改小区域，或在两个环境属性不同的生物群系交界处运行装置。例如，雪傀儡所在方块显示为安全生物群系，但旧版粗采样却落在会使其融化的生物群系一侧。

### 版本变化

- 26.3：`/fillbiome` 的两个角点向下对齐到 4 格网格，修改整组采样点；实际生物群系边界还受细化过程影响。除自然生物生成设置等少数属性外，生物群系环境属性通常直接使用粗采样点，可能与该方块的生物群系查询结果不同。
- 26.4-snapshot-1：`/fillbiome` 精确修改给定的方块坐标范围，返回的修改数量也按实际改变的方块计数；生物群系环境属性直接读取该位置保存的生物群系。雪傀儡融化、沼泽地表史莱姆生成机会等规则在交界处可能随之改变。

旧区块升级时先保留原来的采样数据，再重新细化生物群系，并跳过已经完成的地形、建筑和光照等生成阶段。新版的天空、雾和水下雾等平滑环境效果则从方块生物群系采样，过渡表现也可能改变。`/fillbiome` 的体积限制按输入范围计算，不再先把角点对齐到 4 格网格。

## 洞穴生物群系的湿度分界和参数上界判定改变

主世界的多噪声选择根据参数距离决定生物群系。新版缩小溶洞和硫黄洞穴的湿度候选范围，同时改变参数上界的距离计算，影响相同种子中新生成区域的生物群系分布。

### 差异出现的场景

新生成主世界区域，某位置符合地下洞穴候选条件，且湿度位于繁茂洞穴一侧；或者噪声值恰好落在候选参数区间的上界附近。

### 版本变化

- 26.3：溶洞和硫黄洞穴候选覆盖全部湿度，与繁茂洞穴的高湿区间重叠；参数取到区间上界时，仍可按处于区间内计算距离。
- 26.4-snapshot-1：溶洞和硫黄洞穴候选的湿度上界改为 0.7，减少与繁茂洞穴的高湿范围重叠；参数上界按不包含端点计算，改变交界处候选的距离和竞争结果。

参数上界的改动适用于整个多噪声选择，因此洞穴以外的参数交界也可能选出不同生物群系。

## 旧高度世界的地下补生成可以出现硫黄洞穴

旧高度世界在 Y＜0 区域补生成时，会限制新加入的地下生物群系。新版将固定名单改为标签，并扩大了默认名单。

### 差异出现的场景

升级来自旧高度世界的区块，在 Y＜0 的区域执行地下补生成，且生物群系选择结果为硫黄洞穴。

### 版本变化

- 26.3：补生成只允许繁茂洞穴、溶洞和深暗之域作为新的地下生物群系，硫黄洞穴不在名单中。
- 26.4-snapshot-1：改用 `generated_in_below_zero_retrogen` 标签，默认名单还包含硫黄洞穴，因此上述补生成区域可以出现硫黄洞穴。

## 升级后的主世界地形加入接壤混合

地形混合让后续生成的区域参考已有区块的高度、密度和生物群系。新版为从 26.3 升级的主世界地形补写这类混合信息。

### 差异出现的场景

将已经在 26.3 生成主世界地形的存档升级到新版，再到这些区域外继续生成新区块。

### 版本变化

- 26.3：本版本生成的区块不会作为需要混合的旧地形处理。
- 26.4-snapshot-1：升级转换为这些区块写入新的地形混合信息，后续生成的接壤区域可以依据已有地形进行过渡。变化发生在之后生成的区域，已有方块会保留。

代码出处：[26.4-snapshot-1：新增地形混合转换](https://github.com/TISUnion/guardian/blob/b9de237a46a3ec9a8a970c768b2b973573d4a2d4/src/main/java/net/minecraft/util/datafix/DataFixers.java#L1712)；[26.4-snapshot-1：主世界混合数据](https://github.com/TISUnion/guardian/blob/b9de237a46a3ec9a8a970c768b2b973573d4a2d4/src/main/java/net/minecraft/util/datafix/fixes/BlendingDataFix.java#L35)。

## 部分树木生成时不再立即替换树干下方方块

部分树木使用直树干生成方式，原本会在放置树干前应用下方方块提供器。新版省去这一步，使生成瞬间的地面方块得以保留。

### 差异出现的场景

自然生成或通过树苗长成使用直树干生成方式的树木，例如普通橡树、白桦、单株云杉、单株丛林树和丛林灌木；树干下方存在草方块、菌丝体或自定义换土规则会替换的其他方块。

### 版本变化

- 26.3：先应用树干下方的方块提供器，例如把草方块或菌丝体替换为泥土，再生成树干。
- 26.4-snapshot-1：直接生成树干，不再执行这次替换。自定义树木原本通过 `below_trunk_provider` 为这类树干换土的配置也随之失效。

保留的是生成瞬间的地面状态，草方块之后仍可能因树干遮光退化为泥土。新版还允许指定 `trunk_width`，默认仍为 1，已有单格树干不会因此自行变粗。

## 洞穴切穿地表后的覆土处理扩大适用范围

洞穴切穿地表时，生成器可能为下方新露出的泥土重新应用地表材料。新版将这一步并入地形填充，扩大了触发条件。

### 差异出现的场景

新生成的洞穴切除了某段固体的顶部，下方泥土因此暴露。差异尤其出现在顶部使用草方块、菌丝体以外材料的地形，包括自定义材料规则生成的地形。

### 版本变化

- 26.3：只有雕刻移除了草方块或菌丝体后，才会尝试把下方露出的泥土转换为当地地表材料。
- 26.4-snapshot-1：只要洞穴雕刻移除了该段固体的顶部，之后遇到的泥土就可能按表层深度为 1 重新执行地表规则；原顶部不必是草方块或菌丝体。因此同样的洞口可能出现不同的表层材料。

## 含雪层或空气层的超平坦配置可能在生成建筑时失败

超平坦会将部分特殊层留到后续生成步骤填入。新版合并了原始地形柱与高度查询，但遗漏了这些暂时留空的层。

### 差异出现的场景

超平坦世界包含雪层、空气等不计入阻挡移动高度图的层，且某个建筑生成过程需要查询原始地形柱或地形高度。例如“雪之王国”预设启用了村庄和雪屋，并包含一层雪。

### 版本变化

- 26.3：这类层先转交给后续特性生成，地形层列表中的对应位置留空；高度查询会跳过空位置，地形柱查询会把它们当作空气。
- 26.4-snapshot-1：新的地形柱查询直接对每个列表元素检查是否为空气，没有处理上述空位置，会触发空指针异常。村庄等建筑投射到地形高度时也改为经过此查询，因此会导致相应区块生成失败。

普通的草方块、泥土和基岩层不满足这个触发条件。该问题来自地形高度查询，不能仅凭存在雪层就判定所有区块都会立刻失败。

## 材料规则不再使用 default_block 补齐地形

### 差异出现的场景

- 26.4-snapshot-1：不再读取 `default_block`，材料规则返回空结果的位置会留空。原版主世界规则已经显式补入石头兜底；自定义规则需要自身提供兜底，才能继续得到完整的固体地形。

## cuboid 的尺寸参数改为实际边长

`cuboid` 放置修饰器按给定尺寸遍历一个长方体区域。新版改变尺寸参数的含义，影响沿用旧参数的自定义生成配置。

### 差异出现的场景

自定义特性使用 `cuboid`，升级后保留相同的 `xz_size` 和 `y_size` 数值。

### 版本变化

- 26.3：尺寸参数表示包含最大坐标的范围。例如填 3 时遍历 0 到 3，每轴共 4 格。
- 26.4-snapshot-1：尺寸参数表示实际边长。同样填 3 时遍历 0 到 2，每轴共 3 格，因此未调整的配置会在相应轴上缩小一格。

原版暖水海洋珊瑚配置将 3–5 同步改为 4–6，补偿这项含义变化并维持原来的尺寸。

## 生物群系引用的特性新增水平候选范围校验

新版在加载生物群系注册表时检查顶层已放置特性的水平候选范围，过大的放置范围会成为加载错误。

### 差异出现的场景

数据包让生物群系引用一个顶层已放置特性，其放置修饰器组合计算出的候选坐标，可能超出生成区块原点的 X/Z 相对范围 −16 至 31。

### 版本变化

- 26.3：没有这项注册表校验，上述配置可以通过这一阶段的加载。

## 服务器可以要求地址携带指定连接 ID

新版支持服务器地址参数，并以 `_id` 属性实现登录、服务器转移和状态查询的连接筛选。

### 差异出现的场景

专用服务器设置 `allowed-connection-ids=alpha,beta`，玩家使用普通地址，或使用 `alpha@example.com:25565`、`example.com:25565?_id=alpha` 连接或刷新服务器列表；转移到这台服务器时也适用。

### 版本变化

- 26.3：没有这项服务器筛选；客户端也没有将 `@` 前缀或 `?` 参数解析为连接属性的机制。
- 26.4-snapshot-1：配置为空时接受普通连接；配置非空时，只接受 `_id` 与列表某一项精确匹配的连接。缺少或填错 ID 的登录、转移和现代状态查询都会在握手阶段被关闭。列表按逗号分隔，去除条目首尾空格并忽略空项。

新版地址可附加 `?key=value&other=value`，参数按 URL 表单规则编码；`id@` 简写会覆盖参数中的 `_id`。客户端将参数带入握手，并在 DNS/SRV 解析改变主机或端口时，通过 `_o` 记录原始地址。

### 实际影响

启用筛选后，保存的服务器地址、直连地址及转移入口都需要携带匹配的 ID。转移数据包虽然新增了属性映射，原版 `/transfer` 仍发送空映射，不能通过命令的主机参数替代这份映射传递连接 ID，因此常规 `/transfer` 转入受限服务器也会被拒绝。ID 由客户端提供，这项筛选不会增加用户身份验证。

## 联机脚下方块纠错改用移动后的位置

服务器在客户端报告着地、上一轮服务端状态却没有脚下支撑时，会按既有冷却时间重发脚下方块。新版将取样时机移到本次玩家移动之后。

### 差异出现的场景

客户端移动数据包报告玩家已经着地，服务器记录的上一轮状态没有脚下支撑，且纠错冷却已满足；玩家本次移动后，脚下范围与移动前不同，例如横向走到客户端与服务器方块状态不一致的位置。

### 版本变化

- 26.3：处理本次移动前，先根据旧站位选取脚下方块并发送纠错数据。
- 26.4-snapshot-1：先移动玩家，再根据移动后的站位选取脚下方块。纠错数据因此针对新的位置，改善这类站位变化时的方块不同步恢复。

代码出处：[26.3：旧发送时机在 move 之前](https://github.com/TISUnion/guardian/blob/d5822ca2a1bd154ee42b8610f8b169b5c601b619/src/main/java/net/minecraft/server/network/ServerGamePacketListenerImpl.java#L1176)；[26.4-snapshot-1：新版先移动后发送](https://github.com/TISUnion/guardian/blob/b9de237a46a3ec9a8a970c768b2b973573d4a2d4/src/main/java/net/minecraft/server/network/ServerGamePacketListenerImpl.java#L1176)；[26.4-snapshot-1：脚下方块范围及冷却](https://github.com/TISUnion/guardian/blob/b9de237a46a3ec9a8a970c768b2b973573d4a2d4/src/main/java/net/minecraft/server/network/ServerGamePacketListenerImpl.java#L1261)。

## 客户端数据包处理异常改为抛出崩溃异常

客户端处理已解码数据包出错时，新版在通常的断线处理之前调用默认异常处理，使这类错误直接作为崩溃异常传播。

### 差异出现的场景

客户端已经成功解码一个数据包，但在执行该数据包的处理逻辑时抛出异常。普通网络断线或数据包解码失败不直接属于这个场景。

### 版本变化

- 26.3：保存断线报告并退出服务器，按数据包错误断线流程结束当前连接。
- 26.4-snapshot-1：先调用默认报错处理，抛出包含数据包信息的崩溃异常，后面的保存断线报告和通常断线步骤不再继续执行。

## 事件循环不再吞掉通常任务异常

客户端和服务器通过事件循环执行任务。新版移除了仅传播不可恢复异常的限制，改变任务出错后的继续运行行为。

### 差异出现的场景

事件循环执行某个任务时，抛出能被其异常处理捕获、但旧版没有认定为不可恢复的异常。

### 版本变化

- 26.3：记录错误日志后继续运行，只有被认定为不可恢复的异常才会重新抛出。
- 26.4-snapshot-1：记录日志后重新抛出所有捕获到的异常。因此某些旧版只留下日志的任务错误，现在会向外传播并可能中断运行。

## 区块加载错误仅对读写和 NBT 失败回退为空区块

区块读取失败时，旧版对广泛的错误采用空区块回退。新版限制了回退范围，将其他运行错误转为区块加载崩溃报告。

### 差异出现的场景

读取区块失败，解开异步或崩溃异常包装后，实际原因是 `IOException`、`NbtException` 以外的运行错误，而非 `Error`。

### 版本变化

- 26.3：对非 `Error` 的失败统一报告后返回空区块，后续可能重新生成该处地形。
- 26.4-snapshot-1：不再为上述运行错误返回空区块，而是抛出带区块位置的加载崩溃报告。只有读写或 NBT 一类失败仍保留原有空区块回退；`Error` 在两个版本中都会传播。

## NBT 浮点数转整数改用限幅和向下取整

浮点 NBT 被作为整数字段读取，或插入整数数组时，会执行数值转换。新版改变了 byte、short 的超范围转换和 float 转 long 的负小数转换。

### 差异出现的场景

命令或存档提供的浮点 NBT 超出 byte、short 的范围，或者提供带负小数部分的 float 并将其转成 long。通过浮点值驱动布尔字段时，也会使用其中的 byte 转换。

### 版本变化

- 26.3：转为 byte、short 时先向下取整再截取低位，超范围值可能回绕，例如向 byte 数组追加 `256.0f` 得到 `0b`。float 转 long 直接截去小数，`-0.5f` 得到 0。
- 26.4-snapshot-1：转为 byte、short 时先向下取整，再限制到目标类型的最小值或最大值；同样追加 `256.0f` 得到 `127b`。float 转 long 也先向下取整，同样的 `-0.5f` 得到 −1。

实体数据的布尔读取使用转换后的 byte。因此同样的超范围浮点值也可能得到不同真假结果，例如上述 256 从 byte 0 变为非零值。

代码出处：[26.3：旧 float 整数转换](https://github.com/TISUnion/guardian/blob/d5822ca2a1bd154ee42b8610f8b169b5c601b619/src/main/java/net/minecraft/nbt/FloatTag.java#L80)；[26.4-snapshot-1：新版向下取整及饱和转换](https://github.com/TISUnion/guardian/blob/b9de237a46a3ec9a8a970c768b2b973573d4a2d4/src/main/java/net/minecraft/nbt/FloatTag.java#L81)；[26.3：旧 double 截取低位](https://github.com/TISUnion/guardian/blob/d5822ca2a1bd154ee42b8610f8b169b5c601b619/src/main/java/net/minecraft/nbt/DoubleTag.java#L90)；[26.4-snapshot-1：新版 double 饱和转换](https://github.com/TISUnion/guardian/blob/b9de237a46a3ec9a8a970c768b2b973573d4a2d4/src/main/java/net/minecraft/nbt/DoubleTag.java#L91)；[26.4-snapshot-1：byte 数组追加转换](https://github.com/TISUnion/guardian/blob/b9de237a46a3ec9a8a970c768b2b973573d4a2d4/src/main/java/net/minecraft/nbt/ByteArrayTag.java#L118)；[26.4-snapshot-1：long 数组追加转换](https://github.com/TISUnion/guardian/blob/b9de237a46a3ec9a8a970c768b2b973573d4a2d4/src/main/java/net/minecraft/nbt/LongArrayTag.java#L124)；[26.4-snapshot-1：实体数据布尔读取](https://github.com/TISUnion/guardian/blob/b9de237a46a3ec9a8a970c768b2b973573d4a2d4/src/main/java/net/minecraft/world/level/storage/TagValueInput.java#L145)。

## 默认图形后端优先尝试 Vulkan，并调整启动回退

客户端的“默认”图形 API 选项决定后端尝试顺序。新版改为优先尝试 Vulkan，并同时调整旧选项升级、启动失败回退和 Vulkan 能力要求。

### 差异出现的场景

客户端使用“默认”图形 API 启动，或者从旧版升级图形选项。上次启动未正常结束、或设备缺少部分 Vulkan 能力时，也可能出现差异。

### 版本变化

- 26.3：默认先尝试 OpenGL，失败后才尝试 Vulkan；检测到上次启动未正常结束时，还会重置 Vulkan 偏好或强制尝试 OpenGL。Vulkan 要求包含 `VK_KHR_dynamic_rendering`、`VK_KHR_push_descriptor` 和 `dynamicRendering`。
- 26.4-snapshot-1：默认先尝试 Vulkan，再回退到 OpenGL；删除根据上次启动结果切换的分支，并在升级选项时重新应用一次默认图形 API 转换，因此旧配置中的后端选择可能被重置。Vulkan 不再要求上述三项能力，满足其余条件的设备也有机会使用该后端。

最终采用哪个后端仍取决于设备检查和初始化结果。
