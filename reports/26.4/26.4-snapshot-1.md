# Minecraft 26.4 Snapshot 1 变更分析

- 上一个版本：`26.3`
- 当前版本：`26.4-snapshot-1`

## 蘑菇可以在强光下放置，但自然扩散出现异常

红色蘑菇和棕色蘑菇的存活检查与自然扩散检查在新版分开；其中扩散判断同时改变了光照、支撑方块和目标位置是否为空的条件。

### 差异出现的场景

在普通完整、不透光方块上放置蘑菇，或让蘑菇在附近自然扩散。扩散仍受随机刻及附近同种蘑菇数量限制。

### 版本变化

- 26.3：普通支撑方块上要求目标处亮度低于 13；菌丝体、灰化土、绯红菌岩和诡异菌岩豁免光照限制。自然扩散还要求目标为空气。
- 26.4-snapshot-1：放置和存活只检查下方是否为完整、不透光方块，不再检查亮度。自然扩散却不再接受普通完整方块上方的空气，因此原有暗室蘑菇农场会停止向这种位置扩散。

新版对菌丝体、灰化土和两种菌岩上方的扩散目标直接放行，省去了空气检查；蘑菇因此可以替换这些方块上方已有的方块。另一路异常条件是：下方不满足普通支撑要求、目标亮度至少为 13，且目标原来不是空气时，也会被选为扩散位置。此时新蘑菇可能因缺乏支撑而在后续方块更新时消失，但被替换的方块已经改变。

### 实际影响

暗室中依靠普通地板繁殖蘑菇的设计失去原有扩散条件；改用菌丝体等材料时，上方原有方块又可能被扩散覆盖。强光下手动放置蘑菇与自然繁殖的条件已经不同。

## 含水铜格栅不再把内部水源视为下落水流

对于所有氧化程度、包括涂蜡状态的含水铜格栅，26.3 将内部水源标记为下落状态，26.4-snapshot-1 改为普通水源。旧版在附近满足水流的固体侧面判断时，会为该格栅内部的水流增加向下分量；新版不再因这个标记产生向下水流。接触该含水区域、会受水流推动的实体因此可能获得不同的竖直推动，使用含水格栅引导实体的装置需要按这一条件重新判断。

## 在水或熔岩中靠墙上浮需要跳跃或游泳状态

通常的液体移动会在撞墙时检查前上方空间，帮助实体越过岸边。新版为这次辅助上浮增加了动作条件。

### 差异出现的场景

使用通常液体移动方式的玩家或生物横向撞到墙壁，且其上方有足够空间，满足原有的出水空间检查。

### 版本变化

- 26.3：碰撞和空间条件满足时，会直接把向上速度设为 0.3，即使实体没有跳跃，也没有处于游泳状态。
- 26.4-snapshot-1：只有正在跳跃或处于游泳状态时，才执行这一步向上推动。

因此，玩家仅向岸边移动时不再必然获得这次上浮；保持跳跃或游泳仍可触发。依靠实体在水边、熔岩边碰墙自动抬升的运输或困住实体的布局，也会受到同一条件约束。采用独立游动逻辑的实体应以各自移动实现为准。

## 朝下的物品展示框把掉落物生成在更低位置

破坏朝下、安装在方块底面的物品展示框或荧光物品展示框时，在本来会掉落展示框或内容物的条件下，26.3 使用默认的掉落高度；26.4-snapshot-1 将两者的生成位置下移 0.25 格。只打掉框内物品时也使用这个偏移。这会改变紧贴天花板布置的收集区域内，掉落物最初出现的位置。

## 生物重复请求同一路径时不再不断重置卡住检查

生物沿路径移动时，另有一次约每 100 个寻路刻检查实际位移的判断；移动距离不足会停止当前导航。

- 26.3：每次接受移动请求都会重置这次检查的计时和起点，即使请求的是相同路径。持续重复请求同一路径的 AI 可以一直推迟这项检查。
- 26.4-snapshot-1：只有路径改变，或导航前进到下一个路径节点时，才重置这次检查。反复请求同一路径而又没有推进节点的生物，可以触发卡住判定并停止导航。

另一项针对单个节点的超时判断仍独立存在。因此，这一变化影响的是重复导航请求、停滞和缓慢推进之间的判定，不等于所有生物每隔五秒都必须重新寻路。

## 旁观者进入末地不再重建黑曜石平台

通过末地传送门进入末地时，26.3 对旁观者也会重建出生黑曜石平台并清理平台上方空间。26.4-snapshot-1 在此处跳过旁观者，已有平台及附近建筑不再因这次旁观者传送而被重置。其他会执行平台生成的实体仍走原有处理。

## 生物群系按单个方块保存，环境规则与精细修改使用同一边界

新版保存已经细化到每个方块的生物群系，而旧版每 4×4×4 格保存一个采样值，再在查询时生成不规则边界。这同时改变了 `/fillbiome` 的实际修改范围，以及一部分环境属性在边界附近的取值。

### 差异出现的场景

使用 `/fillbiome` 修改小区域，或在两个环境属性不同的生物群系交界处运行装置。例如，雪傀儡的位置处于显示为安全生物群系、但旧版粗采样落在会融化雪傀儡的生物群系一侧的位置。

### 版本变化

- 26.3：`/fillbiome` 的两个角点向下对齐到 4 格网格，修改整组采样点；实际生物群系边界还受细化过程影响。除自然生物生成设置等少数属性外，生物群系环境属性通常直接使用粗采样点，可能与该方块的生物群系查询结果不同。
- 26.4-snapshot-1：`/fillbiome` 精确修改给定的方块坐标范围，返回的修改数量也按实际改变的方块计数；生物群系环境属性直接读取该位置保存的生物群系。雪傀儡融化、沼泽地表史莱姆生成机会等规则在交界处可能随之改变。

旧区块升级时先保留原来的采样数据，再重新细化生物群系，并跳过已经完成的地形、建筑和光照等生成阶段。新版的天空、雾和水下雾等平滑环境效果则从方块生物群系采样，过渡表现也可能改变。`/fillbiome` 的体积限制按输入范围计算，不再先把角点对齐到 4 格网格。

## 洞穴生物群系选择和旧世界接壤生成调整

- 同时符合地下洞穴候选条件、湿度位于繁茂洞穴一侧的位置：26.3 的溶洞和硫黄洞穴候选覆盖全部湿度，与繁茂洞穴的高湿区间重叠；26.4-snapshot-1 将这两种候选的湿度上界改为 0.7，并将参数区间的上界按不包含端点计算，减少交界处由同等距离竞争产生的结果。相同种子新生成区域中的洞穴生物群系分布因此会变化。参数上界的变化适用于整个多噪声选择，洞穴以外的参数交界也可能产生不同结果。
- 对从旧高度世界补生成的 Y＜0 区域，26.3 只允许繁茂洞穴、溶洞和深暗之域作为新的地下生物群系；26.4-snapshot-1 使用 `generated_in_below_zero_retrogen` 标签，默认还包含硫黄洞穴。这类旧世界的地下补生成区域可以出现硫黄洞穴。
- 26.3 已经生成的主世界地形升级到新版时，会写入新的地形混合信息；26.3 本身不会把同版本区块作为旧地形处理。新版在这些区域外继续生成地形时，可以按已有高度、密度及生物群系进行过渡。变化发生在后续生成的接壤区域，已有方块不会因此整体重生。

## 部分树木生成时不再立即替换树干下方方块

对于使用直树干生成方式的普通橡树、白桦、单株云杉、单株丛林树和丛林灌木等，26.3 会先应用树干下方的方块提供器，例如把草方块或菌丝体换成泥土；26.4-snapshot-1 省去了这一步，直接生成树干。自然生成和树苗长成都使用同一套树木特性，因此下方方块在生成瞬间得以保留。草方块之后仍可能因树干遮光而退化为泥土。

对自定义树木，原来通过 `below_trunk_provider` 为这类树干换土的配置也会失效。新版另外允许指定 `trunk_width`，但其默认宽度仍为 1，不会自行把已有单格树干变粗。

## 洞穴切穿地表后的覆土处理扩大适用范围

26.3 在洞穴雕刻移除草方块或菌丝体后，才会尝试把其下方露出的泥土重新转换为当地地表材料。26.4-snapshot-1 在地形填充过程中同时处理洞穴：只要雕刻移除了该段固体的顶部，之后遇到的泥土就可能按表层深度为 1 重新执行地表规则，不再要求被移除的顶部是草方块或菌丝体。

因此，使用其他表层材料覆盖泥土的地形，尤其是自定义材料规则生成的地形，洞口暴露出的泥土可能得到不同的表层材料。此处处理的是新生成洞穴与地表交会的位置。

## 含雪层或空气层的超平坦配置可能在生成建筑时失败

超平坦会将部分特殊层留到后续生成步骤填入。新版合并了原始地形柱与高度查询，但遗漏了这些暂时留空的层。

### 差异出现的场景

超平坦世界包含雪层、空气等不计入阻挡移动高度图的层，且某个建筑生成过程需要查询原始地形柱或地形高度。例如“雪之王国”预设启用了村庄和雪屋，并包含一层雪。

### 版本变化

- 26.3：这类层先转交给后续特性生成，地形层列表中的对应位置留空；高度查询会跳过空位置，地形柱查询会把它们当作空气。
- 26.4-snapshot-1：新的地形柱查询直接对每个列表元素检查是否为空气，没有处理上述空位置，会触发空指针异常。村庄等建筑投射到地形高度时也改为经过此查询，因此会导致相应区块生成失败。

普通的草方块、泥土和基岩层不满足这个触发条件。该问题来自地形高度查询，不能仅凭存在雪层就判定所有区块都会立刻失败。

## 服务器可以要求地址携带指定连接 ID

新版增加服务器地址参数，并用其实现登录和状态查询的连接筛选。

### 差异出现的场景

专用服务器设置 `allowed-connection-ids=alpha,beta`，玩家使用普通地址，或使用 `alpha@example.com:25565`、`example.com:25565?_id=alpha` 连接或刷新服务器列表。

### 版本变化

- 26.3：没有这项服务器筛选；客户端也没有将 `@` 前缀或 `?` 参数解析为连接属性的机制。
- 26.4-snapshot-1：配置为空时继续接受普通连接。配置非空时，服务器只接受 `_id` 与列表中某一项精确匹配的连接；缺少或填错 ID 的登录、转移和现代状态查询都会在握手阶段被关闭。列表条目按逗号分隔、去除首尾空格并忽略空项。

地址还可以附加 `?key=value&other=value`，参数按 URL 表单规则编码；`id@` 简写会覆盖参数中的 `_id`。客户端把这些参数带入握手，并在 DNS/SRV 解析改变主机或端口时通过 `_o` 记录原始地址。服务端转移数据包也增加了属性映射，但原版 `/transfer` 仍发送空映射，不能通过命令的主机参数替代这份映射给目标服务器传递连接 ID。

### 实际影响

启用该配置后，服务器列表里保存的地址、玩家直连地址以及转移入口需要携带匹配的 ID。使用没有 ID 的常规 `/transfer` 转入这类服务器也会被拒绝。ID 是客户端提供的连接属性，本项筛选不会增加用户身份验证。

## 多类运行异常改为直接传播，加载错误的区块不再一律回退为空区块

这些差异只在相应异常发生时出现，但会改变世界和联机会话如何结束。

- 客户端已经成功解码的数据包在处理时抛出异常：26.3 保存断线报告并退出服务器；26.4-snapshot-1 先调用默认的报错处理，抛出带数据包信息的崩溃异常，后面的通常断线流程不会继续执行。普通网络断线或解码失败不直接等同于这个场景。
- 客户端或服务器事件循环执行任务抛出异常：26.3 对通常异常记录日志后继续，只有被认定为不可恢复的异常才重新抛出；26.4-snapshot-1 对捕获到的异常全部重新抛出。因此某些之前只留下日志的任务错误会中断运行。
- 读取区块失败：26.3 对非 `Error` 的失败统一报告后返回空区块；26.4-snapshot-1 仅对 `IOException`、`NbtException` 一类读写或 NBT 失败保留这个回退。其他运行错误会生成区块加载崩溃报告，避免继续把这类错误表现为空区块并重新生成。

## 自定义世界生成规则的兼容变化

- `noise_settings` 的 `default_block` 不再被读取。26.3 在材料规则没有匹配时保留该默认固体；26.4-snapshot-1 直接按材料规则填充，规则返回空结果的位置会留空。因此原有依靠 `default_block` 补齐地形的数据包，需要在材料规则末尾显式提供兜底方块。原版主世界规则已经补入石头兜底。

## NBT 浮点数转整数时的结果变化

当命令或存档把浮点 NBT 作为整数字段读取，或把浮点数插入整数数组时，新版改变了转换结果。

- 转为 byte、short：26.3 向下取整后截取低位，超范围数值可能回绕；26.4-snapshot-1 向下取整后限制到目标类型的最小值或最大值。例如向 byte 数组追加 `256.0f`，旧版得到 `0b`，新版得到 `127b`。通过这类浮点值驱动布尔字段时也可能改变真假结果，因为实体数据的布尔读取使用转换后的 byte。
- float 转 long：26.3 直接截去小数，`-0.5f` 得到 0；26.4-snapshot-1 先向下取整，得到 −1。向 long 数组追加该数值会体现这一差异。

## 默认图形后端改为优先尝试 Vulkan

对于“默认”图形 API 设置，26.3 先尝试 OpenGL，失败后才尝试 Vulkan；26.4-snapshot-1 改为先尝试 Vulkan，再回退到 OpenGL。升级选项时还会重新应用一次默认图形 API 的数据转换，因此旧配置中的后端选择可能被重置。

26.3 在检测到上次启动未正常结束时，还会重置 Vulkan 偏好或强制尝试 OpenGL；新版删除了这条根据上次启动结果切换的分支。新版的 Vulkan 所需能力同时不再包含 `VK_KHR_dynamic_rendering`、`VK_KHR_push_descriptor` 和 `dynamicRendering`，满足其余要求、但缺少这些能力的设备也有机会使用 Vulkan。实际最终使用的后端仍取决于设备检查和初始化结果。

## 实体显示、物品模型和骑乘声音调整

- 物品展示框和画在客户端重建时，新版在确定朝向后立即设置旧位置和旧旋转，画的变种变化后也更新旧位置；26.3 缺少这一步，刚加载或改变尺寸时可能从先前的位置插值到正确位置。盔甲架同样在生成数据包处理后立即统一身体和头部朝向，减少刚出现时的朝向跳变。
- 狼铠的破损纹路在 26.3 使用固定绘制顺序；新版放到实际铠甲图层之后，避免染色等多图层铠甲覆盖裂纹。
- 使用生成式二维物品模型的物品，新版合并连续侧面，减小侧面纹理内缩，并将正反面略向内移动；与 26.3 相比，物品边缘接缝和侧面取样表现会变化。
- 玩家在同一轮声音更新之间快速离开并重新骑上同一个矿车、快乐恶魂或鹦鹉螺时，26.3 的旧循环声只看当前是否仍骑着该实体，可能与新声音并存；新版为每次开始骑乘分配序号，旧序号的声音会在下一次更新时停止。

## 测试命令选择手动测试的方式改变

用 `/test` 一次选中一批测试时，26.3 会运行选中的全部测试；26.4-snapshot-1 如果其中包含可自动运行的测试，只运行这些自动测试，跳过标记为仅手动运行的测试。只有选中结果全部为手动测试时，才运行这些手动测试。使用标签或大范围筛选运行测试的现有流程，实际执行的测试数量可能减少。旋转步数参数也从任意整数收紧为 0–3。
