# Minecraft 1.19-rc2 变更分析

- 上一个版本：1.19-rc1
- 当前版本：1.19-rc2

## 成书解析增加长度检查，并改为整本写回

成书首次被玩家打开，或在服务端放入讲台时，会把书页中的实体选择器、NBT 引用等动态文本解析为当时的内容。新版在写回书页之前检查解析结果，避免把原本有效的成书改写为含有超长书页的状态。

### 差异出现的场景

成书尚未标记为已解析，原始普通书页通过有效性检查，但任一普通页或过滤后书页在解析、重新序列化后超过 32767 个字符。例如，命令制作的书用很短的 NBT 引用读取大量文字，或者用实体选择器展开许多实体的名称。

这里的长度是整页 JSON 字符串的长度，包括文本格式、悬停内容等数据，并非屏幕上可见文字的数量。

### 版本变化

- 1.19-rc1：逐页把解析结果写回成书，不检查结果长度。普通页一旦超过 32767 个字符，成书便不再通过客户端的有效性检查；在超长内容能够完整同步给客户端的情况下，打开书会显示“无效的书本标签”。过滤后书页同样直接写入解析结果。
- 1.19-rc2：先暂存所有普通页和过滤后书页的解析结果。任意一项超过 32767 个字符，就终止本次解析，保留整本书原来的普通页和过滤后书页；已经成功解析的其他页也不会写回。不会截短超长页，也不会只跳过该页。

过滤后书页的检查不取决于当前读者是否启用文本过滤。因此，即使超长结果只出现在过滤后书页中，也会阻止普通书页更新。

### 实际影响

依靠动态书页汇总大量实体或 NBT 数据的成书，达到上述限制后不再保存展开结果；其他本可正常展开的书页也一并保留原始内容。普通书页因此不会因这次解析而越过既有长度上限。

解析开始时仍会先把成书标记为已解析，即使新版随后因超长而放弃写回，这个标记也会保留。因此，之后减少匹配实体、缩短引用的数据，再次打开同一本书或重新放到讲台上，都不会自动重试。已经带有已解析标记的旧书也不会因升级而重新检查或修复。

整本写回还会改变未超长的书页读取本书 NBT 时的结果。例如，具有实体选择器使用权限的玩家用主手打开一本命令制作的书：第一页用实体选择器显示玩家名称，第二页通过 `SelectedItem.tag.pages[0]` 读取第一页，并把读到的 JSON 当作普通文字显示。1.19-rc1 中，第二页会读到第一页刚写回的、包含玩家名称的 JSON；1.19-rc2 中，第二页读到的仍是包含选择器表达式的原始 JSON。过滤后书页引用本书普通页时，也会读取尚未写回的原始内容。依赖前面书页先解析、后面书页再读取其结果的用法会因此改变。
