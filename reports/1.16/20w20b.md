# Minecraft 20w20b 变更分析

- 上一个版本：20w20a
- 当前版本：20w20b

## 独立服务器恢复正常启动

独立服务器需要先初始化游戏内容，再构造依赖这些内容的世界设置。本次调整了启动入口与初始化顺序，修复了启动时的崩溃，使服务器能够继续加载世界。

### 差异出现的场景

在新的 Java 进程中通过对应版本的入口启动独立服务器，且没有其他程序预先初始化 Minecraft 的游戏内容。故障发生在读取世界之前，因此加载已有存档和创建新世界都受影响。

### 版本变化

- 20w20a：启动入口位于服务器类本身。执行入口方法前，该类就会构造默认世界设置，提前触发地形特征、实体和注册表之间的初始化依赖，导致启动崩溃，无法进入世界或接受玩家连接。
- 20w20b：启动入口移至单独的类，先初始化并校验游戏内容，再读取服务器配置和世界。在已接受 EULA、配置及存档正常的条件下，可以继续完成服务器启动。

同一调整也恢复了启动辅助功能：新版使用 `--help` 可以显示帮助后退出，使用 `--initSettings` 可以初始化 `server.properties` 和 `eula.txt` 后退出；旧版在进入这些参数的处理分支之前，就已受到服务器类初始化故障的影响。

## 显式指定服务器入口类的启动脚本需要更新

服务器入口从 `net.minecraft.server.MinecraftServer` 移至 `net.minecraft.server.Main`，影响在 Java 命令中直接指定主类的启动脚本。

### 差异出现的场景

启动脚本通过类路径加载服务器，并显式指定 `net.minecraft.server.MinecraftServer` 作为 Java 主类。升级服务器后仍沿用这一主类名称。

### 版本变化

- 20w20a：`net.minecraft.server.MinecraftServer` 提供 `main` 方法，主类名称可以解析到入口，但仍会遇到上文所述的初始化崩溃。
- 20w20b：`net.minecraft.server.MinecraftServer` 不再提供 `main` 方法，沿用旧名称会因找不到启动入口而失败。将主类改为 `net.minecraft.server.Main` 后，才能使用新版的启动流程。
