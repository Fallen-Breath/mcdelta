# Minecraft 26.2-snapshot-5 变更分析

- 上一个版本：`26.2-snapshot-4`
- 当前版本：`26.2-snapshot-5`

## 斧头先除去铜块上的蜡，再刮除氧化层

斧头对铜方块的处理会先尝试刮除氧化层，再尝试除蜡。新版将涂蜡铜方块移出氧化阶段映射，使操作顺序改为先除蜡、后刮除氧化层。

### 差异出现的场景

对已经有氧化程度的涂蜡铜方块使用斧头，适用于铜块及其切制、雕纹、台阶、楼梯、门、活板门、栏杆、格栅、灯、灯笼、箱子、铜傀儡像、避雷针和锁链等铜方块。

### 版本变化

- Snapshot 4：涂蜡状态也参与氧化阶段映射。每次使用斧头先降低一个氧化阶段，同时保留蜡；刮到最初阶段后，再次使用斧头才会除蜡。
- Snapshot 5：第一次操作先除蜡，保持当前氧化程度；后续操作才逐级刮除氧化层。

除蜡后的方块重新具备继续氧化的条件。旧版直接用斧头获得“氧化程度较低、仍然涂蜡”的方块的流程不再成立。

## 蜜蜂和多种幼体的碰撞箱、眼睛高度及乘客位置调整

实体的身体尺寸决定碰撞与命中范围，眼睛高度和乘客附着位置则用于水中状态、视线及骑乘位置等计算。新版缩小蜜蜂，并为多种幼体设置独立尺寸及位置参数。

### 差异出现的场景

蜜蜂或下列幼体进入狭窄通道、分离装置和运输空间，或处于水面、视线遮挡边缘及骑乘状态。以下数值均按默认缩放计算，宽度与高度的单位为格。

### 版本变化

- Snapshot 4：蜜蜂使用原有尺寸；多种幼体沿用按年龄缩放的身体尺寸、眼睛高度和乘客位置。
- Snapshot 5：改用下表中的身体尺寸，并为多种幼体单独设置眼睛高度和乘客位置。

| 实体或姿态 | Snapshot 4：宽 × 高 | Snapshot 5：宽 × 高 |
| --- | --- | --- |
| 成年蜜蜂 | 0.7 × 0.6 | 0.55 × 0.5 |
| 幼年蜜蜂 | 0.35 × 0.3 | 0.275 × 0.25 |
| 幼年美西螈 | 0.5 × 0.25 | 0.375 × 0.21 |
| 幼年骆驼，站立 | 0.85 × 1.1875 | 0.95 × 1.4 |
| 幼年骆驼，坐下 | 0.85 × 0.4725 | 0.95 × 0.425 |
| 幼年疣猪兽、僵尸疣猪兽 | 约 0.6982 × 0.7 | 0.75 × 0.85 |
| 幼年鱿鱼及继承此尺寸的荧光鱿鱼 | 0.5 × 0.63 | 0.5 × 0.5 |
| 幼年村民、僵尸、尸壳、溺尸、僵尸村民、猪灵和僵尸猪灵 | 0.49 × 0.99 | 0.49 × 0.98 |

蜜蜂、幼年美西螈和幼年鱿鱼变小，幼年疣猪兽变大，幼年骆驼则站立时变大、坐下时变矮。因此，同一方块布局能否容纳这些实体，或能否阻挡它们通过缝隙，可能发生变化。

另一些幼体的身体宽高不变，但眼睛高度或乘客附着位置改为单独设置，涉及犰狳、鸡、牛、哞菇、海豚、猫、豹猫、狐狸、山羊、恶魂宝宝、鹦鹉螺、熊猫、猪、北极熊、绵羊、狼和炽足兽，以及上表中的部分实体。例如，幼年猫的眼睛高度从 0.175 升至 0.34375，幼年美西螈从 0.2 降至 0.09375，幼年海豚从约 0.195 降至 0.09375。依赖眼睛是否入水的判定、视线检测及骑乘叠放位置会随之变化；身体宽高不变的物种，通道所需空间不因此改变。

## 关闭怪物生成规则开始正确阻止普通自然刷怪

普通自然刷怪会按生物类别筛选生成对象。新版将“允许生成怪物”的开关接入这一筛选，使关闭怪物生成规则后不再尝试怪物类别。

### 差异出现的场景

世界允许生物生成，但设置了 `/gamerule minecraft:spawn_monsters false`，附近仍满足怪物的自然生成条件。

### 版本变化

- Snapshot 4：普通区块自然生成筛选没有使用怪物开关，仍会尝试怪物类别；通过其他检查的怪物仍可能生成。
- Snapshot 5：关闭该规则后直接排除怪物类别。既有刷怪场在这一配置下停止产生普通自然生成的怪物，属于怪物类别的硫方怪也受限制。

这一变化作用于区块自然生成；命令、刷怪笼和物品等生成方式由各自逻辑控制。

## 和平难度提前拒绝受限制的实体，疣猪兽也开始受限制

新版在创建实体时检查和平难度限制，并将疣猪兽列为不能存在于和平难度的生物。这既改变生成失败的时机，也改变和平世界能保留的生物。

### 差异出现的场景

在和平难度通过 `/summon`、实体数据加载、生成物品或转换等路径创建受限制的实体，或将已有疣猪兽的世界切换为和平难度。刷怪蛋点击刷怪笼时，也会先执行这一检查。

### 版本变化

- Snapshot 4：实体创建阶段只检查功能开关；一些路径会先创建受限制的实体，再由后续生物更新移除。疣猪兽没有和平难度限制，成年和幼年疣猪兽均可保留；用受限制生物的刷怪蛋点击刷怪笼，也可先改变刷怪笼类型。
- Snapshot 5：受限制的实体在创建阶段即返回失败。疣猪兽同样受限，切换到和平难度后会被清除，在和平难度加载时也无法正常创建；刷怪蛋在处理刷怪笼交互前就拒绝操作，不能借此更改其类型。

## 发射器生成实体失败时保留刷怪蛋

发射器使用刷怪蛋时，新版根据实体是否实际生成来决定是否消耗物品及发出游戏事件。

### 差异出现的场景

发射器尝试使用刷怪蛋，生成调用没有抛出异常，但返回空结果。例如，新版在和平难度拒绝创建受限制的实体时会出现这种结果。

### 版本变化

- Snapshot 4：不检查生成结果，仍消耗一个刷怪蛋，并发出放置实体的游戏事件。
- Snapshot 5：保留刷怪蛋，不发出成功放置实体的游戏事件。这一规则适用于所有返回空结果的生成失败；生成调用抛出异常的分支仍有独立处理。

## 跨生物群系治愈僵尸村民时保留原来的村民类型

村民类型决定其生物群系外观，启用村民交易平衡实验时也参与交易选择。新版在感染和治愈转换中传递“类型已确定”的状态，避免治愈初始化覆盖已有类型。

### 差异出现的场景

将已经确定类型的僵尸村民运到另一生物群系后治愈，包括由已有村民感染而来的僵尸村民。

### 版本变化

- Snapshot 4：治愈时先复制原类型，随后在新村民初始化阶段又按治愈地点重设类型，外观及依赖类型的交易选择可能随所在地改变。
- Snapshot 5：感染和治愈时都传递类型确定状态，治愈初始化不再覆盖原类型，保留原来的生物群系外观及依赖该类型的交易选择。

通过特殊数据创建、尚未确定类型的实体仍会在初始化时选择类型。

## 制箭师药箭交易的涨价与折扣转到绿宝石上

大师级制箭师的药箭交易仍以 2 个绿宝石和 5 支箭为基础成本，但新版交换了两个输入的主次顺序。需求和声望等价格变化只应用于主输入，因此实际资源消耗会改变。

### 差异出现的场景

村民新生成这一药箭交易，并因需求或声望等因素产生价格变化。已经作为具体报价保存在村民身上的旧交易，不会仅因交易配方修改而自动交换输入。

### 版本变化

- Snapshot 4：箭是主输入，绿宝石是第二输入。涨价或折扣改变箭的数量，绿宝石保持 2 个。
- Snapshot 5：绿宝石是主输入，箭是第二输入。涨价或折扣改变绿宝石数量，箭固定为 5 支；交易界面的两项需求也随之交换位置。

## 吞入方块的硫方怪改变爆炸和生物攻击响应

硫方怪吞入方块后，会根据伤害类型决定是否免伤，并对部分攻击作出特殊推动响应。新版扩大爆炸免伤范围，增加随吞入方块类型变化的爆炸击退抗性，并允许其他生物触发击打推动。

### 差异出现的场景

硫方怪已经吞入方块，随后受到爆炸，或受到免伤列表内、来源实体为生物的非爆炸攻击。

### 版本变化

- Snapshot 4：爆炸免伤只覆盖具有实体归属的 `player_explosion` 类型；吞入方块类型没有额外提供爆炸击退抗性。按攻击者眼睛位置与朝向计算的特殊击打推动只由玩家触发，玩家来源的爆炸也可能叠加这一推动。
- Snapshot 5：所有爆炸类型均纳入免伤，包括没有生物归属的 TNT、床、重生锚及烟花爆炸。特殊击打推动可由其他生物的非爆炸攻击触发；玩家来源的爆炸只采用爆炸推动，不再叠加按视线计算的击打推动。

新版还按吞入方块的类型增加爆炸击退抗性：蓝冰、浮冰和雪块对应 0.5，蘑菇方块、菌光体等对应 0.8，金属方块类及灵魂沙、灵魂土类对应约 0.7。其他原版类型新增的负值被属性下限限制为 0。在相同爆炸距离和遮挡下，正抗性类型受到的爆炸推动减小，影响已有爆炸推动和运输装置。

## TNT 可以先装入硫方怪，再作为可移动炸弹点燃

硫方怪新增吞入 TNT 的类型，发射器也优先尝试将 TNT 装入硫方怪。吞入后，硫方怪可被点燃并带着引信移动。

### 差异出现的场景

将 TNT 喂给硫方怪，或让装有 TNT 的发射器朝向硫方怪所在的相邻格。

### 版本变化

- Snapshot 4：TNT 不在原版可吞入列表中；发射器照常生成点燃的 TNT。
- Snapshot 5：TNT 可以被吞入。发射器先尝试把 TNT 装进目标格内的硫方怪，成功时消耗一个 TNT，不生成点燃的 TNT；没有成功接收的硫方怪时才照常发射点燃的 TNT。

吞入 TNT 后，硫方怪具备浮力和弹性，并可被打火石、火焰弹、火焰伤害、着火的箭或爆炸点燃；站在自身或相邻位置存在红石信号的格子中，也会尝试点燃。普通引信是 120 游戏刻，受到爆炸触发时缩短为 15～44 游戏刻；爆炸强度为 3，使用 TNT 类爆炸的方块交互规则。

红石触发会读取所处方块自身的输出能力，因此不要求该方块的输出方向恰好指向硫方怪。实体在点燃后获得无敌状态；成年硫方怪不再接受剪出方块、替换内容或用桶收起等普通交互。引信随实体保存，重新加载不会恢复为未点燃状态。

点燃要求 `minecraft:tnt_explodes` 为真。规则为假时，发射器的 TNT 分支也在喂食前直接返回；玩家直接使用打火石或火焰弹的交互仍会扣耐久或消耗物品，但无法成功点燃。

### 实际影响

原来朝向硫方怪的 TNT 发射装置会先改变硫方怪的内容；已有硫方怪装置若接收了 TNT，接近红石输出方块、接触火或遭受爆炸就可能进入倒计时。普通玩家交互无法在点燃后取回 TNT 来停止倒计时。

## 岩浆块上的烈性硫黄形成间歇喷泉

烈性硫黄原本在水面附近产生有毒气体；新版在下方紧贴岩浆块时，改为在休眠和喷发之间循环。

### 差异出现的场景

烈性硫黄上方为连续 1～4 格水源，水柱顶端为空气，正下方为岩浆块。水柱长度超出检测范围，或水面出口被非空气方块阻塞时，不会进行正常的喷发倒计时和推动。另一个场景是直接加载旧世界中已经放置的烈性硫黄，且尚未发生相邻方块形状更新。

### 版本变化

- Snapshot 4：下方是否为岩浆块不改变机制，持续按原有规则给水面附近符合条件的生物施加反胃。
- Snapshot 5：休眠时继续产生气体与反胃效果；喷发时停止施加这一反胃效果，改为向上加速水柱同一列内、与喷口之间没有视觉方块遮挡的存活实体，包括玩家、生物和掉落物，旁观者除外。

设水源深度为 N，休眠计时初值为随机的 15～30 秒加上 `10 × (N−1)` 秒，喷发计时为随机的 1～2 秒加上 `N−1` 秒。每个烈性硫黄方块初始化时确定随机时长，并随方块实体保存。喷发期间每游戏刻增加约 0.2 的竖直速度，但只对当前竖直速度低于 `0.3 + 0.1 × N` 的实体施加这次加速；这不是固定传送高度。

新版自然生成的硫黄温泉模板已给烈性硫黄设置休眠状态，因而可以形成喷泉。加载旧世界中的烈性硫黄时，还存在状态衔接差异：

- Snapshot 4：方块没有干燥、湿润等状态，已有气体装置按原规则继续运行。
- Snapshot 5：旧方块缺少新增状态属性，加载后采用默认的干燥状态；这一状态没有更新器，尚未发生相邻方块形状更新的旧气体装置会停止工作。触发一次相邻更新或重新放置后，方块才会按水和岩浆块条件改为湿润或休眠状态。

## 管理服务可提前发送心跳，但默认心跳间隔会阻断启用后的启动

管理服务将心跳计时从游戏服务器更新循环移到网络事件循环，并提前到加载世界前启动。正数间隔下可以更早监控启动状态，但旧版用 0 关闭心跳的配置会在本版触发启动失败。

### 差异出现的场景

专用服务器设置 `management-server-enabled=true`，通过管理协议监控启动过程，或在启动时及运行中设置 `status-heartbeat-interval`。默认间隔为 0；管理服务未启用时不进入以下分支。

### 版本变化

使用正数心跳间隔时：

- Snapshot 4：管理服务在专用服务器初始化中启动，心跳由游戏服务器更新循环发送，计时受主线程运行情况影响。
- Snapshot 5：管理服务在加载世界前启动，网络事件循环定时发送心跳；尚未就绪时也能发送 `started=false` 的状态，主线程卡住或暂停不会像旧版一样直接拖住心跳计时。初始化完成前只有发现接口获准执行，其他普通请求会收到无效请求错误。

使用默认的 0，或负数间隔时：

- Snapshot 4：管理服务可以启动，不发送心跳；运行中改为这类值也表示停发。
- Snapshot 5：启动管理服务后无条件注册固定周期任务，0 和负数周期均导致 `IllegalArgumentException`，在加载世界前中断启动流程。运行中改为 0 时，先取消原任务，再尝试注册非法周期，同样会出错；改为正数时，后续心跳按新周期运行。

## 实体选择器拒绝更多互相矛盾的筛选组合

名称、游戏模式、队伍和类型选项统一使用正反向条件规则：正向条件只能出现一次，出现后不能再追加同类条件；多个反向条件可以共存，但其后不能追加正向条件。名称和游戏模式的既有规则大体不变，队伍及类型标签筛选则进一步收紧。

### 差异出现的场景

命令或函数在同一个选择器中先排除队伍再指定队伍，或在正向类型标签后追加其他类型条件。例如 `@e[team=!red,team=blue]` 和 `@e[type=#minecraft:skeletons,type=!minecraft:stray]`。

### 版本变化

- Snapshot 4：前一个选择器可解析，要求实体不属于 red 且属于 blue。正向类型标签也不会像具体类型一样锁定选项，因此后一个选择器可以继续排除流浪者，也可追加正向类型标签取交集。
- Snapshot 5：反向队伍条件后再写正向条件会报错；正向类型标签同样会锁定类型选项，后续追加类型条件也会报错。上述命令和函数中的选择器因此不再被接受。

仅重复多个反向条件的写法仍可使用。

## 自定义数据中的无效字段不再普遍退回默认值

多种字段将“读取失败就使用默认值”改为“仅字段缺失时使用默认值”。这一共同的解码规则会让原先被静默替换的无效数据暴露为解析错误。

### 差异出现的场景

自定义配方写入无效的分类或烹饪时间，或在物品数量、属性基础值、告示牌文字颜色及部分世界生成设置等受修改的字段中提供无效值。

### 版本变化

- Snapshot 4：这些字段读取失败时可退回默认值，例如配方仍可能按默认分类或烹饪时间加载。

## 触屏模式及其容器操作方式移除

### 差异出现的场景

旧配置中启用了 `touchscreen`，玩家在容器中按住槽位拖动物品、在目标槽位停留，或点击容器外侧；另一个相关场景是开启失去焦点暂停后，在按住右键时切走游戏窗口。

### 版本变化

- Snapshot 4：触屏模式可按住容器槽位后拖动物品，在另一槽位停留时连续放入单个物品，点击容器外侧还可关闭界面；按住右键失去焦点时保留触屏模式的暂停例外。
- Snapshot 5：已有 `touchscreen` 设置不再生效，容器按普通鼠标拾取、拖拽分配和丢出规则处理，不再提供上述触屏操作；失去焦点时按通常规则打开暂停界面。

## 结构方块界面的 0° 旋转按钮始终不可用

结构方块加载界面通过旋转按钮设置结构方向。新版重设按钮可用状态时始终禁用 0°，导致界面无法将其他角度切回 0°。

### 差异出现的场景

打开结构方块的加载界面，已有旋转角度为 90°、180° 或 270°，并尝试通过按钮恢复 0°。

### 版本变化

- Snapshot 4：只禁用当前选中的角度，其余三个角度均可选择，因此可以切回 0°。
- Snapshot 5：无论当前角度是什么，都禁用 0°，并启用 90°、180°、270°，无法通过按钮切回 0°。本来就是 0° 的结构会保持该方向，直到选择其他角度。

这一变化影响实际结构加载方向的设置。

## 透明物品与移动方块统一按距离排序

新版将透明物品、移动方块和方块模型放到同一透明绘制阶段，统一排序，改变跨类别对象重叠时的透明混合结果。

### 差异出现的场景

透明物品、方块模型或活塞推动的透明方块在画面中相互重叠，例如透明物品与移动的透明方块互相遮挡。

### 版本变化

- Snapshot 4：按物品、移动方块、方块模型等类别分别提交绘制，跨类别对象不能统一按距离排序。
- Snapshot 5：这些透明对象在同一阶段按与相机的距离从远到近排序，并保持这一提交顺序，重叠区域的透明混合结果可能与旧版不同。
