# Minecraft 26.2-snapshot-6 变更分析

- 上一个版本：`26.2-snapshot-5`
- 当前版本：`26.2-snapshot-6`

## 区块重载后保留同一时刻计划刻的先后次序
同一区块中，多个方块或流体计划刻具有相同的执行时间和优先级时，其先后次序会影响中继器竞争、水流展开等结果。本次修改让存盘保留它们原来的排序依据。

### 差异出现的场景

装置已经排入多个待执行的计划刻，在执行前保存并卸载区块，随后重新加载；其中存在执行时间及优先级相同的计划刻。

### 版本变化

- Snapshot 5：直接按优先队列的内部遍历顺序写盘。这个顺序不保证等同于原先排入的次序，重载时重新分配顺序编号后，同条件计划刻可能换序。
- Snapshot 6：先按原顺序编号排序再写盘，重载后保留同一区块内这些计划刻的相对先后关系。

依赖同刻执行顺序的装置，保存和重载造成的这一种换序因素被消除；这项保留保证限于同一区块内部。

## 发射器优先点燃硫方怪，空点火也会损耗打火石

发射器使用打火石时，新版先处理目标格内可点燃的硫方怪，并改变没有点燃任何目标时的成功判定。

### 差异出现的场景

发射器使用打火石，前方一格与吞有 TNT、尚未点燃的硫方怪相交，同时该格允许放火或存在其他可点燃方块；或者前方被普通实心方块堵住，没有任何可以点燃的目标。

### 版本变化

- Snapshot 5：先尝试放火、点燃营火或蜡烛、点燃 TNT 方块；这些分支均未接管时才尝试点燃硫方怪。所有目标均无法点燃时，播放失败声且不消耗耐久。
- Snapshot 6：先选择目标格内第一个符合条件的硫方怪，找到后便不再尝试方块点火。即使没有点燃任何目标，也按成功处理，消耗 1 点打火石耐久并播放正常发射声。

若目标格内有可爆炸的硫方怪，但 `tnt_explodes` 已关闭，新版仍把找到它视为成功，阻止后续点火分支并损耗耐久。依靠堵住发射器前方来保护打火石的装置，因此会持续消耗耐久。

## 竖直反弹计入碰撞前运动阶段的空气阻力

实体碰撞后的竖直反弹速度现在会计入本刻碰撞前一段运动的阻力，影响黏液块弹射、具有弹性属性的生物及硫方怪运动。

### 差异出现的场景

实体没有抑制反弹，在一刻中先沿竖直方向移动一段距离，再撞到具有有效弹性的地面或其他竖直碰撞面。

### 版本变化

- Snapshot 5：根据碰撞前速度、重力补偿和反弹系数直接得到反弹速度，没有为已经走过的这段路程计入空气阻力。
- Snapshot 6：再乘一个由碰撞前运动比例决定的阻力系数。普通玩家默认空气阻力为 0.98，因此有碰撞前位移时，反弹后的竖直速度比旧版略低；没有这段位移时，不产生该项差异。

新版对填充硫方怪使用其空气阻力属性，并在落地时计入脚下方块与自身摩擦修正。依靠连续反弹维持高度或周期的装置，其高度和落地时刻可能变化。此次新增的阻力因子只用于竖直反弹。

## TNT、下落方块、掉落物和矿车的空气减速出现精度差异

新版统一通过单精度返回值取得部分实体的空气阻力。数值与旧版的双精度常量略有不同，会积累为很小的运动偏差。

### 差异出现的场景

TNT、下落方块或掉落物在空中运动，或矿车脱轨后在空中减速；比较相同初始位置和速度下的轨迹。

### 版本变化

- Snapshot 5：TNT、下落方块和掉落物的相关减速使用双精度的 0.98；矿车脱轨后的空气减速使用双精度的 0.95。
- Snapshot 6：这些位置改用单精度的 0.98 或 0.95 换算出的数值，差异约在小数点后八位。长时间运动或精密弹射轨迹可能出现很小的坐标偏差。

## 出水后的鱿鱼开始使用空气阻力属性

鱿鱼离开水体后的竖直减速，改为读取自身的空气阻力属性。

### 差异出现的场景

使用命令改变鱿鱼的 `air_drag_modifier`，随后让它离开水体，比较竖直运动。

### 版本变化

- Snapshot 5：出水后的竖直速度固定乘 0.98，不读取该属性。
- Snapshot 6：出水后的竖直速度按该属性修正后的阻力衰减；默认属性下结果不变。

## 硫方怪的击打方向、力度与命中后续处理改变
吞有方块的硫方怪仍免疫相应攻击的生命值伤害，但受到击打后的运动和攻击是否算作成功命中发生了变化。

### 差异出现的场景

玩家或其他实体击打吞有方块的硫方怪，或者用箭等投射物命中它。攻击类型需要属于硫方怪的方块状态免疫范围；普通受击击退还受该伤害类型是否禁止击退限制。

### 版本变化

- Snapshot 5：具有生物攻击者的非爆炸攻击，用攻击者眼睛位置、瞄准位置和硫方怪大小构造一个推力，之后返回“未造成伤害”。其他免疫伤害来源不会通过这一分支施加普通受击击退。
- Snapshot 6：免疫伤害也返回“命中成功”，并在允许击退时调用普通受击击退入口。攻击者存在时，硫方怪用攻击者朝向与双方高低差调整方向，再按吞入方块提供的水平、竖直力度、伤害平方根和击退抗性施加推力；没有攻击者时使用普通实体的击退计算。

新版可以通过瞄准硫方怪的不同高度、从不同高低位置击打来改变水平与竖直推力分配。不同填充方块也有各自的击打力度，旧版以同一个公式处理。

返回成功还会使玩家攻击继续执行成功命中后的流程，例如适用时触发横扫、冲刺或附魔的额外击退，并消耗武器耐久。旧版被上述免疫分支判为未命中的攻击不执行这些成功分支。硫方怪本身依然不因此扣除生命值，反复击打它不再能保持原有武器损耗和运动结果。

## 多类填充方块改变硫方怪的运动特性

硫方怪吞入的方块决定它的弹性、击退抗性及减速属性。新版重新划分石质方块，并调整金属、海绵等配置。

### 差异出现的场景

成年硫方怪吞入以下方块后，在相同地面上受到相同外力，或连续反弹、滑行。

### 版本变化

- Snapshot 5：石头、圆石、深板岩、下界岩、黑石、朱砂、硫黄、石英块、海晶石、紫珀块、混凝土、陶瓦及多数矿石等采用普通配置：击退抗性为 0、反弹系数为 0.5、空气阻力修正为 0.1。金属类的相应参数为击退抗性 0.7、反弹系数 0.2、摩擦修正 0.3；海绵、珊瑚块、干海带块、苔藓类方块、南瓜、西瓜等的反弹系数为 0.2、摩擦修正为 0.1。
- Snapshot 6：上述石质方块转入 `slow_bouncy`，击退抗性增至 0.4、反弹系数增至 0.6、空气阻力修正降至 0.05。铁块、金块、铜块等金属类的击退抗性降至 0.5、反弹系数增至 0.4、摩擦修正增至 0.4；上述海绵等 `fast_flat` 填充物的反弹系数增至 0.5、摩擦修正增至 0.2。

石质填充物更难推动，金属类更容易推动；这些配置的反弹与滑行轨迹也随之变化。泥土、草方块、黏土、骨块、煤炭块和混凝土粉末等仍使用普通配置。各类方块还提供新的水平、竖直击打力度，会与前述击退算法共同决定轨迹。

## 硫方怪新增可吞侦测器和红石灯，移除四种填充物

新版调整硫方怪的可吞方块列表，同时影响玩家喂入、捡拾掉落物和已有填充物恢复运动配置。

### 差异出现的场景

对成年硫方怪使用侦测器、红石灯、沙子、红沙、沙砾或红石块，或让它捡拾这些物品；也包括载入已经吞有后四种物品的旧存档。

### 版本变化

- Snapshot 5：可吞沙子、红沙、沙砾和红石块，并取得其配置提供的运动特性；侦测器和红石灯不属于可吞方块。
- Snapshot 6：侦测器和红石灯可以吞入，采用 `slow_bouncy` 配置；后四种方块不再可吞。旧存档中已经吞下的物品仍保留，但不再匹配内置运动配置，失去原配置提供的反弹、减摩擦及液体上浮特性，换入其他可吞方块后才取得相应配置。

## 吞入岩浆块的硫方怪造成接触伤害

岩浆块从普通填充配置转入 `hot` 配置，使硫方怪能够在接触时烫伤其他实体。

### 差异出现的场景

吞有岩浆块的硫方怪与实体发生推挤，或玩家进入其推动接触范围；玩家推动还要求身体与它在竖直方向重叠。

### 版本变化

- Snapshot 5：吞入岩浆块不会为硫方怪增加接触伤害。

## 吞有 TNT 的硫方怪改按生物爆炸规则结束引信

硫方怪吞入 TNT 后的默认威力仍为 3、正常引信仍为 120 刻，但爆炸使用的规则与引信结束处理改变。

### 差异出现的场景

吞有 TNT 的硫方怪已被点燃，引信归零；世界设置了生物破坏、爆炸掉落规则，或在引信期间关闭 `tnt_explodes`。硫方怪也可能带有死亡时生效的状态效果，或刚经过下界传送门。

### 版本变化

- Snapshot 5：按 TNT 爆炸处理，方块破坏不受 `mob_griefing` 约束，掉落衰减采用 `tnt_explosion_drop_decay`。开始引信后再关闭 `tnt_explodes`，到时仍会爆炸。爆炸中心在脚底，爆炸前直接移除实体，不按被杀死触发状态效果。
- Snapshot 6：按生物爆炸处理。关闭 `mob_griefing` 时保留方块；允许破坏时，掉落衰减由 `mob_explosion_drop_decay` 控制。引信归零时再次检查 `tnt_explodes`，关闭后只移除硫方怪。结束时按死亡触发相关状态效果，例如相应效果产生的织网或渗浆结果。

新版爆炸中心提升到实体高度的 1/16；传送冷却尚未结束时，还使用保护下界传送门方块的爆炸计算。因此，爆炸装置的破坏范围和掉落结果可能改变。已经点燃的大型硫方怪被强制杀死时，新版也不再分裂成幼体。

## 硫黄洞穴改变生物群系分布

硫黄洞穴参与主世界生物群系选择的气候参数改变，使同一种子中新生成区域的洞穴位置变化。

### 差异出现的场景

## 管理服务器允许用 0 关闭状态心跳

管理协议用 `status-heartbeat-interval` 控制状态心跳推送。新版允许间隔为 0，但运行中关闭后再次设置仍有任务取消限制。

### 差异出现的场景

启用服务器管理协议，并以间隔 0 启动；或在运行中把已有正数间隔改为 0，再尝试设置其他间隔。

### 版本变化

- Snapshot 5：间隔为 0 时仍尝试创建零间隔定时任务并抛出异常，不能正常用该配置关闭心跳。
- Snapshot 6：以 0 启动时不创建心跳任务；运行中从正数改为 0，也会取消现有任务并返回成功。

新版取消任务后仍保留已取消任务的引用。因此先开启、再动态设为 0、随后再次设置间隔时，重复取消返回失败，新配置不会应用。以 0 启动且尚未创建任务时没有这一恢复问题；已经动态关闭后，需要重启服务器才能恢复后续设置。

## NBT 中由编解码器读取的布尔数值采用非零判断

物品组件等通过编解码器读取 NBT 布尔值时，新版按完整数值是否为零判断，改变了部分非常规数值的解析结果。

### 差异出现的场景

命令或数据通过 NBT 编解码器提供布尔值，使用 `256`、`0.5f` 这类完整数值非零、截为字节后却为零的数字。例如执行 `/give @s stick[enchantment_glint_override=256]`。

### 版本变化

- Snapshot 5：先把数字截为一个字节，再判断是否为零；上述数值读成假，示例中的木棍不强制显示附魔光效。
- Snapshot 6：按完整数值是否为零判断；上述数值读成真，示例中的木棍强制显示附魔光效。

常规 `true`、`false` 和 0、1 的结果不变。这项变化针对编解码器使用的 NBT 入口，不涉及所有直接读取 NBT 字节标记的逻辑。
