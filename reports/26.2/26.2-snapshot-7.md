# Minecraft 26.2 Snapshot 7 变更分析

- 上一个版本：`26.2-snapshot-6`
- 当前版本：`26.2-snapshot-7`

## 烈性硫黄涌泉增加连续喷发，并修改通路与周期判定

烈性硫黄上方有水源时，会根据下方热源进入不同状态。新版增加熔岩驱动的连续喷发，同时改变既有岩浆块涌泉的阻挡规则和定时方式。

### 差异出现的场景

烈性硫黄正上方有水源，并在向上最多四格的水柱后留有出气位置；下方放置岩浆块或熔岩。水柱、出口或喷流上方也可能放有含水方块、告示牌、活板门等方块。

### 版本变化

- Snapshot 6：下方只有岩浆块能形成间歇喷发。下方是熔岩时保持湿润状态，散发会造成反胃的气体。检查水柱时从烈性硫黄上方第二格开始，只按水源判断含水方块是否可以通过，出口必须为空气。喷流在固定高度内逐个检查实体眼睛与水面之间是否被视觉形状挡住。
- Snapshot 7：下方是熔岩时持续喷发，对进入喷流的实体施加上推力，不进入休眠，也不执行湿润状态的反胃效果。岩浆块仍驱动间歇喷发。水柱检查从紧贴烈性硫黄的第一格开始，带碰撞形状的含水方块也会阻断通路；出口允许没有碰撞形状的方块。喷流从下向上检查整列方块，遇到具有碰撞形状的方块就截断其上方的推力范围，不再逐个向实体眼睛发射检查射线。

旧存档中原有的湿润状态，要在烈性硫黄重新放置或相邻方块变化触发状态检查后，才会按熔岩热源规则切入连续喷发。

因此，含水的台阶或活板门可以堵住原先能通过的水柱；出口处的告示牌等无碰撞方块则不再使涌泉失效。活板门即使打开后侧面留有空间，只要该格仍有碰撞形状，就会截断喷流。没有阻挡时，推力检查的最高范围仍为水柱格数的六倍；创造模式中正在飞行的玩家仍不受上推力。

反胃气体也改用碰撞形状判断玩家眼睛所在方块是否可到达，水面之间的遮挡检查从视觉形状改为碰撞形状。玩家眼睛处于无碰撞方块内时，旧版因该格不是空气而拒绝施加效果，新版在其余距离、水源和通路条件满足时可以施加。

间歇喷发的基础休眠时长仍为 15～30 秒、基础喷发时长仍为 1～2 秒，水深的附加时长也保留。旧版在方块实体初始化时随机选取并保存这两个基础时长；新版根据世界种子和方块坐标重复计算固定值。同一位置拆掉重建不再重新抽取基础周期，升级后已有的倒计时先继续运行，下一阶段使用新算法。数据包还可分别通过 `causes_periodic_geyser_eruptions` 和 `causes_continuous_geyser_eruptions` 方块标签调整两种热源。

喷发循环音从每秒在烈性硫黄位置播放、音量随水深增大，改为每两秒在出气位置以固定音量播放；连续喷发使用独立声音。

## 封顶的甜浆果丛和枯草丛也能接受骨粉

- 对尚未成熟的甜浆果丛使用骨粉时，旧版还要求正上方为空气且未超出建筑高度；新版只要求浆果丛尚未成熟。因此，紧贴顶棚的浆果丛也能用骨粉提高一阶段成熟度。
- 对矮枯草丛使用骨粉时，新版无须检查上方空间，可以在上方被占用或位于建筑高度顶端时变为高枯草丛。高枯草丛仍是占据一格的植物。
- 对高枯草丛使用骨粉时，新版只要求周围存在可生成矮枯草丛的位置；旧版还要求高枯草丛正上方有有效的空气格。因此，带顶棚的枯草丛扩散装置也能消耗骨粉并正常扩散。

上述变化同时适用于玩家使用与发射器施用骨粉。

## 硫方怪的浮力、保存与发射器穿戴调整

- 填入圆石、石头、黑曜石等属于 `slow_bouncy` 类型的方块后，硫方怪在旧版获得液体浮力；新版移除这一类型提供的浮力，因此相同填充物的硫方怪不再靠该效果在水或熔岩中上浮。若数据包让填充物同时匹配另一种提供浮力的类型，另一类型仍可提供浮力。
- 从桶中放出的硫方怪，在旧版失去体内方块后仍可能按普通生物规则自然消失；新版将“来自桶”也列为保留条件，空心状态也会保留。
- 空心硫方怪在旧版能被发射器穿戴普通头盔、胸甲等装备，幼体也没有额外的身体槽限制。新版发射器只允许向成年且存活的硫方怪的身体槽装备物品，仍须满足物品本身允许该实体装备、身体槽为空等条件。普通的头部、胸部等装备不再进入硫方怪。使用身体槽的装备接口也会拒绝幼体；原有向成年硫方怪填入可吞方块的发射器流程仍使用专门的填充判断。

## 监守者能够维持对恶魂的攻击

当恶魂使监守者积累足够愤怒、成为其攻击目标时，旧版通用生物攻击检查会排除恶魂，导致监守者不能维持这一攻击目标。新版让监守者统一使用自己的目标条件，恶魂不再被额外排除，可以被追击和攻击；队友、创造或旁观玩家、其他监守者等仍受监守者原有目标条件限制。

## 潜影贝开壳时更新眼睛高度

旧版潜影贝开壳时只更新实际碰撞箱，通用实体高度和眼睛高度仍保持闭壳时的值。新版还随开壳进度更新实体尺寸：默认大小的潜影贝完全开壳时，通用高度从 1 格增至 2 格，眼睛相对实体位置的高度从 0.5 格增至 1 格。以眼睛为锚点的命令、附身潜影贝时的旁观视角，以及依赖眼睛位置的判断会随开壳升高。

这里更新的是通用尺寸与眼睛位置；潜影贝向附着面的反方向展开实际碰撞箱的算法仍由独立的开壳形状计算。

## 玩家纯水平移动不再重复处理上一次竖直碰撞

服务器处理玩家移动时可能保留上一轮的竖直碰撞状态。若接下来的移动没有竖直位移，也没有撞到侧面，旧版仍会依据旧状态执行碰撞后的速度处理，可能再次改写竖直速度，或在弹性方块上重新处理反弹。新版只有本次确实尝试竖直移动并发生竖直碰撞，或本次发生水平碰撞时，才执行这一处理，避免纯水平移动沿用旧的落地碰撞状态。

## “爆炸后下落”的进度判定独立于落伤保护

旧版使用风弹的落伤保护记录来判定 `fall_after_explosion`，清除保护记录时也会丢失进度判定的位置。新版单独记住最近一次爆炸击中玩家的位置与来源，在玩家随后第一次开始下落时进行判定，再清除此记录。落伤保护提前重置不再连带删除这份记录。

## 单人世界可通过好友在线联机，并能随时关闭开放

新版将暂停菜单中的“对局域网开放”改为多人游戏设置，增加好友列表与在线开放模式。

### 差异出现的场景

玩家正在运行单人世界，需要邀请好友加入、调整开放范围，或者在不退出世界的情况下停止接待其他玩家。好友功能须已在账号及客户端设置中启用，好友列表可从主菜单、暂停菜单或默认的 O 键打开。

### 版本变化

- Snapshot 6：菜单只能在世界尚未开放时设置局域网开放。开放后没有对应菜单来关闭监听或重新调整全部玩家的命令权限，也没有内置的好友邀请和请求加入流程。
- Snapshot 7：可以选择关闭、局域网、在线三种范围。在线模式可向好友发出邀请，好友也可请求加入；房主接受请求，或对方接受房主尚有效的邀请后，双方通过内置 WebRTC 连接进入世界，无须手动填写服务器地址。没有启用好友功能时，设置中不提供在线选项。

邀请和等待房主接受的加入请求在一分钟后失效。房主只接受好友的请求，建立传输后仍核对实际登录账号是否与被接受的好友一致；在线传输认证失败或认证服务器不可用时，不采用旧局域网连接允许离线身份进入的回退。在线开放也启用安全档案要求。

关闭开放会停止对外监听和局域网广播，断开房主以外的玩家，并清除邀请；房主继续留在世界。局域网与在线之间切换也会先关闭原开放，因此当前访客会断线。在线模式还会建立原有的 TCP 监听和局域网广播。

另有一个命令入口差异：通过 `/publish` 开放世界时，新版仍会启动 TCP 监听，却没有同步新加入的开放范围字段。此时多人设置会显示“关闭”，好友在线开放也没有启用；保持这一“关闭”选项并应用其他设置不会取消实际的开放。

多人设置现在还可在世界运行时更改所有玩家的命令权限并同步客户端权限。在已经开放且非极限模式的世界里，修改默认游戏模式会立即切换当前在线玩家，房主也包含在内。关闭开放时，“允许所有玩家使用命令”的临时开关会重置为关闭。

## 资源加载、显卡兼容与异常退出处理

- 同名纹理同时存在于物品图集和方块图集时，旧版流体模型优先取物品图集中的纹理；新版流体只从方块图集取材，避免被物品纹理覆盖。资源缺失但材料要求半透明时，新版缺失材质也保留该要求，旧版统一回退为普通缺失材质。
- 资源包把缺失方块模型的面指向方块图集以外的纹理时，旧版没有对这个特殊回退模型执行普通方块模型已有的图集限制；新版拒绝该缺失方块模型并使资源加载失败。
- 反复重载带动画纹理的资源包时，新版释放上传动画参数使用的原生临时内存，并清理旧动画缓冲；旧版临时上传内存没有释放，可能随重复重载累积。
- 资源包导致必要着色器编译失败时，旧版清空着色器缓存后直接报告失败；新版先重新载入原版界面必需着色器，再进入失败处理，使恢复加载期间的界面仍有可用着色器。
- Vulkan 新增 `multiDrawIndirect` 和 `shaderDrawParameters` 必需能力，并跳过一组指定的显卡与驱动组合。旧版能通过原有条件的设备，新版可能不再被选中；没有合格设备时，Vulkan 初始化失败。Vulkan 图集和窗口尺寸上限还会考虑驱动的单次内存分配上限，旧版只按纹理最大边长限制。
- 窗口最小化时，旧版仍尝试获取下一幅窗口显示图像，新版跳过这一获取，恢复窗口后再继续。
- Vulkan 报告设备丢失时，新版异常在支持的驱动上附带最后执行到的渲染检查点；等待 GPU 超时时也会尝试附带检查点。旧版主要给出错误码或超时信息，新增信息用于定位发生故障的渲染阶段。
- 为没有错误消息的空指针、栈溢出或内存不足异常补充崩溃标题时，旧版会丢失原异常的原因链与附带异常，新版保留这些信息。栈帧缺少文件名时，新版也避免在生成报告过程中再次因空指针失败。
- 客户端退出卡住超过 15 秒时，旧版退出看门狗尝试生成 Java 崩溃报告；新版在这一流程之前主动触发原生崩溃，进程在此被终止，后续 Java 报告生成流程通常无法继续执行。
