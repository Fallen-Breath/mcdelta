# Minecraft 26.2-pre-3 变更分析

- 上一个版本：`26.2-pre-2`
- 当前版本：`26.2-pre-3`

## 放置床时，床尾不再补发方块更新

此次修改移除了床头放好后，对床尾周围额外发送的邻居更新与形状更新，影响检测床放置的红石装置。

### 差异出现的场景

玩家正常放置床，侦测器朝向床尾所在方格，且没有其他方块变化同时触发该侦测器；床头仍能正常放下。

### 版本变化

- 26.2-pre-2：床尾先以不通知邻居的方式放置，床头放好后再补发床尾周围的更新。朝向床尾的侦测器能收到形状更新并输出脉冲。
- 26.2-pre-3：床尾的初次放置方式不变，但不再补发上述更新。单凭这次放置，朝向床尾的侦测器不再收到相应触发；床头放置本身仍正常通知其周围方块。

依赖床尾放置更新来唤醒处于待更新状态的红石元件，也会失去这一更新来源。客户端现在还会在本地放置预测中同时补上床头，旧版需要等待服务器同步床头。

## 切换快捷栏后，同一刻的攻击和使用操作采用新物品

### 差异出现的场景

在同一次客户端游戏刻处理输入时，切换快捷栏槽位，并攻击或使用物品。数字键与鼠标滚轮切换都涉及此次修改。

### 版本变化

- 26.2-pre-2：切槽先更新待生效的选择，快捷栏选中框可以先移动；攻击、使用等输入处理完后，实际主手才切换。因此切槽与操作落在同一刻时，操作可能仍使用上一格物品。
- 26.2-pre-3：直接更新实际选择。数字键切槽发生在攻击和使用输入处理之前，同一刻的这些操作使用新槽位物品，并在交互前同步槽位；滚轮切槽也不再等待后续应用。

同一刻按数字键切槽并按丢弃键还有一个例外：丢弃操作不主动发送新槽位。旧版客户端与服务器都从旧槽位丢弃；新版客户端先从新槽位扣除用于预测的物品，但服务器实际仍从旧槽位丢弃，产生物品栏显示与实际内容不一致。鼠标滚轮若在本刻输入处理前已经切槽，新版则会在游戏模式更新时先同步新槽位。

## 按潜行键下坐骑后，服务器继续保留潜行状态

玩家按住潜行键离开坐骑时，26.2-pre-2 会在服务器执行下坐骑的同一刻强制清除潜行标记；如果之后没有新的输入包刷新该标记，服务器状态会与仍按住按键的客户端不一致。26.2-pre-3 移除了这次清除，下坐骑后继续保留按住潜行键的状态，直到后续输入将其改变。依赖服务器潜行状态的交互和实体行为因此可以连续生效。

## 烈性硫黄间歇泉改由负责实体运动的一端施力

### 差异出现的场景

实体进入正在喷发或持续喷发的烈性硫黄间歇泉作用范围，包括玩家、玩家控制的载具和载具上的乘客。

### 版本变化

- 26.2-pre-2：服务器对范围内符合条件的实体加上升速度，并强制同步速度；玩家和玩家控制的载具也走这条路径，乘客本身同样可能得到额外速度。
- 26.2-pre-3：本地玩家及其控制载具在负责运动的客户端直接获得上升速度，普通实体仍由服务器施力；乘客自身不再获得额外上升速度，随载具运动。玩家接触喷流时，无需先等待服务器回传这次加速。

上升速度未达到门槛时每刻增加的量仍为 0.2。坠落距离检查也移到施力之前，并对范围内所有有效实体执行：当前竖直速度大于 -0.5、累计坠落距离大于 1 格时，将累计值降到 1 格。旧版只在本刻实际施力后进行该检查；因此，已经不需要继续加速的实体现在也会接受检查，而恰好由这次加速跨过 -0.5 门槛的下落实体，不会在本次检查中立即得到旧版的坠落距离压低效果。

## 硫方怪的击退、推行与爆炸行为调整

以下变化针对吞入方块的硫方怪。

- **受到攻击后的运动改变。** 全部内置方块类型的基础水平击退参数提高 25%，竖直参数提高 50%。同时，攻击者与硫方怪存在高度差、或瞄准位置使水平与竖直力度互相转换时，新版会按比例缩小转换后的两项力度，使其绝对值分别不超过该类型的基础参数，再应用伤害、抗性等倍率。旧版没有这一限制。因此平打可能更有力，但依赖上下落差制造强竖直弹射的装置不能按整体增幅推算，部分角度的实际击退反而会减小。
- **骑乘时按载具位置推行。** 旧版使用玩家自身的位置和身高判断能否推到硫方怪；新版在玩家骑乘时，改用最底层载具的位置和高度，推行方向也从载具指向硫方怪。相同速度下，骑乘推行使用的速度倍率从步行所用的 0.3 改为 0.16，仍受 0.5 的总上限约束。骑着较高坐骑时，即使玩家身体高于硫方怪，也可以在载具高度与其重叠时推行它。
- **替换吞入的方块立即更新属性。** 旧版替换后，要等后续装备变化检测才移除旧方块提供的属性并应用新方块效果；新版替换已有方块时立即执行这一步。浮力、摩擦、接触伤害和可爆炸状态等不再在替换与后续检测之间短暂沿用旧方块。
- **点燃后可以被矛命中并击退。** 旧版点燃会将硫方怪设为无敌，矛在选取目标时直接跳过它；新版对已点燃的硫方怪放行矛的目标筛选，能在倒计时期间继续用矛推动它。吞入方块时对矛伤害的免疫仍通过既有受击处理实现，放行目标筛选不会使这一攻击扣除生命值。
- **爆炸掉落改用 TNT 规则。** 允许生物破坏方块时，旧版依据 `minecraft:mob_explosion_drop_decay` 决定方块掉落是否随机损失；新版改用 `minecraft:tnt_explosion_drop_decay`。默认前者开启、后者关闭，所以默认规则下，新版被炸毁方块的掉落物不再额外承受这种爆炸损失。`minecraft:mob_griefing=false` 时仍不破坏方块，`minecraft:tnt_explodes=false` 时仍不产生该爆炸。

## 弩最多保存 64 项已装填弹射物，超高等级多重射击会触发异常

### 差异出现的场景

命令、战利品函数或数据包为弩写入超过 64 项 `minecraft:charged_projectiles`，或用自定义附魔使一次装填产生超过 64 项弹射物。

### 版本变化

- 26.2-pre-2：该组件没有列表数量上限，能够保存并使用超过 64 项的列表。
- 26.2-pre-3：数据读取、网络编解码和组件构造都限制为最多 64 项。超过上限的数据不再作为合法组件接受；通过游戏逻辑直接构造超过上限的列表会抛出 `IllegalArgumentException`。

后者也会影响命令给予的高等级附魔弩：原版多重射击每级增加 2 项，32 级得到 65 项。弹射物生成过程没有相应截断，因此携带弹药将这类弩装填至完成时，旧版能装入 65 项，新版会在服务器玩家或实体更新中抛出异常，造成服务器运行崩溃，而不是自动只装前 64 项。普通附魔等级的弩不达到这一上限。

## 和平难度下刷怪笼恢复展示生物，试炼刷怪笼可进入等待状态

首次生成展示实体、尚未缓存展示实体时，旧版会对展示模型也执行实际生成所用的难度与功能开关检查。因此和平难度下，配置为僵尸等敌对生物的刷怪笼和试炼刷怪笼可以没有笼内模型。新版为展示实体及其乘客跳过这项检查，恢复笼内展示。

这还影响试炼刷怪笼的实际方块状态：对于处于 `inactive` 的上述试炼刷怪笼，旧版因无法创建展示生物而保持停用；新版可以进入 `waiting_for_players`，发光等级由 0 变为 4。正常配置下，和平难度的后续玩家检测和实际刷怪仍受原有难度检查限制。

## 部分被视为静态图的动画贴图会导致资源重载失败

若方块或物品图集贴图是一张多格图片，但动画元数据最终只保留零或一个有效帧，例如 16×32 图片配上 `{"animation":{"frames":[0]}}`，两版都会将其作为静态图处理，单帧尺寸为 16×16。

- 26.2-pre-2：上传静态图时只读取一个帧尺寸的区域，上述例子可正常显示图片左上角的 16×16 内容。
- 26.2-pre-3：改为上传整张图片，尝试将 16×32 内容写入 16×16 目标，尺寸检查直接抛出异常，资源重载失败。普通的手动资源包重载会走已有恢复流程，移除已选资源包并尝试重新加载。

这是上传逻辑引起的兼容性变化，不要求修改图片或元数据就会出现差异；有效帧数至多为一、且整图尺寸大于帧尺寸时才触发。

## Vulkan 资源包着色器出错时，缓存清理不再释放非法内存

使用 Vulkan 加载缺失或编译失败的着色器时，两版都会记录错误并把该着色器标记为无效。26.2-pre-2 的无效占位对象却持有普通 Java 堆缓冲区，清空着色器缓存时会将它交给原生内存释放接口，可能在资源重载的错误恢复之前使客户端崩溃。26.2-pre-3 将占位对象的缓冲区改为空，清理时安全跳过这块不存在的原生内存，继续既有的着色器加载失败处理。

## Vulkan 在部分设备上回收临时显存，避免持续累积

使用 Vulkan，且所选最大设备内存堆允许 CPU 直接访问并保持内存一致时，26.2-pre-2 每次提交错误地重复轮换上传缓存，没有轮换实际使用的 GPU 临时缓存。这些临时分配不能在正常提交之间回收复用，运行过程中持续产生的分配会累积，增加耗尽内存的风险。26.2-pre-3 改为在提交完成后回收正确的 GPU 缓存。此修改适用于上述显存路径，不代表所有 Vulkan 设备都会遇到旧版问题。

## 背景音乐间隔不再每刻重新抽取

- 在“默认”和“频繁”音乐播放频率下，旧版每刻都会重新抽一个等待时间，并取其与现有倒计时的较小值，可能不断缩短已选间隔；新版等待期间只按当前音乐的最大间隔约束倒计时，随机间隔在切换频率、上一首结束等具体时点选取。
- 切换维度等操作主动停止音乐时，旧版只给现有倒计时增加 100 刻；新版重新按当前情境和频率选择间隔，再加 100 刻。
- 世界加载画面显示期间，旧版可以启动一首新背景音乐；新版等待离开该画面后才启动新曲，并暂停这部分待播倒计时。

## 调试组合键不再吞掉同键绑定的普通操作

未打开界面、正常接收游戏输入时，如果某个按键既触发调试功能，也绑定了调试分类以外的操作，旧版会在成功执行调试功能后清除该键的按下状态；新版继续向普通按键绑定传递按下与点击。因此，例如把移动操作绑到某个调试快捷键的字母键后，按住调试修饰键再按该字母，会同时触发调试功能与对应普通操作。

## 硫方怪模型与半透明方块的显示变化

- 吞入方块后，旧版硫方怪身体和内部方块仍随史莱姆式伸缩一起变形；新版有内部方块时不再应用这项伸缩。幼年硫方怪若通过数据拥有内部方块，新版将内部方块额外缩小为原来的一半，并调整身体上下位置。
- 半透明地形与半透明方块的片元透明度裁剪阈值从 0.01 提高到 0.1。纹理采样和颜色计算后透明度落在这两个阈值之间的部分，旧版参与渲染，新版直接丢弃；使用低透明度边缘的资源包模型尤其容易出现可见差异。

## 进度与好友界面的操作反馈调整

- 进度界面悬停时的背景淡入淡出，旧版每渲染一帧改变一次，速度随帧率变化；新版每个界面更新刻改变一次，淡入约需 5 刻、淡出最多约需 3 刻。悬停目标本身也改为每刻刷新。
- 在好友界面尝试添加自己、已存在的好友或已有待处理请求的玩家（自己发出或对方发来），旧版直接拒绝且不说明原因，并把发送按钮切回空输入状态；新版给出对应通知，并保留可继续编辑、发送的就绪状态。好友界面也开始把键盘事件交给顶部标签导航，允许使用其标签切换快捷操作。
- Unihex 字体中宽度为奇数的字形，旧版前进宽度计算会向下取整；新版保留半像素，后续文字位置与换行测量可能相应变化。
