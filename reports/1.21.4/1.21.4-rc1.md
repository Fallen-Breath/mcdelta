# Minecraft 1.21.4-rc1 变更分析

- 上一个版本：1.21.4-pre3
- 当前版本：1.21.4-rc1

## 更多区块加载异常会改为重新生成区块

已有区块加载失败时，新版扩大了可以记录错误并继续运行的异常范围。这也使更多种加载失败会导致原区块被重新生成。

### 差异出现的场景

服务器读取或还原磁盘中的区块时发生普通运行时异常。这里指文件读写异常、NBT 解析异常之外的异常；两版对文件读写异常和 NBT 解析异常原本都会采用重新生成的处理。

### 版本变化

- 1.21.4-pre3：这类异常会生成区块加载崩溃报告，随后通过区块生成与加载流程触发服务器崩溃。
- 1.21.4-rc1：记录区块加载失败，并返回一个尚未生成的空区块。后续需要完整区块时，按当前世界生成规则重新生成该位置；服务器可以继续运行。单人游戏还会显示区块加载失败通知。

新版仍会把 Java `Error` 类错误交给崩溃分支，因此这一变化不涵盖内存耗尽等严重错误。

### 实际影响

遇到上述异常的旧区块不再保留原有方块与方块实体，而是进入重新生成流程。重新生成后的区块可以在正常保存时覆盖该位置的原区块数据，原有建筑、红石装置和容器内容因此可能丢失。错误日志和区块错误报告仍会记录加载失败。

## 客户端处理数据包失败时改为断开连接

在连接配置阶段或游戏过程中，客户端把收到的数据包交给主线程处理，处理过程抛出普通异常时，旧版会进一步抛出崩溃异常，导致客户端崩溃；新版改为断开当前连接，显示网络协议错误界面，客户端本身继续运行。

新版会尝试把详情保存到游戏目录的 `debug/disconnect-…-client.txt`。保存成功时，断线详情携带报告路径；服务器提供了错误反馈链接时，也会带上该链接。这一变化针对数据包已经进入主线程处理后的异常；被专门识别为内存耗尽的崩溃异常仍会直接上抛。

## 排队任务的普通异常不再直接终止主线程

客户端、服务器或区块系统的主线程执行已经排队的任务时，旧版会记录任务抛出的异常并继续上抛，可能导致游戏或服务器崩溃；新版会记录并结束当前失败任务，继续处理后续任务。失败任务不会自动重试，因此该项操作可能只完成了异常发生前的部分。

此处的适用范围是任务队列对异常的统一处理。任务直接抛出 Java `Error`，或抛出的崩溃异常最终由内存耗尽、栈溢出引起时，仍会向外传播。

## 副手使用望远镜时修正第三人称显示

玩家没有挥手攻击，并正在用副手使用望远镜时，旧版仍把贴近眼睛的望远镜模型分配给主手：主手另有物品时，该物品的模型会被眼前的望远镜替代，副手还会保留普通手持位置的望远镜；主手为空时，则不会显示贴近眼睛的望远镜模型。

新版按实际使用的手显示眼前的望远镜，主手物品正常显示。第三人称视角及其他玩家看到的人物模型因此与副手使用动作一致。
