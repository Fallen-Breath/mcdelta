# Minecraft 1.21.4-rc1 变更分析

- 上一个版本：1.21.4-pre3
- 当前版本：1.21.4-rc1

## 更多区块加载异常会改为重新生成区块

已有区块加载失败时，新版扩大了可以记录错误并继续运行的异常范围。这也使更多种加载失败会导致原区块被重新生成。

### 差异出现的场景

服务器读取或还原磁盘中的区块时发生普通运行时异常。这里指文件读写异常、NBT 解析异常之外的异常；两版对文件读写异常和 NBT 解析异常原本都会采用重新生成的处理。

### 版本变化

- 1.21.4-pre3：这类异常会生成区块加载崩溃报告，随后通过区块生成与加载流程触发服务器崩溃。
- 1.21.4-rc1：记录区块加载失败，并返回一个尚未生成的空区块。后续需要完整区块时，按当前世界生成规则重新生成该位置；服务器可以继续运行。单人游戏还会显示区块加载失败通知。

新版仍会把 Java `Error` 类错误交给崩溃分支，因此这一变化不涵盖内存耗尽等严重错误。

### 实际影响

遇到上述异常的旧区块不再保留原有方块与方块实体，而是进入重新生成流程。重新生成后的区块可以在正常保存时覆盖该位置的原区块数据，原有建筑、红石装置和容器内容因此可能丢失。错误日志和区块错误报告仍会记录加载失败。

## 客户端处理数据包失败时改为断开连接

客户端收到的数据包可以转交主线程处理。新版改变了这一处理过程发生异常后的退出方式：断开当前连接，并让客户端继续运行。

### 差异出现的场景

客户端处于连接配置阶段或游戏过程中，收到的数据包已经转交主线程，处理时抛出进入数据包错误处理流程的普通异常。

### 版本变化

- 1.21.4-pre3：错误处理先调用默认实现，进一步抛出崩溃异常，导致客户端崩溃；后面的断开连接操作无法执行。
- 1.21.4-rc1：记录错误并断开当前连接，显示网络协议错误界面，客户端本身继续运行。

新版会尝试把详情保存到游戏目录的 `debug/disconnect-…-client.txt`。保存成功时，断线详情携带报告路径；服务器提供了错误反馈链接时，也会带上该链接。被专门识别为内存耗尽的崩溃异常仍会直接上抛，不进入上述断线处理。

## 排队任务的普通异常不再直接终止主线程

客户端、服务器及区块系统通过任务队列执行部分工作。新版调整了任务循环对异常的统一处理，使普通任务失败后仍能继续处理后续任务。

### 差异出现的场景

主线程从队列中取出任务并执行，任务抛出普通异常。任务直接抛出 Java `Error`，或抛出的崩溃异常最终由内存耗尽、栈溢出引起时，不属于这里的恢复范围。

### 版本变化

- 1.21.4-pre3：记录任务异常后继续上抛，可能导致游戏或服务器崩溃。
- 1.21.4-rc1：记录异常并结束当前失败任务，继续处理后续任务。失败任务不会自动重试，该项操作可能只完成了异常发生前的部分。

## 副手使用望远镜时修正第三人称显示

玩家使用望远镜时，第三人称人物模型会把望远镜显示在眼前。新版按照实际使用的手安排这一模型，修正副手使用时的错位。

### 差异出现的场景

玩家没有挥手攻击，正在用副手使用望远镜，并通过第三人称视角或其他玩家的视角观察人物模型。

### 版本变化

- 1.21.4-pre3：贴近眼睛的望远镜模型仍分配给主手。主手另有物品时，该物品的模型会被眼前的望远镜替代，副手还保留普通手持位置的望远镜；主手为空时，不显示贴近眼睛的望远镜模型。
- 1.21.4-rc1：按照实际使用的副手显示眼前的望远镜，主手物品正常显示。
