# Minecraft 1.20.3-pre4 变更分析

- 上一个版本：1.20.3-pre3
- 当前版本：1.20.3-pre4

## 容器快捷交换只接受快捷栏和副手目标

在容器界面中按数字键或副手交换键，会将鼠标指向的栏位与指定的玩家物品栏位交换。新版在服务器端限制了交换目标，关闭自定义客户端直接操作主物品栏、绕过盔甲栏限制及使用越界编号的路径。

### 差异出现的场景

玩家打开有效的容器界面，使用自定义客户端发送 `SWAP` 类型的点击请求：被点击的容器栏位有效，但交换目标不是快捷栏编号 `0–8` 或副手编号 `40`。涉及取出物品的操作，还要求被点击的容器栏位允许玩家取走物品。

### 版本变化

交换目标为主物品栏编号 `9–35` 或盔甲栏编号 `36–39` 时：

- 1.20.3-pre3：服务器直接读写指定的玩家物品栏位，可以与主物品栏或盔甲栏交换。作为交换目标的盔甲栏不经过自身的物品类型、堆叠数量和绑定诅咒检查。例如，普通物品可以从容器栏位放进空的盔甲栏；穿着的绑定诅咒装备也可以换到空的普通容器栏位中。
- 1.20.3-pre4：忽略这些目标编号，物品保持在原栏位，无法再通过这类请求直接交换主物品栏或绕过盔甲栏限制。

交换目标大于 `40`，且被点击的容器栏位中有可取出的物品时：

- 1.20.3-pre3：读取交换目标得到空物品，向目标写回则不生效。服务器仍会清空被点击的容器栏位，导致其中的物品丢失。
- 1.20.3-pre4：忽略请求，被点击栏位中的物品保留。

交换目标为负数时：

- 1.20.3-pre3：读取玩家物品栏时访问负下标，产生容器点击异常。
- 1.20.3-pre4：在读取物品栏前忽略请求，不再触发这一异常。

原版客户端的数字键和副手交换键本来就只发送 `0–8` 和 `40`，正常使用这些快捷键的表现不变。

## 进度奖励函数中的 return 不再中断触发它的外层函数

数据包函数可以通过完成进度来触发奖励函数。新版保留这类间接调用与外层函数的嵌套关系，使奖励函数执行 `return` 时只结束自己的调用。

### 差异出现的场景

一个正在执行的数据包函数通过 `advancement grant` 等操作完成玩家进度，并触发该进度的奖励函数。奖励函数执行了结束自身调用的 `return`，包括 `return <值>`、`return fail` 或实际执行到的 `return run …`；此时外层函数仍有命令等待执行。

例如，外层函数先给当前玩家授予一个尚未完成的自定义进度，再执行 `say after`；该进度的奖励函数直接执行 `return 0`。

### 版本变化

- 1.20.3-pre3：间接启动奖励函数时，服务器按全新顶层调用安排它的执行，未保留与外层函数的嵌套关系。奖励函数中的 `return` 会一并丢弃外层函数尚未执行的命令，还可能影响其他等待恢复的调用层。在上述例子中，`say after` 不会执行。
- 1.20.3-pre4：服务器根据当前命令的调用深度，将奖励函数安排在更深的调用层。奖励函数中的 `return` 只结束该奖励函数，随后继续执行外层剩余命令；上述例子的 `say after` 会执行。

奖励函数自身位于 `return` 之后的命令仍会被跳过；变化在于提前返回不再连带跳过触发它的外层逻辑。

## 多人游戏服务器列表恢复悬停提示

- 将鼠标移到服务器列表的连接状态图标上时，1.20.3-pre3 会在绘制列表后清空刚生成的提示，无法显示延迟、连接失败或版本不兼容等状态说明；1.20.3-pre4 在清空提示后重新绘制列表，使本次生成的状态说明正常显示。
- 将鼠标移到在线人数区域时，1.20.3-pre3 同样无法显示玩家名单；1.20.3-pre4 恢复显示服务器提供的名单，是否有名单可显示仍取决于服务器返回的内容。
