# Minecraft 23w43b 变更分析

- 上一个版本：23w43a
- 当前版本：23w43b

## 修正世界启动末段的计时，避免异常等待及看门狗误判

世界启动时，服务器会准备出生点附近的区块，并重新登记存档中保存的强制加载区块。新版修正这一流程最后一次等待所用的时间单位，影响单人世界加载和专用服务器启动。

### 差异出现的场景

创建、重新进入单人世界或启动专用服务器，走到出生点准备完成后的最后一次等待。即使世界没有通过 `/forceload` 设置强制加载区块，也会执行这里的计时。是否出现明显故障，取决于系统纳秒时钟的读数，以及专用服务器看门狗线程的执行时序。

### 版本变化

- 23w43a：把当前时间的毫秒读数加上以纳秒表示的 10 毫秒，作为纳秒时钟的等待截止时间。时钟读数为较大正值时，这个截止时间已经在过去，最后一次等待通常立即结束；读数为较大负值时，截止时间反而远在未来，可能长期停留在进入世界前的加载阶段。
- 23w43b：使用当前纳秒读数加上 10 毫秒，恢复正常的短暂任务处理和等待阶段。

### 实际影响

在时钟读数为正、且 `max-tick-time` 大于 0 的专用服务器上，旧版还存在启动后立即被看门狗关闭的可能。看门狗线程在服务器主循环重设截止时间之前就会启动；如果它先读到错误的截止时间，并据此算出超过 `max-tick-time` 的延迟，就会把服务器判定为卡死并强制关闭。新版消除了这次单位混用造成的误判；旧版是否触发取决于线程时序，并非每次启动都会发生。

## 上传世界后修改 Realms 配置，再返回列表时不再崩溃

Realms 世界上传结束后，返回配置页的操作会创建一个尚未打开的服务器列表，供之后退出配置页时使用。新版调整退出配置页时的执行顺序，避免在这个列表初始化之前清除其中的选择。

### 差异出现的场景

从 Realms 世界上传结束界面返回配置页，成功修改 Realm 名称、描述或开关状态等会标记配置已更改的设置，然后退出配置页、返回服务器列表。

### 版本变化

- 23w43a：先重置服务器列表，再显示列表。重置操作会直接访问尚未初始化的列表控件，因空指针异常导致客户端崩溃。
- 23w43b：先显示并初始化服务器列表，再清除选择、刷新数据，可以正常返回。

## 联机版本校验更新

原版服务器在登录握手阶段检查客户端的协议版本。23w43b 更新了协议号，因此不能与 23w43a 原版客户端或服务器混用。

### 差异出现的场景

客户端与服务器的一端固定使用 23w43a，另一端使用被比较的版本，尝试登录服务器。

### 版本变化

- 23w43a：协议号为 `1073741983`，与固定使用 23w43a 的另一端相同，可以通过协议版本校验。
- 23w43b：协议号为 `1073741984`，与另一端不匹配，服务器在登录握手阶段发送不兼容版本的断开提示并断开连接，玩家无法进入服务器。

## GameTest 结构导出兼容目录符号链接

GameTest 结构导出会将结构写成 `.snbt` 文件。新版在创建输出目录前解析现存目录的真实路径，修复部分 Java 运行时下向目录符号链接写入时的失败。

### 差异出现的场景

在启用开发环境专用 `/test` 命令的运行方式下，使用 `/test export`、`/test exportthis` 或 `/test exportthese` 导出结构。输出文件的直接父目录是指向现存目录的符号链接，目标目录可写、输入结构有效，且所用 Java 运行时仍存在 `JDK-8294193` 所述的目录链接处理问题。

### 版本变化

- 23w43a：直接对父目录的链接路径执行创建目录操作，抛出“文件已存在”异常，结构转换失败，命令报告导出失败。
- 23w43b：先将现存父目录解析为真实路径，再创建目录并写入文件，可以完成导出。

结构 SNBT 升级工具写回文件时也使用同一个无缓存输出接口；在相同的目录链接和运行时条件下，旧版写回失败，新版可以完成写回。

这项差异受 Java 运行时版本限制。后续 Java 版本也修复了相应问题，已修复该问题的运行时下，旧版便可能正常处理此类目录。Liberica JDK 17.0.14 的修复列表收录了 `JDK-8294193`，可参见其[发布说明第 14 页](https://download.bell-sw.com/documentation/liberica-jdk/17.0.14%2B10-psu/release-notes-17.0.14%2B10-psu-liberica-jdk.pdf#page=14)。
