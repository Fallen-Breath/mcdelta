# Minecraft 1.20.3-pre2 变更分析

- 上一个版本：1.20.3-pre1
- 当前版本：1.20.3-pre2

## 旧存档中的矮草丛物品与拼图方块补全重命名转换

此前草丛的标识符由 `minecraft:grass` 改为 `minecraft:short_grass`，但旧版只转换了方块名称。本次补上物品及拼图方块最终状态的转换。

### 差异出现的场景

加载数据版本低于 3692 的旧玩家数据、区块或结构模板，其中保存了 `minecraft:grass` 物品，或拼图方块的 `final_state` 使用 `minecraft:grass`。

### 版本变化

- 1.20.3-pre1：普通方块状态会改名，但物品保留已经失效的旧标识符，加载后成为空物品；拼图方块的最终状态也保留旧名，实际替换拼图方块时会因找不到方块而报错。
- 1.20.3-pre2：物品标识符和拼图方块最终状态中的方块名一并转换，旧物品可继续作为矮草丛使用，拼图方块也能正常生成矮草丛。

修复加入的是数据版本 3692 的既有转换步骤。已经以 3692 或更高版本保存的数据不会重新执行这一步；此前已加载并丢失的物品也不会凭空恢复。

## 饰纹陶罐插入物品改由服务器确认

对饰纹陶罐执行使用操作时，旧版客户端会先根据本地陶罐内容判断是否可以插入，在生存模式下立即从手中扣掉一个物品，并修改本地陶罐内容。新版客户端只接收这次交互，插入判断和物品变更交给服务器执行，再通过同步反映结果。

因此，当漏斗或其他玩家已改变陶罐内容、而本地内容尚未同步时，新版不会再依据过时内容先做一次本地扣减。正常插入的手部挥动也从立即在本地启动，改为收到服务器确认后启动；高延迟连接中两者的时机更容易区分。服务器仍按每次一个物品处理插入。

## 命名箭和三叉戟会给投射物实体命名

使用在铁砧中命名的普通箭、药箭、光灵箭或三叉戟时，旧版只保留供拾取的物品名称，生成的投射物实体本身没有继承名称；新版同时把物品名称赋给实体。弓、弩及发射器发射箭，以及玩家投出三叉戟，都经过这项处理。

例如用名为 `test` 的箭射击后，新版可以通过 `@e[type=minecraft:arrow,name=test]` 找到该箭，旧版不能。无射手的发射器箭还会以箭实体本身作为伤害来源，因而击杀消息中的来源名称也可显示这个自定义名称。已经存在的无名投射物不会在升级时根据其保存的拾取物品补名。

开启 1.21 实验内容时，燃烧的箭击中旋风人，旧版会先把旋风人点燃，再因其免疫箭伤害而反弹，留下燃烧及后续火焰伤害；新版在点火前排除能够反弹箭的实体，旋风人会反弹箭而不被这次命中点燃。数据包放入 `minecraft:deflects_arrows` 实体类型标签的其他实体也受同一检查影响。

## 风弹可以打碎饰纹陶罐和紫颂花，入水后不再减速

这些变化适用于启用 1.21 实验内容的世界。

- 旋风人的风弹直接命中饰纹陶罐或紫颂花，且 `projectilesCanBreakBlocks`、`mobGriefing` 均为 `true` 时，旧版会产生风爆但保留被命中的这两种方块；新版把风弹加入可破坏方块的投射物标签，命中后会打碎陶罐或破坏紫颂花，并按相应方块规则产生掉落物。已有陶罐储物或紫颂花种植区域会因此受到直接命中的影响。
- 风弹进入水中后，旧版每游戏刻将速度乘以 0.8，飞行会迅速减慢；新版在水中使用与空气中相同的速度保留系数 1.0。相同发射条件下，穿过水域的风弹能更快到达后方目标。

## 命令执行额度低于零时也会中止

命令系统会给执行上下文修改、函数调用和普通命令执行计入开销。一次上下文准备可以连续计入多次开销，把剩余额度从正数直接扣到负数；新版修复了这种情况下不能及时停止的问题。

### 差异出现的场景

函数或直接输入的命令接近 `maxCommandChainLength` 上限，并在一次执行上下文准备中连续消耗多次额度。例如玩家将上限设为 1 后，执行 `/execute as @s at @s run say reached`。

### 版本变化

- 1.20.3-pre1：只在剩余额度恰好为零时停止。上述上下文准备把额度扣到负数后，后续的 `say` 仍可执行；更长的函数链也可能借此越过限制继续运行。
- 1.20.3-pre2：剩余额度为零或负数都停止取出下一项执行任务。上述命令不会继续执行 `say`。

新版检查仍发生在执行任务之间，不会在一次上下文准备的每次扣减后立刻打断它。依赖旧漏洞继续运行的命令链会更早结束。

代码出处：[1.20.3-pre1 · 旧版只检查等于零](https://github.com/TISUnion/guardian/blob/22aa5713280c4d12f8f540cb8dc7985491816f4b/src/main/java/net/minecraft/commands/execution/ExecutionContext.java#L100)；[1.20.3-pre2 · 新版检查小于等于零](https://github.com/TISUnion/guardian/blob/3199dac4dcc08dc5e1348b24548c309d47664ef9/src/main/java/net/minecraft/commands/execution/ExecutionContext.java#L96)；[1.20.3-pre2 · 一次准备中连续计入上下文开销](https://github.com/TISUnion/guardian/blob/3199dac4dcc08dc5e1348b24548c309d47664ef9/src/main/java/net/minecraft/commands/execution/tasks/BuildContexts.java#L50)；[1.20.3-pre2 · 额度取自 maxCommandChainLength](https://github.com/TISUnion/guardian/blob/3199dac4dcc08dc5e1348b24548c309d47664ef9/src/main/java/net/minecraft/commands/Commands.java#L339)。

## 记分板通配符遍历顺序可能改变运算结果

记分板保存计分对象的容器从 Java `HashMap` 改为 fastutil 映射。`*` 取得的对象列表直接使用容器遍历顺序，因此这项内部替换会传递到逐对象执行的记分板运算。

### 差异出现的场景

使用 `/scoreboard players operation`，并让 `*` 涉及多个计分对象，运算采用覆盖赋值、交换等依赖先后顺序的操作。

一个具体例子是，在全新记分板上建立 `src`、`dst` 两个虚拟计分项，仅给 `a` 和 `c` 分别设置 `src` 分数 1、2，然后首次执行：

```mcfunction
scoreboard players operation #out dst = * src
```

### 版本变化

- 1.20.3-pre1：上述两个来源的遍历顺序是 `a`、`c`，连续赋值后 `#out` 的结果为 2。
- 1.20.3-pre2：同样的两个来源遍历为 `c`、`a`，结果为 1。

这种顺序本来就不是按名称或分数排序的约定；不同对象集合和容器状态下不能套用固定的新顺序。但已经依赖旧版实际遍历顺序的数据包，升级后确实可能出现不同的计算结果。

代码出处：[1.20.3-pre1 · 旧版计分对象容器](https://github.com/TISUnion/guardian/blob/22aa5713280c4d12f8f540cb8dc7985491816f4b/src/main/java/net/minecraft/world/scores/Scoreboard.java#L30)；[1.20.3-pre2 · 替换计分对象容器](https://github.com/TISUnion/guardian/blob/3199dac4dcc08dc5e1348b24548c309d47664ef9/src/main/java/net/minecraft/world/scores/Scoreboard.java#L35)；[1.20.3-pre2 · 通配符来源按容器顺序收集](https://github.com/TISUnion/guardian/blob/3199dac4dcc08dc5e1348b24548c309d47664ef9/src/main/java/net/minecraft/world/scores/Scoreboard.java#L190)；[1.20.3-pre2 · 逐来源依次应用运算](https://github.com/TISUnion/guardian/blob/3199dac4dcc08dc5e1348b24548c309d47664ef9/src/main/java/net/minecraft/server/commands/ScoreboardCommand.java#L478)。

## 旧版保存的 styled 记分板数字格式会丢失

`styled` 数字格式的序列化类型名由 `minecraft:result` 改为 `minecraft:styled`，命令中的 `styled` 语法仍然相同。

加载 1.20.3-pre1 保存、使用这种格式的记分项或单个分数时，新版无法识别旧类型名：记分项格式被清空，单个分数的格式覆盖也会被忽略。分数数值仍保留，显示改用相应的默认或上级格式；重新执行格式设置命令后，会以新类型名保存。其他 `blank`、`fixed` 格式不受这次改名影响。

## 可解析为 UUID 的特殊玩家名不再优先按名字查找

在离线模式等允许特殊玩家名的环境中，名字可能采用 Java 接受的缩写 UUID 写法，例如 `1-1-1-1-1`，可解析为 `00000001-0001-0001-0001-000000000001`。

若在线玩家使用这个名字，而世界中另有对应 UUID 的已加载实体，旧版的记分板计分对象参数先匹配在线玩家名，操作该玩家的分数；新版先按 UUID 查找实体，操作对应实体的分数。这个变化影响记分板、队伍及 `execute if score` 等使用同一计分对象参数的命令。通常的正版玩家名不会满足此条件。

## 保存世界时移除 level.dat 回读检查与诊断崩溃

旧版每次写入并替换 `level.dat` 后，会立即重新读取整个文件。文件损坏、读取失败，或 NBT 读取的内存计量超过 100 MiB 等情况，都会进入诊断分支：首次失败抛出崩溃异常，并尝试把现有文件移为带时间戳的损坏文件，同时输出未压缩数据。

新版写入后不再做这次回读，也不再由这一分支移动文件、输出诊断副本或触发崩溃。相同的保存后回读异常条件因而不会在此处中断服务器。实际写入或替换文件时发生的异常仍记录为保存失败；这次移除检查也不等于已经修复损坏文件。

代码出处：[1.20.3-pre1 · 旧版保存后回读及诊断处理](https://github.com/TISUnion/guardian/blob/22aa5713280c4d12f8f540cb8dc7985491816f4b/src/main/java/net/minecraft/world/level/storage/LevelStorageSource.java#L504)；[1.20.3-pre2 · 新版保存流程](https://github.com/TISUnion/guardian/blob/3199dac4dcc08dc5e1348b24548c309d47664ef9/src/main/java/net/minecraft/world/level/storage/LevelStorageSource.java#L502)；[1.20.3-pre2 · NBT 内存与深度限额](https://github.com/TISUnion/guardian/blob/3199dac4dcc08dc5e1348b24548c309d47664ef9/src/main/java/net/minecraft/nbt/NbtAccounter.java#L29)。

## 声音定位与字幕使用一致的镜头状态

声音字幕的距离判断从声音开始播放时，移到了每次绘制字幕时，方向也改为使用实际听音位置与朝向。

新版还会在提交听音位置更新时，一起复制镜头朝向。玩家一边移动一边转头、音频更新稍后才处理时，旧版可能将较早的位置与后来变化的朝向混用于声音定位；新版的位置和方向来自同一次采样。

- 对有距离衰减的声音，旧版只在声音开始时判断是否在可听范围内；字幕出现后，即使离开范围仍保留到显示时间结束。新版走出范围就隐藏，显示时间内回到范围可再次显示。若客户端已经接收到播放事件，最初在范围外的声音也能在玩家及时靠近后显示字幕。
- 第三人称，尤其镜头位于玩家前方时，旧版仍按玩家眼睛位置和面朝方向绘制左右箭头；新版使用与声音播放一致的镜头位置、朝向，字幕方向随镜头改变。
- 同名字幕合并仍只保留最新一次事件的位置。新版连范围外的同名事件也会刷新位置和计时，因此远处同名声音可能让原先可见的字幕条目暂时隐藏。字幕半径取自该文本首次记录的声音，刷新时不更新；即使上一次显示已经过期，后续同名声音仍使用这个半径。共用字幕但音量或衰减距离不同的自定义声音会受到这一点影响。

上述距离过滤不限制相对声音和无距离衰减的声音。默认显示时间仍为三秒，并受“通知显示时长”设置缩放。

## 药水和状态效果时长按当前刻速率换算

通过 `/tick rate` 改变目标游戏刻速率后，旧版药水、滞留药水、药箭、创造模式谜之炖菜提示，以及物品栏状态效果的剩余时间，仍固定按每秒 20 游戏刻显示；新版按世界当前目标刻速率换算。例如同样剩余 600 游戏刻的效果，在每秒 10 刻时，旧版显示 `0:30`，新版显示 `1:00`。试玩模式的剩余时间也使用相同的新换算方式。

这项变化调整的是显示，效果剩余的游戏刻数及试玩期限没有因此改变；它也没有按服务器实际卡顿后的运行速度估算时间。

## 暂停时的按键和界面操作调整

- 在未向局域网开放的单人世界中，用 `F3+Esc` 进入不显示菜单按钮的暂停界面后，旧版仍会把普通游戏按键记入按键状态与点击队列，恢复时可能执行暂停期间积累的操作；新版只在没有打开任何界面时记录普通游戏按键。该暂停界面的调试组合键仍可处理。普通界面未拦截的松键事件，新版也会清除对应按键状态。
- 铁砧中放有可命名物品时，旧版重命名输入框会吞掉按键，却没有把按键交给文本编辑处理，导致退格、删除、左右移动光标、复制粘贴等失效；新版先处理文本框的按键，这些编辑操作恢复正常。
- 命令补全列表打开时按 `Esc`，旧版只关闭候选列表，输入框内灰色的补全文字可能留下；新版同时清除这段提示。
- Realms 中使用通用弹窗的提示与确认窗口打开时，新版清除背景页面的键盘焦点，背景控件不再保留原先的焦点状态。

## 雨幕滚动更连贯

旧版雨幕贴图滚动把时间与位置偏移合并后每 32 游戏刻重置一次，雨线会周期性跳动。新版让时间连续推进更长的周期，并在算出滚动偏移后折回纹理坐标，消除了原先每 32 刻一次的重置跳动。这只改变雨幕动画，不改变降雨对世界的作用。
