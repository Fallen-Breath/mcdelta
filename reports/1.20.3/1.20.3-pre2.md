# Minecraft 1.20.3-pre2 变更分析

- 上一个版本：1.20.3-pre1
- 当前版本：1.20.3-pre2

## 旧存档中的矮草丛物品与拼图方块补全重命名转换

此前草丛的标识符由 `minecraft:grass` 改为 `minecraft:short_grass`，但旧版只转换了方块名称。本次补上物品及拼图方块最终状态的转换。

### 差异出现的场景

加载数据版本低于 3692 的旧玩家数据、区块或结构模板，其中保存了 `minecraft:grass` 物品，或拼图方块的 `final_state` 使用 `minecraft:grass`。

### 版本变化

- 1.20.3-pre1：普通方块状态会改名，但物品保留已经失效的旧标识符，加载后成为空物品；拼图方块的最终状态也保留旧名，实际替换拼图方块时会因找不到方块而报错。
- 1.20.3-pre2：物品标识符和拼图方块最终状态中的方块名一并转换，旧物品可继续作为矮草丛使用，拼图方块也能正常生成矮草丛。

修复加入的是数据版本 3692 的既有转换步骤。已经以 3692 或更高版本保存的数据不会重新执行这一步；此前已加载并丢失的物品也不会凭空恢复。

## 饰纹陶罐插入物品改由服务器确认

对饰纹陶罐使用物品时，客户端原先会先按本地陶罐内容尝试插入。新版把插入判断和物品变更交给服务器，再通过同步反映结果。

### 差异出现的场景

玩家手持物品对饰纹陶罐执行使用操作。联机延迟较高，或漏斗、其他玩家刚改变陶罐内容而客户端尚未收到同步时，差异更明显。

### 版本变化

- 1.20.3-pre1：客户端根据本地内容判断能否插入。判断成功时，生存模式玩家手中的物品立即减少一个，本地陶罐内容也随之改变，并立即启动挥手动画；服务器再独立处理同一次操作。
- 1.20.3-pre2：客户端只接收这次交互，不先修改手中物品或陶罐内容。服务器判断插入结果并同步，挥手动画也在服务器确认后启动。

因此，本地陶罐内容过时时，新版不会先按过时内容扣减物品。服务器仍按每次一个物品处理成功的插入。

## 命名箭和三叉戟会给投射物实体命名

箭和三叉戟会保存供拾取的物品。新版在创建投射物时，还将该物品的自定义名称赋给投射物实体。

### 差异出现的场景

用弓、弩或发射器发射在铁砧中命名的普通箭、药箭、光灵箭，或由玩家投出命名的三叉戟。

### 版本变化

- 1.20.3-pre1：名称保留在拾取物品上，生成的投射物实体本身没有继承名称。例如发射名为 `test` 的箭后，不能仅凭该物品名称用 `@e[type=minecraft:arrow,name=test]` 选中它。
- 1.20.3-pre2：新生成的投射物实体继承物品名称，上述选择器可以选中对应的箭。无射手的发射器箭以箭实体自身作为伤害来源，击杀消息中的来源名称也可显示这个自定义名称。

已经存在的无名投射物不会在升级时根据其保存的拾取物品补上实体名称。

## 燃烧的箭不再点燃旋风人

能够反弹箭的实体会拒绝箭造成的伤害。新版将这项反弹条件也用于命中时的点火检查，避免箭被反弹后仍留下燃烧。

### 差异出现的场景

启用 1.21 实验内容，燃烧的箭击中旋风人。数据包将其他实体类型加入 `minecraft:deflects_arrows` 标签时，同样受这项点火检查影响。

### 版本变化

- 1.20.3-pre1：先点燃旋风人，再因其免疫箭伤害而反弹箭，旋风人会留下燃烧及后续火焰伤害。
- 1.20.3-pre2：点火前检查目标是否属于反弹箭的实体类型，旋风人会反弹箭而不被这次命中点燃。

## 风弹直接命中可以打碎饰纹陶罐和紫颂花

饰纹陶罐和紫颂花会对指定类型的投射物命中作出破坏响应。新版将旋风人的风弹加入这一范围。

### 差异出现的场景

启用 1.21 实验内容，旋风人的风弹直接命中饰纹陶罐或紫颂花，且 `projectilesCanBreakBlocks`、`mobGriefing` 均为 `true`。

### 版本变化

- 1.20.3-pre1：风弹命中后产生风爆，但保留被直接命中的饰纹陶罐或紫颂花。
- 1.20.3-pre2：风弹属于可触发方块破坏响应的投射物，直接命中会打碎陶罐或破坏紫颂花，并按相应方块规则产生掉落物。

原先能承受风弹直接命中的陶罐储物和紫颂花种植区域，在满足上述游戏规则时会受到破坏。

## 风弹入水后不再减速

投射物在水中飞行时会应用水中的速度保留系数。新版为风弹指定系数 1.0，使其与空气中的速度保留系数一致。

### 差异出现的场景

启用 1.21 实验内容，旋风人的风弹在飞行途中进入水中。

### 版本变化

- 1.20.3-pre1：每游戏刻将风弹速度乘以 0.8，入水后会迅速减慢。
- 1.20.3-pre2：水中每刻使用系数 1.0，不再受到这项减速；相同发射条件下，穿过水域的风弹能更快到达后方目标。

## 隐藏菜单的暂停界面不再积累普通游戏按键

`F3+Esc` 可以打开不显示菜单按钮的暂停界面。新版将该界面的调试按键处理与普通游戏按键记录分开，避免暂停期间的操作延后执行。

### 差异出现的场景

在未向局域网开放的单人世界中，用 `F3+Esc` 暂停，然后按下会控制游戏动作的普通按键，再恢复游戏。另一项相关差异出现在普通界面打开时，界面没有拦截某个松键事件的情况下。

### 版本变化

- 1.20.3-pre1：隐藏菜单的暂停界面仍会更新普通按键状态并积累点击，恢复时可能执行暂停期间积累的操作；普通界面未拦截的松键事件也不会进入清除游戏按键状态的分支。
- 1.20.3-pre2：仅在没有打开任何界面时记录普通游戏按键，隐藏菜单的暂停界面不会再积累这些操作；界面未拦截的松键事件会清除对应按键状态。

隐藏菜单的暂停界面仍可处理原有调试组合键。

## 命令执行额度低于零时也会中止

命令系统会给执行上下文修改、函数调用和普通命令执行计入开销。一次上下文准备可以连续计入多次开销，把剩余额度从正数直接扣到负数；新版修复了这种情况下不能及时停止的问题。

### 差异出现的场景

函数或直接输入的命令接近 `maxCommandChainLength` 上限，并在一次执行上下文准备中连续消耗多次额度。例如玩家将上限设为 1 后，执行 `/execute as @s at @s run say reached`。

### 版本变化

- 1.20.3-pre1：只在剩余额度恰好为零时停止。上述上下文准备把额度扣到负数后，后续的 `say` 仍可执行；更长的函数链也可能借此越过限制继续运行。
- 1.20.3-pre2：剩余额度为零或负数都停止取出下一项执行任务。上述命令不会继续执行 `say`。

新版检查仍发生在执行任务之间，不会在一次上下文准备的每次扣减后立刻打断它。依赖旧漏洞继续运行的命令链会更早结束。

## 记分板通配符遍历顺序可能改变运算结果

记分板保存计分对象的容器从 Java `HashMap` 改为 fastutil 映射。`*` 取得的对象列表直接使用容器遍历顺序，因此这项内部替换会传递到逐对象执行的记分板运算。

### 差异出现的场景

使用 `/scoreboard players operation`，并让 `*` 涉及多个计分对象，运算采用覆盖赋值、交换等依赖先后顺序的操作。

一个具体例子是，在全新记分板上建立 `src`、`dst` 两个虚拟计分项，仅给 `a` 和 `c` 分别设置 `src` 分数 1、2，然后首次执行：

```mcfunction
scoreboard players operation #out dst = * src
```

### 版本变化

- 1.20.3-pre1：上述两个来源的遍历顺序是 `a`、`c`，连续赋值后 `#out` 的结果为 2。
- 1.20.3-pre2：同样的两个来源遍历为 `c`、`a`，结果为 1。

这种顺序本来就不是按名称或分数排序的约定；不同对象集合和容器状态下不能套用固定的新顺序。但已经依赖旧版实际遍历顺序的数据包，升级后确实可能出现不同的计算结果。

## 可解析为 UUID 的特殊玩家名不再优先按名字查找

计分对象参数既能接受在线玩家名，也能接受实体 UUID。新版先尝试按 UUID 查找实体，改变了两者同时匹配时的对象选择。

### 差异出现的场景

在离线模式等允许特殊玩家名的环境中，在线玩家使用 Java 可解析为 UUID 的缩写名称，例如 `1-1-1-1-1`，同时世界中另有 UUID 为 `00000001-0001-0001-0001-000000000001` 的已加载实体。对这个参数执行记分板、队伍或 `execute if score` 等使用计分对象参数的命令。

### 版本变化

- 1.20.3-pre1：先匹配在线玩家名，操作该玩家的计分对象。
- 1.20.3-pre2：先解析 UUID 并查找实体，操作对应实体的计分对象。

普通实体以 UUID 计分，玩家以名字计分，因此上述选择会落到不同的计分对象。通常的正版玩家名不会满足这一条件。

## 保存世界时移除 level.dat 回读检查与诊断崩溃

世界保存会写入并替换 `level.dat`。旧版随后还会立即回读整个文件并在失败时进入诊断分支，新版移除了这次回读及其异常处理。

### 差异出现的场景

一次保存后的 `level.dat` 若立即回读，会发生文件损坏、读取失败或 NBT 内存计量超过 100 MiB 等异常。

### 版本变化

- 1.20.3-pre1：保存后立即回读。首次回读失败会抛出崩溃异常，并尝试把现有文件移为带时间戳的损坏文件，同时输出未压缩数据。
- 1.20.3-pre2：保存后不再回读，不会因这一检查触发崩溃、移动文件或输出诊断副本；同样的保存后回读异常条件不会在此处中断服务器。

实际写入或替换文件时的异常仍记录为保存失败。移除这次检查并不会修复已经损坏的文件。

## 字幕按当前听音位置筛选距离和方向

声音字幕的距离检查从声音开始播放时移到了每次绘制时，方向也改为使用声音系统的听音位置与朝向。

### 差异出现的场景

开启字幕后，在一次有距离衰减的声音事件前后移动，或使用第三人称镜头观察声源。距离变化的比较以客户端已收到播放事件、且仍在字幕显示时间内为前提。

### 版本变化

- 1.20.3-pre1：只在声音开始时判断是否处于可听范围。已经显示的字幕离开范围后仍保留到时间结束，最初在范围外的声音不会因后来靠近而显示。左右箭头按玩家眼睛位置和面朝方向绘制。
- 1.20.3-pre2：每次绘制按当前听音位置检查距离，走出范围即隐藏，在显示时间内回到范围可再次显示；最初在范围外的声音也可在及时靠近后显示。左右箭头使用与声音播放一致的镜头位置和朝向，第三人称镜头位于玩家前方时尤其明显。

同名字幕仍合并为一个条目，只保留最新事件的位置。新版连范围外的同名事件也会刷新位置和计时，因此远处同名声音可能让原先可见的条目暂时隐藏。其半径取自该文本首次记录的声音，刷新时不更新；即使上一次显示已过期，后续同名声音仍使用这个半径。共用字幕但音量或衰减距离不同的自定义声音会受到这一点影响。

距离过滤不限制相对声音和无距离衰减的声音。默认显示时间仍为三秒，并受“通知显示时长”设置缩放。
