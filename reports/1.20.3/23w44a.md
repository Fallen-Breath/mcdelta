# Minecraft 23w44a 变更分析

- 上一个版本：23w43b
- 当前版本：23w44a

## 地图、记分板等独立数据无法首次保存

新版修改了 NBT 文件的写入方式。直接保存到尚不存在的文件时，写入会失败，影响多种需要跨重启保留的世界数据。

### 差异出现的场景

世界需要第一次保存某个独立数据文件，例如新地图对应的 `data/map_<编号>.dat`、首次建立的记分板、某个命名空间的命令存储，或此前没有保存过的强制加载区块列表。旧世界也可能遇到此问题，条件是这次保存的具体文件尚不存在。

### 版本变化

- 23w43b：写入时可以创建文件，地图图像、记分板、命令存储等能够在退出世界后重新读取。
- 23w44a：写入要求目标文件已经存在。首次保存会报错，数据仅留在当前运行中的内存里；保存失败后仍会清除待保存标记。

这一变化也影响地图编号计数、袭击状态和命名随机序列。已有对应文件的数据仍可更新；世界信息和玩家数据的保存会先创建临时文件，因此不符合上述“目标文件不存在”的触发条件。

### 实际影响

新生成的地图可能在重进世界后失去图像；如果地图编号计数文件也从未建立，之后创建的地图还会再次使用先前的编号。首次保存失败的记分板、命令存储和强制加载列表会在重启后丢失；命名随机序列则会从重新初始化的状态继续生成随机结果。是否出现这些后果，取决于对应文件是否已由旧版或其他途径建立。

## 已保存的服务器列表和创造模式快捷栏不再载入

同一次 NBT 文件读写调整还把未压缩文件的存在性判断反转。服务器列表和已保存的创造模式快捷栏都会受到影响。

### 差异出现的场景

游戏目录中已有正常的 `servers.dat` 或 `hotbar.nbt`，随后在新版中重新读取服务器列表，或第一次访问已保存的创造模式快捷栏。

### 版本变化

- 23w43b：文件存在时读取其中的服务器条目或九组快捷栏。
- 23w44a：文件存在时直接当作没有数据，服务器列表显示为空，保存的快捷栏也以空组开始。

没有 `hotbar.nbt` 时，新版保存快捷栏还会因为无法创建目标文件而失败。当前游戏进程中的快捷栏仍会更新，重启后不会恢复。已有该文件时能够写入，但保存过程会把当前内存中的九组快捷栏全部写回；未重新建立的旧分组会被空组覆盖。

服务器列表使用预先创建的临时文件保存，因此本次添加的服务器可以写入磁盘，但再次载入列表时仍会被忽略。保存当前空列表或重新建立的列表，也会替换原来保存的列表。

## 饰纹陶罐支持延迟生成战利品

饰纹陶罐现在可以像箱子一样保存战利品表和随机种子，影响通过命令、物品数据或结构模板配置的陶罐。

### 差异出现的场景

为空饰纹陶罐设置 `LootTable` 和可选的 `LootTableSeed`，随后让玩家尝试放入物品、让漏斗读取或取出物品、使用比较器读取容量，或破坏陶罐。

### 版本变化

- 23w43b：陶罐只读取实际存储的物品，忽略战利品表字段；上述操作不会根据战利品表生成内容。
- 23w44a：陶罐保存战利品表，首次读取、取出或设置槽位内容时生成物品。生成后清除战利品表，后续操作使用已生成的物品。

陶罐依然只有一个槽位，战利品表生成多组物品时，无法放入该槽位的额外物品不会全部保存。这些触发入口没有向战利品表传入玩家，因此玩家幸运值和依赖玩家实体的条件不会因玩家亲手操作而自动生效。

结构模板放置也开始为陶罐重新生成战利品随机种子。模板中陶罐的固定种子会被替换；由于每个带方块实体数据的陶罐会额外消耗一次随机数，同一模板、同一放置种子下，后续箱子等容器得到的战利品种子也可能改变。

## return 会更新结果存储，return run 在没有执行分支时也结束函数

函数返回的数值与命令成功状态改为统一传递，改变了 `execute store`、命令方块成功次数及函数提前结束的表现。

### 差异出现的场景

用 `execute store result` 或 `execute store success` 包裹 `return`，或者在函数中使用 `return run execute ... run ...`，而后面的条件没有通过、选择器没有找到目标，或最终命令执行失败。

### 版本变化

- 23w43b：直接执行 `execute store result score ... run return 5` 不会把 5 写到指定分数。`return run` 还会替换它前面已经设置的结果存储。新版会保留这些存储，成功返回 5 时写入结果 5、成功值 1；直接以 `return 5` 为命令的命令方块也由成功次数 0 变为 1。
- 23w43b：函数执行到 `return run execute if entity @e[tag=不存在的标签] run ...`，没有产生执行分支时，可以继续运行函数的下一行。23w44a 在进入 `return run` 后立即丢弃本函数剩余命令；后续没有执行分支时，以失败、数值 0 返回。
- 23w43b：`return run` 只转交整数，最终命令抛出命令错误时，外层函数调用仍可能把返回的 0 记为成功。23w44a 在函数内部调用的路径上保留失败状态，结果为 0、成功值为 0。

新版还新增 `return fail`，以数值 0 和失败状态结束当前函数；`return 0` 仍是成功返回数值 0。

调用方式会影响本快照的失败状态：从聊天或命令方块直接调用单个含 `return fail` 的函数时，函数结果反馈的包装会把失败改成成功，因此外部 `execute store success` 会得到 1；同一调用发生在已抑制输出的函数内部时，得到 0。上述差异由是否抑制命令输出决定，并非由聊天反馈游戏规则决定。

## 函数标签调用改为最后汇总一次结果

普通 `function #标签` 仍会依次调用标签内的函数，但结果写入的时机和命令方块计数发生变化。

### 差异出现的场景

标签中至少有两个函数显式返回数值，并使用 `execute store ... run function #标签` 记录结果，或由命令方块执行该标签。例如两个函数分别执行 `return 5` 和 `return 7`。

### 版本变化

- 23w43b：第一个函数返回后立刻写入 5，第二个返回后写入累计值 12；命令方块因此收到两次成功，成功次数为 2。
- 23w44a：所有成员调用结束后才一次写入总和 12，命令方块成功次数为 1。成员函数的返回反馈分别显示本函数的结果，后一个不再显示先前成员的累计值。

### 实际影响

利用比较器读取命令方块成功次数的装置会得到不同强度。标签后面的函数如果读取同一次调用正在写入的分数、存储或 Boss 栏，也不能再依靠前面成员已经把中间累计值写入。

## if function 与 unless function 由第一个返回值决定

函数条件现在按一次独立调用处理函数或函数标签，首个显式返回会终止该次条件求值；全部函数都没有返回时，条件按 0 判断。

### 差异出现的场景

使用 `execute if function` 或 `execute unless function` 检查一个函数标签，或者检查一个正常执行到末尾、没有任何 `return` 的函数。

### 版本变化

- 23w43b：标签内的各函数都可以继续执行，任意一个符合条件的返回值就能保留当前执行分支。例如第一个函数返回 0、第二个返回 7，`if function` 和 `unless function` 两种检查都能通过，而且第二个函数也会执行。
- 23w44a：上例在第一个函数返回 0 时结束，`if function` 不通过、`unless function` 通过，第二个函数的命令也不会执行。值为 0 的成功返回和 `return fail` 都会在此处按 0 判断。
- 23w43b：没有返回值的函数不会提交条件结果，`if function` 和 `unless function` 都不能继续后面的命令。23w44a 在函数正常执行到末尾时补交 0，因此 `unless function` 可以继续；标签中先执行到末尾而未返回的成员，则会继续尝试后面的成员。

上述补交 0 的处理还会作用于无法展开的宏函数：直接以函数条件调用一个需要参数的宏函数时，两个版本都会报告缺少参数，但旧版 `unless function` 不会继续，新版仍会按 0 让该条件通过。

### 实际影响

把函数标签当作一组都会执行的检查或副作用操作时，后面的成员可能因前面的显式返回而不再运行。标签成员顺序现在直接决定条件结果。

## execute 中途发生命令错误时，不再自动把存储写为零

若已经设置 `execute store`，随后在调整执行位置或计算执行条件时抛出命令错误，最终的 `run` 命令没有执行，旧版会把这次错误交给结果存储，写入结果 0 或成功值 0；新版不再提交这一次中途错误，原来保存的值保持不变。例如 `positioned over` 读取尚未加载区块的高度时便会抛出错误。最终 `run` 后面的普通命令真正执行后再失败，仍会提交失败结果。

## debug function 禁止接在 return run 后

旧版允许 `return run debug function ...` 进入函数跟踪；新版立即报错，不再创建此次函数跟踪或执行对应函数。调用者在到达 `return run` 时已终止自己的剩余命令。

## 紫颂果传送音效集中到传送终点

成功食用紫颂果传送时，23w43b 会在原位置播放传送声，并通过实体再在终点向其他玩家播放一次；23w44a 只在终点播放一次，并让传送的玩家本人也直接收到终点音效。狐狸食用紫颂果时，原位置原本归入“玩家”音量类别的那次音效被移除，终点统一使用“友好生物”类别。玩家通过声音判断传送位置及调整分类音量时，听到的结果会改变。

## 结构方块加载空作者模板时清除旧作者

同一个结构方块先前保存着作者信息，随后加载没有作者信息的模板时，23w43b 会留下旧作者，23w44a 会把作者清空。另一个可见差异发生在红石加载改变结构尺寸时：旧版会立即同步尺寸变化，新版只更新服务器中的结构信息；在没有其他同步更新的情况下，客户端的结构边界框仍可能保留旧尺寸。通过结构方块界面点击加载会另行发送更新，因此该入口仍能同步尺寸。

## GameTest 等待区块就绪后开始，并改变测试结构管理

这些变化适用于启用 GameTest 的开发环境及专用测试服务器。

- 23w43b 在安排测试时就放置结构并开始计时；23w44a 先等待结构覆盖的全部区块达到实体可活动状态，再等待 20 个游戏刻，随后放置结构、清除区域内的计划方块刻和方块事件并开始测试计时。区块未就绪的时间不再计入测试超时。
- 专用测试服务器旧版总从 `(0, -59, 0)` 附近排列测试，新版把起点的 X、Z 随机选在 −14,999,992 到 14,999,992 之间，Y 仍为 −59。依赖固定绝对坐标的测试会受到影响。测试方法改为按方法名注册，批次则保留首次遇到的顺序，测试排列也可能改变。
- 测试使用独立模板名称时，旧版会在加载后把结构方块名称改成测试名称；新版保留实际模板名称。启动按钮、`/test runthis` 和 `/test runthese` 仍根据结构方块名称查找测试，因此模板名称与测试名称不同时，新版可能无法重跑原测试，或选中与模板同名的其他测试。
- `/test create` 生成的结构方块、底板及启动按钮比旧版低一格。新版清理区域按方块上方的实际结构范围计算。
- `/test exportthis` 和 `/test exportall` 旧版导出已经保存的结构；新版先把当前测试区域保存到结构文件，再尝试导出。不过新版传入的名称包含 `minecraft:` 等命名空间前缀，导出函数仍把整个名称作为路径拼接，导致有效命名结构在这里因路径包含冒号而失败。区域保存已经发生，随后才出现导出错误。
