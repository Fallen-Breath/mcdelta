# Minecraft 25w18a 变更分析

- 上一个版本：25w17a
- 当前版本：25w18a

## 喷溅药水按命中位置与实体身体之间的距离分配效果

喷溅药水的作用中心和距离算法同时改变，影响同一落点对附近玩家、生物施加效果的强度与持续时间。

### 差异出现的场景

带有效果的喷溅药水命中方块或实体，附近有可受药水影响的生物。比较时保持投掷路线、目标位置和药水相同。

### 版本变化

- 25w17a：以药水实体当时的位置搜索附近生物，按药水与生物位置点之间的距离衰减效果；直接命中的实体另行获得完整效果。
- 25w18a：先把药水的碰撞箱平移到实际命中点，再计算该碰撞箱与目标身体碰撞箱之间的最短距离。计算前，目标碰撞箱向各方向扩大 0.3 格。两个箱体接触或重叠时，距离为零，目标获得完整效果。

新版仍用距离每增加 1 格、效果系数减少 1/4 的线性衰减：瞬时效果按此系数结算，持续性效果按此系数缩短时间。搜索范围仍是以药水碰撞箱向水平各扩展 4 格、竖直各扩展 2 格的区域，随后还要求箱体最短距离小于 4 格。

### 实际影响

相同命中点附近，生物身体的一部分靠近落点即可获得较强效果；向高大生物的上半身或身侧投药，不再只按其位置点计算距离。依赖药水落点给一群生物分配固定治疗量、伤害或效果时长的装置，所得结果会改变。普通水瓶的灭火、伤害怕水生物及给美西螈补水仍走原有独立逻辑，不适用这套新距离算法。

## 拴绳改用五根线合成，配方解锁条件随之变化

- 25w17a：每次以四根线和一个黏液球合成两根拴绳，取得黏液球可解锁配方。
- 25w18a：原黏液球所在的中央格改放线，即五根线合成两根拴绳；取得线即可解锁配方。

已有拴绳合成装置需要把原本供应黏液球的槽位改为供应线；每批少用一个黏液球、多用一根线。

## 猪灵交易加入失水恶魂，既有产物概率略降

成年猪灵接受金锭后的交易表新增一次给出一个失水恶魂的结果，权重为 10。总权重由 459 增至 469，因此新版取得失水恶魂的概率为 10/469，约 2.13%；已有各项结果的权重及单次数量不变，但每次交易抽中它们的概率都变为原来的 459/469，约降低 2.13%。已有猪灵交易农场会多出一种产物，相同金锭消耗下，其余产物的长期平均产量略减。

失水恶魂的合成配方也把中央骨块换为灵魂沙，外围仍为八个恶魂之泪。

## 生物活动中心开始存盘，快乐恶魂下客后重新确定活动范围

### 差异出现的场景

生物已建立活动中心后卸载、重新加载；或玩家骑乘快乐恶魂后全部下客、为其装卸挽具、小恶魂成年。

### 版本变化

- 25w17a：生物的活动中心和半径只保留在内存中。重新加载后，这些限制丢失，需要相关 AI 再次建立。快乐恶魂最后一名乘客下去时不主动清除旧中心；只要仍在旧中心附近，也不会因为应有半径改变而立即重设。
- 25w18a：生物有活动范围时，把中心和半径保存为 `home_pos`、`home_radius`，加载后恢复。快乐恶魂最后一名乘客下去时清除旧中心，之后在没有拴绳和乘客的条件下，以当前位置重新建立范围；应有半径改变时，也立即以当前位置重设。

快乐恶魂的应有半径为：成年且未装备挽具时 64 格，其余情况 32 格。因此，小恶魂成年、装卸挽具以及短程骑乘后下客，都可能改变其后续自由活动的中心或范围。已在新版存过盘的远古守卫者也会保留原有 16 格活动中心，而非每次重新加载都以加载时的位置另建中心。旧版存档此前没有保存的中心无法凭空恢复。

新版还将成年快乐恶魂加入小恶魂可跟随的友好生物名单。附近存在可见成年快乐恶魂、且跟随行为满足其距离等条件时，小恶魂现在也会把它选作跟随对象。

## 恶魂的飞行路线改按实际碰撞形状检查

普通恶魂及快乐恶魂的自动飞行在检查路线上经过的方块时，旧版只要方块拥有非空碰撞形状就拒绝；新版检查生物沿路线移动时，身体是否真正扫到该形状。路线经过台阶、楼梯等只占部分空间的方块所在格，但身体实际避开其碰撞部分时，新版可以接受该路线。

快乐恶魂另外改为检查流体状态，而不只识别水方块、熔岩方块。因此，含水方块里的水也会参与避让：尚未在水中的快乐恶魂，不会把实际穿过这些水体的路线当作干燥通路。已有“位于同种流体中时允许穿过”的判断继续适用。快乐恶魂对目标区域周围一格的预留空间检查仍然存在，不能据此认为所有狭窄终点都可到达。

## 附魔之瓶的经验球从命中表面向外散开

附魔之瓶击中方块时，旧版在命中点生成经验球，并使用通常向上的随机初速度；新版给实际新生成的经验球加上朝命中面外侧的位置偏移，并把随机速度约束在该面朝外的一侧。击中实体时，使用瓶子运动的反方向作为外侧方向。向墙面、天花板扔瓶子时，经验球的出现位置和初始散射方向会随命中面改变，更少一开始进入被击中的方块。经验总量的随机计算不变；如果本次经验并入已有经验球，就不会为这些经验重新设置位置和速度。

所有经验球还调整了陷入方块时的处理：没有正在跟随的玩家、且当前身体与方块相交时，旧版立即尝试寻找旁边的空位；新版先检查沿当前速度走一步是否仍会碰撞，只有仍然受阻才执行挤出处理。能自行从方块中飞出的经验球可继续原有运动。

## 钓鱼浮漂落地及刚挂住实体时的重力处理调整

浮漂不在水里且执行到运动结算时，旧版会增加向下速度；新版仅在浮漂没有落地、也没有挂住实体时增加这部分重力。差异包括浮漂刚在本刻碰撞检测中挂住物品或其他实体时：旧版仍会先受一次重力并移动，新版不再增加这次向下速度。已经进入挂住实体状态的后续刻，两版都会直接定位到被挂实体，原本就不执行这段重力。落地浮漂同样不再进入额外加重力的分支。

客户端收到浮漂的位置更新后，新版使用通常三步的位置插值，替代原本没有插值处理器时的直接定位。共用插值逻辑也修正了碰撞检查的位置：检查真正的目标位置，而不是把目标坐标再次加到实体当前位置上；这会影响生物、船、普通矿车等实体在有本地位移时的画面位置校正。

## 联机移动校验不再把脚手架和细雪计入新增碰撞

服务端收到玩家移动后，会检查玩家报告的新位置是否进入了原位置没有接触的碰撞形状；命中这一检查会把玩家传回原位置。

- 25w17a：根据服务端执行移动后的玩家状态取得这些形状，脚手架平台及细雪在相应站立、下落条件下可能参与检查。
- 25w18a：这项事后校验使用移动前的脚底高度，并采用使脚手架、细雪返回空形状的碰撞上下文。这两个方块不再因为该检查产生位置回退。

实际移动时的碰撞、攀爬、下陷仍由各自的运动逻辑处理。变化针对移动完成后的新增碰撞校验，不能据此推断玩家可以穿过其他实体或普通实心方块。

## 异常实体、方块实体数据的保存由抛错改为保留可编码部分

本次大量 NBT 读写代码改用统一存取接口，其中一个实际变化是编码失败时的处理。

### 差异出现的场景

已有实体、容器或其内部物品包含无法由保存格式编码的值，执行存盘、复制数据、读取实体 NBT，或使用需要先序列化实体的 NBT 选择器。此处指编码器判定失败的数据，不包括普通有效存档。

### 版本变化

- 25w17a：常用字段保存和物品序列化遇到编码错误会直接抛异常。实体保存可进一步转为保存实体 NBT 的崩溃报告；玩家存盘等外层有捕获的调用则中止本次保存。
- 25w18a：新存取接口记录具体字段或列表项目的编码问题；编码器提供部分结果时保存该部分，没有部分结果时不写入失败字段或项目，并继续处理其他数据。因此，同样的数据不再仅因这一类编码错误就中止整个序列化操作。

### 实际影响

原本可能失败的 NBT 查询、选择器或保存过程可以完成，但结果可能缺少异常字段或物品项目，重载后也可能使用默认值。此修改没有把异常值变成合法存档值；缺失内容是否可恢复，取决于各字段读取默认值和编码器给出的部分结果。

## 错误类型的属性修饰符字段会使该条属性不再加载

若实体的 `attributes` 中有一条合法属性 ID 和基础值，但把 `modifiers` 写成字符串等非列表类型，旧版先应用基础值，再把无法读取的修饰符列表当作空列表；新版先把整条属性解析为完整记录，这种无法给出部分记录的错误会使该条属性被跳过。

例如，通过命令加载 `{id:"minecraft:max_health",base:40d,modifiers:"bad"}` 时，旧版仍应用 40 的最大生命值基础值；新版不会从这条记录应用基础值，新生成实体因而保留其原有最大生命值。其他可成功解析的属性记录仍可加载。

## 删除盔甲架 Pose 标签不再重置姿势

## 更新试炼刷怪笼配置时保留更多运行状态

通过 `/data` 等方式修改已存在的试炼刷怪笼时，旧版重新创建整套刷怪逻辑和运行数据；新版在现有对象中分别加载配置与运行状态。

- 配置包含非法值、例如 `required_player_range:0`，以致配置整体解析失败时，旧版连同已登记玩家、当前存活怪物、生成计数等一起恢复默认；新版只把配置恢复默认，仍可加载成功的运行状态继续保留。

## 旧地图的数字维度标识在升级时转换

## 数据包及多类资源文件改为严格 JSON 解析

### 差异出现的场景

数据包的配方、进度、战利品表、标签、世界生成注册表数据，或资源包的方块状态、物品模型定义、图集、着色器配置等 JSON 文件，使用了注释、未加引号的键、单引号字符串等宽松写法。

### 版本变化

- 25w17a：这些入口使用宽松 JSON 解析，上述一些非标准写法可通过 JSON 读取，随后再做各自的数据格式校验。
- 25w18a：改用严格 JSON 解析，拒绝这些写法，也要求非空内容解析后不再有额外文档内容。对应资源会进入加载失败处理；失败的是启动所需注册表数据时，还可能使数据包或世界加载失败。

服务端资源包提示 `resource-pack-prompt` 也改走严格解析；失败时提示文本不被采用。玩家进度、统计文件原本已使用较严格读取，新版另增加整份文档结束检查，原先只读取首个 JSON 值、忽略尾随内容的文件现在也会失败。

联机协议没有统一改为严格模式：状态查询响应及登录阶段踢出原因仍使用宽松 JSON 路径，不能把资源文件的新限制套用到所有网络 JSON。

## 命令中的战利品表、谓词和物品修饰器引用不再接受引号包围的 ID

在 `/loot`、`/execute if predicate`、`/item modify` 等接受“资源 ID 或内联定义”的参数位置：

- 25w17a：先把参数作为 SNBT 读取，再交给同时支持资源引用的格式处理，因此 `"minecraft:empty"` 这类带引号的资源 ID 可以作为引用。
- 25w18a：先识别不带引号的资源 ID，并直接查找对应注册项；另一条内联定义分支只按定义本身的格式解析。带引号的 ID 会成为内联字符串，不能再作为资源引用。原有这类命令需要去掉 ID 外的引号。

此外，只有数字、`true` 等同样可构成资源路径的名称，现在优先当作资源 ID；旧版可能先把它们当作 SNBT 数字或布尔值而解析失败。内联对象和列表继续通过相应定义格式解析。

## NBT 条件匹配中的默认值与异常配方书数据发生变化

- 方块实体没有额外组件时，旧版省略 `components` 字段，新版保存 `components:{}`。例如方块 NBT 条件显式要求 `{components:{}}` 时，新版可匹配这些没有额外组件的方块实体；旧版因字段缺失而不匹配。
- 玩家配方书的“是否打开”“是否只显示可合成配方”等开关为假时，旧版保存显式 `0b`，新版省略对应字段。依赖 `{recipeBook:{isGuiOpen:0b}}` 一类实体 NBT 条件的命令，不再能把字段缺失的默认状态匹配出来。
- 若玩家文件的 `recipeBook` 缺少 `recipes` 或 `toBeDisplayed` 其中一个列表，旧版会分别加载已有列表及界面开关，缺失列表按空处理；新版把它们解析为一条完整记录，缺少必需列表会使本次配方书加载被跳过。对刚登录的玩家，这会保留初始空配方书及默认开关状态。

## 书与笔的编辑、签名和保存操作调整

正文改用多行文本输入框，签名改为独立页面。对已有书与笔，实际差异包括：

- 书名现在能使用文本框的光标移动、选择、复制、剪切和粘贴；旧签名输入主要处理打字、退格和确认。
- 正文每页字符上限由少于 1024 个改为最多 1024 个；新版明确限制最多 14 行，计入末尾换行产生的空行。超出行数的输入整体不被接受。通过命令取得的已有页面若本来就超出行数限制，新版在把该页放进编辑框时也会拒绝，首次打开可显示空白，翻页时则可能仍显示上一页编辑框内容。
- 点击“完成”现在即使没有修改也会清理末尾空白页、更新本地书内容并提交页面；旧版只有标记为已修改时才保存。开启文本过滤时，提交的是本次编辑器读出的过滤后页面，即使只是打开后点击完成，也可能替换原先保留的未过滤页面文本。

阅读书籍时，旁白还会读出当前页码和页面内容，翻页按钮获得可朗读的上一页、下一页名称。

资源包使用 `unihex` 字体提供器、只指定字形文件而没有 `size_overrides` 时，旧版因缺少必需字段而无法加载这条字体定义；新版把缺失列表视为空列表，直接按字体的通常尺寸规则加载，不再需要显式写入 `size_overrides:[]`。
