# Minecraft 26.1 变更分析

- 上一个版本：`26.1-rc-3`
- 当前版本：`26.1`

本次正式版没有修改方块、物品、实体、地形生成或装置运行规则；差异来自正式版身份和版本号切换，涉及联机、Realms、本地世界备份询问及界面入口。

## 正式版与 RC 3 不能直接混用联机

原版服务端在登录握手时检查客户端的协议号。26.1 将协议号从 RC 3 的 `1073742127` 改为 `775`，因此两端需要使用相同版本。

### 差异出现的场景

使用原版客户端连接原版服务端，在 `26.1-rc-3` 与 `26.1` 之间更换客户端或服务端版本。

### 版本变化

- 26.1-rc-3：服务端接受 RC 3 客户端的协议号；26.1 客户端连接时，因协议号不匹配而被拒绝。
- 26.1：服务端接受 26.1 客户端的协议号；RC 3 客户端连接时，因协议号不匹配而被拒绝，并收到版本不兼容提示。

原先客户端和服务端都使用 RC 3 的联机环境，只升级其中一端便无法继续连接；两端都切换到 26.1 后，协议号重新一致。

## Realms 切回正式版服务流程

Realms 根据客户端是否为正式版选择世界列表请求和加入世界的流程。26.1 的正式版标志使客户端退出预发布版本模式。

### 差异出现的场景

在正常的 Realms 服务环境中，以默认模式打开服务器列表并加入世界。加入流程的对比针对普通世界，且未主动跳过兼容性检查。

### 版本变化

- 26.1-rc-3：默认使用预发布模式，通过预发布世界列表接口请求世界，并在请求中携带预发布标志。加入世界时，根据 Realms 返回的兼容性状态，可能出现升级、降级、兼容性无法验证等确认流程，或因不兼容而阻止继续加入。
- 26.1：使用正式版模式，通过正式版世界列表接口请求世界，请求中的预发布标志随之关闭。加入世界时直接请求连接详情，不再经过上述预发布模式专用的兼容性分支。

RC 3 中使用的测试 Realm 不再通过预发布世界列表入口获取。正式版中实际列出哪些世界、能否成功加入，仍取决于 Realms 返回的服务器状态和版本。

## 打开世界时的备份询问随正式版身份和数据版本变化

打开本地世界时，客户端会根据世界数据版本和自身是否为预发布版本决定是否询问备份。26.1 不再触发“升级到快照”的询问，同时将世界数据版本从 `4785` 提高到 `4786`。

### 差异出现的场景

打开与当前版本兼容、无需文件结构迁移的本地世界。以下对比分别针对数据版本低于 `4785` 的旧世界，以及经 26.1 保存、数据版本为 `4786` 的世界。

### 版本变化

- 26.1-rc-3：打开数据版本低于 `4785` 的世界时，因客户端属于预发布版本而询问是否先备份；打开数据版本为 `4786` 的世界时，则进入降级备份警告流程。
- 26.1：打开上述旧世界时，不再仅因世界版本较旧而询问备份，继续加载；打开数据版本为 `4786` 的世界时，版本一致，也不会触发降级备份警告。

因此，经 26.1 保存的世界再用 RC 3 打开，会出现旧客户端已有的降级警告。本次没有新增数据转换规则。

## 创建世界界面的实验入口调整

- 创建世界时，26.1-rc-3 在“游戏”页中额外显示“实验”按钮；26.1 隐藏这处入口。“更多”页中的“实验”按钮仍然可用，实验功能的配置能力保持不变。
