# Minecraft 26.1-rc-1 变更分析

- 上一个版本：`26.1-pre-3`
- 当前版本：`26.1-rc-1`

## 区块加载发生更多类型的异常时，改为重新生成该区块

新版扩大了区块加载失败后的继续运行范围。一些原先会使服务器崩溃的区块加载异常，现在会使整个区块被当作尚未生成的区块处理。

### 差异出现的场景

服务器加载已有区块时，读取、解析或还原区块的流程抛出普通运行时异常。例如，区块存档中的 `BlockLight` 或 `SkyLight` 字节数组存在，但长度不是所需的 2048 字节：读取光照数据会抛出参数异常，导致该区块加载失败。单人世界的内置服务器和独立服务器均适用。

这里讨论的是此次新增捕获的异常。I/O 异常和 NBT 异常在旧版已经会采用重新生成的处理；属于 Java `Error` 的严重错误仍然进入崩溃流程。

### 版本变化

- 26.1-pre-3：上述运行时异常会使区块加载失败，并由区块生成、加载流程触发服务器崩溃。
- 26.1-rc-1：记录区块加载失败，创建一个空白的生成中区块，后续加载所需的生成阶段会重新生成该位置的地形。单人世界还会显示区块加载失败的提示，并尝试将错误详情保存到 `debug` 目录。

### 实际影响

原本会因这类区块问题而停服、或无法打开的世界，现在可以继续运行，但发生错误的区块会重新生成。该区块原有的建筑、装置和容器等方块数据不会从加载失败的存档中保留下来；重新生成后的区块在正常保存时可以覆盖原位置的数据。即使错误只出在光照数组中，也会放弃整个区块的加载，而非仅重新计算光照。

## 客户端处理服务器数据包发生普通异常时，改为断开连接

连接配置阶段或进入世界后，客户端主线程处理已经成功解码的服务器数据包时，如果处理逻辑抛出普通异常，新版会退出连接并保留客户端运行。

- 26.1-pre-3：错误处理会先重新抛出带崩溃报告的异常，使客户端崩溃，后面的断线与断线报告保存无法执行。
- 26.1-rc-1：尝试保存 `debug/disconnect-<时间>-client.txt`，断开当前连接并显示断线界面。报告保存成功时，界面提供打开报告目录的按钮；服务器提供了错误反馈链接时，也可以从该界面前往反馈页面。

同一服务器问题仍会导致玩家离开世界，但普通数据包处理错误不再要求重新启动客户端。内存耗尽仍保留崩溃处理，不属于这一恢复范围。

## 已提交的客户端、服务端及声音任务发生普通异常时继续运行

客户端的按键输入处理、声音操作及服务端提交的主线程工作等操作，会经过任务执行器。如果异常从任务内部传到执行器，新版会限制异常对整个游戏的影响。

- 26.1-pre-3：任务抛出的异常在记录日志后继续向外传播，可以导致客户端崩溃、服务器停服；声音线程中的未捕获异常也会请求客户端崩溃。
- 26.1-rc-1：普通异常只记录日志，当前任务在出错处中止，执行器可以继续处理后续任务。任务出错前已经完成的操作不会回滚，失败任务也不会因此自动重试。

这一变化仅作用于经过该执行器的任务，并未统一接管实体、方块等正常游戏刻的异常。直接抛出的 Java `Error` 仍不由此处捕获；以崩溃异常包装的内存耗尽、栈溢出也仍会继续抛出。区块生成、加载流程主动上报的延迟崩溃同样保留。
