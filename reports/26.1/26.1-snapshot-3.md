# Minecraft 26.1-snapshot-3 变更分析

- 上一个版本：`26.1-snapshot-2`
- 当前版本：`26.1-snapshot-3`

## 南瓜和西瓜改为只能在耕地上结出

成熟瓜茎选择结果位置时，新版收窄了果实下方允许的方块，直接影响使用泥土、草方块等作为结果面的农场。

### 差异出现的场景

成熟南瓜茎或西瓜茎旁边留有空气，空气下方是泥土、草方块、砂土、灰化土等原本属于 `minecraft:dirt` 标签的方块。

### 版本变化

- Snapshot 2：果实下方是耕地或上述泥土类方块时，可以结出果实。
- Snapshot 3：果实下方必须属于 `minecraft:grows_crops`；原版数据中该标签只有耕地。原有泥土类结果面不能再产生新的南瓜或西瓜。

已有果实不会因此消失。使用普通泥土结果面的自动农场，在收走已有果实后停止补充；瓜茎本身能够继续生长，并不表示结果面仍然有效。

## 气泡柱能够替换含水方块，拆除底座也不再使整列消退

气泡柱的延伸检查改为读取方块中的流体，同时改变了失去底座后的处理。

### 差异出现的场景

气泡柱上方有含完整静止水源的方块，例如含水台阶、含水栅栏，或海带；或者拆除已经形成气泡柱的灵魂沙、岩浆块底座。首次生成的时序差异还出现在：水上已安排了生成检查，并在等待的 20 刻内更换底座。

### 版本变化

- Snapshot 2：气泡柱只能继续替换独立水源方块，遇到含水方块会停止。拆除底座后，失去支持的气泡柱会向上变回普通水。
- Snapshot 3：已有气泡柱向上延伸时，只检查目标是否含完整水源，能够直接把上述含水方块替换为气泡柱。拆除底座后，更新保留原来的气泡柱状态，整列仍然上推或下拉。

以含水台阶为例，延伸会移除台阶本体，调用普通方块状态替换，不会按采掘台阶生成其方块掉落物。依赖含水方块阻断气泡柱，或通过移走底座来关闭升降水道的装置，会出现不同结果。直接在灵魂沙上放一个含水方块，并不等于一定触发延伸；上述替换需要气泡柱从下方传播到它。

首次生成的延迟也改由底座上方的水方块记录。若水已等待生成气泡柱，又在这 20 刻内更换底座，新版可以沿用原先的水方块计划刻；旧版新底座重新安排自己的 20 刻检查。例如放下灵魂沙 10 刻后换成岩浆块，新版可能再过 10 刻就生成下拉气泡柱，旧版从放下岩浆块重新等待 20 刻。

## 村民不再因刚刚看见或召唤过铁傀儡而暂停召唤

新版村民没有注册“最近发现铁傀儡”的记忆。发现附近铁傀儡、成功召唤铁傀儡后写入的冷却因此失效。

### 差异出现的场景

村民已经在最近一个游戏日内睡过觉，数量和其他召唤条件满足，并处于恐慌或能够通过交流发起召唤的状态。

### 版本变化

- Snapshot 2：发现或召唤铁傀儡后，村民保留 599 刻的相关记忆；记忆存在时不参与下一次召唤。
- Snapshot 3：上述记忆写入被忽略。即使原铁傀儡仍在附近，村民也能够在下一次符合条件的检查中继续召唤。

恐慌中的检查仍然每 100 刻执行一次。因此有足够可用生成位置的刷铁装置，可以在原先约 30 秒的抑制时间内继续产生铁傀儡；生成位置被已有实体占据等其他限制仍会影响每次尝试。

## 重新加载生物会丢失部分已经保存的行为记忆

新版改为在添加行为时注册行为所需的记忆，但从存档恢复记忆发生在添加行为之前。只由行为注册、未由传感器或额外清单提前注册的记忆，会在读取存档时被忽略。

### 差异出现的场景

生物所在区块卸载后重新加载，或者保存退出后重新进入世界；存档中含有尚未失效的相应记忆。

### 版本变化

- Snapshot 2：生物的大脑预先注册这些记忆，恢复保存的值和剩余冷却。
- Snapshot 3：读取时丢弃尚未注册的记忆；之后虽然会注册相应类型，却只得到空值。

直接影响包括：

- 村民失去原来的床、工作站、潜在工作站、集合地点及最近睡眠时间等记忆。恢复后的村民需要重新建立相应关联；缺少工作站关联时不能按原关联工作补货，缺少近期睡眠记忆时不能参与召唤铁傀儡，直到重新实际睡觉。原来已经占用的床和工作站不保证还能立即被重新认领。
- 已经怀孕但尚未产卵的青蛙，重新加载后丢失怀孕状态，不能继续完成这次产卵。
- 嗅探兽的挖掘冷却不再从存档恢复，可以提前开始下一轮寻找种子；已探索地点仍在新版保留的额外记忆清单中。
- 猪灵的愤怒目标与近期狩猎记忆、山羊的冲撞和长跳冷却等，也不再沿用保存的值。

这既影响从 Snapshot 2 升级后首次读取生物，也影响在 Snapshot 3 中保存后再次读取。它与上一条铁傀儡冷却完全没有注册的问题分别发生：这里所列记忆通常可以在加载完成后的正常运行中重新写入。

## 红沙不再支持甘蔗

甘蔗底部的支持方块改由新标签判断，默认名单漏掉了红沙。

### 差异出现的场景

在相邻有水且满足其他种植条件的红沙上种甘蔗，或让已有红沙甘蔗收到生存检查更新。

### 版本变化

- Snapshot 2：接受整个沙子标签，可以在红沙上种植和保留甘蔗。
- Snapshot 3：检查 `minecraft:supports_sugar_cane`；默认名单只有泥土标签和普通沙子，不能再在红沙上正常种植，已有甘蔗会在生存检查时折断。

## 铁傀儡、旋风人和其他生物恢复各自的攻击对象限制

新版统一了生物选择、保留攻击目标时调用的判断方法，使原先未进入这些调用路径的种类限制生效。

### 差异出现的场景

玩家攻击自己搭建的铁傀儡；旋风人搜索范围内存在牛、村民等生物；或生物经使用通用目标判断的路径尝试把恶魂设为目标。

### 版本变化

- Snapshot 2：玩家可以经反击逻辑成为自己搭建的铁傀儡的目标；旋风人能够选中牛、村民等其他可攻击生物；通用判断的这些路径没有应用排除恶魂的规则。
- Snapshot 3：玩家搭建的铁傀儡拒绝把玩家作为攻击目标，目标判断也统一排除苦力怕；旋风人只接受玩家和铁傀儡；通用生物目标判断排除恶魂，包括经反击建立目标的尝试。

## 猪灵在疣猪兽数量占优时改变受击反应

成年猪灵因数量劣势而撤退的分支，改为由疣猪兽的攻击触发。

### 差异出现的场景

一只成年猪灵看到的成年疣猪兽数量，多于可见成年猪灵数量加上它自己；此时分别由玩家等其他生物或疣猪兽伤害它。

### 版本变化

- Snapshot 2：被玩家等非猪灵、非疣猪兽生物伤害时进入逃避，并向同伴传播撤退；被疣猪兽伤害反而走通常的报复分支。
- Snapshot 3：被疣猪兽伤害才触发数量劣势下的撤退；玩家等其他攻击者走通常的报复分支。

利用附近疣猪兽让成年猪灵在玩家攻击后逃跑的用法因此失效。幼年猪灵的逃跑分支不受这次条件互换影响。

## 繁殖出的村民保留按父母和繁殖地点选出的类型

村民繁殖时会在父母类型与繁殖地点类型之间选择幼村民的类型。新版保留这一选择，取消了随后覆盖类型的出生初始化。

### 差异出现的场景

让不同生物群系类型的村民繁殖，或者在与世界原点生物群系不同的位置繁殖村民。

### 版本变化

- Snapshot 2：先进行一次类型选择，但随后在幼村民尚未被移动到父母位置时执行出生初始化，使用幼村民默认位置 `(0, 0, 0)` 所在生物群系覆盖结果。因此此前选出的父母类型或繁殖地点类型不保留。
- Snapshot 3：不再对这只繁殖幼村民执行上述初始化。类型真正按 50% 取发起繁殖村民所在生物群系、25% 取这位父母的类型、25% 取另一位父母的类型决定；候选相同时概率合并。

这使沼泽、丛林等类型村民的定向繁殖恢复按上述规则工作，也会影响启用村民交易平衡实验时按类型提供的交易。由于同时跳过通用生物出生初始化，繁殖幼村民也不再获得那次随机跟随范围修正与 5% 左利手抽选。

## 具名时间设置前进到下一次时刻

原版昼夜、月相和村民日程等时间轴改用命名世界时钟。具名设时会在该时钟上向前寻找下一次对应时刻，保留累计天数。

### 差异出现的场景

在主世界执行 `/time set day`、`noon`、`night` 或 `midnight`，尤其是世界已过数天，或当前恰好处于指定时刻时。

### 版本变化

- Snapshot 2：将累计昼夜时间直接设为 1000、6000、13000 或 18000，累计天数和月相也随之回到对应的首日状态。
- Snapshot 3：前进到指定时刻的下一次出现；当前已是该时刻时也前进整轮。数字形式 `/time set 1000` 仍直接设置累计时间。

例如累计时间为 30000 时执行 `/time set noon`，旧版变为 6000，新版变为 54000。具名设时不再将依赖累计昼夜时间的月相等进度退回第一天。

## 时钟可以单独暂停，也可以用负数回退

## 时间查询与命令返回值改变含义

时间查询现在区分累计时钟值、时间轴内的刻数和已经完成的周期，部分旧命令会得到不同含义的结果。

### 差异出现的场景

命令装置使用 `/time query daytime`、`/time query day`，或读取设时、加时命令的返回值。

### 版本变化

- Snapshot 2：`query daytime` 返回一天内的刻数，`query day` 返回经过天数；设置和增加时间返回一天内的刻数。
- Snapshot 3：一天内刻数改用 `query day` 或 `query minecraft:day`，经过天数改用 `query day repetition`，累计时间用 `query time`。加时和具名设时返回累计时钟值对 2147483647 取余的结果；数字设时返回指定值。

旧 `query day` 命令仍可解析，但现在读到一天内的刻数。依赖其数值含义的条件判断会随之改变。
