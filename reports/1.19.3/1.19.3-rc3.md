# Minecraft 1.19.3-rc3 变更分析

- 上一个版本：1.19.3-rc2
- 当前版本：1.19.3-rc3

## 手动放置盔甲架时读取物品保存的实体数据

盔甲架物品可以通过 `EntityTag` 保存实体数据。新版在玩家手动放置时读取这些数据，让预先配置的盔甲架物品生成具有相应特征的实体。

### 差异出现的场景

玩家手持通过命令、数据包等途径获得的盔甲架物品，对方块使用。物品的 `EntityTag` 中设置了小型、有手臂、无底座、装备或姿势等数据，并且放置位置通过空间检查。

### 版本变化

- 1.19.3-rc2：手动放置时没有应用这些实体数据，生成普通盔甲架。例如，物品指定了小型、有手臂且无底座，放下后仍是普通大小、没有手臂且带底座的盔甲架。
- 1.19.3-rc3：创建盔甲架后应用物品保存的实体数据，以上配置可以生效，装备、隐身、无重力等实体数据也会随之读取。

新版仍先按普通大小的盔甲架检查放置空间，再应用实体数据。最终朝向仍由玩家放置方向决定，头部和身体会在读取到的姿势基础上继续加入放置时的随机偏移，因此物品中保存的朝向和这两部分的姿势并非原样保留。

## 重建客户端玩家时按场景保留实体同步状态

客户端在重生或切换维度时会创建新的玩家实体。新版将实体同步状态与属性的保留分开控制，使死亡重生能清除旧状态，并修复复制默认状态时的异常。

### 差异出现的场景

第一种场景是玩家死亡前仍处于燃烧或冰冻状态，或者身上插有箭矢、蜂刺，随后重生。从末地出口返回重生点时，也会经过这次调整的玩家重建流程。

第二种场景是通过普通传送门或命令跨维度传送，需要保留旧玩家的实体同步状态，但旧玩家的所有同步数据恰好都处于默认值。

### 版本变化

- 1.19.3-rc2：死亡重生与末地返回时，客户端仍将旧玩家的非默认同步状态复制给新玩家。服务器新玩家的对应状态已恢复默认，但这些默认值未必再次发送，客户端可能继续显示死亡前的火焰遮挡、冰冻边框或箭矢、蜂刺，直到相应状态再次更新。在第二种场景中，读取旧状态得到空引用，客户端仍尝试复制，因异常中断玩家初始化。
- 1.19.3-rc3：死亡重生与末地返回时不再复制旧实体同步状态，新玩家从默认状态开始，再接收服务器同步。普通传送门和命令引起的跨维度传送仍保留这些状态；如果读取结果为空，就跳过复制并继续完成维度切换。

## 客户端补齐 Windows ARM64 的原生库

客户端的图形、声音和窗口等功能依赖与运行架构匹配的原生库。新版补充了 Windows ARM64 对应的依赖。

### 差异出现的场景

在 Windows ARM64 系统中，使用 ARM64 原生 Java 环境启动客户端。

### 版本变化

- 1.19.3-rc2：Windows 的这些原生依赖只包含 x86 与 x64 版本，缺少与 ARM64 原生 Java 环境匹配的库。
- 1.19.3-rc3：增加对应的 ARM64 原生库，消除启动时缺少这些匹配架构依赖的障碍。

代码出处：1.19.3-rc2 [build.gradle.kts:111](https://github.com/TISUnion/guardian/blob/04b9080a10e72ef92267675a379cc56bd29c345e/build.gradle.kts#L111)、1.19.3-rc3 [build.gradle.kts:110](https://github.com/TISUnion/guardian/blob/9732da8f9e3a755fd17e5ab0d11ee101dec0687b/build.gradle.kts#L110)（Windows 原生依赖的架构范围）。

## 复述功能初始化更改 Linux 依赖和失败处理

复述功能使用的语音库从 1.13.9 升级到 1.16.7，改变了 Linux 上初始化所需的库，以及部分初始化错误的处理。客户端在启动期间就创建语音实现，即使复述选项关闭也会执行。

### 差异出现的场景

Linux 系统没有提供可加载的 `flite` 或 `flite_cmu_us_kal16` 语音库；或者，语音初始化抛出未被转换为语音库自身初始化异常的运行时错误，例如 macOS 语音桥初始化直接抛出此类错误。

### 版本变化

- 1.19.3-rc2：Linux 可以使用随游戏分发的 `fliteWrapper`。语音初始化遇到上述运行时错误时，旧库捕获错误并关闭复述功能。
- 1.19.3-rc3：Linux 直接加载 `flite` 与 `flite_cmu_us_kal16`，缺少其中任意一个都会使复述功能不可用。未转换的运行时错误则继续向外传播，可能在创建复述功能时中断客户端启动。

新版 Linux 缺少 Flite 库的错误会被转换为语音库自身的初始化异常，仍会正常降级为复述不可用，不属于上述可能中断启动的情况。

## Linux 复述功能可以取消尚未朗读的旧消息片段

- Linux 上启用系统消息复述，连续收到要求打断先前朗读的消息时，1.19.3-rc2 仍将整条新消息加入队列，继续读完旧消息；1.19.3-rc3 会取消此前尚未开始的朗读片段，在当前播放片段结束后处理新消息。新版按标点拆分消息，因此被取消的可以是旧消息中尚未读到的后半部分。

## 重载资源后恢复孢子花环境粒子的生成名额

- 附近已有孢子花环境粒子时，使用 F3+T 或切换资源包重载资源，1.19.3-rc2 会清除现存粒子，却保留它们占用的计数，减少重载后的可用名额；多次重载可逐步占满 1000 个名额，使孢子花周围的悬浮粒子停止出现。1.19.3-rc3 在清除粒子时同时重置计数，重载后可以重新正常生成这些粒子。
