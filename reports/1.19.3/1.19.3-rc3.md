# Minecraft 1.19.3-rc3 变更分析

- 上一个版本：1.19.3-rc2
- 当前版本：1.19.3-rc3

## 手动放置盔甲架时读取物品保存的实体数据

玩家放置盔甲架时，新版会读取物品内的 `EntityTag`，让预先配置的盔甲架物品能够生成具有相应特征的实体。

### 差异出现的场景

玩家手持通过命令、数据包等途径获得的盔甲架物品，对方块使用。物品的 `EntityTag` 中设置了小型、有手臂、无底座、装备或姿势等数据，并且放置位置通过空间检查。

### 版本变化

- 1.19.3-rc2：手动放置时没有应用这些实体数据，生成普通盔甲架。例如，物品指定了小型、有手臂且无底座，放下后仍是普通大小、没有手臂且带底座的盔甲架。
- 1.19.3-rc3：创建盔甲架后应用物品保存的实体数据，以上配置可以生效，装备、隐身、无重力等实体数据也会随之读取。

新版仍先按普通大小的盔甲架检查放置空间，再应用实体数据。最终朝向仍由玩家放置方向决定，头部和身体会在读取到的姿势基础上继续加入放置时的随机偏移，因此物品中保存的朝向和这两部分的姿势并非原样保留。

## 重生后不再继承旧玩家的燃烧、冰冻等同步状态

客户端在重生或切换维度时都会创建新的玩家实体。新版将是否保留实体同步状态与是否保留属性分开控制，使死亡重生可以清除旧实体的状态。

### 差异出现的场景

玩家死亡前仍处于燃烧或冰冻状态，或者身上插有箭矢、蜂刺，随后重生。通过末地出口返回重生点时，也会经过这次调整的玩家重建流程。

### 版本变化

- 1.19.3-rc2：客户端无条件将旧玩家的非默认同步状态复制给新玩家。服务器的新玩家已经恢复默认状态，但这些默认值未必再次发送，客户端可能继续显示死亡前的火焰遮挡、冰冻边框或插在身上的箭矢、蜂刺，直到相应状态再次更新。
- 1.19.3-rc3：死亡重生与从末地出口返回时不再复制这些旧状态，客户端新玩家从默认状态开始，再接收服务器的同步。普通传送门和命令引起的跨维度传送仍会保留实体同步状态。

同一处修改还处理了空数据列表：在需要保留状态的跨维度传送中，如果旧玩家的所有实体同步数据恰好都处于默认值，旧版会因复制空引用而抛出异常，中断玩家初始化；新版会跳过复制并继续完成维度切换。

## 重载资源后恢复孢子花环境粒子的生成名额

附近已有孢子花环境粒子时，使用 F3+T 或切换资源包重载资源，1.19.3-rc2 会清除现存粒子，却保留它们占用的粒子计数。重载后的可用名额因此减少；多次重载可逐步占满 1000 个名额，使孢子花周围的悬浮粒子停止出现。1.19.3-rc3 在清除粒子时同时重置计数，资源重载后可以重新正常生成这些粒子。

## 复述功能更换语音库，改变 Linux 的依赖和打断行为

复述功能使用的语音库从 1.13.9 升级到 1.16.7，Linux 客户端的可用条件和连续朗读行为随之改变。

- Linux 系统没有提供可加载的 `flite` 与 `flite_cmu_us_kal16` 语音库时，1.19.3-rc2 可以使用随游戏分发的 `fliteWrapper`；1.19.3-rc3 改为直接加载前述两个系统库，缺少其中任意一个都会使复述功能不可用。
- Linux 上启用系统消息复述，先后收到多条需要打断先前消息的朗读请求时，1.19.3-rc2 会继续将整条消息加入队列；1.19.3-rc3 会使此前尚未开始的朗读片段失效，在当前正在播放的片段结束后处理新消息。新版按标点拆分消息，因此被取消的可以是旧消息中尚未读到的后半部分。
- 语音初始化遇到未转换为库自身初始化异常的运行时错误时，旧库会捕获错误并关闭复述功能，新库会让错误继续向外传播。例如 macOS 的语音桥初始化直接抛出此类错误时，新版可能在创建复述功能时中断客户端启动；这一初始化发生在客户端启动期间，即使复述选项关闭也会执行。Linux 缺少前述 Flite 库的错误会被转换并正常降级为复述不可用，不属于这种启动失败情况。

## 客户端补齐 Windows ARM64 的原生库

1.19.3-rc2 的 Windows 图形、声音和窗口等原生依赖只包含 x86 与 x64 版本。1.19.3-rc3 增加对应的 ARM64 版本，使在 Windows ARM64 原生 Java 环境中启动客户端时能够加载匹配架构的这些库，消除旧版依赖中缺少相应原生库这一障碍。
