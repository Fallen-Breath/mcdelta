# Minecraft 1.20.2-pre1 变更分析

- 上一个版本：23w35a
- 当前版本：1.20.2-pre1

## 伤害吸收再次施加时，可以补回生命值而无需延长效果

再次获得伤害吸收时，新版始终按这次施加的等级补回吸收生命值；旧版只有在新增效果、延长时长或改变效果状态时，才执行补充。

### 差异出现的场景

玩家仍有较长时间的伤害吸收 IV，但受伤后只剩 2 点吸收生命值，此时吃下提供伤害吸收 I 的普通金苹果。假定这次较弱效果没有改变现有效果的时长、粒子或图标设置。

### 版本变化

- 23w35a：现有效果没有发生可见更新，不补充吸收生命值，仍为 2 点。
- 1.20.2-pre1：即使现有效果没有更新，也执行补充，将吸收生命值提高到伤害吸收 I 对应的 4 点；原有高等级效果继续生效。

新版补充后的数值为“当前吸收生命值”和“本次效果等级对应的标准值”中的较大值。已经高于较弱效果标准值时，不会减少已有生命值，也不会再额外相加。例如当前有 8 点，施加伤害吸收 I 后仍为 8 点。旧版在确实触发效果更新的情况下，使用的是相加算法。

两版最终都受实体的最大吸收生命值属性限制。新版还将“吸收生命值耗尽便移除效果”的判断限定在服务端执行，客户端不再因暂时读到 0 而自行提前清掉效果。

## 可以关闭玩家死亡时的末影珍珠清除

新增游戏规则 `enderPearlsVanishOnDeath`，默认值为 `true`。

### 差异出现的场景

玩家已经抛出末影珍珠，珍珠仍在飞行或被滞留装置保存；随后玩家死亡，珍珠所在区块继续进行实体运算。

### 版本变化

- 23w35a：珍珠下一次运算时，只要仍能找到已经死亡的玩家作为投掷者，就会被清除。
- 1.20.2-pre1：默认仍会清除；执行 `/gamerule enderPearlsVanishOnDeath false` 后，珍珠不会因这项死亡检查而消失。

### 实际影响

关闭死亡清除后，保持加载的珍珠滞留装置可以保留主人死亡期间的珍珠，供主人重生后触发。珍珠仍须在碰撞时找到可用的投掷者，并满足投掷者与珍珠处于同一维度、没有睡觉等原有传送条件；此规则本身不提供跨维度传送或区块加载能力。如果珍珠在主人尚未重生时就发生碰撞，它仍会执行原有命中逻辑并被消耗，不会自动等待重生。

## 实验性盔甲匠交易按村民类型分化，钻石装备需要额外资源

以下变化仅在启用“村民交易重平衡”实验时生效，影响此后生成的交易。23w35a 的实验交易尚未覆盖盔甲匠，使用普通交易表；新版替换为按村民类型分化的表。已经保存的交易不会在升级时自动重抽。这里的类型是村民自身的沙漠、平原等类型，搬到另一种生物群系不会直接改换交易。

### 差异出现的场景

在启用该实验的世界里，培养新的盔甲匠，或让尚未生成高等级交易的盔甲匠升级。

### 版本变化

- 23w35a：所有类型的盔甲匠都能在专家等级销售随机附魔的钻石护腿和靴子，在大师等级销售随机附魔的钻石头盔和胸甲，付款只需绿宝石。
- 1.20.2-pre1：钻石装备销售集中到大师等级，按村民类型限定部位和附魔；每次还需支付 2～4 颗钻石。丛林和沼泽类型改为销售附魔锁链装备。装备自带的附魔均固定为 I 级。

下表列出大师等级的装备候选及基础价格。每个类型另外还有一项收购金属块的候选，每次升级只从有效候选中抽出两项，因此单个大师不保证同时拥有表中两项装备交易。

| 村民类型 | 大师装备候选及每件基础付款 | 固定附魔 |
| --- | --- | --- |
| 沙漠 | 钻石胸甲：16 绿宝石＋4 钻石；钻石护腿：16 绿宝石＋3 钻石 | 荆棘 I |
| 平原 | 钻石护腿：16 绿宝石＋3 钻石；钻石靴子：12 绿宝石＋2 钻石 | 保护 I |
| 热带草原 | 钻石头盔：6 绿宝石＋2 钻石；钻石胸甲：8 绿宝石＋3 钻石 | 绑定诅咒 I |
| 雪原 | 钻石靴子：12 绿宝石＋2 钻石；钻石头盔：12 绿宝石＋3 钻石 | 靴子为冰霜行者 I；头盔为水下速掘 I |
| 针叶林 | 钻石胸甲：18 绿宝石＋4 钻石；钻石护腿：18 绿宝石＋3 钻石 | 爆炸保护 I |
| 丛林 | 锁链头盔：9 绿宝石；锁链靴子：8 绿宝石 | 头盔为弹射物保护 I；靴子为摔落保护 I |
| 沼泽 | 锁链头盔：9 绿宝石；锁链靴子：8 绿宝石 | 头盔为水下呼吸 I；靴子为深海探索者 I |

这些装备交易每次补货最多使用 3 次。绿宝石价格可受需求、声望等影响；钻石位于第二个付款槽，数量不随绿宝石折扣下降。

低等级和专家交易也随之改变：

- 新手固定收购煤炭和铁锭，铁锭由原来的学徒级 4 个换 1 绿宝石，提前到新手级 5 个换 1 绿宝石；煤炭交易每次补货的使用次数由 16 降为 12。
- 学徒销售四个部位中的两件普通装备：丛林、沼泽为锁链装备，其余为铁装备；靴子、头盔、护腿、胸甲的基础售价依次为 4、5、7、9 绿宝石。
- 老手从熔岩桶收购、盾牌销售、钟销售中抽两项；旧表在此等级的单颗钻石收购被移除。
- 专家通常销售两件固定附魔的铁装备，丛林、沼泽则为锁链装备。沙漠附荆棘、平原附保护、热带草原附绑定诅咒、丛林附耐久、沼泽附经验修补，均为 I 级；雪原提供冰霜行者 I 铁靴与水下速掘 I 铁头盔。
- 针叶林专家改为钻石装备互换：靴子＋4 绿宝石换护腿、护腿＋4 绿宝石换胸甲、头盔＋4 绿宝石换靴子、胸甲＋2 绿宝石换头盔，从中抽两项。输入装备可以带有损耗或附魔，输出是全新的普通装备，原附魔和其他物品数据不会被保留。
- 大师额外候选中，针叶林村民用 42 绿宝石收购 1 钻石块，其余类型用 4 绿宝石收购 1 铁块。

### 实际影响

原来只靠可再生物品换取绿宝石，再从新盔甲匠处购买整套钻石装备的路线，在这项实验下需要钻石投入和不同类型的村民。绑定诅咒装备价格较低，但装备后受诅咒约束；针叶林的互换则可利用已有或损坏的钻石装备改变部位。新增交易的随机抽取会跳过不适用该类型的候选，直到成功生成两条或候选用尽。

## 实验性制图师提供跨生物群系的地图，原有探险地图推迟解锁

同样只在“村民交易重平衡”实验下，新生成的制图师交易根据村民类型提供其他地区的村庄地图，或指向丛林神庙、沼泽小屋的地图。原有海洋和林地探险家地图也调整了解锁等级。

### 差异出现的场景

培养尚未生成相关等级交易的制图师，购买寻找村庄、海底神殿或林地府邸的地图。

### 版本变化

- 23w35a：学徒出售海洋探险家地图，老手出售林地探险家地图，大师只有地球旗帜图案交易。
- 1.20.2-pre1：学徒的地图候选改为下表所示目的地；海洋探险家地图移到老手，林地探险家地图移到大师。林地地图每次补货可购买次数由 12 降为 1，基础付款仍为 14 绿宝石＋1 指南针。

| 制图师类型 | 学徒地图候选 |
| --- | --- |
| 沙漠 | 热带草原村庄、平原村庄、丛林神庙 |
| 热带草原 | 平原村庄、沙漠村庄、丛林神庙 |
| 平原 | 针叶林村庄、热带草原村庄 |
| 针叶林 | 雪原村庄、平原村庄、沼泽小屋 |
| 雪原 | 平原村庄、针叶林村庄、沼泽小屋 |
| 丛林 | 热带草原村庄、沙漠村庄、沼泽小屋 |
| 沼泽 | 雪原村庄、针叶林村庄、丛林神庙 |

新地图的基础价格为 8 绿宝石＋1 指南针，每次补货最多购买 12 次。学徒还保留玻璃板收购，整个等级只抽两条交易，因此不会保证出售所有地图；搜索范围内没有合适目标的地图候选会被跳过。地图查找的是对应村庄、丛林神庙或沼泽小屋结构，而不是任意一片目标生物群系。

### 实际影响

玩家可以沿不同地区的制图师寻找其他类型的村民，进而取得实验中按村民类型限定的交易。寻找海底神殿和林地府邸需要把新制图师培养到更高等级，同一制图师批量供应林地地图的速度也显著降低。

## 实验性结构战利品增加指定附魔书，沙漠神殿普通附魔书减少

启用“村民交易重平衡”数据包后，五种已有结构的战利品表被覆盖。新版在原有掉落之外，为指定附魔书提供单独的机会。

### 差异出现的场景

在启用该实验的世界中，首次打开尚未生成内容的废弃矿井、远古城市、沙漠神殿、丛林神庙或掠夺者前哨站战利品容器。已有区块中尚未展开战利品表的箱子和运输矿车也适用；已经生成的物品不会重新抽取。

### 版本变化

- 23w35a：该实验使用普通结构战利品表，没有下表中的指定附魔书额外机会。
- 1.20.2-pre1：五种结构增加下表所列的附魔书机会，沙漠神殿原有随机附魔书的抽取权重同时降低。

| 容器所用的结构战利品表 | 新增附魔书机会，每个容器计算一次 |
| --- | --- |
| 废弃矿井 | 20% 获得效率附魔书 |
| 远古城市 | 5% 获得经验修补附魔书 |
| 沙漠神殿 | 2/7（约 28.6%）获得耐久附魔书 |
| 丛林神庙 | 50% 获得耐久附魔书 |
| 掠夺者前哨站 | 2/3（约 66.7%）获得快速装填附魔书 |

效率、耐久和快速装填的等级在各自可用等级中随机选择；经验修补只有 I 级。表中是新增机会，原有随机附魔书仍可能另外产生同种附魔。

沙漠神殿还把原有普通随机附魔书在主要抽取池中的权重从 20 降为 10，单次抽中概率由 `20/232` 降为 `10/222`。新增的耐久书与原有沙丘盔甲纹饰锻造模板共用一次抽取，两者不会在这一池里同时产生；模板的机会仍为 1/7。远古城市的经验修补书占用了原来空结果的权重，盔甲纹饰模板机会保持不变。

## 红石方块的状态及时同步给客户端

## 配方书可搜索未解锁配方，但搜索匹配发生回归

新版允许通过非空搜索查询查看尚未解锁的配方，并允许服务端在未开启限制合成时为这些配方自动摆放材料；搜索为空时，仍主要显示已知配方。

### 差异出现的场景

打开工作台、背包或带配方书的熔炼界面，在配方书输入物品名称；比较已知与未知配方，以及中文、英文不同搜索词。

### 版本变化

- 23w35a：搜索只显示已经解锁的配方，支持在物品提示文本中查找子串，也支持带命名空间的物品 ID 搜索。服务端拒绝自动摆放未解锁配方。
- 1.20.2-pre1：非空搜索可以显示未解锁配方，已知配方排在前面。在 `doLimitedCrafting=false` 时，点击未知配方也可由服务器填入材料。

新版不再查询原来的全文索引，而是仅按结果物品名称中的单词前缀筛选。以英文 `Oak Planks` 为例，`pla` 可以匹配，`lank` 或带空格的 `oak planks` 不能匹配；`minecraft:oak_planks` 这种物品 ID 查询也不再受支持。

这段拆词使用 Java 默认的 `\W+`，没有启用 Unicode 单词匹配。纯中文物品名会全部被当成分隔符，因此用中文名称搜索不到这些配方；一些带非 ASCII 字母的其他语言名称也会受到影响。这是实际搜索功能回归。

### 实际影响

默认规则下，玩家可以不先取得解锁材料，就通过搜索查阅并填入已加载的配方，但中文版的名称搜索在此版本失效。

`doLimitedCrafting=true` 时还存在客户端与服务端不一致：服务器仍拒绝为未知配方摆放材料；客户端虽然收到服务器同步的规则值，却把它存到玩家对象中，而搜索读取的是另一个保持默认 `false` 的客户端世界规则。因此未知配方仍可能出现在搜索结果中，点击后服务器不接受。该问题同样适用于使用这套客户端世界的单人游戏界面。

服务端用客户端选项决定聊天消息的发送、状态查询样本是否显示玩家名字，以及玩家请求的视距。新版在重生时保留完整选项，并把首次登录时的选项接收提前到配置阶段。

## 修正实体只移动或只转向时的客户端插值

客户端会在数次更新之间逐渐把实体移动、转向到服务端同步的目标。新版在收到只包含移动或只包含转向的数据时，保留另一部分尚未完成的目标。

### 差异出现的场景

生物、其他玩家、船、矿车或展示实体还没有在客户端移动到上一次同步的目标位置，就收到仅包含转向的数据；或尚未转到目标角度，就收到仅包含移动的数据。

### 版本变化

- 23w35a：仅转向的数据会把实体当前显示位置设为新的位置目标，提前截断尚未完成的移动；仅移动的数据也会用当前显示角度覆盖尚未完成的转向。
- 1.20.2-pre1：只更新本次数据包含的位置或角度，另一部分继续使用上一次同步的目标，减少移动、转向交替同步时的停顿和抖动。

变化发生在客户端插值，服务端的实际坐标与装置计算保持原逻辑。

## 登录与重新配置时，已解码的数据包等待阶段切换完成

登录或服务器要求重新配置时，连接会暂停接收处理，切换到新阶段的数据包处理器后再恢复。新版让暂停期间已经解码的数据包也等待切换完成。

### 差异出现的场景

连接正在切换协议阶段，同一批网络输入中，阶段切换数据包之后还有已被解码的数据包。TCP 连接和单人游戏的内存连接都适用。

- 23w35a：暂停只关闭网络的自动读取，当前批次中已经解码的后续数据包仍可能交给旧阶段处理器，造成无效数据包断线。
- 1.20.2-pre1：新增的流量控制处理器将后续数据包排队，等新阶段处理器就绪并恢复读取后再交付，避免上述阶段错配。

## 签名聊天命令与普通聊天按同一队列交付

包含签名消息的聊天命令需要等待文本过滤等异步工作。新版让这些命令与玩家普通聊天共用同一条消息队列。

### 差异出现的场景

玩家接连发送普通聊天和 `/say`、`/msg` 等包含签名消息的命令，服务器启用了异步文本过滤，各条消息的过滤完成时间不同。玩家在消息交付前断线也会触发差异。

## 函数宏的数值参数去掉 NBT 类型后缀

函数宏会将传入的 NBT 值替换到命令文本中。新版对数值型参数采用普通数字格式，使其可以直接填入要求数字的命令参数。

### 差异出现的场景

函数宏接收 byte、short、long、float 或 double 参数，并将它替换到普通数字参数位置，或替换到需要保留具体 NBT 数值类型的 SNBT 文本中。

### 版本变化

- 23w35a：替换文本带有 NBT 类型后缀，例如 `2b`、`1.5d`，放到只接受普通数字的命令参数中会解析失败。
- 1.20.2-pre1：上述值替换为 `2`、`1.5`，可以用于普通数字参数。若宏需要在 SNBT 中保留 byte、double 等类型，必须在宏文本中明确写出对应后缀。

字符串、复合标签等参数不采用这次数值转换。

## 快速游戏目标支持 Java 风格转义

启动器可以通过快速游戏参数指定要进入的世界、服务器或 Realms。新版在使用这些目标前先解码 Java 风格转义，并在快速游戏日志中对目标 ID 使用对应编码。

### 差异出现的场景

启动器通过 `quickPlaySingleplayer`、`quickPlayMultiplayer` 或 `quickPlayRealms` 传入含 Java 风格转义的目标字符串，例如用字面量 `\u4e16` 表示汉字“世”；或者读取快速游戏日志，再把目标 ID 作为启动参数传回。

### 版本变化

- 23w35a：把反斜杠和后续字母直接当作目标的一部分，不会将上述 Unicode 转义解码为汉字。日志中的目标 ID 也没有额外经过这套转义编码。
- 1.20.2-pre1：先解释目标中的 Java 风格转义，再寻找世界或连接目标。日志对目标 ID 使用同一套编码，供启动器读取并原样传回；直接构造参数的工具也需要按这套规则处理反斜杠。

## 快速游戏遇到非法单人世界路径时显示无效目标页面

快速游戏会先检查指定的单人世界是否存在。新版把操作系统不接受的路径也作为无效目标处理。

### 差异出现的场景

启动器为快速游戏传入单人世界路径，而路径包含当前操作系统不接受的字符或格式，路径构造因此抛出 `InvalidPathException`。

### 版本变化

- 23w35a：检查世界是否存在时，异常向外抛出，无法按普通无效目标处理。
- 1.20.2-pre1：捕获该异常，检查结果返回“世界不存在”，进入原有的无效目标提示页面。

## 世界目录校验允许继续检查特殊路径类型

打开世界前，游戏会遍历世界目录并校验其中的符号链接。新版放宽了目录入口处的文件类型检查。

### 差异出现的场景

世界路径被文件系统标记为 `isOther()`，而非普通文件或通常的目录类型。

### 版本变化

- 23w35a：仅因路径属于这种特殊类型，就以“不是目录”为由拒绝访问。
- 1.20.2-pre1：继续遍历并校验路径，使部分可作为目录访问的特殊路径有机会进入正常加载流程。普通文件仍被拒绝，内部符号链接仍按原有规则检查。
