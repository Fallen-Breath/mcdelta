# Minecraft 1.20.2-pre2 变更分析

- 上一个版本：1.20.2-pre1
- 当前版本：1.20.2-pre2

## 配方书不再搜索和自动填入尚未解锁的配方

配方书以玩家已经解锁的配方为使用范围，同时收紧客户端显示和服务端自动摆放材料的检查。

### 差异出现的场景

`doLimitedCrafting=false`，玩家持有足够材料，但尚未解锁目标配方，在配方书中搜索该物品并尝试点击配方。配方组中只有部分具体配方已解锁时，也适用这一变化。

### 版本变化

- 1.20.2-pre1：输入搜索词后可以找到未解锁的配方；这些配方可以参与“可制作”判断，服务端也允许点击后自动填入材料。
- 1.20.2-pre2：配方书只显示已解锁的具体配方，未解锁的配方不再参与可制作判断。服务端也只接受玩家已解锁配方的自动填入请求，因此使用修改过的客户端发送请求也不能继续使用旧行为。

`doLimitedCrafting=true` 时，旧版服务端已经拒绝未解锁配方的自动填入请求。默认关闭这条规则的世界中，玩家仍可按记忆手动摆放材料制作未解锁的普通配方；本次改变的是配方书提供的查找和自动摆放能力。

## 配方书搜索支持名称中间片段、提示文本和物品 ID

配方书的搜索改用完整文本子串索引，扩大了查询能够匹配的内容。这项变化适用于已经解锁的配方，与未解锁配方的显示限制共同决定搜索结果。

### 差异出现的场景

玩家搜索已解锁配方，输入结果物品名称的中间片段、连续多个词、中文名称或普通悬浮提示中的文字；也可以输入带命名空间的物品 ID，例如 `minecraft:oak_planks`。

### 版本变化

- 1.20.2-pre1：只将结果物品名称按 `\W+` 分词，并匹配单词开头。名称中间片段和多词连写受到限制，中文名称在分词时会被排除；普通提示文本和物品 ID 也不属于这一搜索范围。
- 1.20.2-pre2：对结果物品的普通悬浮提示文本进行完整子串搜索，因此名称中间片段、中文名称及其片段均可匹配。带冒号的输入还可以按命名空间和结果物品 ID 搜索。

新版索引根据服务端同步的配方建立，并在资源重载时刷新；资源包、语言提供的结果名称和提示文本会参与当前搜索。

## 只更新位置或朝向时，实体不再使用失效的插值目标

客户端收到生物、其他玩家、船和矿车的移动更新时，有些数据包只带位置或只带朝向。新版修正了如何保留数据包没有更新的另一部分状态。

### 差异出现的场景

实体由服务端控制，客户端当前已经没有进行中的平滑移动，但保存的上一次移动目标与实体当前位置或朝向不同。一个直接场景是：客户端刚看见一个远离世界原点的静止实体，还没有收到过带坐标的移动更新，便先收到它原地转向的更新。

### 版本变化

- 1.20.2-pre1：仅转向时仍取保存的目标坐标，仅位移时仍取保存的目标朝向。这些值尚未初始化时为零，已经过期时则是旧值，因此可出现原地转向却向 `(0, 0, 0)` 插值移动，或移动时朝向突然恢复旧值的表现。
- 1.20.2-pre2：没有进行中的平滑移动时，取实体当前实际位置和朝向；仍在平滑移动时，才沿用尚未完成的目标。上述仅转向更新因而保持原地，位移更新也保留当前朝向。

这一变化修复的是观察客户端上的错误跳位和转向。

## 其他玩家出现时同步初始头部朝向和速度

其他玩家进入客户端视野时，需要通过生成包初始化位置、朝向和运动状态。新版让玩家使用通用实体生成包，并按生物的生成流程初始化头部、身体朝向及速度。

### 差异出现的场景

另一个玩家首次进入观察范围，或离开观察范围后重新被客户端加载；其头部朝向与身体朝向不同，或生成时正在移动。

### 版本变化

- 1.20.2-pre1：专用玩家生成包只提供位置、俯仰和水平朝向。客户端不会据此初始化独立的头部、身体朝向及速度，可能在首次出现时显示错误的头部方向，并等待后续运动更新才取得速度。
- 1.20.2-pre2：通用实体生成包同时携带头部朝向和速度，客户端按生物流程初始化这些状态，使其他玩家刚出现时的朝向和运动状态更完整。

### 实际影响

协议中的专用玩家生成包被移除。处理玩家生成的代理、协议转换器和自定义客户端，需要识别实体类型为玩家的通用生成包；创建远程玩家前仍须收到该玩家的个人信息。

## 关闭死亡清除规则时，末影珍珠不再被客户端提前隐藏

`enderPearlsVanishOnDeath` 决定玩家死亡时是否清除其投出的末影珍珠。新版把这项判断留给服务端，避免客户端按本地默认规则提前隐藏仍被服务端保留的珍珠。

### 差异出现的场景

服务端设置 `enderPearlsVanishOnDeath=false`，玩家投出的珍珠仍在飞行或滞留，随后玩家死亡，且观察客户端看见了投掷者的死亡状态。

### 版本变化

- 1.20.2-pre1：服务端保留珍珠，但客户端也会自行检查投掷者是否死亡。客户端保存的这条规则为默认开启值，因此可能先把珍珠删除，造成珍珠仍实际存在、画面上却已消失的情况。
- 1.20.2-pre2：死亡清除判断只针对服务端玩家执行。客户端等待服务端决定珍珠是否消失，因此能继续显示被保留的珍珠。

利用这条规则跨死亡保留珍珠的传送装置，其服务端保留行为没有改变；新版修正了观察客户端的显示与实际状态不一致的问题。

## 黑曜石柱顶端的火焰随地物一起生成

末地黑曜石柱地物会在柱顶放置基岩和末地水晶。新版在这一生成过程直接放置火焰，改变了火焰出现的时机，也使其他维度中的同类地物能够带火生成。

### 差异出现的场景

首次生成末地黑曜石柱、复活末影龙时重新生成柱子，或在其他维度通过命令、数据包成功放置同一种地物。

### 版本变化

- 1.20.2-pre1：地物生成只放置基岩和水晶。常规末地中，火焰由水晶随后进行实体更新时补上；其他维度没有末影龙战斗管理，水晶不会自动补火。
- 1.20.2-pre2：地物生成时，立即在柱顶基岩上、水晶所在格放置火焰。常规末地无需等到水晶更新；其他维度生成的同类地物也会多出实际的火方块。

已经生成的柱子不会仅因更新版本而重新执行地物生成。

## 空管理名单可正常加载，但损坏白名单重载会清空旧名单

封禁名单、IP 封禁名单、管理员名单和白名单共用的读取逻辑增加空结果处理，同时把清空内存名单的时机提前到 JSON 解析之前。这两点分别影响空文件和语法损坏文件。

### 差异出现的场景

- 对应 JSON 文件为空、只有空白字符，或内容为 `null`。
- 专用服务器已经加载了有效白名单，之后磁盘上的 `whitelist.json` 被改成无法解析为数组的内容，例如只有一个 `{`，再执行 `/whitelist reload`。

### 版本变化

- 1.20.2-pre1：空文件或 `null` 会在遍历读取结果时抛出空指针异常。封禁名单的启动加载只捕获 I/O 异常，因此可导致专用服务器启动失败；管理员和白名单加载会捕获异常并记警告。对于第二种场景，JSON 解析在清空内存名单之前失败，服务器保留此前已加载的白名单。
- 1.20.2-pre2：空文件或 `null` 被当作空名单成功读入。对于第二种场景，服务器先清空旧名单，再因 JSON 错误进入异常处理，内存白名单因此保持为空。

### 实际影响

在启用白名单准入的服务器上，第二种场景会令原先获准的普通玩家无法再次加入。`/whitelist reload` 的调用方会继续执行后续处理；若还设置了 `enforce-whitelist=true`，它会按清空后的名单踢出不在名单内的在线玩家。管理员身份不会在这一步的在线踢出检查中替代白名单记录。

## 客户端拒绝重复或顺序错误的登录握手

新版客户端记录登录握手所处的阶段，并检查收到的数据包是否符合允许的转换顺序。重复的加密请求和过早的登录成功包会导致连接终止。

### 差异出现的场景

服务器在同一次登录中重复发送加密握手请求，或已经发起加密验证，却在账户验证完成、客户端进入启用加密阶段之前发送登录成功包。

### 版本变化

- 1.20.2-pre1：没有对应的阶段检查，客户端仍会执行数据包处理，可能再次发起账户验证，或提前进入配置阶段。
- 1.20.2-pre2：客户端只允许从连接阶段发起账户验证，随后进入启用加密阶段，再接受登录成功包。上述重复请求或从验证阶段直接跳到加入阶段的包会触发协议异常，连接随之终止。

无需加密验证的登录仍可从连接阶段直接接受登录成功包并进入配置阶段；正常在线验证顺序也仍然允许。

## 函数宏浮点参数改用固定小数表示

函数宏将 NBT 中的 float、double 参数替换到命令文本时，pre2 改为使用小数点为 `.`、最多保留 15 位小数的普通十进制格式，同时省略无用的小数零。旧版使用 Java 的默认浮点文本，可能出现科学计数法。

### 差异出现的场景

数据包通过 `/function` 的宏参数，把浮点数插入坐标、数值参数、文本或 SNBT 字面量。例如宏命令 `$tp @s $(x) ~ ~`，参数为 `{x:10000000d}`。

### 版本变化

- 1.20.2-pre1：上述参数替换为 `1.0E7`。坐标等使用普通命令数字解析器的位置不能完整读取这个表达式，宏实例化失败。`0.0001d` 同样可能替换为 `1.0E-4`。
- 1.20.2-pre2：分别替换为 `10000000` 和 `.0001`，可以作为普通命令数值读取。整数值浮点参数也会去掉 `.0`，例如 `1.0d` 变成 `1`。

### 实际影响

依赖较大或较小浮点坐标的宏可以正常实例化。由于替换的是文本，已有宏也会遇到以下直接差别：

- 无后缀插入 SNBT 时，`1.0d` 的替换结果从 `1.0` 变为 `1`，解析出的标签由 double 变成 int；依赖标签类型的存储或匹配会随之变化。
- 小数部分超过 15 位会舍入，极小数例如 `1.0E-16d` 会变成 `0`。float 参数会展开其实际二进制数值，`0.1f` 从旧版 `0.1` 变成新版 `.100000001490116`，因此直接输出文本或转成 double 保存时也可能看到差别。

## 截图翻转不再受临时栈的单行容量限制

截图保存前需要上下翻转从画面读取的像素。新版将翻转所用的一行临时缓冲从 LWJGL 临时栈移到单独分配的原生内存，消除了该栈容量对这一操作的限制。

### 差异出现的场景

玩家截图时，画面非常宽，或 LWJGL 临时栈配置很小，使一行像素所需空间超过临时栈的剩余容量。

### 版本变化

- 1.20.2-pre1：翻转时需要从临时栈分配一行像素缓冲，分配失败会令截图无法完成。
- 1.20.2-pre2：单独分配并释放这一行缓冲。在原生内存分配成功的情况下，临时栈容量不再阻止截图保存。

## GLX 启动时统一 GLFW 与 LWJGL 的 OpenGL 库

客户端启动图形系统时，GLFW 和 LWJGL 需要使用一致的 OpenGL 共享库。新版在初始化 GLFW 前统一库路径，避免库不一致导致的启动故障。

### 差异出现的场景

使用 GLX 的图形环境中，GLFW 和 LWJGL 原本会加载不同的 OpenGL 共享库。这主要涉及 Linux 图形环境。

### 版本变化

- 1.20.2-pre1：没有在初始化前统一两者的库路径，两套库不一致时可能无法正确创建图形上下文，导致客户端启动失败。
- 1.20.2-pre2：先将 GLFW 使用的 OpenGL 库路径设为 LWJGL 当前使用的库，避免由这类不一致引发的故障。

代码出处：

- 旧初始化流程 [1.20.2-pre1](https://github.com/TISUnion/guardian/blob/a17d4eb1778effd1e9da6fce9ee0639907a9b35b/src/main/java/com/mojang/blaze3d/platform/GLX.java#L58)
