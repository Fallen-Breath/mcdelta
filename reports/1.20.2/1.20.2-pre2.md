# Minecraft 1.20.2-pre2 变更分析

- 上一个版本：1.20.2-pre1
- 当前版本：1.20.2-pre2

## 配方书不再搜索和自动填入尚未解锁的配方

配方书以玩家已经解锁的配方为使用范围，同时收紧客户端显示和服务端自动摆放材料的检查。

### 差异出现的场景

`doLimitedCrafting=false`，玩家持有足够材料，但尚未解锁目标配方，在配方书中搜索该物品并尝试点击配方。配方组中只有部分具体配方已解锁时，也适用这一变化。

### 版本变化

- 1.20.2-pre1：输入搜索词后可以找到未解锁的配方；这些配方可以参与“可制作”判断，服务端也允许点击后自动填入材料。
- 1.20.2-pre2：配方书只显示已解锁的具体配方，未解锁的配方不再参与可制作判断。服务端也只接受玩家已解锁配方的自动填入请求，因此使用修改过的客户端发送请求也不能继续使用旧行为。

`doLimitedCrafting=true` 时，旧版已经有上述解锁限制。默认关闭这条规则的世界中，玩家仍可按记忆手动摆放材料制作未解锁的普通配方；本次改变的是配方书提供的查找和自动摆放能力。

## 只更新位置或朝向时，实体不再使用失效的插值目标

客户端收到生物、其他玩家、船和矿车的移动更新时，有些数据包只带位置或只带朝向。新版修正了如何保留数据包没有更新的另一部分状态。

### 差异出现的场景

实体由服务端控制，客户端当前已经没有进行中的平滑移动，但保存的上一次移动目标与实体当前位置或朝向不同。一个直接场景是：客户端刚看见一个远离世界原点的静止实体，还没有收到过带坐标的移动更新，便先收到它原地转向的更新。

### 版本变化

- 1.20.2-pre1：仅转向时仍取保存的目标坐标，仅位移时仍取保存的目标朝向。这些值尚未初始化时为零，已经过期时则是旧值，因此可出现原地转向却向 `(0, 0, 0)` 插值移动，或移动时朝向突然恢复旧值的表现。
- 1.20.2-pre2：没有进行中的平滑移动时，取实体当前实际位置和朝向；仍在平滑移动时，才沿用尚未完成的目标。上述仅转向更新因而保持原地，位移更新也保留当前朝向。

这一变化修复的是观察客户端上的错误跳位和转向。

## 关闭死亡清除规则时，末影珍珠不再被客户端提前隐藏

玩家投出仍在飞行或滞留的末影珍珠后死亡，且服务端设置 `enderPearlsVanishOnDeath=false` 时，pre1 的服务端会保留珍珠，但看见其投掷者死亡的客户端仍可能把珍珠自行删除：客户端保存的是这条规则默认开启的本地值。pre2 将死亡清除判断限定为服务端玩家，客户端等待服务端决定珍珠是否消失，因而能继续显示这些保留下来的珍珠。利用这条规则跨死亡保留珍珠的传送装置，其服务端保留逻辑继续生效，观察到的珍珠也与实际状态一致。

## 黑曜石柱顶端的火焰随地物一起生成

首次生成末地黑曜石柱、复活末影龙时重新生成柱子，或在其他维度通过命令、数据包成功放置同一种地物时，pre2 都会立即在柱顶基岩上、末地水晶所在格放置火焰。pre1 只在这一过程生成基岩和水晶，火焰依赖水晶随后进行实体更新时补上；而水晶的补火逻辑要求所在维度具有末影龙战斗管理，因此在其他维度不会自动补火。

常规末地中主要差别是火焰出现时机；对在其他维度生成该地物的玩法，则新增了实际的火方块。已经生成的柱子不会仅因更新版本重新执行地物生成。

## 空管理名单可正常加载，但损坏白名单重载会清空旧名单

封禁名单、IP 封禁名单、管理员名单和白名单共用的读取逻辑增加空结果处理，同时把清空内存名单的时机提前到 JSON 解析之前。这两点分别影响空文件和语法损坏文件。

### 差异出现的场景

- 对应 JSON 文件为空、只有空白字符，或内容为 `null`。
- 专用服务器已经加载了有效白名单，之后磁盘上的 `whitelist.json` 被改成无法解析为数组的内容，例如只有一个 `{`，再执行 `/whitelist reload`。

### 版本变化

- 1.20.2-pre1：空文件或 `null` 会在遍历读取结果时抛出空指针异常。封禁名单的启动加载只捕获 I/O 异常，因此可导致专用服务器启动失败；管理员和白名单加载会捕获异常并记警告。对于第二种场景，JSON 解析在清空内存名单之前失败，服务器保留此前已加载的白名单。
- 1.20.2-pre2：空文件或 `null` 被当作空名单成功读入。对于第二种场景，服务器先清空旧名单，再因 JSON 错误进入异常处理，内存白名单因此保持为空。

### 实际影响

在启用白名单准入的服务器上，第二种场景会令原先获准的普通玩家无法再次加入。`/whitelist reload` 的调用方会继续执行后续处理；若还设置了 `enforce-whitelist=true`，它会按清空后的名单踢出不在名单内的在线玩家。管理员身份不会在这一步的在线踢出检查中替代白名单记录。

## 函数宏浮点参数改用固定小数表示

函数宏将 NBT 中的 float、double 参数替换到命令文本时，pre2 改为使用小数点为 `.`、最多保留 15 位小数的普通十进制格式，同时省略无用的小数零。旧版使用 Java 的默认浮点文本，可能出现科学计数法。

### 差异出现的场景

数据包通过 `/function` 的宏参数，把浮点数插入坐标、数值参数、文本或 SNBT 字面量。例如宏命令 `$tp @s $(x) ~ ~`，参数为 `{x:10000000d}`。

### 版本变化

- 1.20.2-pre1：上述参数替换为 `1.0E7`。坐标等使用普通命令数字解析器的位置不能完整读取这个表达式，宏实例化失败。`0.0001d` 同样可能替换为 `1.0E-4`。
- 1.20.2-pre2：分别替换为 `10000000` 和 `.0001`，可以作为普通命令数值读取。整数值浮点参数也会去掉 `.0`，例如 `1.0d` 变成 `1`。

### 实际影响

依赖较大或较小浮点坐标的宏可以正常实例化。由于替换的是文本，已有宏也会遇到以下直接差别：

- 无后缀插入 SNBT 时，`1.0d` 的替换结果从 `1.0` 变为 `1`，解析出的标签由 double 变成 int；依赖标签类型的存储或匹配会随之变化。
- 小数部分超过 15 位会舍入，极小数例如 `1.0E-16d` 会变成 `0`。float 参数会展开其实际二进制数值，`0.1f` 从旧版 `0.1` 变成新版 `.100000001490116`，因此直接输出文本或转成 double 保存时也可能看到差别。

## 配方书搜索支持名称中间片段、提示文本和物品 ID

对已经解锁的配方，pre1 只把结果物品名称按 `\W+` 分词，再匹配单词开头；因此名称中间片段、多词连写的查询都受限制，中文名称也会在分词时被排除。pre2 使用完整文本子串索引，搜索范围包括结果物品的普通悬浮提示文本，中文名称及其片段因而可以用于搜索。带冒号的输入还可按命名空间和结果物品 ID 搜索，例如 `minecraft:oak_planks`。

这个索引根据服务端同步的配方建立，并在资源重载时刷新，所以资源包、语言所提供的结果名称和提示文本会参与当前搜索。

## 其他玩家出现时同步初始头部朝向和速度

当另一个玩家进入观察范围或重新被客户端加载时，pre1 的专用玩家生成包只提供位置、俯仰和水平朝向，客户端不会据此初始化独立的头部、身体朝向及速度。pre2 让玩家改用通用实体生成包，并按生物的生成流程初始化这些状态，减少初次出现时头部方向不正确、等待后续运动更新才取得速度的情况。

协议上的专用玩家生成包同时被移除。处理玩家生成的代理、协议转换器和自定义客户端需要改为识别实体类型为玩家的通用生成包，并仍须提前提供该玩家的个人信息。

## 客户端拒绝重复或顺序错误的登录握手

服务器在登录时重复发送加密握手请求，或已经发起加密验证却在验证完成前发送登录成功包时，pre1 会继续执行对应处理，可能再次发起账户验证，或提前进入配置阶段。pre2 记录并检查连接、账户验证、启用加密、加入服务器几个阶段；重复请求以及从验证阶段直接跳到加入阶段都会触发协议异常，连接随之终止。

正常在线验证的顺序，以及无需加密验证、直接进入配置阶段的登录路径，仍属于允许的状态转换。

## 截图翻转不再受临时栈的单行容量限制

截图需要上下翻转从画面读取的像素。若画面非常宽，或 LWJGL 临时栈配置很小，使一行像素超过该栈剩余空间，pre1 会在分配这一行临时缓冲时失败，截图无法完成。pre2 改为单独分配并释放普通原生内存；在该分配成功的情况下，这个临时栈容量限制不再阻止截图保存。

## GLX 启动时统一 GLFW 与 LWJGL 的 OpenGL 库

在 GLFW 和 LWJGL 原本会加载不同 OpenGL 共享库的 GLX 环境中，旧版可能因两套库不一致而无法正确创建图形上下文。pre2 在初始化 GLFW 前，将它使用的 OpenGL 库路径设置为 LWJGL 当前使用的库，避免这一类不一致造成的启动故障；这项变化主要涉及使用 GLX 的 Linux 图形环境。

## 实验性地图的结构标签仅随“村民交易的平衡性调整”提供

## 内存故障报告更容易定位到资源或世界

- 读取世界列表中的某个世界摘要耗尽内存时，两版都会终止客户端；pre2 的崩溃报告会额外标明具体世界文件夹及 `level.dat` 文件大小，便于定位导致世界列表无法打开的存档。该信息通过异步加载异常传递后仍会保留在最终报告中。
- 加载资源、创建截图等流程在分配原生图像内存时，如果分配器返回空地址，pre1 仍会构造一个没有可用像素的图像对象，后续访问才失败；pre2 在构造时立即报错，并附带宽、高和通道数，使失败直接指向所申请的图像。
