# Minecraft 1.16.4-pre1 变更分析

- 上一个版本：1.16.3
- 当前版本：1.16.4-pre1

## 书与笔按保存请求中的槽位回写

书与笔保存和署名时，客户端会请求服务器写入书页及标题。新版将请求中的目标从主手或副手改为具体物品栏槽位，服务器按该槽位回写。

### 差异出现的场景

客户端提交保存或署名请求，目标书与笔位于快捷栏或副手。对于能够自行构造请求的客户端，目标可以是未被选中的快捷栏槽位；启用新版外部文本过滤时，请求还可能等待服务返回，期间玩家可以切换选中的快捷栏物品。

### 版本变化

- 1.16.3：请求只指定主手或副手。主手请求修改服务器处理时玩家正在选中的物品，副手请求修改副手物品；对应位置必须是书与笔。
- 1.16.4-pre1：请求指定快捷栏槽位或副手槽位，服务器只接受这两类位置。回写时检查并修改指定槽位中的书与笔，即使该快捷栏槽位未被选中，也可以保存或署名。

新版在过滤等待期间保留请求指定的槽位，切换当前选中的快捷栏物品不会改变回写目标。服务器不会跟随书本移动：原槽位已不是书与笔时忽略保存，原槽位换成另一本书与笔时则会修改替换进去的书。

## 湖泊生成检查村庄时减少等待主线程

生成水湖或熔岩湖前，游戏会查询候选位置所在区块是否引用了村庄结构，以决定是否放弃这次湖泊生成。新版改为使用当前地形生成区域中的区块及结构数据，减少这一步对服务端主线程的等待。

### 差异出现的场景

创建世界或探索未生成区域时，地形生成线程进行湖泊生成检查，服务端主线程同时在处理其他工作。

### 版本变化

- 1.16.3：结构查询经由服务端世界取区块，生成线程需要把请求交给服务端主线程并等待完成；主线程繁忙时，这一步生成工作也会等待。
- 1.16.4-pre1：直接使用本次地形生成已经准备好的区块及其中的结构数据，不再为这次检查等待主线程取区块。

变化发生在生成调度中。村庄附近放弃湖泊生成的判断条件保持不变，已经生成的地形也不会重新生成。

## 多人游戏可以单独隐藏某名玩家的消息

新版增加按玩家隐藏消息的功能，改变了客户端接收和显示聊天消息的方式。

### 差异出现的场景

玩家的账号允许使用聊天，正在服务器中游玩，或单人世界已经对局域网开放；希望继续接收其他人的消息，同时隐藏某一名玩家的消息。

### 版本变化

- 1.16.3：没有按玩家隐藏消息的名单，允许聊天时不会通过这种方式屏蔽指定发送者。
- 1.16.4-pre1：默认按 P 打开 Social Interactions 界面，可以按名称前缀搜索在线玩家，分别隐藏或恢复其消息，也可以查看已隐藏的在线玩家。此后收到的、发送者 UUID 为该玩家的消息会被客户端丢弃。

隐藏范围包括普通聊天、该玩家的 `/me` 和发给自己的私聊。聊天朗读也采用同一项隐藏检查。判断依据是消息携带的发送者 UUID；服务器以系统身份发送的消息不会仅因正文提到某个隐藏玩家而被隐藏。

隐藏名单保存在本次客户端进程中：退出服务器、换服后，对同一 UUID 的隐藏仍生效；重新启动客户端后清空。此操作只影响自己的消息显示，其他玩家仍会收到服务器广播。

## 专用服务器可接入外部文本过滤

专用服务器新增 `text-filtering-config` 配置，用于连接兼容的外部文本过滤服务。默认值为空，不启用过滤；单人游戏的内置服务器也不使用这一服务。

### 差异出现的场景

管理员在服务器配置中提供可用的服务地址和 API 密钥，玩家发送普通聊天或执行 `/me`，或者保存告示牌、书与笔及署名书本。

### 版本变化

- 1.16.3：上述文字直接进入各自的聊天或保存流程，没有这一外部过滤步骤。
- 1.16.4-pre1：先把文字和发送者身份提交给配置的服务，等待结果后广播或保存。服务可以允许原文、返回处理后的文字，或者拒绝内容。

不同输入被拒绝时，表现有所不同：

- 普通聊天和玩家执行的 `/me`：整条消息不广播。
- 告示牌：按行处理，未获通过的行替换为空行，其余行照常写入。
- 书与笔：按页处理，未获通过的页替换为空字符串；署名时标题也单独处理，标题被拒绝会保存为空标题。通过其他有效性检查且目标仍为书与笔时，书本保存或署名仍会继续。

管理员还能设置丢弃阈值：`hashesToDrop` 为默认的 -1 时保留服务返回的替换文本，为 0 时丢弃全部字符都被过滤的文本，为正数时按服务报告的过滤字符数达到阈值而丢弃。书页、标题和告示牌行的丢弃结果仍按上述方式转为空字符串。

### 实际影响

过滤服务的延迟会推迟聊天显示和文字落盘。其他命令照常执行，后发命令可能先于先发的普通聊天生效；其中 `/me` 另行接入过滤，而 `/msg`、`/say` 等命令的文字没有加入这条过滤流程。

配置解析失败时，服务器记录警告并关闭过滤。已经成功启用过滤后，服务连接失败、超时或返回无法解析的结果会按拒绝文字处理：普通聊天和 `/me` 消失，告示牌对应行以及书本对应页或标题可能被保存为空。这个差异使服务故障会直接影响玩家提交的文字内容。

普通聊天、书本及告示牌在过滤结果返回时还会检查连接；玩家已断线就放弃处理。`/me` 使用独立回调，本版没有这一断线检查，因此过滤结束后仍可能广播离线玩家先前提交的动作消息。

## 服务器卡死报告增加运行规模信息

专用服务器的监视线程会在游戏刻运行时间超过限制时生成报告并强制关闭服务器。新版为这份报告增加世界运行规模统计，并直接向标准输出打印完整报告。

### 差异出现的场景

专用服务器启用了监视线程，一次游戏刻超过 `max-tick-time`，触发卡死报告和强制关闭。

### 版本变化

- 1.16.3：报告包含线程堆栈等信息，并尝试保存到报告文件；没有新增的运行规模统计，也不会在保存前直接向标准输出打印完整报告。
- 1.16.4-pre1：报告增加随机刻速度及各维度的玩家数、实体数、可更新方块实体数、方块和流体计划刻数量、区块状态统计，并列出数量最多的五种实体和五种可更新方块实体；完整报告在保存文件前输出到标准输出，即使文件保存失败，控制台仍可留下这些信息。

## Realms 将 HTTP 277 作为等待重试响应

加入 Realm、切换世界槽位等操作可以在服务要求等待时重试请求。新版将 HTTP 277 纳入这一处理方式。

### 差异出现的场景

客户端执行支持等待重试的 Realms 操作，服务返回 HTTP 277，并给出重试等待时间。

### 版本变化

- 1.16.3：仅将 HTTP 503 交给等待重试流程；HTTP 277 属于成功响应范围，会立即继续解析响应内容。
- 1.16.4-pre1：将 HTTP 277 与 503 一样交给等待重试流程；加入 Realm、切换世界槽位等支持重试的操作会等待后再次请求，避免立即把该响应作为最终结果解析。
