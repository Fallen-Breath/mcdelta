# Minecraft 24w14a 变更分析

- 上一个版本：24w13a
- 当前版本：24w14a

## 工作方块界面的保持距离改为随交互距离变化

打开工作方块的界面后，玩家走远时的自动关闭条件改为使用方块交互距离属性。招牌释放编辑权限的距离也采用同一规则。

### 差异出现的场景

玩家打开工作台、附魔台、砂轮、切石机、制图台、织布机、信标、铁砧或锻造台后移动，或者在界面开启期间改变玩家的方块交互距离属性。招牌的对应场景是玩家获准编辑后被传送或以其他方式远离招牌。

### 版本变化

- 24w13a：上述工作方块界面要求玩家脚部位置距离方块中心不超过 8 格；招牌要求玩家脚部位置距离方块所在位置的整数坐标不超过 8 格。改变方块交互距离属性不改变这两个阈值。
- 24w14a：从玩家眼睛到目标方块完整一格立方体的最近距离，必须小于“方块交互距离属性值 + 4 格”。在默认属性下，生存模式阈值为 8.5 格，创造模式为 9 格；这些数值使用新版的测距方式。

### 实际影响

使用命令或装备扩大交互距离后，可以在相应距离维持工作界面，并保留招牌编辑权限。默认属性下界面关闭的具体边界也发生变化，因为测距起点与目标范围均改变；特别是玩家位于方块上方或下方时，不能直接把新版视作旧版半径增加半格。

## 旋风人真正弹开更多弹射物，反弹速度提高

启用“1.21 更新”实验后，旋风人反弹弹射物时，反弹处理会先于弹射物自身的命中效果完成。反弹后的弹射物也能再次被旋风人反弹。

### 差异出现的场景

末影珍珠、喷溅药水、滞留药水、雪球、鸡蛋、附魔之瓶或火球等击中旋风人；或者同一枚弹射物在反弹后再次撞到能够反弹它的实体。箭也受本次反弹速度修改影响。

### 版本变化

- 24w13a：部分弹射物虽然先执行反弹，随后仍继续执行自身的命中处理。例如，末影珍珠仍传送投掷者，药水仍破碎并施加效果，雪球仍消失，小火球仍被移除。没有自行清除反弹标记的弹射物，在之后再次碰撞时还会跳过反弹判断。
- 24w14a：符合反弹条件时直接结束本次命中处理，末影珍珠继续飞行，药水保留到后续实际命中时才破碎，其他上述弹射物也不会仅因这次反弹而执行消失或爆炸效果。每次碰撞重新判断是否反弹。

通用反弹将速度反向，并由保留原速的 25% 改为保留 50%。火球类弹射物在被反弹时，还会把持续加速度改到反弹方向，数值为反弹后速度的 5%；旧版保留原先的加速度方向。

## 玩家风弹击中旋风人时正常爆发

在“1.21 更新”实验中，玩家使用风弹物品发出的风弹，旧版会被旋风人反弹；新版将其与旋风人自己发出的风弹一同排除在反弹范围外。玩家风弹命中旋风人后，会执行直接命中的 1 点伤害并触发风爆，因此可用来攻击和击退旋风人，或在其附近触发风爆对方块的作用。

## 反击火球后的客户端轨迹与服务端一致

玩家击打恶魂火球等可反击的火球，或者弹射物被旋风人反弹后，旧版只同步即时速度，没有同步发生改变的持续加速度。客户端可能继续按旧加速度绘制飞行，随后再被服务端的位置更新纠正。

新版在同步这些弹射物的即时速度时，同时同步三轴加速度，客户端据此计算后续飞行。玩家击打火球本身的服务端反击规则没有因这个同步修改而改变。

## 收纳袋按自定义堆叠上限精确计算容量

启用收纳袋实验、并使用命令或数据包修改物品的 `minecraft:max_stack_size` 时，容量计算不再把每件物品的占用量截断为整数。

- 24w13a：每件普通物品占用 `64 / 最大堆叠数` 向下取整后的容量。例如最大堆叠数为 40 的物品每件占 1，空袋能装 64 件；最大堆叠数大于 64 时，每件占用量变成 0，尝试存入时会发生除零错误。
- 24w14a：每件普通物品占整个袋子的 `1 / 最大堆叠数`。上述上限为 40 的物品最多装 40 件，上限为 99 的物品最多装 99 件，混装也按分数累加。收纳袋内容的存储与网络编码同时取消了最多 64 个物品堆的限制，因此自定义物品可以占用超过 64 个独立条目。

这也改变已经存在的收纳袋：读取时重新计算占用量，原先因截断而装下的自定义物品组合可能超过新版容量。在取出足够物品前，袋子无法继续存入。

新版的分数计算另有一个限定于自定义物品的溢出问题：依次放入最大堆叠数为 61、59、53、47、43 的物品各一件后，再尝试放入最大堆叠数为 41 的物品，会发生分数运算溢出。旧版能完成这六次存入，新版在第六次存入时抛出异常；普通客户端会在本地执行这次容器点击时崩溃。袋中仅有第五件后的容量数字也可能因整数乘法溢出而显示为负数。这组物品的实际总占用远未达到一袋。

## 从旧快照读取书籍时存在内容兼容问题

书与笔的书页、成书的标题与书页，原本都支持“原始文本 + 过滤后文本”的对象形式。新版将该对象内的原始文本字段从 `text` 改为 `raw`，但没有为已使用物品组件格式保存的书籍增加迁移。

### 差异出现的场景

世界中的书与笔或成书已经在 24w13a 保存过，然后直接用 24w14a 打开世界；这些书的标题或书页对象中保存的是 `text` 字段。这个问题不要求书里实际存在过滤后文本，旧版保存普通文本时也会使用对象形式。

### 版本变化

- 24w13a：能够读回自己保存的 `text` 格式，保留书名、作者和正文。
- 24w14a：对象形式必须提供 `raw`。旧格式书与笔的书页无法解析，对应页会被舍弃；普通旧书全部采用该格式时，正文会变空。旧格式成书的标题无法解析，整个 `minecraft:written_book_content` 组件被舍弃，书物品保留，但失去标题、作者与正文内容。

新版新建的书，以及从物品组件化之前的旧版本直接升级而来的书，会写入 `raw` 格式。数据包中自行构造标题、书页对象的内容也需要使用新版字段。

## 配方书能一次填入多份带空位的配方

配方本身包含空格时，例如箱子的环形配方，旧版在计算一次能够填入多少份材料时，会把空格当作最大堆叠数为 1 的空物品，从而把填入数量压到 1。新版跳过这些空格。

因此，材料足够时，Shift 点击这类配方可以按材料数量与各材料堆叠上限填入多份；已经填好一份时继续点击，也能增加各材料槽的数量。旧版在同样条件下仍可能只留下每槽一件材料。

## 创造模式复制方块实体时保留来源坐标

创造模式按住 Ctrl 使用选取方块，复制箱子等方块实体时，旧版复制自定义数据与物品组件；新版还会把来源的 `x`、`y`、`z` 坐标放入方块实体数据。

因此，从两个不同位置复制状态与内容相同的箱子等方块时，旧版得到的复制物品可以匹配为同一种物品；新版因来源坐标不同而具有不同数据，无法合并堆叠，选取时也不会直接复用另一位置的复制物品。

## 自定义属性的覆盖与追加方式改变

战利品表和物品修饰器中的 `minecraft:set_attributes` 新增 `replace` 选项，并改变了省略该字段时的行为。

- 24w13a：在物品已有的属性修饰符列表后追加。对本来依靠装备默认属性的护甲追加第一个自定义属性时，会使默认护甲等属性失效。
- 24w14a：省略 `replace` 时按 `true` 处理，先清空属性列表，再写入本次提供的修饰符。现有的“给武器追加属性”修饰器因此可能同时移除武器原有的伤害与攻速加成。显式使用 `replace:false` 时保留已有列表；护甲尚无显式列表时，也先保留它原来的护甲、韧性等默认属性再追加。

新版追加时，还会移除物品列表内所有 UUID 与新修饰符相同的旧项，再加入新项。这个替换按 UUID 判断，覆盖范围包含使用同一 UUID 的其他属性或装备槽位；旧版直接累加列表项。

同属属性处理的另一项变化涉及实验性重锤：它的基础伤害与攻速改为默认的 `minecraft:attribute_modifiers` 组件。对重锤明确设置空属性列表或删除此组件，旧版仍回退到重锤硬编码的基础加成，新版会失去这部分加成。普通重锤的基础数值保持原样。

## 旧存档物品与结构数据的升级修正

这些差异发生在读取尚未经过对应格式转换的旧存档时，不会自动重新修复已经在旧快照中转换并保存的结果。

- 旧物品使用字节数保存数字方块状态时，旧版会把它误作布尔值。例如物品的 `BlockStateTag:{age:1b}` 会被转成 `age:"true"`，放置时无法恢复相应生长阶段。新版仅对已知布尔属性做布尔转换，数字属性转为 `"1"`，能够保留该状态。
- 旧物品使用空的 `Enchantments:[]` 获得附魔光效时，旧版升级会丢失光效；新版保留“存在附魔字段但没有有效附魔”的光效标记。
- 旧格式展示框、船、运输船和数种矿车物品的 `EntityTag` 缺少实体类型时，新版能根据物品补出实体类型，再进行内部数据转换；旧版只为刷怪蛋等已有映射的物品补充该字段。运输矿车等物品内实体数据中的物品也因此能随之升级。
- 数据版本低于 2970 的区块包含转换器不认识的结构名称时，旧版抛出异常，中断该区块的升级与加载；新版记录警告并舍弃未知结构的起点、引用，继续处理其余内容。起点或引用字段不是有效映射时，新版也改为按空映射处理，旧版会因取值失败而中断。若多个旧条目转换成同一个结构名称，新版合并它们的引用数组，并只保留一个结构起点；旧版转换后同名的条目会相互覆盖。未知结构的方块本身不会因这一步转换而移除。

## 物品替换命令尊重自定义堆叠上限

`/item replace ... with <物品> <数量>` 的数量语法上限由 64 提高到 99，并在应用物品组件之后检查堆叠上限。

因此，最大堆叠数设为 99 的物品可以一次替换为 99 件，旧版命令不接受这个数量。反过来，将石头的最大堆叠数设为 1、同时要求替换为 2 件时，旧版按石头原有的 64 件上限放行；新版按修改后的上限拒绝这次命令。

## 联机配置阶段切换时停止旧阶段的保活请求

服务器结束配置阶段、或要求已进入游戏的客户端重新进入配置阶段后，在等待客户端确认的这段时间内，旧版仍可能由旧阶段的连接处理器继续发出新的保活请求。新版发送阶段切换数据包后，不再从这个处理器发起新的保活请求；如果客户端 15 秒仍未完成切换确认，则按超时断开。此前已经发出且等待回复的保活请求，仍会按原有规则判定超时。

这使延迟确认阶段切换的客户端不再收到旧处理器追加的保活数据包，也限制了停留在切换过程中的连接时间。

## 自定义区域效果云的粒子保留与运动

- 区域效果云同时设置自定义粒子与药水内容时，旧版加载药水内容会把粒子改回普通状态效果粒子；新版保留原粒子类型，仅在该粒子类型支持颜色时更新颜色。因此，这类效果云重载后能保留自定义外观。
- 等待生效期间，旧版自定义粒子有一半机会被替换为白色状态效果粒子；新版只有普通状态效果粒子使用这种白色闪烁。正式生效后，自定义粒子的初始速度由零改为少量随机水平速度和向上的速度，具体视觉效果取决于粒子种类。

## 启动环境与辅助操作

- 运行环境要求从 Java 17 提升到 Java 21。仍使用 Java 17 的自建服务端启动配置需要切换运行时后才能启动本版。
- “复述功能快捷键”选项现在实际控制 Ctrl+B（macOS 为 Cmd+B）。旧版即使关闭该选项，快捷键仍会轮换复述模式；新版关闭选项后，该快捷键不再切换复述功能。
- 死亡界面选择返回标题画面、进入确认界面时，新版沿用死亡画面的背景渐变；旧版使用普通确认界面的背景。
- 区块升级异常的崩溃报告新增原始数据版本，便于定位来自哪种旧存档；这项修改本身不改变正常区块的生成结果。
