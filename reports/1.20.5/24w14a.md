# Minecraft 24w14a 变更分析

- 上一个版本：24w13a
- 当前版本：24w14a

## 工作方块界面的保持距离改为随交互距离变化

打开工作方块的界面后，玩家走远时的自动关闭条件改为使用方块交互距离属性。招牌释放编辑权限的距离也采用同一规则。

### 差异出现的场景

玩家打开工作台、附魔台、砂轮、切石机、制图台、织布机、信标、铁砧或锻造台后移动，或者在界面开启期间改变玩家的方块交互距离属性。招牌的对应场景是玩家获准编辑后被传送或以其他方式远离招牌。

### 版本变化

- 24w13a：上述工作方块界面要求玩家脚部位置距离方块中心不超过 8 格；招牌要求玩家脚部位置距离方块所在位置的整数坐标不超过 8 格。改变方块交互距离属性不改变这两个阈值。
- 24w14a：从玩家眼睛到目标方块完整一格立方体的最近距离，必须小于“方块交互距离属性值 + 4 格”。在默认属性下，生存模式阈值为 8.5 格，创造模式为 9 格；这些数值使用新版的测距方式。

### 实际影响

使用命令或装备扩大交互距离后，可以在相应距离维持工作界面，并保留招牌编辑权限。默认属性下界面关闭的具体边界也发生变化，因为测距起点与目标范围均改变；特别是玩家位于方块上方或下方时，不能直接把新版视作旧版半径增加半格。

## 旋风人反弹弹射物时不再触发命中效果

启用“1.21 更新”实验后，旋风人反弹弹射物时，反弹处理会先于弹射物自身的命中效果完成。反弹后的弹射物也能再次被旋风人反弹。

### 差异出现的场景

末影珍珠、喷溅药水、滞留药水、雪球、鸡蛋、附魔之瓶或火球等击中旋风人；或者同一枚弹射物在反弹后再次撞到能够反弹它的实体。箭也受本次反弹速度修改影响。

### 版本变化

- 24w13a：部分弹射物虽然先执行反弹，随后仍继续执行自身的命中处理。例如，末影珍珠仍传送投掷者，药水仍破碎并施加效果，雪球仍消失，小火球仍被移除。没有自行清除反弹标记的弹射物，在之后再次碰撞时还会跳过反弹判断。
- 24w14a：符合反弹条件时直接结束本次命中处理，末影珍珠继续飞行，药水保留到后续实际命中时才破碎，其他上述弹射物也不会仅因这次反弹而执行消失或爆炸效果。每次碰撞重新判断是否反弹。

通用反弹将速度反向，并由保留原速的 25% 改为保留 50%。火球类弹射物在被反弹时，还会把持续加速度改到反弹方向，数值为反弹后速度的 5%；旧版保留原先的加速度方向。

## 玩家风弹击中旋风人时正常爆发

旋风人的弹射物反弹规则改为同时排除玩家风弹与旋风人自己的风弹。

### 差异出现的场景

启用“1.21 更新”实验，玩家使用风弹物品发出的风弹击中旋风人。

### 版本变化

- 24w13a：玩家风弹会被旋风人反弹。
- 24w14a：玩家风弹不再被反弹，命中时执行直接命中的 1 点伤害并触发风爆。风爆可以击退旋风人，也可以触发附近方块对风爆的响应。

## 反击火球后的客户端轨迹与服务端一致

火球类弹射物的后续飞行既受即时速度影响，也受持续加速度影响。新版在速度更新时一同同步加速度，减少客户端显示轨迹与服务端轨迹的偏差。

### 差异出现的场景

玩家击打恶魂火球等可反击的火球，或者启用“1.21 更新”实验后，火球类弹射物被旋风人反弹。

### 版本变化

- 24w13a：只同步即时速度，未同步发生改变的持续加速度。客户端可能继续按旧加速度显示飞行，随后被服务端的位置更新纠正。
- 24w14a：同步即时速度时，同时同步三轴加速度，客户端据此计算后续飞行。

这项同步修改本身不改变玩家击打火球时的服务端反击规则。

## 收纳袋按自定义堆叠上限精确计算容量

收纳袋改用分数计算每件物品的容量占用，避免按自定义堆叠上限换算时发生整数截断。

### 差异出现的场景

启用收纳袋实验，使用命令或数据包修改物品的 `minecraft:max_stack_size`，再将这些物品装入收纳袋；或者读取已经装有这些物品的收纳袋。

### 版本变化

- 24w13a：每件普通物品占用 `64 / 最大堆叠数` 向下取整后的容量。例如最大堆叠数为 40 的物品每件占 1，空袋能装 64 件；最大堆叠数大于 64 时，每件占用量变成 0，尝试存入时会发生除零错误。
- 24w14a：每件普通物品占整个袋子的 `1 / 最大堆叠数`。上述上限为 40 的物品最多装 40 件，上限为 99 的物品最多装 99 件，混装也按分数累加。收纳袋内容的存储与网络编码同时取消了最多 64 个物品堆的限制，因此自定义物品可以占用超过 64 个独立条目。

### 实际影响

这也改变已经存在的收纳袋：读取时重新计算占用量，原先因截断而装下的自定义物品组合可能超过新版容量。在取出足够物品前，袋子无法继续存入。

新版的分数计算另有一个限定于自定义物品的溢出问题：依次放入最大堆叠数为 61、59、53、47、43 的物品各一件后，再尝试放入最大堆叠数为 41 的物品，会发生分数运算溢出。旧版能完成这六次存入，新版在第六次存入时抛出异常；原版客户端会在本地执行这次容器点击时崩溃。袋中仅有第五件后的容量数字也可能因整数乘法溢出而显示为负数。这组物品的实际总占用远未达到一袋。

## 从旧快照读取书籍时存在内容兼容问题

书与笔的书页、成书的标题与书页，原本都支持“原始文本 + 过滤后文本”的对象形式。新版将该对象内的原始文本字段从 `text` 改为 `raw`，但没有为已使用物品组件格式保存的书籍增加迁移。

### 差异出现的场景

世界中的书与笔或成书已经在 24w13a 保存过，然后直接用 24w14a 打开世界；这些书的标题或书页对象中保存的是 `text` 字段。这个问题不要求书里实际存在过滤后文本，旧版保存普通文本时也会使用对象形式。

### 版本变化

- 24w13a：能够读回自己保存的 `text` 格式，保留书名、作者和正文。
- 24w14a：对象形式必须提供 `raw`。旧格式书与笔的书页无法解析，对应页会被舍弃；普通旧书全部采用该格式时，正文会变空。旧格式成书的标题无法解析，整个 `minecraft:written_book_content` 组件被舍弃，书物品保留，但失去标题、作者与正文内容。

新版新建的书，以及从物品组件化之前的旧版本直接升级而来的书，会写入 `raw` 格式。数据包中自行构造标题、书页对象的内容也需要使用新版字段。

## 配方书能一次填入多份带空位的配方

配方书计算可填入的材料份数时，新版跳过配方中的空位，避免空位压低各材料槽的填充数量。

### 差异出现的场景

材料足够，配方本身包含空位，例如箱子的环形配方。玩家 Shift 点击该配方，或在已经填好一份材料后继续点击配方。

### 版本变化

- 24w13a：把空位当作最大堆叠数为 1 的空物品纳入限制，可能使各材料槽只留下一个物品，无法增加填入的份数。
- 24w14a：空位不再参与堆叠上限计算。Shift 点击可以按材料数量及各材料的堆叠上限填入多份；已有一份材料时继续点击，也能增加各材料槽的数量。

## 无乐器组件的山羊角也能吹响

山羊角在缺少乐器组件时，提示与使用时长已有默认乐器。新版实际吹奏时也采用这一默认值。

### 差异出现的场景

玩家右键使用没有 `minecraft:instrument` 组件的山羊角，且山羊角乐器标签内有可用乐器。

### 版本变化

- 24w13a：使用失败，无法吹奏。
- 24w14a：使用标签中的第一个可用乐器正常吹奏，播放声音、进入使用动作并产生冷却。原版标签中的默认乐器为“沉思”。

## 镐能更快挖掘沉重核心

沉重核心加入可用镐挖掘的方块标签，使镐的工具速度与效率附魔能够参与其挖掘速度计算。

### 差异出现的场景

## 自定义属性的覆盖与追加方式改变

战利品表和物品修饰器中的 `minecraft:set_attributes` 新增 `replace` 选项，默认从追加改为覆盖。追加属性时也会处理已有默认属性与重复 UUID。

### 差异出现的场景

### 版本变化

- 24w13a：始终在物品已有的属性修饰符列表后追加。护甲尚无显式属性列表时，追加第一个自定义属性会使默认护甲等属性失效；UUID 相同的列表项也直接累加。
- 24w14a：省略 `replace` 时按 `true` 处理，清空列表后写入新修饰符。显式使用 `replace:false` 时保留已有列表；原列表为空时，先以物品默认属性为基础再追加。追加还会移除列表中所有 UUID 与新修饰符相同的旧项，再加入新项，覆盖范围包括使用该 UUID 的其他属性或装备槽位。

现有修饰器若依赖“省略选项即追加”的行为，新版执行后可能同时移除武器原有的伤害与攻速加成。

本版将 Java 运行环境要求从 17 提升到 21，影响客户端及自建服务端的启动环境。

### 差异出现的场景

仍使用满足旧版要求的 Java 17 启动配置运行游戏或自建服务端。

### 版本变化

- 24w13a：Java 17 满足版本声明的运行要求。
- 24w14a：要求 Java 21，原有 Java 17 运行时无法启动本版，需要使用符合新要求的运行时。
