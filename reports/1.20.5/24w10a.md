# Minecraft 24w10a 变更分析

- 上一个版本：24w09a
- 当前版本：24w10a

## 砂轮预览会把下槽附魔写入上槽输入

新版砂轮在计算双物品结果时修改了上槽的实际物品。即使玩家没有领取结果，也能把下槽附魔留在上槽物品上。

### 差异出现的场景

在砂轮上槽放入一把普通铁剑，下槽放入同材质、带锋利附魔的铁剑。两件物品都只有一件，满足砂轮的合并条件。

### 版本变化

- 24w09a：计算结果时先复制上槽物品，再向副本合并下槽附魔。取回两件输入时，两把剑的附魔保持原样。
- 24w10a：向真实的上槽输入合并下槽附魔。玩家取回两件输入时，上槽铁剑也已获得锋利附魔，下槽铁剑仍保留原附魔。

新版会把下槽的普通附魔按较高等级合入上槽；下槽诅咒也会在上槽缺少该诅咒时写入。玩家无需领取结果、消耗物品或支付经验，就能通过预览转移并复制附魔。这也改变了领取结果时的经验计算：下槽独有的普通附魔可能同时计入已经被改写的上槽和下槽，增加返还经验。

新版结果副本在改写上槽之前创建，随后再次更新输入时才可能把新增诅咒反映到结果中；普通点击放入物品会触发多次更新。因此，这一回归最稳定的直接表现是输入物品被改写，不能把第一次计算的临时结果等同于界面最终显示。

砂轮的放入条件也有调整：没有任何附魔的附魔书不再仅凭物品种类被接受；带 `stored_enchantments` 的其他物品可以被接受。不过实际处理哪种附魔仍按物品是否为附魔书选择，普通物品上的储存附魔不因此自动成为可清除的普通附魔。

对于带无法破坏和附魔的同种工具，若它们不可堆叠且全部组件相同，旧版会把两件作为不可损坏物品合并，生成数量为 2 的工具堆；新版新增最大堆叠数量检查，拒绝这种超出工具堆叠上限的合并。

## 谜之炖菜恢复生存模式的状态效果，饱和炖菜时长缩短

### 差异出现的场景

生存模式玩家吃完一碗谜之炖菜，包括用花制作、从棕色哞菇取得或通过交易得到的炖菜。

### 版本变化

- 24w09a：先执行进食并把物品数量减到零，随后从已经为空的物品堆读取效果，得到空效果列表。正常单碗炖菜只完成进食并留下碗，丢失其额外状态效果。创造模式不消耗炖菜，因而不受这一读取顺序影响。
- 24w10a：先读取并施加炖菜效果，再执行进食。正常单碗炖菜能施加对应效果。

同时，用蒲公英或兰花产生的饱和效果从 140 游戏刻改为 7 游戏刻，即从 7 秒改为 0.35 秒。该时长来自制作或取得炖菜时写入的物品数据；已经存有 140 刻效果的旧炖菜不会仅因升级而被重写。两项变化共同作用于新取得的饱和炖菜：生存模式效果恢复，但不会使用上一快照错误放大的持续时间。

## 狼的自然生成地点、群体和繁殖规则改变

### 差异出现的场景

在对应生物群系生成新区块，或让已加载区域满足动物自然生成条件；另包括让两只已驯服的狼繁殖。

### 版本变化

- 24w09a：热带高原、稀疏丛林、疏林恶地的动物列表没有狼。雪林可以生成羊、猪、鸡、牛，以及狼、兔子和狐狸；狼的列表群体数量为 4。
- 24w10a：上述三个生物群系加入狼；雪林移除羊、猪、鸡和牛的自然生成条目，并重新分配狼、兔子和狐狸的权重。

| 生物群系 | 24w10a 的相关动物生成条目 |
| --- | --- |
| 热带高原 | 加入狼，权重 8，列表群体数量 4～8 |
| 稀疏丛林 | 加入狼，权重 8，列表群体数量 2～4 |
| 疏林恶地 | 犰狳与狼的权重分别为 6、2；狼的列表群体数量 4～8。新区块动物生成循环的继续概率由 0.03 调为 0.04 |
| 雪林 | 狼、兔子、狐狸权重改为 1、8、4，列表群体数量分别为 1、2～3、2～4；旧版对应权重为 8、4、8 |

列表中的数量是生成尝试采用的群体规模，仍受落点和其他生成条件限制。狼可生成的地面新增砂土和灰化土，原始针叶林等地的这些地面因此能够成为有效落点。

新版还为自然生成的狼群传递专用群体数据，关闭原有的自然幼体随机选择。旧版一群狼中第一只之后的成员有 5% 的幼体选择机会；新版自然生成的狼群由成年狼组成。这会改变依赖野生幼狼出现的收集方式。

繁殖方面，新版幼狼随机继承任一亲本的变种；驯服幼狼的项圈颜色也随机继承任一亲本。旧版幼狼的项圈使用默认红色。旧世界已有的狼没有变种字段时保留默认变种，不会根据当前所在地重新选择。

## 磁石被破坏后，指南针保持磁石指南针状态

当磁石指南针进入其目标所在维度的玩家物品栏，并发现磁石已经不存在或目标越出世界范围时：

- 24w09a：删除整个磁石目标组件，指南针恢复普通指南针状态。在主世界会重新指向世界出生点，并失去磁石指南针的默认附魔光效和名称。
- 24w10a：保留磁石追踪组件，只清空目标。指南针保持磁石指南针名称及默认光效，指针因没有有效目标而随机转动。

这使“磁石失效”与“普通指南针”成为不同的物品状态。检查磁石组件是否存在的数据包，在磁石失效后仍会匹配该物品。目标位于其他维度或设置了 `tracked:false` 时，不在本次失效清空条件之内。

组件由 `minecraft:lodestone_target` 改名为 `minecraft:lodestone_tracker`，坐标与维度移入可选的 `target` 对象。存档有对应迁移，手写命令和数据包需要使用新名称及结构。

## 熔炉输出按完整物品数据匹配，酿造台命令修改会更新比较器

- 熔炉、高炉和烟熏炉的输出槽如果已有与配方产物同种、但名称或其他组件不同的物品，24w09a 仍可继续熔炼，并把新产物数量加到现有物品上，继承现有槽位的组件。24w10a 要求组件也一致，不一致时停止继续处理。例如，输出槽放着命名铁锭时，新版不会把普通铁锭并入该堆并继续沿用名称。这也保证自定义熔炼配方的特殊组件不会被已有普通产物吞掉。
- 用 `/item replace block` 或 `/item modify block` 修改酿造台库存时，24w09a 的直接写入没有标记方块实体变化，也没有通知比较器。24w10a 使用带变化通知的容器写入，比较器可以响应库存变化，修改也会标记为需要保存。正常界面和漏斗路径原本另有通知，不能把这项变化理解为所有酿造台操作都会改变信号时序。

## 更多容器方块使用物品的 container 组件保存内容

箱子、陷阱箱、木桶、漏斗、发射器、投掷器、熔炉及其变种、酿造台，以及实验性的合成器，现在会从 `minecraft:container` 组件恢复物品内容。营火、灵魂营火、雕纹书架和饰纹陶罐也增加了相应支持。潜影盒原有的组件容器行为移入公共实现。

### 差异出现的场景

使用命令或战利品函数制作带内容的方块物品，然后放置；或者在创造模式复制带数据的容器方块。

### 版本变化

- 24w09a：除已有专门实现的潜影盒等情况外，给箱子等物品设置 `container` 不会把其中物品放进方块，通常要依赖 `block_entity_data.Items`。`set_contents` 战利品函数也把结果写进方块实体数据。
- 24w10a：这些方块从 `container` 逐槽复制物品，保存为物品时也把内容移入该组件；`set_contents` 直接写入或替换 `container`。饰纹陶罐只采用第 0 槽，普通选取方块得到的陶罐物品也会收集罐内内容。

### 实际影响

24w09a 已保存的箱子等物品，如果内容仍放在 `block_entity_data.Items`，新版放置时会先读这部分数据，再被 `container` 覆盖。未提供 `container` 时按空容器处理，原有内容会被清空；饰纹陶罐的旧 `block_entity_data.item` 同样如此。直接从组件化之前的存档升级时，新修订的旧数据迁移会把这些内容搬到 `container`；已经在 24w09a 完成组件化的物品不会重新执行这段更早的迁移。

组件恢复是直接复制槽位，还存在两个具体限制：雕纹书架不会据此自动设置六个槽位的占用方块状态，只提供 `container` 的书本不会自动变成可直接点击取出的显示状态；营火不会据此初始化烹饪计时，如果只提供食物组件而没有另行设置计时，默认计时为零，点燃后下一次烹饪刻就会产出结果。

这里涉及带内容物品的制作、复制和放置。普通生存挖掘的箱子、营火、陶罐等掉落表没有因此统一改成保留内部物品。

## 组件物品的堆叠、移除和属性比较修正

- 对相同物品分别写入内容一致、直接列出方块的 `can_place_on` 或 `can_break` 条件，24w09a 可能把两次独立创建的方块集合视为不同对象，使物品不能堆叠。24w10a 按集合内容比较，这类组件完全一致的物品可以正常堆叠。
- 当上述冒险模式条件仅有 `show_in_tooltip` 不同时，旧版比较会忽略这个差别，物品合并后只留下其中一种提示显示设置。新版将显示开关纳入比较，两堆物品保持分开。
- 两个物品的属性修饰符 UUID 相同，但名称、数值或运算不同，旧版可能仍把它们视为相同组件。新版比较完整修饰符内容，避免此类物品合并而丢失差异，也能识别装备替换后属性内容的变化。
- 通过 `set_components` 使用 `!minecraft:custom_name` 等移除一个物品原本没有、后来才添加的组件时，24w09a 可能留下已有自定义值。24w10a 会正确删除该修改，恢复物品默认状态。

实体存档中的重复属性修饰符也更一致：同一属性里出现 UUID 相同且运算相同的多条永久修饰符时，新版计算与保存采用最后一条；旧版按 UUID 查找可能得到最后一条，实际计算却沿用集合中先留下的一条。

## 旧世界物品转换保留更多原有数据

以下修正发生在从物品组件化之前的存档执行转换时，不会自动重新修复已经在 24w09a 转换并保存、且数据已经丢失的物品。

- 旧 `BlockStateTag` 使用数字或布尔值表示的方块状态，现在会转换成组件要求的字符串。例如旧式数值等级、布尔状态不再因为类型不符而被丢弃，放置时能保留相应状态。
- 旧箱子、熔炉、酿造台、营火、雕纹书架等方块物品内部的物品，以及饰纹陶罐内的物品，现在迁移到 `container`。容器槽号按无符号字节解释，避免高位槽号变成负数。
- 旧属性修饰符缺少 `Name`、`Amount` 或 `Operation` 时，转换分别补上空名称、0 和加法运算，减少原本可读取的数据因为新字段要求而丢失的情况。
- 旧地图装饰出现相同标识时，转换保留第一条，避免收集成映射时抛出重复键异常。
- 旧玩家头颅档案中的非法玩家名会被去掉，但 UUID、纹理属性等仍可保留；配合玩家名可选的新结构，无需为保留纹理而强制提供一个合法名字。
- 旧画、刷怪蛋物品的 `EntityTag` 会按物品种类写入对应实体 ID，使内部实体数据能继续经过后续转换并成为有效的 `entity_data`。该写入也会覆盖原有的实体 ID；旧刷怪蛋若原先通过 `EntityTag.id` 指定其他生物，升级后会改为蛋物品对应的种类。

## 零重力玩家不再因悬空超时被立即踢出

## 配方产物可以携带组件，熔炼结果格式改变

24w09a 的普通有序、无序、切石和锻造转换配方只从结果读取物品 ID 与数量，结果中写入的组件不会因此成为产物组件。24w10a 统一读取完整物品堆，可在普通合成、切石与烹饪配方产物中指定名称、附魔等组件。烹饪配方仍固定产出单件，手写 `count` 不会增加产量。

## 命令可检查物品槽位，并访问光标与随身合成格

- 新增 `/execute if items entity <实体> <槽位> <物品条件>` 与 `block <坐标> <槽位> <物品条件>`，以及对应的 `unless`。可使用 `container.*`、`hotbar.*`、`inventory.*`、`weapon.*`、`armor.*` 等槽位集合。它检查指定范围内是否存在匹配物品；命令停在 `if items` 条件末尾时，返回的是匹配物品的总件数，包括所选多个实体，而非匹配槽位数。
- 实体谓词新增 `slots`，用于把物品条件作用到指定槽位集合。一个集合内任一槽位匹配即可，但同时写出的多个集合条件必须分别满足。
- 新增 `player.cursor` 和 `player.crafting.0`～`player.crafting.3`。既有 `/item replace`、`/item modify` 可以读取、替换或修改玩家鼠标光标上的物品和随身 2×2 合成格。随身合成格指向玩家自己的物品栏合成格，不会转为当前工作台的 3×3 格子。

槽位名称按数字映射，旧有 `horse.chest` 与 `horse.0`～`horse.3` 在玩家上现在也分别指向光标和随身合成格。原先对玩家使用这些名称会找不到对应槽位的命令，现在可能真正修改这些位置。

普通 `/item` 的单槽参数仍只接受单个槽位，不会因为加入 `container.*` 检查能力就一次替换整组。

## 旗帜图案由数据包定义

24w09a 的旗帜图案集合由内置注册表固定；24w10a 从数据包的 `banner_pattern` 目录加载图案，图案记录资源 ID 与翻译键，并同步给客户端。数据包可以新增或覆盖图案定义，再通过图案标签控制织布机的可选项；物品的图案层还支持直接内嵌图案定义。

这项能力也作用于现有旗帜、盾牌和灾厄旗帜。原版队长旗帜会按当前世界注册的图案生成，若原版所需图案缺失，会跳过缺失层而不是在生成时直接要求该条目存在。依赖自定义图案、织布机可选项或队长旗帜完整组件的数据包因此可以改变实际匹配结果。

## 物品数据与命令的异常输入处理改变

- 存档物品的 `count` 缺失或无法解成正整数时，新版回退到 1；旧版只对缺失使用默认值，非法值会导致物品读取失败。例如用实体 NBT 创建 `count:0` 的石头掉落物，旧版会因空物品被移除，新版会成为一件石头。村民交易需求物品的数量也采用这一回退规则。
- 读取存档中的超长描述、烟花效果等受限列表时，新版返回截取到上限的部分结果。组件映射也接纳可恢复的部分值，所以可保留受损物品的其余数据；旧版会丢掉整个出错组件。命令直接填写超长组件仍会报告解析错误，不会把这个存档容错当成命令自动截断。
- 保存数据中使用两个写法不同、但解码后相同的组件键时，新版报告重复键并保留先读到的值，旧版构建映射可能直接抛出异常。物品命令参数中重复填写同一组件则改为明确拒绝；旧版后一次赋值可以覆盖前一次。
- 物品组件引用不存在的方块等标签时，缺失标签由直接抛出的查找异常改为可报告的解码错误，命令可以给出组件解析错误，存档组件映射可以走部分恢复路径。
- 文本组件与样式的 JSON 参数不再额外吞掉一个字符。旧版可能把紧跟 JSON 的一个多余字符当作已经读取的输入；新版保留该字符供命令解析器检查并报错。

附魔、药水内容、染色颜色和属性修饰符还新增简写形式，例如附魔可以直接填写等级映射，药水内容可以直接填写药水 ID，染色颜色可以直接填写整数；完整结构仍用于设置隐藏提示等选项。

## 发射音、效果粒子与界面悬停处理

- 玩家用弩发射时，旧版服务器的发射音广播排除了射手自身，新版把射手也包含在内。新版直接广播还绕过了生物的静音判断，因此带 `Silent` 的生物用弩发射时也会产生该发射音。
- 实体所有状态效果都设置为隐藏粒子时，旧版仍可能发出默认颜色的效果粒子；新版使用独立的“无粒子”状态，不再因默认颜色继续生成粒子。
- 已存档的药箭重新加载时，旧版恢复物品数据没有重新计算同步颜色，可能不再显示应有的颜色和粒子。新版通过带更新逻辑的设置方法恢复，使客户端重新得到颜色。
- 可滚动界面中的控件被裁剪到可视区域外时，旧版仍可能因鼠标坐标落在完整控件范围内而显示悬停提示；新版悬停判定同时检查裁剪区域，隐藏部分不再据此显示提示。
