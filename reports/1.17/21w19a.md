# Minecraft 21w19a 变更分析

- 上一个版本：21w18a
- 当前版本：21w19a

## 工具适用范围与采集等级改由方块标签控制

镐、斧、锹和锄现在通过数据包中的方块标签确定挖掘加速范围；最低工具等级也改由标签决定。默认数据基本保留原有工具分工，但有少量实际速度变化。

### 差异出现的场景

使用上述工具挖掘方块，或使用数据包修改方块所属标签。

### 版本变化

- 21w18a：挖掘加速由工具内部的固定名单和方块材质决定；镐的最低采集等级也使用固定名单。
- 21w19a：四类工具分别读取 `minecraft:mineable/axe`、`mineable/hoe`、`mineable/pickaxe`、`mineable/shovel`，并读取 `needs_stone_tool`、`needs_iron_tool`、`needs_diamond_tool` 检查最低等级。

默认数据下，镐现在能加速挖掘全部虫蚀方块，包括虫蚀深板岩；旧版这些方块不在镐的加速范围内。斧现在也能加速破坏盛开的杜鹃树叶，旧版斧没有这一加速，而锄原本已有的加速继续保留。镐失去加速的默认方块均为基岩、末地传送门框架、命令方块、结构方块、拼图方块等生存模式无法正常挖掘的方块。

### 实际影响

数据包可以直接改变已有方块适用哪类工具、需要哪一级工具采集，无须修改工具代码。最低等级标签不会自行让一个原本不要求正确工具的方块变成必须用工具才能掉落；实际掉落仍结合方块本身的采集要求判断。

## 重载世界后保留已扫描的末影龙战斗状态

末影龙战斗管理器现在保存“是否仍需扫描旧世界战斗状态”的标记，避免每次重载都重新根据退出传送门和现存末影龙推断战斗进度。

### 差异出现的场景

末地中心区域已经完成一次战斗状态扫描，此后保存并重载世界。首次末影龙战斗尚未结束，或玩家改造、拆除了退出传送门时，差异尤其明显。

### 版本变化

- 21w18a：每次加载战斗管理器都重新要求扫描。扫描时若没有激活的退出传送门，会把战斗视为尚未首次完成；检测到的现存末影龙会被移除，再由战斗逻辑重新建立末影龙。找不到退出传送门结构时，还会重建未激活的传送门结构。
- 21w19a：已完成扫描的状态随世界保存并恢复，重载后继续使用保存的战斗状态，不再执行上述重置扫描。

从旧版升级的存档没有这个新标记，首次加载仍会扫描一次；之后的保存才会保留扫描完成状态。

## 潜影盒开盖改为按箱盖移动距离推动实体

当实体与正在打开的潜影盒箱盖相交时，推动距离的计算方式发生变化。

- 21w18a：根据实体包围盒侵入箱盖本刻扫过区域的深度，再加 0.01 格，决定这一刻的推动距离。
- 21w19a：统一按箱盖本刻扫过区域沿开盖方向的厚度加 0.01 格推动，不再根据每个实体的侵入深度单独计算。

因此，实体原本已深深嵌入箱盖区域时，旧版可能在一刻内将其推出很远，新版只按这一刻的开盖进度推动。利用潜影盒精确移动实体的装置，其位移会随这个变化而改变；最终移动仍受周围方块碰撞限制。

## 避雷针移动时清理供电，带小数高度的雷电改正命中位置

### 差异出现的场景

活塞移动正在供电的避雷针；通过命令放置带 `powered=true` 状态的避雷针；或在带小数的 Y 坐标生成雷电。

### 版本变化

- 21w18a：避雷针被活塞移走时跳过原位置的邻居供电更新。供电状态被带到新位置、却没有对应的熄灭计划刻时，也不会主动复位，可能持续供电。
- 21w19a：移走供电避雷针时更新其原来供电的邻居；当避雷针作为新方块放置，若带有供电状态却没有待执行的计划刻，则立即清除该状态。活塞搬运供电状态不再形成永久供电的避雷针。

雷电对避雷针供电、对铜块除锈的检查位置也由“雷电所在方块的下一格”改为“雷电坐标向下微移后所在的方块”。例如雷电位于 Y=64.5，旧版检查 Y=63，新版检查 Y=64。通常位于整数高度的落雷仍检查落点下方那格。

## 蜜蜂可以催熟洞穴藤蔓末端的发光浆果

携带花蜜、已有有效蜂巢且尚未完成本轮作物催熟任务的蜜蜂，在自身下方一至两格遇到洞穴藤蔓末端时，旧版不改变其浆果状态；新版会直接使该末端长出发光浆果。藤蔓中间的茎段不在新增范围内。

这一步只让末端结果，不使藤蔓伸长，也不消耗骨粉。与原有农作物催熟分支不同，新版让藤蔓结果时没有增加蜜蜂本轮“已催熟作物”的计数，因此单靠催熟藤蔓不会耗尽原有的十次作物额度。

## 水浸发光地衣脱落与细雪融化会发出方块破坏振动

- 水浸发光地衣失去最后一个附着面时，21w18a 直接把它替换成水；21w19a 改走方块破坏流程，随后仍留下原有水源，同时产生破坏音效、粒子和方块破坏游戏事件。未水浸地衣原本就走破坏流程，不属于这个新增差异。
- 燃烧中的实体进入细雪并使其消失时，21w18a 直接把细雪换成空气；21w19a 使用不掉落物品的方块破坏流程，增加破坏音效及方块破坏游戏事件。

附近已有的幽匿感测体在满足正常振动传播条件时，可以对这两种新增的破坏事件作出反应，比较器读到的对应振动频率为 13。

## 大型垂滴叶只在实体着地后开始受压倾斜

实体处于未倾斜、未被红石信号锁定的大型垂滴叶上方时，21w18a 只检查实体脚部是否高于叶片的触发高度，尚在下落或跳跃中的实体也可能启动倾斜；21w19a 还要求实体已经着地，因此悬空经过不会启动这一受压过程。弹射物命中触发的直接倾斜另有入口，仍可发生。

此外，施骨粉令大型垂滴叶长高、或将小型垂滴叶长成大型时，新生成的叶片和茎会发送普通邻居更新；旧版放置这些方块时不发送这类更新。依赖相邻方块获知生长的装置会收到额外更新。

## 河豚会因美西螈接近而膨胀并蜇伤它

21w18a 将美西螈和其他水生生物一起排除在河豚的威胁判断与接触蜇伤范围之外。21w19a 单独把美西螈列入这两项判断：美西螈进入河豚周围两格扩张范围时可触发膨胀；接触已膨胀河豚的伤害范围时，会受到其伤害与中毒效果。装死中的美西螈也没有被这项非战斗检查排除。

## 生物的攻击目标与非战斗观察采用不同条件

- 生物已经选定某个目标后，如果目标被命令设为无敌，21w18a 的通用目标持续判断仍可能保留它；21w19a 会在通用攻击目标有效性检查中排除无敌目标。使用大脑行为的开始攻击、停止攻击判断也应用了这项限制。
- 凋灵侧头已经锁定美西螈，而美西螈开始装死时，21w18a 只在这一持续检查中特别排除无敌玩家，仍可能继续向美西螈射击；21w19a 会清除装死美西螈这个目标。
- 21w18a 的蝙蝠惊醒判断和海豚伴游判断还会检查该生物能否攻击目标玩家，因而排除创造模式玩家。21w19a 的这两种非战斗行为不再受攻击资格限制：创造模式玩家靠近也能惊醒蝙蝠，游泳时也能成为海豚伴游与给予海豚的恩惠的目标。旁观模式玩家仍被排除。
- 大脑的通用可见生物感知也改为非战斗检查，能将带有 `Invulnerable` 标记的生物纳入感知；旧版在这一阶段就将它们过滤掉。后续是否互动或攻击仍由具体行为判断。

## 水下洞穴与峡谷改变邻接空气和区块边缘处的填水

水下洞穴和水下峡谷共用的开凿逻辑，在 Y 大于 10、且该位置允许被开凿时，改变了填水位置与水流更新方式。只影响此后生成的区块。

- 21w18a：直接把正在开凿的这一格替换成水，不在这一步预约水更新。
- 21w19a：检查水平邻格；找到第一个空气邻格，或第一个越出当前区块的邻格时，改在该邻格写入水并预约水更新，不再在这次调用中把当前格替换成水。四个邻格均不满足条件时，才仍在当前格填水。

这会改变水下开凿与已有空气空间交界处的形状和水流。区块边缘还有一个具体后果：写入对象仍是当前正在生成的区块，而区块存储将水平坐标按区块内坐标取值。因此，越界邻格的写入与预约更新实际会落在当前区块的相对另一侧。例如从局部 Z=0 向北越界，会落到同区块局部 Z=15 的位置。这个分支会改变区块边缘附近的水分布，不能视为只给原有水源补一次更新。

## 服务器地址先解析原主机，再执行 SRV 重定向与屏蔽检查

### 差异出现的场景

多人服务器地址通过 DNS SRV 记录重定向到另一主机或端口；服务器使用虚拟主机路由；或服务器地址命中客户端加载的屏蔽列表。

### 版本变化

- 21w18a：默认端口地址在解析字符串时就被 SRV 结果替换，之后只解析替换后的目标。原域名即使没有可用的地址记录，只要 SRV 目标可解析，也可能连接成功；握手中发送的是替换后的目标主机与端口。
- 21w19a：先解析原主机，成功且通过屏蔽检查后才查询 SRV，再解析并检查重定向目标。仅有 SRV、原主机本身无法解析的配置会在重定向前失败。实际连接仍前往 SRV 目标，但登录及服务器列表查询握手保留玩家输入的原主机与端口，因此依赖握手地址路由的代理会收到不同信息。

命中已加载屏蔽列表的解析结果会被过滤，包括原地址和 SRV 目标；服务器列表查询及加入服务器都停止于解析阶段，加入时显示无法解析主机的失败界面。此检查读取解析后的主机名和 IP，具体屏蔽内容由加载的列表提供。

通过启动参数直接加入服务器也改用同一解析流程。Realms 则改为直接解析其下发的主机和端口，若下发地址使用默认端口并依赖旧解析阶段的 SRV 重定向，新版会改为直接连接原主机。

## 发送端提前拒绝超过 2 MiB 的数据包正文

21w18a 没有在数据包正文序列化后直接执行这项大小检查；压缩后的数据即使能发出，接收端也可能因解压长度过大而断开连接。21w19a 在压缩和发送前检查序列化正文，超过 2,097,152 字节就触发编码异常，检查值不包括数据包编号。

对于普通数据包，这会在发送端进入连接错误处理。对于允许跳过的数据包，编码异常会改为丢弃该包并保持连接，例如过大的聊天包、死亡消息包、实体或方块 NBT 查询回复。因而这些可跳过回复过大时，新版可能只是收不到该回复，旧版则可能把问题留到接收端并导致断线。

## 启动目标改为 Java 16，并增加初始分辨率回退

21w18a 的源码编译目标为 Java 8，21w19a 改为 Java 16。手动指定旧 Java 运行时的客户端或服务器启动配置需要相应更新，Java 8 无法运行这一编译目标的类文件。

客户端启动时，旧版直接按窗口尺寸创建主画面缓冲区；新版在尺寸超过显卡支持范围，或该尺寸分配发生显存不足时，会尝试使用 854×480 的缓冲区。回退成功后改为对应尺寸的窗口模式并显示提示；回退尺寸也无法分配时仍会启动失败。这一回退发生在主画面缓冲区的初始创建阶段。
