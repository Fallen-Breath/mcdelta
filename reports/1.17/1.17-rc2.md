# Minecraft 1.17-rc2 变更分析

- 上一个版本：1.17-rc1
- 当前版本：1.17-rc2

## 发射器生成实体出错时会清空所选槽位，并让世界继续运行

发射器使用刷怪蛋时，新版会接住实体生成过程抛出的异常。这个处理也改变了出错后刷怪蛋的消耗方式。

### 差异出现的场景

发射器选中刷怪蛋，而生物初始化、读取实体数据或加入世界的过程中抛出异常。例如，通过命令或外部编辑获得的刷怪蛋带有会让实体数据读取失败的 `EntityTag`。

### 版本变化

- 1.17-rc1：异常向方块计划刻的调用方传播，形成崩溃报告，无法正常完成这次世界刻。
- 1.17-rc2：记录错误后继续运行，并将选中槽位清空。该槽位即使存放了多枚刷怪蛋，也会整叠消失；其余槽位不受这次清空影响。

新版的异常分支仍会播放发射器的普通发射声音和粒子，但会跳过后面的“实体放置”游戏事件，因此不会由这次失败调用发出供幽匿感测体检测的实体放置信号。

## 巨型云杉只生成树叶时，跳过无法执行的灰化土地面装饰

巨型云杉生成后会在树底附近铺设灰化土。新版修复了没有新增树干、却仍然生成了树叶时，这个地面装饰步骤报错的问题。

### 差异出现的场景

生成巨型云杉的过程中，没有放置任何树干原木，也没有替换树干下方的泥土，但至少放置了一片树叶。一个能满足条件的场景是：预定树干位置已经全部被原木占据，树底四格原本就是普通泥土，树冠周围仍有可放置树叶的空间。

已有原木可以通过树木的空间检查，却不会被新的树干原木替换；普通泥土也不需要再次放置。因此，负责记录树干及其下方泥土位置的列表可以为空，而树叶列表非空，生成流程仍会进入地面装饰步骤。

### 版本变化

- 1.17-rc1：灰化土装饰直接读取空列表的第一个位置，抛出越界异常，中止生成流程。
- 1.17-rc2：发现该列表为空后，跳过这次灰化土装饰，继续完成生成流程；本次不会因此在树底周围新增灰化土。

## 玩家皮肤与自定义玩家头颅增加资源校验

- 加载皮肤时，1.17-rc2 只接受宽 64、高 32 或 64 像素的图像，其余尺寸会被丢弃，并保留默认皮肤。1.17-rc1 没有尺寸检查：足够大的非标准图像，例如 128×128，仍可进入皮肤显示流程；尺寸不足的图像，例如 32×64，则会在固定区域的像素处理过程中越界，并可能使客户端崩溃。新版同时将图像读取和处理的异常捕获范围从 I/O 异常扩大到普通异常。该变化也适用于使用皮肤资源的自定义玩家头颅。
- 皮肤来源检查随 Authlib 升级而收紧：1.17-rc1 允许的域名后缀为 `.minecraft.net` 和 `.mojang.com`；1.17-rc2 在此基础上拒绝主机名以 `education.minecraft.net` 或 `bugs.mojang.com` 结尾的地址。使用这些地址作为自定义皮肤来源的玩家头颅，新版不再下载该皮肤，改为默认玩家头颅外观。一份皮肤资料中只要有一个皮肤或披风地址命中阻止规则，整份纹理列表都会被拒绝。

## 原版资源初始化增加一次恢复尝试

当 Java 在取得游戏 JAR 的已有文件系统时，抛出“文件系统不存在”以外的普通异常，1.17-rc1 会让异常直接中断原版资源初始化；1.17-rc2 会尝试为该 JAR 新建文件系统。如果这一步成功，原版资源便可以继续初始化，避免此次异常导致游戏启动失败。这个恢复分支仅覆盖取得已有文件系统时的异常；新建文件系统本身仍可能失败。
