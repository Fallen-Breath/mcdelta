# Minecraft 1.17-pre2 变更分析

- 上一个版本：1.17-pre1
- 当前版本：1.17-pre2

## 史莱姆和岩浆怪恢复朝目标跳跃

史莱姆和岩浆怪通过追击行为面向攻击目标，并朝该方向跳跃。新版修正了追击行为的启动和维持条件，恢复这项引导机制。

### 差异出现的场景

附近的生存模式玩家或铁傀儡已经被选作攻击目标，且仍符合攻击条件。

### 版本变化

- 1.17-pre1：追击行为错误地排除可攻击的目标；个体虽然已有目标，仍不能通过这项行为正常转向并朝目标跳跃。
- 1.17-pre2：追击行为可以启动并维持，个体会转向目标、朝目标跳跃。能够造成接触伤害的个体还会进入攻击跳跃状态，将下一次起跳的等待时间除以 3；小史莱姆也会转向目标，但仍不能造成接触伤害。

依赖玩家或铁傀儡吸引史莱姆、岩浆怪进入收集区域的装置，因此恢复相应的引导效果。

代码出处：[1.17-pre1 · 旧版错误地排除可攻击目标](https://github.com/TISUnion/guardian/blob/c0104b15c89d1abc3516f8f7352727fda140a0e8/src/main/java/net/minecraft/world/entity/monster/Slime.java#L368)；[1.17-pre2 · 启动、维持追击及朝向目标](https://github.com/TISUnion/guardian/blob/b4eb5ceb1235451a51e007b361e47f01a92cf065/src/main/java/net/minecraft/world/entity/monster/Slime.java#L368)；[1.17-pre2 · 攻击状态缩短跳跃等待](https://github.com/TISUnion/guardian/blob/b4eb5ceb1235451a51e007b361e47f01a92cf065/src/main/java/net/minecraft/world/entity/monster/Slime.java#L475)。

## 攻击已点燃的 TNT 不再产生成功受击的附带效果

已点燃的 TNT 没有生命值，但旧版会把对它的伤害请求报告为成功，使攻击方继续执行命中后的处理。新版将这类实体的默认受击结果改为失败，也改变了箭击中下落方块后的表现。

### 差异出现的场景

玩家对已点燃的 TNT 进行带击退效果的近战攻击，或在满足横扫条件时用剑攻击它；另一种情况是普通、无穿透的箭击中已点燃的 TNT 或下落的方块。下落的方块本来就不能被玩家直接近战攻击，因此近战差异仅针对已点燃的 TNT。

### 版本变化

- 1.17-pre1：冲刺或击退附魔的近战攻击可以给 TNT 增加速度，满足条件的剑攻击可以据此对附近生物发动横扫；普通、无穿透的箭将 TNT 或下落方块视为成功命中的对象，随后被移除。
- 1.17-pre2：攻击 TNT 不再触发这次近战击退或横扫。箭击中上述两种实体后，以原速度的十分之一反向弹回；速度很低时，按箭原本的拾取规则转为掉落物。

## 地图增加 256 个计数标记的使用限制

新版限制玩家继续向标记密集的同一张地图添加旗帜标记，以及把该地图放入空的物品展示框。地图副本共用同一份地图数据，限制也随之共用；不同地图编号分别计算。

### 差异出现的场景

一张地图当前已经拥有至少 256 个需要计数的标记。普通玩法中，玩家位置标记、物品展示框标记和旗帜标记都会计入；地图外的玩家指示也计入。林地府邸、海底神殿和藏宝图的红叉等探索目标图标不计入。

### 版本变化

- 1.17-pre1：玩家仍可继续用地图右击旗帜添加标记，也可以继续把地图放进空展示框。
- 1.17-pre2：添加新旗帜标记失败；向空的普通物品展示框或荧光物品展示框放入该地图也会失败，手中地图不被消耗。达到上限时，仍可以再次右击内容未改变的已记录旗帜，移除对应标记；已有展示框中的地图也仍可旋转或取出。

### 实际影响

大规模展示同一地图、密集标记旗帜的用法会受到限制，其他玩家携带同一地图产生的位置标记也会占用这部分计数。

这项检查发生在上述两种玩家操作入口。旧存档中超过上限的地图不会在加载时被截断，玩家位置更新和物品 NBT 中的自定义标记也没有在添加时套用同一上限。因此，256 是继续执行这两种操作的门槛，地图实际持有的标记数仍可能超过它。

## 跨维度后的旧猪灵不能再次使用副手金锭完成以物易物

生物跨维度时，游戏先在目标维度创建并恢复一个副本，再移除出发维度中的旧对象。新版在移除旧对象时额外清空其双手和盔甲槽中的物品，影响同一次更新尚未结束时的物品处理。

### 差异出现的场景

成年猪灵副手拿着用于以物易物的金锭，在穿过下界传送门的同一次更新中，欣赏物品的倒计时恰好结束。传送发生在该次 AI 更新之前，目标维度的猪灵已经复制了副手金锭及相关状态。

### 版本变化

- 1.17-pre1：出发维度的旧猪灵仍持有金锭，接下来运行的 AI 可以完成一次以物易物并扔出物品；目标维度的猪灵仍保留那枚金锭，之后还可完成一次以物易物。
- 1.17-pre2：出发维度旧猪灵的副手已经清空，不满足继续处理副手物品的条件；目标维度的猪灵正常保留金锭。

利用传送时机让一枚金锭在两端重复触发以物易物的用法因此失效。这项清理针对旧对象的手持物品和盔甲，不能据此推及所有生物内部物品栏。

## 山羊能在和平难度冲撞其他生物

山羊通过攻击资格检查选择冲撞目标。新版将和平难度限制从目标本身移到攻击者的判断中，并允许山羊在和平难度选择非玩家目标。

### 差异出现的场景

和平难度下，山羊附近有其他非山羊生物，且该生物满足距离、可见性、世界边界等原有冲撞条件。

### 版本变化

- 1.17-pre1：通用目标检查受和平难度限制，山羊不能选择这些生物冲撞。
- 1.17-pre2：山羊可以选择符合条件的非玩家生物冲撞。因此，和平难度的围栏中，山羊与其他动物共处时也可能发生冲撞；玩家在和平难度仍不会成为冲撞目标。

代码出处：[1.17-pre1 · 旧版把和平难度限制放在目标资格中](https://github.com/TISUnion/guardian/blob/c0104b15c89d1abc3516f8f7352727fda140a0e8/src/main/java/net/minecraft/world/entity/LivingEntity.java#L843)；[1.17-pre2 · 新版把难度限制放在攻击者判断中](https://github.com/TISUnion/guardian/blob/b4eb5ceb1235451a51e007b361e47f01a92cf065/src/main/java/net/minecraft/world/entity/LivingEntity.java#L843)；[1.17-pre2 · 山羊对非玩家目标放行和平难度](https://github.com/TISUnion/guardian/blob/b4eb5ceb1235451a51e007b361e47f01a92cf065/src/main/java/net/minecraft/world/entity/animal/goat/Goat.java#L104)。

## 已有攻击目标也遵守攻击者的限制

生物维持已有攻击目标时，需要不断复查目标资格。新版让这项复查同时考虑攻击者自身的限制，驯服生物不能因此继续追击主人；中立生物判断愤怒对象时也采用相同的攻击资格检查。

### 差异出现的场景

一只狼正在追击某玩家，随后通过命令将狼的主人改为该玩家，且目标仍满足距离等其他维持条件。

### 版本变化

- 1.17-pre1：已有目标的复查只检查目标本身是否可以成为敌人，狼可以继续保留这个目标。
- 1.17-pre2：已有目标还须通过狼自身的攻击资格检查。由于驯服生物不能攻击主人，狼会结束这项目标行为。

## 竹子和滴水石锥的碰撞形状查询采用当前位置的偏移

竹子和滴水石锥会根据所在的横向坐标产生模型及形状偏移。新版为这两种方块关闭固定形状缓存，使原先使用该缓存的碰撞查询也按方块当前位置计算偏移。

### 差异出现的场景

船底仅擦到竹子或滴水石锥的边缘，需要根据接触区域计算地面摩擦；或箭在每次更新开始时，检查自身是否位于这两种方块的形状内部。差异发生在当前位置的偏移与坐标原点偏移不同、且判定点处于形状边缘的情况。

### 版本变化

- 1.17-pre1：这些查询复用在坐标原点计算的固定形状，接触或嵌入区域可能与方块当前位置的形状不符。
- 1.17-pre2：这些查询使用当前位置的形状，因此船底是否接触方块、箭是否位于形状内部的判定可能改变。

普通实体移动和射线碰撞原本就有直接按位置计算形状的路径；这里的差异针对原先使用固定缓存的查询。

## 下界化石按地形生成高度选择起始位置

下界化石先抽取一个高度，再向下寻找空气与可承托方块的交界。新版将抽取范围的顶部改为地形生成器的顶部，改变新生成化石的位置。

### 差异出现的场景

生成新的灵魂沙峡谷区块，使用原版下界设置：维度的建筑高度为 256 格，而地形生成器只生成 128 格高的地形。

### 版本变化

- 1.17-pre1：起始高度在 Y=32 至 Y=253 之间均匀抽取。抽到地形生成范围上方时，会从上方往下搜索，可能把化石的放置起点定在下界顶层之上。
- 1.17-pre2：起始高度在 Y=32 至 Y=125 之间均匀抽取，从地形生成范围内开始搜索，不再因为起点高于生成范围而落到顶层上方的界面。

相同种子的化石高度和能否找到合适落点都可能变化。既有区块中的化石保留原状。使用自定义生成高度的数据包时，化石的相对高度锚点同样改按生成器的最低高度和生成高度计算。

## 恶魂与大火球的 ExplosionPower 改为有符号字节

恶魂与大火球通过 `ExplosionPower` 保存爆炸威力。新版把这项 NBT 数据的读写类型从 32 位整数改为有符号字节，影响超出字节范围的自定义威力。

### 差异出现的场景

通过命令、数据包或已有存档，为恶魂或大火球设置超出 -128 至 127 范围的 `ExplosionPower`，随后加载实体数据。即使 NBT 仍以整数形式填写，也会在读取时发生类型转换。

### 版本变化

- 1.17-pre1：按 32 位整数读取并保存，`ExplosionPower:256` 保留威力 256，`ExplosionPower:128` 保留威力 128。

## 盛开的杜鹃树叶更换方块与物品 ID

盛开的杜鹃树叶的注册 ID 改为 `minecraft:flowering_azalea_leaves`。存档升级会迁移已有方块和物品的名称，命令与外部数据包则按当前注册 ID 解析。

### 差异出现的场景

加载包含盛开的杜鹃树叶的旧世界，或执行使用该方块、物品 ID 的命令及数据包内容，包括配方、战利品表、标签和方块匹配。

### 版本变化

- 1.17-pre1：方块与物品使用 `minecraft:azalea_leaves_flowers`，命令和数据包中的旧 ID 能对应到它们。
- 1.17-pre2：方块与物品改用 `minecraft:flowering_azalea_leaves`。旧存档中的已有方块与物品会经数据升级改名；外部数据包文件和命令中写死的旧 ID 不会被这项升级规则改写，需要使用新 ID 才能继续引用。

方块的掉落、树叶标签及可用锄快速挖掘等行为继续对应同一方块。

## 无法解析的方块实体 ID 不再中断加载

方块实体加载时需要先把 NBT 中的 `id` 解析为资源名称。新版为名称语法错误增加处理分支，跳过错误数据并继续加载。

### 差异出现的场景

已有区块或生成过程中的待加载方块实体包含不符合资源名称语法的 `id`，例如含大写字母的 `minecraft:Chest`。

### 版本变化

- 1.17-pre1：构造资源名称时抛出异常，打断该次加载。
- 1.17-pre2：记录错误并跳过这条方块实体数据，让其余加载过程继续。被跳过的数据不会恢复为有效方块实体，其中的容器内容或其他状态也不会因此恢复。

## 世界生成时忽略高度范围外的计划更新

尚在生成的区块会暂存方块和流体的计划更新。新版在写入这份列表前检查高度区段是否有效，避免越界请求中断生成。

### 差异出现的场景

世界生成过程要求为可建筑高度范围以外的位置安排方块或流体更新。

### 版本变化

- 1.17-pre1：直接用越界的区段编号访问数组，抛出异常并中断生成。
- 1.17-pre2：检查到区段不在有效范围内后忽略这次请求，生成过程可以继续；合法高度内的计划更新仍照常暂存。

这项变化针对生成阶段的暂存列表，正常运行区块的计划更新处理没有在此处改动。

## 硬件信息查询出错时不再阻断启动

系统报告会查询硬件信息，客户端和服务端启动时预先创建崩溃报告也会经过这一步。新版扩大了硬件查询错误的捕获范围。

- 1.17-pre2：也捕获这类错误，记录警告后继续，避免硬件查询的这次失败阻断启动或系统报告创建。

## CPU 查询初始化失败后仍可记录其他性能指标

客户端和独立服务端的性能记录会建立 CPU、堆内存和每刻耗时等采样器。新版单独处理 CPU 采样器创建失败，使其他指标仍可记录。

### 差异出现的场景

### 版本变化

- 1.17-pre2：跳过 CPU 指标，继续建立其他可用采样器，保留堆内存、每刻耗时等记录。

这项容错覆盖 CPU 采样器的创建阶段。

## 标题、动作栏与玩家列表更新统一在客户端主线程处理

服务器可以通过网络包更新标题、字幕、动作栏、标题显示时间和玩家列表页眉页脚。新版将这些更新统一交给客户端主线程，避免与画面状态更新并发执行。

### 差异出现的场景

### 版本变化

- 1.17-pre1：直接在网络线程修改这些界面状态，可能与客户端主线程正在进行的状态更新交错。
- 1.17-pre2：先把包加入客户端主线程队列，再处理界面更新；它们与其他采用相同队列的游戏包按接收顺序执行，显示状态的更新顺序因此更稳定。

`/title` 的命令语法和设定的时间参数保持不变。

## 服务器同步打开配方书时补齐界面初始化

配方书打开时需要建立搜索框、分类和配方页。新版将初始化放入设置打开状态的入口，使服务器同步打开与玩家点击按钮打开执行同样的准备工作。

### 差异出现的场景

- 1.17-pre1：服务器同步只切换可见状态，没有像点击按钮那样初始化部件，接下来的更新或绘制可能抛出空引用异常。
