# Minecraft 1.20.3-pre1 变更分析

- 上一个版本：23w46a
- 当前版本：1.20.3-pre1

## 爆炸合并方块掉落物时不再丢失超出的物品

爆炸会先收集被炸方块的掉落物，再把相同物品合并后生成物品实体。本次修复了合并过程中丢失物品的问题，直接影响 TNT 爆破采集装置的产量。

### 差异出现的场景

一次爆炸产生多个可以合并的同种掉落物，累计数量超过爆炸合并时采用的每组 16 个上限。这里比较的是掉落表已经产出的物品，不包括爆炸衰减规则本来就不产出的部分。

### 版本变化

- 23w46a：达到 16 个后，继续合入的物品可能被丢弃。例如，一次爆炸中 20 个方块分别产出 1 个完全相同、可堆叠至 64 个的物品，最终只生成含 16 个物品的一组掉落物。
- 1.20.3-pre1：先填充已有的一组，剩余物品继续寻找其他组，或另起一组。上述例子会生成 16 个和 4 个两组，保留全部 20 个物品。

## TNT矿车以及部分末地水晶爆炸恢复实体伤害

新版为没有显式伤害来源的爆炸补上默认爆炸伤害来源。这会改变一部分原先只有击退和方块破坏的爆炸。

### 差异出现的场景

TNT矿车通过引信结束、撞击或坠落引爆；或者末地水晶受到没有攻击者实体的非爆炸伤害后引爆，例如受到火焰伤害。比较对象是爆炸范围内本来可以受到爆炸伤害的玩家、生物或物品实体。

### 版本变化

- 23w46a：这些路径传入空伤害来源，爆炸会跳过实体受伤处理；方块破坏和击退仍可发生。
- 1.20.3-pre1：这些爆炸会按距离和遮挡计算爆炸伤害，可以伤害、杀死生物和玩家，也可以摧毁可受爆炸伤害的物品实体。

TNT矿车被燃烧的箭直接击中时，原本就显式提供伤害来源，因此已有爆炸伤害。普通 TNT、苦力怕等调用也已经提供默认伤害来源，本次差异不扩大到所有爆炸。

风弹另行明确禁用爆炸范围伤害，保持原有的爆风击退与方块触发效果；直接命中实体时的 1 点弹射物伤害仍然存在。

## 草的 ID 改为 short_grass，但旧草物品缺少迁移

原来 ID 为 `minecraft:grass` 的一格高草，其方块和物品都改为 `minecraft:short_grass`。本次存档升级只增加了方块名称转换，因此已经放置的草与储存起来的草物品会得到不同结果。

### 差异出现的场景

用 1.20.3-pre1 打开 23w46a 的存档，其中既有地面上的草，也有玩家物品栏、箱子等容器或掉落物中保存的 `minecraft:grass` 物品。

### 版本变化

- 23w46a：方块和物品均以 `minecraft:grass` 识别，保存后重新加载可以保留。
- 1.20.3-pre1：存档中的草方块名称会转换为 `minecraft:short_grass`，地面上的草继续存在；旧草物品的物品 ID 没有对应转换，加载时因找不到已删除的物品注册项而成为空物品，原有数量随之丢失。

新版重新剪下的草、高草剪下的草，以及村庄箱子新生成的草，都使用新物品 ID。原版村庄模板、植被生成、方块标签、绵羊吃草与堆肥等引用也同步改为新 ID，因此这些配置并未因重命名改变生成布局或交互规则。

### 实际影响

- 旧命令、函数、物品谓词和自定义掉落表等仍写 `minecraft:grass` 时，不会通过存档的方块转换自动得到更新；需要按各自的数据格式改用新 ID。
- 草的原版掉落表及其随机序列 ID 也从 `blocks/grass` 改成 `blocks/short_grass`。正常破坏草的种子掉落概率不变，但旧随机序列的进度不会作为新序列的进度继续使用，依赖固定序列预测种子掉落的用法会改变。

## 铁砧重命名框的编辑按键失效

在铁砧第一个输入槽放入物品、名称框处于可编辑状态时，23w46a 会把按键交给名称输入框处理；1.20.3-pre1 会直接把按键标记为已处理，省去了输入框实际处理按键的调用。

因此新版的 Backspace、Delete、左右方向键、Home、End，以及 Ctrl+A、Ctrl+C、Ctrl+V、Ctrl+X 等选择、复制、粘贴和删除操作均无法在该状态下正常执行。普通字符输入经由另一条字符事件路径，仍能输入；Esc 仍会关闭铁砧界面。鼠标选择文字后输入字符的替换操作也仍可使用。

## 旋风人在水中、漂浮或乘坐载具时继续射击

此项适用于启用 1.21 实验性内容的世界。

- 23w46a：射击行为要求旋风人落地；乘船、漂浮或处在水中导致不能落地、无法正常跳跃时，可能停止射击。
- 1.20.3-pre1：射击不再检查是否落地；当旋风人已经有攻击目标，且当前没有行走目标、跳跃目标或跳跃蓄力时，乘坐载具、在水中或具有漂浮效果会主动触发射击意图。射击仍受站立姿态、冷却、面向目标等条件限制，目标距离必须大于 2 格且小于 16 格。

旋风人还加入新的实体类型标签 `minecraft:can_turn_in_boats`。旧版乘船时会受到船的朝向限制；新版船不再强制旋转或限制该标签内乘客的朝向，旋风人可以转身瞄准船侧面和后方的目标。仅用船、水或漂浮效果限制其移动，因而不能再保证让它停止攻击。自定义数据包也可以把其他实体类型加入该标签，解除同样的船内朝向限制。

## 指定目标的计分重置实际删除服务端分数

执行 `/scoreboard players reset <目标> <计分项>` 时，23w46a 的底层删除方法只检查分数是否存在，未从服务端记录中删除。因此命令可以报告成功、客户端也可以收到移除显示的通知，但服务端查询和基于分数的命令判断仍能读到原来的分数。

1.20.3-pre1 改为实际移除该分数。重置后，查询会得到“没有分数”，依赖该计分项的分数匹配不再通过，之后需要创建分数的操作会重新建立记录；如果这就是目标最后一个计分项，目标还会从已跟踪的计分对象中移除。未指定计分项、一次重置目标所有分数的路径原本就会删除记录。

## 普通世界的“资深怪物猎人”不再要求击杀旋风人

- 23w46a：普通数据中的“资深怪物猎人”也包含旋风人，共要求 35 种生物。未启用 1.21 实验性内容的世界无法正常获得旋风人，因而不能通过正常击杀完成全部条件。
- 1.20.3-pre1：普通数据只要求原有的 34 种生物；启用 1.21 实验包时，实验包覆盖进度定义，把旋风人重新加入，继续要求 35 种。

“怪物猎人”的可选击杀种类也采用同样的普通版与实验版拆分；其击杀任意一种即可完成的规则不变。

## 服务器资源包可以按 UUID 叠加、替换和移除

### 差异出现的场景

服务器或代理在配置阶段或游玩阶段发送资源包请求，尤其是需要多个资源包共同生效、动态卸载部分资源，或者切回配置阶段的场景。原版 `server.properties` 本身仍只配置一个服务器资源包。

### 版本变化

- 23w46a：客户端只有一个服务器资源包位置；新包生效后替换原来的服务器包，协议没有按标识移除某个包的能力。游玩中重新进入配置阶段时，还会清除服务器资源包。
- 1.20.3-pre1：推送请求包含 UUID。不同 UUID 的包可以同时保留，相同 UUID 的新请求替换原包；移除请求可以指定 UUID，也可以一次移除全部包。进入重新配置阶段时继续保留资源包，真正断开连接时再清理。

这些包发生普通资源文件冲突时，本版本会保留已经选中的包的优先级，新加入的包插在已有固定顶部服务器包下面；同批首次加入的多个包按 UUID 字符串顺序插入，较小的 UUID 优先。因此发送一个不同 UUID 的包，并不等同于让它覆盖已经加载的包。

服务器配置新增 `resource-pack-id`：空值会从资源包 URL 生成稳定 UUID；填写有效 UUID 可以明确指定标识；填写无法解析的非空值时，该服务器资源包配置会被整体忽略。

## 服务器资源包的下载失败与缓存处理改变

- **下载与失败处理**：23w46a 下载未缓存的包时会切到下载界面，下载或应用失败后会移除服务器包并显示继续或断开的确认界面；失败恢复链还可能正常完成，从而回报“成功加载”。1.20.3-pre1 改用角落提示显示下载进度，失败时直接回报对应 UUID 的下载失败或重载失败，无效 URL 也有独立的 `INVALID_URL` 回报，不再弹出原来的继续确认界面。新添的不同 UUID 包下载失败时，未被替换或移除的已生效包可以继续保留；同次等待应用的其他新包可能被一并丢弃，并分别报告 `DISCARDED`。原版服务器强制资源包的断线检查仍只针对拒绝，因此不能把这些失败回报等同于必然被踢出。
- **同 URL 更新资源包**：23w46a 按 URL 建立缓存；URL 不变而 SHA-1 改变时，会先检查旧缓存并因不匹配而失败，删除后才有机会在下一次请求中重新下载。新版按 UUID 与内容 SHA-1 缓存，缺少所需哈希对应的有效缓存时立即下载，能在同一次请求中取得新内容。没有提供有效 SHA-1 时，旧版会直接复用同 URL 的缓存，新版则会重新请求下载，再按实际内容哈希保存，因此同 URL 的无哈希资源包也能随内容更新。
- **磁盘存储**：缓存目录由游戏目录下的 `server-resource-packs` 改为 `downloads/<UUID>/<内容哈希>`，并在 `downloads/log.json` 记录下载结果。旧目录中的缓存不会被新下载器直接复用；旧版只保留最近 10 个缓存文件的自动清理逻辑也随之移除。

## 文本框与暂停画面的操作修正

- 普通单行文本框粘贴包含辅助平面字符的文本时，23w46a 可能在长度上限处截断 UTF-16 代理对，留下半个字符；新版避免在代理对中间截断。Ctrl+Backspace、Ctrl+Delete 逐词删除时，新版直接使用算出的文字位置，修复前方含这类字符时把 UTF-16 长度当作字符数、从而删错范围的问题。
- 命令方块界面的“上一个输出”框虽然不可编辑，23w46a 也会拒绝其选择、复制等按键；新版允许不可编辑但可用且有焦点的文本框处理光标、选择和复制，并允许通过键盘焦点导航到这些框，方便复制完整输出。
- 未开放到局域网的单人世界暂停时，新版保存进入暂停瞬间的画面插值进度，恢复时再还原。旧版保存和还原的方向颠倒，暂停前后的实体画面可能跳动；此项改变的是显示插值。
- 载入单人世界时，旧版在内置服务器就绪后即继续建立本地连接；新版还等待客户端当前的资源重载遮罩结束，避免在资源仍在应用时进入连接流程。
- 没有副标题的系统提示，新版把标题在提示框内垂直居中显示。

## 数据包版本与开发环境命令

- 数据包格式从 25 升为 26，资源包格式从 21 升为 22；已有包的兼容版本声明需要与本版本对应。
- 在注册 GameTest 命令的开发环境中，`/test import` 与 `/test export` 改为把结构名作为完整资源位置解析。带命名空间的结构名可以指向对应命名空间；旧版强行使用 `minecraft` 命名空间，带冒号的名称会触发无效路径错误。SNBT 导入来源仍按传入字符串在测试结构目录下查找。
- 同样仅在开发环境中新增 `/serverpack push <url> [uuid] [hash]` 和 `/serverpack pop <uuid>`，向当前连接推送或移除指定包。此命令需要权限等级 2，普通发布运行环境不会注册它；发布环境要使用多包能力，需要能发送相应协议请求的服务器实现。
