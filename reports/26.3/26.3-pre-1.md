# Minecraft 26.3-pre-1 变更分析

- 上一个版本：`26.3-snapshot-10`
- 当前版本：`26.3-pre-1`

## 完全格挡不再击退防守者，也不再触发攻击者的格挡反应

盾牌完全挡住伤害时，新版跳过两处击退处理，其中一处还负责触发部分生物的特殊反应。

### 差异出现的场景

玩家正面举盾，或实体使用带有 `blocks_attacks` 组件的物品，把一次攻击的伤害全部挡住。

### 版本变化

- Snapshot 10：即使剩余伤害为 0，仍可能受到普通受伤击退；完全挡住生物的近战攻击时，还会调用攻击者的格挡反应。
- Pre-Release 1：完全挡住伤害后跳过普通受伤击退；近战格挡反应仅在挡住了一部分、仍有伤害穿过时触发。

### 实际影响

完全挡住成年疣猪兽或僵尸疣猪兽的近战攻击时，不再由格挡反应把防守者抛起。完全挡住劫掠兽攻击时，也不再进行原有的随机眩晕或强击退判定，因此不会通过这次格挡进入眩晕后的咆哮流程。依赖盾牌反复触发上述反应的装置和战斗方式会改变。

## 末影珍珠传送清除原有速度

### 差异出现的场景

玩家在下落、被击退、乘风或以其他方式具有速度时，被自己的末影珍珠传送；用数据指定非玩家实体为珍珠所有者时也适用。

### 版本变化

- Snapshot 10：玩家传送使用相对速度标志，非玩家实体显式携带原速度，因而传送后保留传送前的运动速度。
- Pre-Release 1：传送目标速度改为零，玩家也移除相对速度标志；传送后原有的水平和竖直速度都被清除。

重置摔落距离的处理仍然执行。变化影响落点之后的运动，例如用珍珠把高速运动延续到另一处的玩法。

代码出处：[`26.3-snapshot-10`：旧版玩家及非玩家传送参数](https://github.com/TISUnion/guardian/blob/d32d0d2013256fcc565adc600b345396e916932b/src/main/java/net/minecraft/world/entity/projectile/throwableitemprojectile/ThrownEnderpearl.java#L121)；[`26.3-pre-1`：新版清零速度的传送参数](https://github.com/TISUnion/guardian/blob/119354d4b26a2236915925ddfff9a3c83eaba499/src/main/java/net/minecraft/world/entity/projectile/throwableitemprojectile/ThrownEnderpearl.java#L120)。

## 上台阶时纳入上方实体的碰撞箱

实体尝试自动跨上障碍时，新版会把原运动范围上方、最大上台阶高度以内的实体碰撞箱一并收集。旧版只收集原运动范围内的实体，可能在抬高身体后穿入先前未被检测到的船、潜影贝等具有实体碰撞的对象。新版会据此限制上台阶的高度或阻止该次跨越。

这项变化针对会参与实体碰撞的对象；普通生物之间的推挤不能一概视为这种实体碰撞。

代码出处：[`26.3-snapshot-10`：旧版碰撞收集范围](https://github.com/TISUnion/guardian/blob/d32d0d2013256fcc565adc600b345396e916932b/src/main/java/net/minecraft/world/entity/Entity.java#L1180)；[`26.3-pre-1`：新版扩大收集范围及台阶尝试](https://github.com/TISUnion/guardian/blob/119354d4b26a2236915925ddfff9a3c83eaba499/src/main/java/net/minecraft/world/entity/Entity.java#L1180)；[`26.3-pre-1`：实体碰撞筛选](https://github.com/TISUnion/guardian/blob/119354d4b26a2236915925ddfff9a3c83eaba499/src/main/java/net/minecraft/world/level/EntityGetter.java#L54)。

## 末影人的传送支撑方块和投射物接触行为改变

- **传送落点**：在身体本身不接触液体、其他碰撞条件均通过时，旧版额外检查脚部所在方块是否含水；新版改为检查脚下一个方块。因此，脚下的含水方块也能使落点被拒绝，例如满足其余落点条件的含水树叶。使用含水方块限制末影人可选落点的范围随之扩大。
- **箭的接触**：箭碰到末影人，而末影人没有接受该次伤害时，旧版会反弹箭并恢复末影人接触前的着火时间；新版跳过这整段失败命中处理，箭继续原方向飞行。由于燃烧箭在伤害判定前点燃目标，新版也保留这次点燃产生的着火时间，后续可产生火焰伤害。
- **三叉戟的接触**：上述未造成伤害的接触，旧版仍反向减速三叉戟；新版不再反弹，也不播放实体命中声。三叉戟仍会被标记为已经命中，因而不会继续伤害沿途其他实体，忠诚返回条件也仍会生效。
- **其他无伤害接触**：三叉戟碰到除末影人之外的实体、但因无敌等原因没有造成伤害时，新版会播放命中声；旧版只在伤害成功时播放。

## 高炉和烟熏炉每份燃料的燃烧时间约减半

新版修正了默认燃料时长在整数计算路径中的倍率处理，高炉与烟熏炉重新点燃燃料时受到影响。

### 版本变化

- Snapshot 10：燃烧时间使用整数乘法逐项读取操作数，预期的 0.5 倍倍率先被四舍五入为 1。因此，同一燃料在高炉、烟熏炉中的燃烧时间与普通熔炉相同，同时加工速度仍为两倍。
- Pre-Release 1：以整数除以 2 计算高炉、烟熏炉燃烧时间，余数丢弃；加工速度仍为两倍。

| 燃料 | Snapshot 10 高炉/烟熏炉 | Pre-Release 1 高炉/烟熏炉 |
| --- | ---: | ---: |
| 煤炭、木炭 | 1600 游戏刻 | 800 游戏刻 |
| 羊毛地毯 | 67 游戏刻 | 33 游戏刻 |
| 干海带块 | 4001 游戏刻 | 2000 游戏刻 |
| 熔岩桶 | 20000 游戏刻 | 10000 游戏刻 |

### 实际影响

在原版连续加工、没有停机浪费燃料的条件下，一份煤炭在高炉或烟熏炉中可支持的加工数量由约 16 个回到 8 个。持续运行装置的供燃料速率需要相应提高，按熄火时间检测的电路也会提前触发。普通熔炉的默认燃烧时间不变。已点燃燃料保存的剩余时间不会被这次公式修改主动重算，差异出现在下一次读取燃料时长时。

## 自定义燃料会保留每次消耗产生的容器

这项变化主要影响通过数据组件赋予燃料用途的物品。

- 熔炉、高炉和烟熏炉消耗带合成剩余物的燃料时，旧版只在整叠燃料用尽后留下最后一份剩余物；新版每消耗一个燃料就产生一份。燃料槽尚有燃料时，剩余物作为掉落物出现在炉子位置；燃料耗尽时，剩余物留在燃料槽。
- 酿造台消耗带合成剩余物的自定义酿造燃料时，旧版直接消耗物品；新版同样在最后一份用完时把剩余物放回燃料槽，否则将其掉出。例如，把龙息设为酿造燃料后，消耗时现在能留下玻璃瓶。
- 从炉子下方抽取燃料槽物品的允许列表改为物品标签 `minecraft:furnace_fuel_bottom_takeable`。原版标签仍只有水桶与铁桶；数据包可扩展它，使自定义剩余物也能被下方漏斗抽走。

## 对方块使用物品也会应用使用冷却和使用剩余物

对带有 `use_cooldown` 或 `use_remainder` 的物品，成功执行物品本身的“对方块使用”动作后，新版会统一应用这两个组件；旧版此调用路径只增加使用统计，没有执行这层组件后处理。

例如，给骨粉添加使用冷却后，成功催熟作物现在也会进入冷却；给会被消耗的方块物品添加使用剩余物后，成功放置也能得到剩余物。最后一个物品被用尽时，剩余物可以直接替换手中物品；还有同类物品时，额外物品交给玩家物品栏或掉落处理。此处不包含方块本身先行接管交互、而没有调用物品使用逻辑的情况。

## 大型矿脉重新受到各自高度范围的硬性限制

在尚未生成的主世界地形中，铜矿脉现在只允许在 `0 ≤ Y < 50` 的位置生成，铁矿脉只允许在 `-60 ≤ Y < -8` 的位置生成。

Snapshot 10 对两种矿脉共用的噪声和边缘衰减进行判断，但没有在最后结果上强制限制各自的高度，因此在范围外仍有满足矿脉条件的位置。Pre-Release 1 增加最外层高度判断，范围外直接返回“无矿脉”，相应的矿石、粗矿块和伴生花岗岩或凝灰岩都不再由这条矿脉规则放置。已生成的区块不会因此重写。

## 探险地图会先排除生成地点所在的目标结构

生成探险地图时，如果 `skip_existing_chunks` 为真，且地图生成位置位于目标类型结构的整体包围盒内，新版会先把这个结构登记为已被引用，再搜索目的地。旧版直接搜索，当前结构尚未被引用时可能把地图指回原地。

因此，在目标结构内获得同类结构的地图时，新版会跳过自己所在的这一座，转向其他可搜索到的结构；如果没有其他符合条件的目标，地图生成会按原有的“找不到目标”路径返回。这个检查使用结构的整体包围盒，包含包围盒内不属于单独结构部件的空间。

## 旧世界未完成区块和多调色板结构的升级处理修正

- 对仍处于旧版 `noise`、`surface` 中间生成阶段的区块，或地下补生成目标状态涉及这些阶段的区块，升级时需要清除旧方块数据并重做地形。旧版在这一步保留 `blending_data`；新版同时移除它，避免在重做地形时继续使用旧的混合边界记录。已经完整生成的普通区块不走这条清理分支；已在 Snapshot 10 升级过的数据也不会因为本次修改重新执行旧的数据修复。
- 加载含 `palettes` 的旧结构模板时，新版把每个候选调色板内的方块状态纳入数据修复。旧版历史结构模式只声明单个 `palette`，候选调色板可能漏过方块名称、属性等升级，之后读入为错误或缺失的方块状态。新版使多种候选布局都接受对应版本的转换。
- 旧版结构 SNBT 的读取、输出也改为按模板 `DataVersion` 选择 `Name`/`Properties` 或 `id`/`properties`；旧数据转换为 SNBT 前先升级到当前数据版本，避免用当前字段名错误解释旧模板。

## 数值提供器拆分为整数与浮点数，改变数据包计算方式

旧的 `number_provider` 注册表由 `context_int_provider` 与 `context_float_provider` 取代。数量、等级、交易次数、燃料时长等读取整数提供器；概率、速度倍率、属性数值等读取浮点提供器。已有数据包需要把定义移到对应目录，并按使用方选择类型；常量以整数形式直接写入整数提供器，不再依靠通用浮点结果自动四舍五入。

### 版本变化

- `/compute` 与 `/data modify … compute` 的类型放到提供器前面，例如 `/compute default integer 5` 和 `/compute default float 0.5`。旧版的默认浮点形式没有 `float`，整数形式在提供器后写 `integer`。
- 旧 `sum`、`product` 等类型改用 `add`、`mul` 等名称，操作数列表由 `operands` 改为 `inputs`；新增减法、除法、取余、乘方、类型转换，以及浮点三角函数等运算。整数转浮点用 `from_int`，浮点转整数用 `from_float`；后者向零截断，例如 `-1.9` 得到 `-1`，不同于旧版通用整数读取的四舍五入。
- 记分板提供器现在直接返回整数，移除自身的 `scale` 字段并增加缺值时使用的 `fallback`。放缩需要显式组合运算；读取超过浮点精确整数范围的分数时，不再先转为浮点数而丢失低位。
- 一般游戏逻辑中，整数运算抛出算术异常、或浮点结果为 NaN/无穷大时，提供器读数回退为 0。`/compute` 采用严格读取，会报告失败；旧版没有这一层统一的结果检查。通过 `/data … compute` 读取则使用前述回退行为。
- 原有 `value_check` 谓词改为 `int_value_check`、`float_value_check`，范围字段从 `range` 改为 `test`。新版可以直接比较浮点范围；整数的精确值、上下界也可使用相应数值提供器。

例如，`add` 的整数结果超过 32 位范围时，普通读取可得到 0，而 `/compute` 报错；这会影响用计算结果驱动物品数量、燃料时长或命令执行结果的数据包。

村民交易定义的 `max_uses`、`xp`、`reputation_discount` 也由宽松可选字段改为普通可选字段。旧版遇到这些字段格式错误时可以忽略并采用默认值；新版会把它们作为定义解析错误处理。

## 方块状态提供器可独立定义，嵌套规则会继续寻找有效结果

原版花卉分布、洞穴藤蔓、红树胎生苗和树下土壤等定义被提取到新注册表，所用状态、权重与条件本身保持原有配置。

## 窗口、鼠标和 Realms 操作调整

- macOS 现在也提供独占全屏及其分辨率选项，并新增全屏时菜单栏可见性开关，默认关闭。旧版在 macOS 隐藏独占全屏设置。

## 渲染、音乐与异常处理的局部变化

- 溺尸抬手准备投掷三叉戟时，僵尸手臂动画不再覆盖投掷手势；游泳动画也改为在相应动画阶段应用。变化只涉及模型动作。
- `dappled_forest` 的背景音乐从繁花森林曲目组改为森林曲目组。
- 停止使用某个后处理效果，或离开世界画面时，新版释放该效果保留的渲染目标；下次重新启用时重新建立。旧版持续保留这些目标，因此自定义依赖持久纹理历史内容的后处理，重新启用后的画面可能不同。
- 渲染区域具有非零纵向起点时，新版正确按“起点加高度”判断裁剪矩形是否越界。旧版错误地只与高度比较，可能把实际合法的绘制作为异常中断。
- 顶点着色器要求的输入没有对应顶点缓冲元素时，新版给出着色器编译错误；旧版可能在读取缺失元素格式时抛出空指针异常。
- OpenGL 后端初始化现在核验实际取得的上下文至少为 3.3，并检查建立上下文后能否再创建窗口。旧版可能继续使用不满足条件的后端，在后续阶段失败。

## 调试启动参数可以关闭噪声坐标折返

同时设置 JVM 属性 `-DMC_DEBUG_ENABLED=true` 和 `-DMC_DEBUG_ENABLE_FARLANDS=true` 时，新版会跳过梯度噪声的坐标折返，直接用原坐标计算。Snapshot 10 没有后一开关，始终折返坐标。它可改变远处新生成地形的噪声结果；默认启动不启用这项行为，已有地形也不会重新生成。

## 从非玩家来源运行测试命令时避免坐标输出异常

测试命令准备输出玩家返回坐标时，新版先确认命令来源关联了玩家；旧版直接读取玩家视角和维度，非玩家来源可在这一输出步骤触发空指针异常。新版跳过这条玩家坐标提示，继续完成其余处理。

## 结构模板数据的可确认范围

`abandoned_camp` 的部分营地模板删除了若干放置坐标，并清理了同时保存战利品表和空 `Items` 列表的冗余数据；一些坐垫实体的 UUID 也随重存改变。

本次提供的两端结构 SNBT 中，这些模板的方块状态与调色板均被导出为 `minecraft:air`，不能据此可靠判断删去的坐标在实际游戏模板中原本是哪类方块，也不能把这些文本直接解释为营地在游戏里全部由空气组成。因此，此处不对具体营地外观、战利品容器是否增减作进一步结论。
