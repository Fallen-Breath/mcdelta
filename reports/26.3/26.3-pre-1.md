# Minecraft 26.3-pre-1 变更分析

- 上一个版本：`26.3-snapshot-10`
- 当前版本：`26.3-pre-1`

## 完全格挡不再击退防守者，也不再触发攻击者的格挡反应

盾牌完全挡住伤害时，新版跳过两处击退处理，其中一处还负责触发部分生物的特殊反应。

### 差异出现的场景

玩家正面举盾，或实体使用带有 `blocks_attacks` 组件的物品，把一次攻击的伤害全部挡住。

### 版本变化

- Snapshot 10：即使剩余伤害为 0，仍可能受到普通受伤击退；完全挡住生物的近战攻击时，还会调用攻击者的格挡反应。
- Pre-Release 1：完全挡住伤害后跳过普通受伤击退；近战格挡反应仅在挡住了一部分、仍有伤害穿过时触发。

### 实际影响

完全挡住成年疣猪兽或僵尸疣猪兽的近战攻击时，不再由格挡反应把防守者抛起。完全挡住劫掠兽攻击时，也不再进行原有的随机眩晕或强击退判定，因此不会通过这次格挡进入眩晕后的咆哮流程。依赖盾牌反复触发上述反应的装置和战斗方式会改变。

## 末影珍珠传送清除原有速度

末影珍珠把所有者送到落点时，新版同时清除传送前的运动速度，改变了珍珠传送后继续运动的方式。

### 差异出现的场景

玩家在下落、被击退、乘风或以其他方式具有速度时，被自己的末影珍珠传送；用数据指定非玩家实体为珍珠所有者时也适用。

### 版本变化

- Snapshot 10：玩家传送使用相对速度标志，非玩家实体显式携带原速度，因而传送后保留传送前的运动速度。
- Pre-Release 1：传送目标速度改为零，玩家也移除相对速度标志；传送后原有的水平和竖直速度都被清除。

两版都会重置摔落距离。本次变化影响落点之后的运动，用珍珠把高速运动延续到另一处的玩法不再保留原速度。

## 上台阶时纳入上方实体的碰撞箱

实体自动跨上障碍时，会重新计算抬高身体后的可行路径。新版扩大了这一步收集实体碰撞箱的范围。

### 差异出现的场景

实体尝试上台阶，原运动范围上方、最大上台阶高度以内有船、潜影贝等参与实体碰撞的对象，而其碰撞箱没有进入原运动范围。普通生物之间的推挤不能一概视为这里的实体碰撞。

### 版本变化

- Snapshot 10：只收集原运动范围内的实体碰撞箱，可能在抬高身体后穿入先前未被检测到的对象。
- Pre-Release 1：把上方最大上台阶高度以内的实体碰撞箱一并收集，据此限制上台阶高度或阻止该次跨越。

## 末影人的传送落点改查脚下方块是否含水

末影人的随机传送除检查身体的碰撞和液体接触外，还会单独排除含水方块。新版把这项额外检查从脚部所在方块移到脚下一个方块。

### 差异出现的场景

传送落点使末影人身体本身不接触液体、其他碰撞条件均通过，但脚下一个方块含水，例如符合其余落点条件的含水树叶。

### 版本变化

- Snapshot 10：额外检查脚部所在方块是否含水；脚下方块含水本身不会通过这项检查否决落点。
- Pre-Release 1：额外检查脚下一个方块是否含水，上述落点会被拒绝。用含水方块限制末影人落点时，受检查的位置随之改变。

## 未伤害末影人的箭和三叉戟不再反弹

投射物命中实体后的反弹等处理，现在可以由目标决定是否执行。末影人只在接受该次伤害后允许这些后处理。

### 差异出现的场景

箭或三叉戟接触末影人，但末影人没有接受该次伤害；使用燃烧箭时，还涉及伤害判定前施加的着火时间。

### 版本变化

- Snapshot 10：箭反弹，并恢复末影人接触前的着火时间；三叉戟即使没有造成伤害也会反向减速。
- Pre-Release 1：跳过箭的失败命中后处理，箭继续原方向飞行，燃烧箭造成的着火时间也会保留，后续可产生火焰伤害。三叉戟不再反弹，也不播放实体命中声。

新版三叉戟仍会被标记为已经命中，因而不会继续伤害沿途其他实体，忠诚返回条件也仍会生效。

## 高炉和烟熏炉每份燃料的燃烧时间约减半

高炉和烟熏炉的默认燃料时长应为普通熔炉的一半。新版修正整数计算路径中的倍率处理，使每份燃料的燃烧时间约减半。

### 差异出现的场景

使用原版默认燃料时长，高炉或烟熏炉消耗下一份燃料并重新点燃。已点燃燃料保存的剩余时间不会被这次公式修改主动重算。

### 版本变化

- Snapshot 10：燃烧时间使用整数乘法逐项读取操作数，0.5 倍倍率先被四舍五入为 1，因此同一燃料的燃烧时间与普通熔炉相同，加工速度仍为两倍。
- Pre-Release 1：以整数除以 2 计算燃烧时间，余数丢弃；加工速度仍为两倍。普通熔炉的默认燃烧时间不变。

| 燃料 | Snapshot 10 高炉/烟熏炉 | Pre-Release 1 高炉/烟熏炉 |
| --- | ---: | ---: |
| 煤炭、木炭 | 1600 游戏刻 | 800 游戏刻 |
| 羊毛地毯 | 67 游戏刻 | 33 游戏刻 |
| 干海带块 | 4001 游戏刻 | 2000 游戏刻 |
| 熔岩桶 | 20000 游戏刻 | 10000 游戏刻 |

### 实际影响

在原版连续加工、没有停机浪费燃料的条件下，一份煤炭在高炉或烟熏炉中可支持的加工数量由约 16 个回到 8 个。持续运行装置维持相同加工量所需的供燃料速率提高，按熄火时间检测的电路也会提前触发。

## 自定义燃料会保留每次消耗产生的剩余物

炉子和酿造台消耗燃料时，新版都会为每个被消耗的物品生成其合成剩余物。变化主要影响通过数据组件赋予燃料用途的物品。

### 差异出现的场景

熔炉、高炉、烟熏炉或酿造台消耗带合成剩余物的燃料，例如将龙息设为酿造燃料。

### 版本变化

- Snapshot 10：炉子只在整叠燃料用尽后留下最后一份剩余物；酿造台直接消耗燃料，不处理剩余物。
- Pre-Release 1：每消耗一个燃料都生成一份剩余物。燃料槽尚有燃料时，剩余物作为掉落物出现在方块位置；最后一份燃料用尽时，剩余物留在燃料槽。龙息作为酿造燃料时因此能够留下玻璃瓶。

## 数据包可扩展炉子下方漏斗能抽取的燃料槽物品

炉子允许从下方抽取哪些燃料槽物品，现在由物品标签控制，能适配自定义燃料留下的剩余物。

### 差异出现的场景

漏斗从熔炉、高炉或烟熏炉的下方抽取燃料槽物品，数据包希望允许抽走水桶、铁桶以外的自定义剩余物。

### 版本变化

- Snapshot 10：允许列表在代码中固定为水桶和铁桶，数据包不能通过标签扩展。
- Pre-Release 1：读取 `minecraft:furnace_fuel_bottom_takeable` 标签。原版标签仍只有水桶和铁桶；数据包加入其他物品后，下方漏斗也能抽走这些物品。

## 对方块使用物品也会应用使用冷却和使用剩余物

物品的使用冷却和使用剩余物组件，现在也会在成功执行物品本身的“对方块使用”动作后生效。

### 差异出现的场景

玩家使用带有 `use_cooldown` 或 `use_remainder` 的物品，且物品本身的对方块使用逻辑成功，例如用自定义骨粉催熟作物，或放置带使用剩余物的方块物品。方块本身先行接管交互、没有调用物品使用逻辑的情况不在此列。

### 版本变化

- Snapshot 10：这条调用路径只增加使用统计，没有执行统一的组件后处理，因此不会由这一步应用所设的使用冷却或返还使用剩余物。
- Pre-Release 1：成功操作后统一应用这两个组件：催熟作物能进入所设冷却，消耗方块物品进行放置也能得到所设剩余物。最后一个物品用尽时，剩余物可以直接替换手中物品；仍有同类物品时，额外物品交给玩家物品栏或掉落处理。

## 大型矿脉重新受到各自高度范围的硬性限制

大型铜矿脉和铁矿脉分别有自己的高度范围。新版在最终矿脉条件外增加高度判断，范围外直接判为无矿脉。

### 差异出现的场景

主世界生成尚未生成的地形，某位置位于铜矿脉的 `0 ≤ Y < 50` 或铁矿脉的 `-60 ≤ Y < -8` 以外，却能通过其余矿脉噪声条件。

### 版本变化

- Snapshot 10：检查共用噪声和边缘衰减，但没有在最终结果上强制限制各自高度，范围外仍可能放置矿脉材料。
- Pre-Release 1：范围外直接拒绝生成，相应的矿石、粗矿块和伴生花岗岩或凝灰岩都不再由这条矿脉规则放置。已生成区块不会因此重写。

## 数值提供器拆分整数与浮点计算并检查异常结果

原来的通用数值提供器拆分为整数和浮点数两类。数量、等级、交易次数和燃料时长等使用整数提供器，概率、速度倍率和属性数值等使用浮点提供器，整数计算不再统一经由浮点数。

### 差异出现的场景

数据包定义并引用数值提供器，计算结果用于物品数量、燃料时长等游戏参数；尤其是包含小数转换、整数溢出或非有限浮点结果的表达式。

### 版本变化

- Snapshot 10：定义放在 `number_provider`，通用整数读取会把浮点结果四舍五入。运算使用 `sum`、`product` 等类型及 `operands` 列表，没有新版统一的结果检查。
- Pre-Release 1：定义分到 `context_int_provider` 和 `context_float_provider`，按使用方选择类型；整数常量直接写整数。运算使用 `add`、`mul` 等名称及 `inputs` 列表，并增加减法、除法、取余、乘方、类型转换和浮点三角函数等。一般读取遇到算术异常或 NaN、无穷大时回退为 0。

整数转浮点使用 `from_int`，浮点转整数使用 `from_float`。后者向零截断，例如 `-1.9` 得到 `-1`，与旧版四舍五入不同。新版整数 `add` 超出 32 位范围时，一般读取回退为 0；用结果控制数量或时长的数据包会随之改变行为。

## 方块状态提供器可独立定义，嵌套规则会继续寻找有效结果

方块状态提供器为地物、树木、方块转换和相关附魔选择状态。新版允许独立定义和引用，并改变嵌套规则没有选出状态时的处理。

### 差异出现的场景

数据包定义方块状态提供器；特别是外层某条规则的条件满足，但它引用的内层规则既没有匹配项，也没有可用回退结果。

### 版本变化

- Snapshot 10：只能在使用位置内联完整提供器。外层首条条件满足后立即读取内层最终结果；内层没有匹配结果时通常返回当前位置已有方块，外层不再尝试后续规则。
- Pre-Release 1：可在 `worldgen/block_state_provider` 独立定义并按标识符引用。外层先读取内层的可选结果，内层没有结果时继续后续规则，最后才尝试外层回退提供器，因此可能执行后续工具转换或地物放置。

类型名称也缩短，例如 `simple_state_provider` 改为 `simple`、`weighted_state_provider` 改为 `weighted`；固定状态可直接写成含 `id`、`properties` 的状态对象。原版花卉分布、洞穴藤蔓、红树胎生苗和树下土壤等定义被提取到新注册表，其状态、权重和条件保持原有配置。
