# Minecraft 26.3-snapshot-3 变更分析

- 上一个版本：`26.3-snapshot-2`
- 当前版本：`26.3-snapshot-3`

## 铜门刮锈和除蜡不再被另一半门还原

铜门的上下两半会通过邻居更新同步状态。新版调整斧的变换顺序，使另一半尚未变化的门不再阻止刮锈或除蜡。

### 差异出现的场景

对有氧化层或涂蜡的铜门任一半使用斧，且满足相应刮锈或除蜡条件。

### 版本变化

- Snapshot 2：先根据邻接方块修正变换后的门。另一半仍是原来的铜门，会把目标状态改回原状，操作消耗耐久却没有完成变换。
- Snapshot 3：这两种变换跳过预先修正，先改变点击的半扇门，再由门的联动更新改变另一半，正常完成刮锈或除蜡。

代码出处：[Snapshot 2 · 旧版先修正目标状态](https://github.com/TISUnion/guardian/blob/01acfd6891342e7e76f0ceca05f9a21fed03afca/src/main/java/net/minecraft/core/component/BlockTransformer.java#L68)；[Snapshot 3 · 新版铜门变换配置](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/item/component/BlockTransformerMappings.java#L111)；[Snapshot 3 · 另一半门同步状态](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/level/block/DoorBlock.java#L94)。

## 挖掘疲劳 III 的挖掘速度提高到原来的十倍

挖掘疲劳通过倍率降低玩家的挖掘速度。新版统一为每升一级再乘 `0.3`，改变了 III 级及更高等级的效果。

### 差异出现的场景

玩家受到挖掘疲劳，使用相同工具、在相同挖掘条件下破坏同一种方块；远古守卫者施加的 III 级效果也在此范围内。

### 版本变化

- Snapshot 2：I、II、III、IV 及以上的倍率分别为 `0.3`、`0.09`、`0.0027`、`0.00081`；IV 之后不再降低。
- Snapshot 3：I、II 不变，III 为 `0.027`，IV 为 `0.0081`，都是对应旧版倍率的十倍；V 为 `0.00243`，VI 为 `0.000729`，更高等级继续递减。

这里比较的是挖掘速度倍率。破坏方块所需刻数还取决于工具、方块硬度及其他挖掘条件。

代码出处：[Snapshot 2 · 旧版倍率](https://github.com/TISUnion/guardian/blob/01acfd6891342e7e76f0ceca05f9a21fed03afca/src/main/java/net/minecraft/world/entity/player/Player.java#L599)；[Snapshot 3 · 新版逐级倍率](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/entity/player/Player.java#L601)。

## 静止实体不再因一个重力步长反复弹起

实体碰撞反弹地面时，会根据向下速度判断是否反弹。新版将速度恰好等于有效重力的情况归入不反弹。

### 差异出现的场景

实体已落稳，随后仅因重力产生一个步长的向下运动，并再次碰到可反弹的地面。

### 版本变化

- Snapshot 2：向下速度等于有效重力时仍允许计算反弹，实体可能反复微小弹起，并触发相应反弹振动。
- Snapshot 3：这一等值情况不再反弹，实体可以保持停稳；依赖这种微小反弹的装置和振动检测失去对应事件。较大下落速度的反弹仍按原有条件处理。

代码出处：[Snapshot 2 · 旧版等值仍可反弹](https://github.com/TISUnion/guardian/blob/01acfd6891342e7e76f0ceca05f9a21fed03afca/src/main/java/net/minecraft/world/entity/Entity.java#L825)；[Snapshot 3 · 新版等值排除](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/entity/Entity.java#L837)；[Snapshot 3 · 反弹振动](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/entity/Entity.java#L861)。

## 酿造台按配方接受物品，默认不再接收玻璃瓶

酿造从固定转换表改为 `minecraft:brewing` 配方。配方既决定酿造产物，也决定酿造台各槽位接受哪些物品，原版常规药水路线保留。

### 差异出现的场景

玩家或漏斗向酿造台下方三个槽位放入玻璃瓶，或数据包改变酿造输入、材料和产物。

### 版本变化

- Snapshot 2：药水槽接受药水及玻璃瓶；酿造路线来自固定转换列表，不能直接通过酿造配方增删。
- Snapshot 3：槽位按配方中出现的输入物品判断能否接收。默认配方不含玻璃瓶，药水槽不再接收玻璃瓶；数据包可添加、移除或修改酿造配方。

槽位接收某类物品，只表示该物品出现在配方输入中；实际开始酿造还要匹配药水内容和材料。

代码出处：[Snapshot 2 · 旧版药水槽接受玻璃瓶](https://github.com/TISUnion/guardian/blob/01acfd6891342e7e76f0ceca05f9a21fed03afca/src/main/java/net/minecraft/world/inventory/BrewingStandMenu.java#L135)；[Snapshot 3 · 新版槽位来自配方](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/inventory/BrewingStandMenu.java#L48)；[Snapshot 3 · 配方结构](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/item/crafting/BrewingRecipe.java#L12)。

## 幸运药水和无基础类型药水不再使用通用容器转换

新版为具体药水类型分别生成普通、喷溅和滞留容器之间的转换配方，取消旧版对药水容器的通用转换路径。

### 差异出现的场景

在酿造台中用火药或龙息处理幸运药水、数据包新增的药水类型，或只有自定义效果而没有基础药水类型的药水。

### 版本变化

- Snapshot 2：幸运药水可用火药转为喷溅型，再用龙息转为滞留型。只有自定义效果而没有基础类型的药水也会启动这两类容器转换并消耗材料，但瓶子保持原样。
- Snapshot 3：默认容器配方只覆盖酿造路线中出现的药水，没有幸运药水。幸运药水仍可放入药水槽，但这两步转换不发生；新增药水类型也需要相应转换配方。没有匹配配方的自定义药水不会启动酿造。

代码出处：[Snapshot 2 · 旧版通用容器转换](https://github.com/TISUnion/guardian/blob/01acfd6891342e7e76f0ceca05f9a21fed03afca/src/main/java/net/minecraft/world/item/alchemy/PotionBrewing.java#L79)；[Snapshot 3 · 新版按药水逐一生成容器配方](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/data/recipes/BrewingProvider.java#L48)；[Snapshot 3 · 配方结构](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/item/crafting/BrewingRecipe.java#L12)。

## 酿造消耗最后一瓶龙息也会返还玻璃瓶

酿造材料用完时应返还对应容器。新版将容器读取提前到扣除材料之前，修复最后一瓶龙息的返还。

### 差异出现的场景

酿造台完成一次需要龙息的酿造，材料槽中的龙息恰好被消耗完。

### 版本变化

- Snapshot 2：先扣除材料，再从空堆叠读取返还物；空堆叠被视为空气，漏掉玻璃瓶。
- Snapshot 3：先读取材料的返还物再扣除材料，最后一瓶龙息也会留下玻璃瓶。

代码出处：[Snapshot 2 · 旧版读取返还物的顺序](https://github.com/TISUnion/guardian/blob/01acfd6891342e7e76f0ceca05f9a21fed03afca/src/main/java/net/minecraft/world/level/block/entity/BrewingStandBlockEntity.java#L182)；[Snapshot 3 · 返还容器先于消耗](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/level/block/entity/BrewingStandBlockEntity.java#L197)。

## 药水内容谓词改为对象并支持效果条件

- 数据包定义药水内容谓词时，Snapshot 2 直接使用基础药水类型集合；Snapshot 3 改为含可选 `potions`、`effects` 的对象，可分别限制基础药水和效果。沿用旧形状会解码失败，影响所在资源的加载。

## 队伍的友军伤害规则扩展到接触伤害和爆炸

关闭队伍友军伤害后，新版让多种接触攻击与爆炸伤害也检查同队关系。

### 差异出现的场景

伤害来源和受击实体属于同一队伍，且队伍关闭了友军伤害；涉及河豚、史莱姆或岩浆怪、末影龙，以及有直接来源实体的爆炸。

### 版本变化

- Snapshot 2：这些伤害路径不检查上述友军伤害设置，仍可能伤害同队目标。
- Snapshot 3：河豚不再刺伤同队生物或玩家，也不会由该次刺伤附加中毒；史莱姆和岩浆怪不再接触攻击同队玩家或铁傀儡；末影龙的接触和翅膀攻击不再伤害同队生物；爆炸直接来源实体不再对同队目标造成爆炸伤害。

末影龙翅膀的推开运动，以及爆炸的击退和方块破坏仍按各自规则处理。爆炸检查的是直接来源实体本身的队伍，例如爬行者或已点燃的 TNT；不会自动改查点燃者的队伍。

## 非生物实体也会读取 Team 数据

实体载入时的队伍读取由生物移到通用实体层，使非生物实体也能通过自身数据加入队伍。

### 差异出现的场景

召唤或载入已点燃的 TNT、掉落物等非生物实体，其 `Team` 数据指定一个已经存在的队伍。

### 版本变化

- Snapshot 2：只有生物读取这一数据；非生物实体不会因此加入队伍。
- Snapshot 3：所有实体均读取这一数据，非生物实体也可以加入指定队伍；例如带队伍的 TNT 可参与新版爆炸友军伤害检查。

代码出处：[Snapshot 2 · 旧版仅生物读取队伍](https://github.com/TISUnion/guardian/blob/01acfd6891342e7e76f0ceca05f9a21fed03afca/src/main/java/net/minecraft/world/entity/LivingEntity.java#L816)；[Snapshot 3 · 新版所有实体读取队伍](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/entity/Entity.java#L2212)。

## 溺尸恢复远距离近战追击，并能向近处不可达目标投掷三叉戟

溺尸按是否应当投掷三叉戟来切换近战和远程目标。新版修正无三叉戟时的追击，并扩大近处目标的远程攻击条件。

### 差异出现的场景

无三叉戟的溺尸追击距离至少 3 格的目标；或持有三叉戟的溺尸面对不足 3 格、超出近战范围，且通向目标所在方块的路径无法到达的目标。

### 版本变化

- Snapshot 2：距离至少 3 格就停用近战追击，而远程攻击还要求持有三叉戟，无三叉戟的溺尸因此无法继续追近。目标不足 3 格时也不会因路径不可达改为远程攻击。
- Snapshot 3：只有确实应当投掷时才停用近战，无三叉戟的溺尸可继续追近远处目标。持三叉戟时，距离至少 3 格仍可投掷；上述近处且路径不可达的目标也可触发投掷。

代码出处：[Snapshot 2 · 旧版近战距离限制](https://github.com/TISUnion/guardian/blob/01acfd6891342e7e76f0ceca05f9a21fed03afca/src/main/java/net/minecraft/world/entity/monster/zombie/Drowned.java#L345)；[Snapshot 3 · 新版分流条件](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/entity/monster/zombie/Drowned.java#L282)；[Snapshot 3 · 3 格距离条件](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/entity/monster/zombie/Zombie.java#L158)。

## 高度边界附近的范围扫描可能抛出数组越界异常

多种邻近方块检测改为直接扫描区块段。新版没有裁剪超出建筑高度的纵向范围，会用越界高度计算区块段数组下标。

### 差异出现的场景

扫描跨出维度最小或最大建筑高度，且没有在扫描到越界区块段前提前返回。例如主世界 `y=319` 的无水耕地进行湿润检测，或在 `y=-64` 的下界岩上使用骨粉。

### 版本变化

- Snapshot 2：逐方块读取范围，建筑高度之外的位置被当作空气处理，可以正常得到检测结果。
- Snapshot 3：耕地会扫描到 `y=320`，下界岩会检查到 `y=-65`，相应区块段下标超过数组长度或为负数，抛出数组越界异常。无水耕地的随机刻等服务器刻路径可能使服务器崩溃；骨粉目标检查也可能首先使客户端崩溃。

同一缺少边界裁剪的扫描还用于蘑菇、藤蔓、眼眸花、蜂巢、树苗的邻近方块检测，以及部分实体空间检查。是否抛出异常取决于实际扫描范围和是否提前找到结果。

代码出处：[Snapshot 3 · 新区块段扫描](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/level/BlockScanUtils.java#L48)；[Snapshot 3 · 直接访问数组](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/level/chunk/ChunkAccess.java#L166)；[Snapshot 3 · 耕地向上多检查一层](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/level/block/FarmlandBlock.java#L133)；[Snapshot 3 · 下界岩向下多检查一层](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/level/block/NetherrackBlock.java#L23)；[Snapshot 2 · 旧版建筑高度外读取](https://github.com/TISUnion/guardian/blob/01acfd6891342e7e76f0ceca05f9a21fed03afca/src/main/java/net/minecraft/world/level/Level.java#L357)。

## 液体检查会计入碰撞箱整数边界外紧贴的方块

碰撞箱液体检查改用范围扫描，最大边界恰好为整数时会额外计入边界外紧贴的一格。

### 差异出现的场景

碰撞箱最大 X、Y 或 Z 边界恰好是整数，该面外侧紧贴水或熔岩；当前位置用于生物生成空间、随机传送落点或实体自由移动空间检查。

### 版本变化

- Snapshot 2：最大边界采用不包含上界的循环，不计入外侧紧贴的方块。满足其他条件时，该位置可以通过检查。
- Snapshot 3：计入最大坐标所在整格，即使液体在碰撞箱之外也会判为接触液体，可能拒绝旧版允许的位置。

代码出处：[Snapshot 2 · 旧版最大边界采用小于上界的循环](https://github.com/TISUnion/guardian/blob/01acfd6891342e7e76f0ceca05f9a21fed03afca/src/main/java/net/minecraft/world/level/LevelReader.java#L142)；[Snapshot 3 · 新版最大坐标所在整格也包含](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/level/BlockScanUtils.java#L113)；[Snapshot 3 · 液体检查改用扫描](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/level/LevelReader.java#L140)；[Snapshot 3 · 随机传送检查](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/entity/LivingEntity.java#L3694)；[Snapshot 3 · 生成空间检查](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/entity/Mob.java#L825)。

## 堆肥改为读取物品组件与可重载的层数规则

堆肥桶从物品种类固定表改为读取 `minecraft:compostable` 组件，组件引用 `number_provider` 的加层规则。

### 差异出现的场景

玩家、漏斗或生物向堆肥桶投料；数据包或自定义物品修改堆肥组件和加层规则，或组件引用不存在的规则。

### 版本变化

## Straw Bed 提供不改变重生点的一次性睡眠

新版新增 Straw Bed，用一次性床完成临时休息，同时保留原有重生点。三块干草块可以合成四张。

### 差异出现的场景

玩家需要跳过主世界夜晚或重置距上次休息时间，同时希望保留重生点；或尝试在下界、末地使用床。

### 版本变化

## 新生成海带更短，浅水和底部条件也有变化

海带生成从专用逻辑改为方块柱地物，改变生成高度、靠近水面的留空要求和底部存活检查。

### 差异出现的场景

### 版本变化

- Snapshot 2：空间充足时生成 2～11 格高，水浅时可缩短，顶端至少留一格水。每层放置前检查海带能否存活，不能在岩浆块上放置海带。

## 服务器接入新连接时避免与旧连接关闭互相等待

新版将网络线程收到的新连接先放入待接入队列，再由服务器主线程转入活动列表，避免接入与关闭共用列表锁导致互等。

### 差异出现的场景

同一个网络线程正在接入新连接；服务器主线程持有连接列表锁更新旧连接，并因登录超时等原因同步等待该网络线程关闭旧连接。

### 版本变化

- Snapshot 2：网络线程接入时直接获取连接列表锁，可能等主线程释放锁；主线程又等网络线程完成关闭，形成互相等待，使服务器停止推进。
- Snapshot 3：网络线程入队无需获取活动列表锁，能够继续完成旧连接关闭；主线程在连接刻开始时转移新连接，避免上述锁等待链造成全服停滞。

## 错误的配方、进度和战利品数据会使整次加载失败

配方、进度、战利品表、物品修饰器、谓词及槽位来源改为统一注册表加载。新版将加载时的解析、解码错误视为整次加载失败。

### 差异出现的场景

启用的数据包在上述资源中含 JSON 解析或数据解码错误，并在世界启动或 `/reload` 时加载。

### 版本变化

- Snapshot 2：通常记录错误并跳过坏文件，继续加载其他有效内容。
- Snapshot 3：收集到解码错误后，整次加载失败。世界启动时可能无法正常打开；运行中的 `/reload` 报告失败并保留上一次成功加载的资源。

这一变化针对加载和解码错误，不涵盖所有运行时条件不满足或校验警告。

## 杨树树叶和红灌木改用专属声音

新版为杨树树叶和红灌木调整声音类型，改变玩家破坏、放置和踩踏等动作的听觉反馈。

### 差异出现的场景

玩家或实体破坏、放置、击打、踩踏杨树树叶或红灌木，或落到这些方块上。

### 版本变化

- Snapshot 2：杨树树叶使用落叶堆声音；红灌木使用原有声音组。
- Snapshot 3：杨树树叶改用专属破坏、踩踏、跌落、放置和击打声音；红灌木改用专属破坏、放置声音，其踩踏、击打和跌落声音设为空。

代码出处：[Snapshot 3 · 杨树树叶声音](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/level/block/Blocks.java#L683)；[Snapshot 3 · 红灌木声音](https://github.com/TISUnion/guardian/blob/64b28cf4946545560a6d214027feaa0f96aed0dd/src/main/java/net/minecraft/world/level/block/SoundType.java#L871)；[Snapshot 2 · 旧版杨树树叶配置](https://github.com/TISUnion/guardian/blob/01acfd6891342e7e76f0ceca05f9a21fed03afca/src/main/java/net/minecraft/world/level/block/Blocks.java#L675)；[Snapshot 2 · 旧版红灌木配置](https://github.com/TISUnion/guardian/blob/01acfd6891342e7e76f0ceca05f9a21fed03afca/src/main/java/net/minecraft/world/level/block/Blocks.java#L856)。
