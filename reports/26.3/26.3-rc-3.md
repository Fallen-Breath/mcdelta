# Minecraft 26.3-rc-3 变更分析

- 上一个版本：`26.3-rc-2`
- 当前版本：`26.3-rc-3`

## 攻击其他玩家时，本机执行命中后的减速与反馈

客户端会先处理本机发动的普通近战攻击，再等待服务器同步结果。新版把其他玩家在本机的受击判定改为成功，使攻击者继续执行命中后的减速和本地粒子反馈。

### 差异出现的场景

在多人游戏中，本机选中另一名玩家并发动能够进入伤害计算的普通近战攻击。移动差异最明显的场景是攻击充能超过 90% 时发动冲刺攻击；粒子差异则出现在满足暴击条件的攻击中。

### 版本变化

- 26.3-rc-2：其他玩家在本机的受击判定返回失败，攻击者跳过命中后的处理。上述冲刺攻击不会立即在本机执行自身减速和结束冲刺；暴击粒子依赖服务器发来的攻击动画消息。
- 26.3-rc-3：其他玩家在本机的受击判定返回成功，攻击者继续执行命中后的处理。上述冲刺攻击会立即把攻击者已有的水平速度乘以 0.6，并结束冲刺；满足暴击条件时，本机会立即额外生成一轮暴击粒子。

因此，连续冲刺攻击时，本机的移动和重新进入冲刺的时机会发生变化。这些处理由本机提前执行，实际扣血、无敌及服务器的玩家间伤害限制仍由服务器判定；本地出现命中反馈并不表示服务器已经接受这次伤害。

## 箭碰到其他玩家时，本机按命中处理

其他玩家的客户端受击判定也用于箭的碰撞处理。新版改变了箭在本机碰到其他玩家后、服务器结果同步前的短暂表现。

### 差异出现的场景

多人游戏中，客户端自行判定一支箭与另一名玩家相撞，并进入受击处理。这里比较的是这次本地碰撞到服务器结果同步之间的表现。

### 版本变化

- 26.3-rc-2：其他玩家在本机的受击判定返回失败，箭进入受击失败分支并反向弹回。
- 26.3-rc-3：其他玩家在本机的受击判定返回成功，箭进入命中分支。没有穿透能力的箭立即在本机消失，有穿透能力的箭按穿透流程继续处理。

实际伤害和服务器上的箭仍由服务器处理，本地命中分支本身不代表服务器已经确认命中。

## 编辑服务器时，服务器资源包选项能够保存

已保存服务器的资源包选项决定连接时如何接受服务器资源包。新版修复了编辑服务器后未保存这一选项的问题，使下次连接采用编辑后的选择。

### 差异出现的场景

在多人游戏列表中选中已经保存的服务器，进入编辑界面，更改“服务器资源包”的“启用”“禁用”或“询问”选项，点击“完成”，随后连接该服务器并收到资源包请求。

### 版本变化

- 26.3-rc-2：编辑完成时只写回名称和地址，资源包选项保留修改前的值。下次连接仍使用旧选择；例如原来设为“询问”，改为“启用”后仍会询问。
- 26.3-rc-3：编辑完成时同时写回资源包选项，下次连接使用新选择。原来设为“询问”的服务器改为“启用”后会自动接受资源包；改为“禁用”后会自动拒绝可选资源包，强制资源包仍会要求确认。

## OpenGL 启动时把垂直同步设置应用到游戏窗口

OpenGL 通过设置交换间隔应用垂直同步选项。新版在启动配置时先切换到游戏窗口，再设置交换间隔，修正设置可能被应用到初始化用隐藏窗口的问题。

### 差异出现的场景

使用 OpenGL 渲染器启动游戏，且窗口系统和显卡驱动使交换间隔按窗口分别生效。在这种环境中，启动时选择的垂直同步状态可能与游戏窗口的实际呈现行为不一致。

### 版本变化

- 26.3-rc-2：首次配置窗口的垂直同步时，OpenGL 仍指向初始化用的隐藏窗口，直到呈现画面时才切到游戏窗口。上述环境中，启动时的垂直同步设置没有应用到实际游戏窗口。
- 26.3-rc-3：首次配置时先切换到游戏窗口，再根据“垂直同步”选项设置交换间隔，使该设置应用到实际游戏窗口。
