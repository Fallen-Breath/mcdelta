# Minecraft 26.3-snapshot-10 变更分析

- 上一个版本：`26.3-snapshot-9`
- 当前版本：`26.3-snapshot-10`

## 自然刷怪采用逐方块群系边界

自然刷怪使用的生物列表与群系刷怪密度费用，现在读取方块位置所属的群系，改变了群系交界处刷怪平台的实际范围。

### 差异出现的场景

一个位置在直接划分的 4×4×4 群系采样格中属于群系 A，但按照游戏逐方块扰动后的群系边界属于群系 B，且两种群系的刷怪列表或密度限制不同。

### 版本变化

- Snapshot 9：自然刷怪属性直接读取该位置所在的 4×4×4 采样格，使用群系 A 的列表和密度费用。
- Snapshot 10：改用逐方块群系查询，使用群系 B 的列表和密度费用。这项读取也用于生成区块时的动物列表，以及计算已有生物对群系刷怪密度的占用。

### 实际影响

群系边缘的平台可能改变可刷出的生物种类和数量，已有区块也会受到影响。结构自带的刷怪表仍先于群系刷怪表生效；例如处在有效结构范围内的女巫小屋、下界要塞刷怪表，不会仅因这次群系查询变化而失去覆盖。

## 村民达到经验要求后立即升级，新交易立即获得折扣

### 差异出现的场景

玩家完成一笔交易，使村民经验达到下一级要求；玩家继续保持交易界面打开，或在很短时间内继续交易。

### 版本变化

- Snapshot 9：每次满足升级条件的交易会将升级倒计时设为 40 游戏刻。倒计时结束后才升级，并获得持续 200 游戏刻的生命恢复 I；在等待期间继续满足条件的交易还会重设倒计时。
- Snapshot 10：在触发交易时直接升一级、加入新交易，并立即获得同样的生命恢复效果，无需等待两秒。

新版在把新增交易发送给当前玩家之前，还会重新应用声望和村庄英雄折扣。旧版在已打开的界面内新增交易时没有这一步，新交易可能先以未折扣价格出现，直到再次重新计算价格。

## 溺尸重新按昼夜与玩家是否入水选择目标，持三叉戟时优先投掷

### 差异出现的场景

白天寻找目标的溺尸、玩家攻击溺尸后的反击，以及手持三叉戟的溺尸接近玩家的战斗。

### 版本变化

- Snapshot 9：溺尸保存持续 20～39 秒的愤怒状态。白天是否作为中立生物处理，取决于它当前已经锁定的目标是否在水中；因此尚无目标时，水中的普通玩家也可能因没有激怒它而无法被主动选中。玩家在陆地上激怒它后，愤怒状态可允许其继续近战追击。
- Snapshot 10：主动选玩家目标和近战攻击均直接要求“外界不明亮，或目标正在水中”。白天无目标的溺尸可以直接选择水中玩家；白天目标离水后，这套近战攻击不再因愤怒状态而继续。持三叉戟的反击仍可由受伤仇恨触发，投掷攻击本身没有加入上述近战限制。

新版移除了溺尸持久愤怒的保存、计时及相关中立生物行为；受伤时通知附近同类也不再被白天的中立条件拦截。与此同时，溺尸恢复普通怪物的阻止睡眠规则：附近没有对玩家发怒的溺尸也可阻止玩家入睡，旧版只由对该玩家愤怒的溺尸阻止。

手持三叉戟时，旧版主要在与目标距离至少 3 格，或目标不在近战范围且无法到达时切换为投掷。新版只要投掷攻击能取得目标且主手是三叉戟，就可启动优先登记的投掷行为，近距离也继续投掷，不再靠旧版的距离条件切回近战。

## 末影人躲开投射物后，箭和三叉戟会按未造成伤害处理

普通末影人受到投射物攻击时会尝试传送。此次变化影响投射物在碰撞之后如何继续运动，也修正了末影人作为乘客、确实能被投射物伤害时的处理。

### 版本变化

- Snapshot 9：末影人成功传送会向投射物返回“命中成功”；箭和三叉戟又对末影人提前退出命中处理，跳过正常反弹。末影人即使作为乘客而实际受到伤害，也会被这项特殊提前退出跳过后续命中效果。
- Snapshot 10：未乘坐载具的末影人躲避投射物时始终返回未造成伤害，箭会反弹，三叉戟也会进入反向运动处理。普通末影人的传送成功与否不再被当作伤害成功。作为乘客而实际受到伤害的末影人则接受正常的箭矢数量、击退、命中后的附魔效果等处理，燃烧的箭也能在这种情况下使其着火。

新版三叉戟的实体命中声仅在实际伤害成功时播放；这同时影响无敌或其他拒绝伤害的目标。药水触发末影人传送时，也改为只按实际的清水伤害返回伤害结果。

## 非实体运算区块中的生物不再接受普通实体挤推

在区块仍已加载、但其中的生物没有进行实体运算时，旧版活着、非旁观且未攀爬的生物仍会被判定为可推动。邻近正在运算的实体可能对这些生物施加碰撞推力。新版对这类生物直接返回不可推动，限制利用区块运算边界持续挤推生物的配置。始终运算的实体不受这项新增条件限制；这项修改针对实体碰撞的可推动判定，不能据此扩大为活塞或全部外力均失效。

## 阳光损耗头盔会应用耐久附魔，装备损坏立即清理原物品效果

- 僵尸、骷髅等用头部装备遮挡阳光时，旧版直接给装备增加随机 0 或 1 点损耗，忽略耐久附魔的损耗调整。新版走正常的物品耐久处理，耐久附魔可以减少这项损耗，因此相同附魔头盔通常能遮挡阳光更久。
- 装备耗尽耐久时，旧版先把物品数量减掉，再从装备槽读取待清理的属性和附魔；槽位已经空了时，这次清理读不到损坏装备。新版保留损坏前的物品副本并立即用它移除属性与位置型附魔效果，避免残留到后续装备变化检查。

## 蝾螈、海豚与青蛙寻找水域时区分水源和流水

新版把几个寻找水域的条件拆成可由数据包修改的流体标签。默认标签只直接列出水源流体 `minecraft:water`，因此默认游戏也有以下差异：

- 蝾螈在陆地上寻找入水目标时，旧版接受任意水方块，包括流水；新版只接受含水源流体的液体方块，流水不再是候选目标。它在流水中也不再仅凭位于水中就停止这项寻找行为。
- 海豚寻找附近水域时，旧版使用包含水源与流水的 `#minecraft:water`；新版目标标签只有水源，流水不再满足“已经在目标液体中”或“可返回的水域”条件。
- 青蛙寻找水边陆地时，旧版检查岸边下方是否为水方块；新版检查其中的流体是否是水源。因此水源型含水方块也可满足岸边条件，流水不再满足。青蛙身处流水时也不再因为旧版的水标签判断而直接跳过这项行为。

地面导航计算可漂浮生物所在的水面高度时，也由逐层检查水方块改为检查 `entity_floatable` 流体标签，默认包括水源、流水及含水方块中的水。数据包还可以独立修改各生物寻找的液体，以及一般生物浮起、骑乘浮起和相关导航所接受的液体。

## 大型矿脉不再按原有高度区间硬性截断

大型铜、铁矿脉从噪声填充阶段移到地形材质规则中，并移除了矿脉密度外层按高度直接拒绝的条件。

### 版本变化

- Snapshot 9：大型铜矿脉密度只在 `0 ≤ Y < 50` 计算，大型铁矿脉只在 `-60 ≤ Y < -8` 计算；区间外直接返回不生成矿脉。
- Snapshot 10：密度仍在原边界附近渐弱，但不再直接按上述区间拒绝。当区间外的位置具有足够强的矿脉噪声时，也能生成对应的矿石、粗矿块及伴生岩石。因此原来的高度界限不能再当作严格上限或下限。

新版还把矿脉规则加入了内置 `caves` 和 `floating_islands` 噪声设置所用的主世界材质规则；旧版这两个设置的矿脉列表为空。使用这些内置设置的自定义维度，也开始具备大型铜、铁矿脉的生成规则。

这些变化作用于新生成的地形，完整生成的旧区块不会重新布置矿脉。区块生成阶段合并为 `terrain` 后，旧存档中停在 `noise` 或 `surface` 阶段的半成品区块会回退到 `biomes`，清除待重建部分的方块和高度图，再按新版生成；旧的 `carvers` 阶段则直接映射到新阶段。

## 联机移动增加客户端刻内位置包限制，并主动修正脚下幽灵方块

- 同一次客户端游戏刻内，旧版可以处理多个携带位置的普通移动包；新版收到第二个就以无效玩家移动断开连接。计数在收到客户端刻结束包时清零，并非按服务器每次执行游戏刻清零。发送重复位置包的自定义客户端或代理需要遵守这一约束。
- 客户端认为玩家已经落地，但服务端记录玩家下方没有支撑碰撞时，旧版没有这项专门的重发措施；新版重发玩家脚下包围盒四角对应的方块及其方块实体更新，修正可能残留的幽灵方块。这项重发最多每 200 服务端刻执行一次，连接开始时也受同一时间条件限制。
- 传送确认包现在同时携带客户端完成传送后的位置和朝向，服务端直接交给移动处理。旧版客户端另发一份普通位置包；与新的每客户端刻位置包限制配合后，传送确认不再占用这份普通位置包。

## 工具的方块转换规则改为数据包注册项，旧自定义组件会被移除

## 无玩家命令源运行游戏测试会触发异常

由服务器控制台、RCON 或命令方块直接执行测试命令，且没有通过 `execute as` 把命令源切换到玩家时：

- Snapshot 9：输出返回位置前会检查命令源是否有玩家；没有玩家就跳过坐标输出。
- Snapshot 10：新的坐标输出方法在无玩家时仍读取玩家朝向，触发空指针异常。`/test locate` 找到测试后会在这一步报命令异常；运行测试后，在全部测试完成并输出汇总时也会触发。

## 自定义地形数据包需要迁移噪声配置

旧版地形数据包直接放到新版时，以下格式变化会影响加载与生成结果：

- 噪声路由的必填字段 `preliminary_surface_level` 改为 `chunk_surface_level`。旧配置未提供新字段时无法通过解析。
- `interpolated` 密度函数现在要求自己提供 `cell_size_xz` 和 `cell_size_y`。原来噪声设置中的 `size_horizontal`、`size_vertical` 被移除，不再全局控制插值网格。
- `cache_2d`、`cache_once`、`cache_all_in_cell`、`flat_cache` 密度函数类型被统一的 `cache` 取代；`shifted_noise` 则合并进 `noise` 的位移参数。继续引用被移除的类型会加载失败。
- 噪声设置不再读取 `ore_veins` 列表。自定义矿脉需要放入材质规则中的 `ore_vein` 规则；仅保留旧字段不会继续生成所配置的矿脉。

## 命令和自定义物品的数据接口调整

- 新增管理命令 `/compute`，可以在默认、方块或实体上下文中计算数值提供器，结果可供 `execute store` 使用；`data modify` 的各项修改操作也新增 `compute` 来源，能直接写入浮点数，或用 `integer` 写入整数。
- 本地坐标 `^ ^ ^` 从双精度四元数运算改回正弦余弦基向量计算，使用游戏的浮点三角函数。方向含义相同，但精确结果会变化，依赖方块边缘或高精度小数落点的命令装置可能受舍入影响。
- 攻击与交互动画组件重新支持 `type:"none"`，时长允许为 0，可以配置无挥手动画；更早物品的动画迁移也不再强制把 `none` 改成普通挥动。
- 五种探索地图物品 ID 改为按目标结构命名：`ocean_monument_map`、`woodland_mansion_map`、`buried_trial_chambers_map`、`jungle_pyramid_map`、`swamp_hut_map`。存档中的旧物品有重命名迁移，地图目标与交易价格并未因此改变；引用旧物品、结构标签或交易注册项 ID 的命令及数据包需要使用新 ID。
- `set_loot_table` 物品修饰器把字段 `tag` 改为 `loot_table_id`，删除原来必填但不参与实际赋值的 `type` 字段。现有自定义修饰器需要更新字段。
- 实体转换现在继承 NBT `invulnerable_time` 的剩余临时无敌时间。旧版转换会丢失它；这适用于带有这种临时保护的实体，包括命令设置的情形，和普通受伤后的伤害冷却是两套不同状态。
