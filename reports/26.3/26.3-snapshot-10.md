# Minecraft 26.3-snapshot-10 变更分析

- 上一个版本：`26.3-snapshot-9`
- 当前版本：`26.3-snapshot-10`

## 自然刷怪采用逐方块群系边界

自然刷怪使用的生物列表与群系刷怪密度费用，现在读取方块位置所属的群系，改变了群系交界处刷怪平台的实际范围。

### 差异出现的场景

一个位置在直接划分的 4×4×4 群系采样格中属于群系 A，但按照游戏逐方块扰动后的群系边界属于群系 B，且两种群系的刷怪列表或密度限制不同。

### 版本变化

- Snapshot 9：自然刷怪属性直接读取该位置所在的 4×4×4 采样格，使用群系 A 的列表和密度费用。
- Snapshot 10：改用逐方块群系查询，使用群系 B 的列表和密度费用。这项读取也用于生成区块时的动物列表，以及计算已有生物对群系刷怪密度的占用。

### 实际影响

群系边缘的平台可能改变可刷出的生物种类和数量，已有区块也会受到影响。结构自带的刷怪表仍先于群系刷怪表生效；例如处在有效结构范围内的女巫小屋、下界要塞刷怪表，不会仅因这次群系查询变化而失去覆盖。

## 村民达到经验要求后立即升级，新交易立即获得折扣

村民升级会解锁下一等级的交易，并提供短暂的生命恢复。新版取消交易触发后的升级等待，同时让新解锁的交易立即采用当前玩家的折扣。

### 差异出现的场景

完成一笔使村民经验达到下一级要求的交易后，保持交易界面打开或立即继续交易；折扣差异出现在玩家具有声望或村庄英雄折扣时。

### 版本变化

- Snapshot 9：满足升级条件的交易把倒计时设为 40 游戏刻，计时结束后才升级并获得持续 200 游戏刻的生命恢复 I。在等待期间继续满足条件的交易会重设计时。已打开界面中新加入的交易没有重新应用玩家折扣，可能暂时显示未折扣价格。
- Snapshot 10：触发交易时立即升一级、加入新交易，并获得相同的生命恢复效果。新增交易发送给玩家前会重新计算声望和村庄英雄折扣。

## 溺尸按明亮程度与目标是否入水决定追击，并取消持久愤怒

溺尸不再依靠持久愤怒状态决定白天对玩家的敌意，主动选玩家目标和近战攻击改为直接检查环境明亮程度及目标是否在水中。睡眠阻挡也随之恢复普通怪物规则。

### 差异出现的场景

白天明亮环境下，尚未锁定目标的溺尸附近有水中玩家，或玩家攻击溺尸后离开水域；另一个相关场景是玩家尝试在附近有溺尸时睡觉。

### 版本变化

- Snapshot 9：溺尸保存 20～39 秒的愤怒状态。白天是否按中立生物处理取决于当前已锁定目标是否在水中，因而无目标时可能不主动选择未激怒它的水中玩家。激怒后的状态可支持继续在陆地近战追击；附近溺尸只有对该玩家发怒时才阻止其睡眠。
- Snapshot 10：主动选择玩家目标和近战攻击要求“外界不明亮，或目标正在水中”。无目标时可直接选择水中玩家，明亮环境下目标离水后不会再由愤怒状态维持这套近战追击。溺尸不再保存或计时持久愤怒，附近溺尸即使未对玩家发怒，也可按普通怪物规则阻止睡眠。

新版受伤时通知附近同类也不再被白天中立条件拦截。受伤仇恨仍可触发持三叉戟溺尸的反击，投掷攻击本身没有加入上述近战条件。

## 持三叉戟的溺尸在近距离也优先投掷

溺尸的三叉戟投掷与近战使用同一组攻击行为优先级。新版移除了投掷启动条件中的距离与路径限制。

### 差异出现的场景

主手持三叉戟的溺尸已有有效目标，双方接近到不足 3 格或进入近战范围。

### 版本变化

- Snapshot 9：主要在距离目标至少 3 格，或目标不在近战范围且路径无法到达时选择投掷；近距离可切换成近战。
- Snapshot 10：只要远程攻击行为本身能取得目标，且主手仍为三叉戟，就可启动优先登记的投掷行为。进入近距离不会再因为旧版距离条件而切回近战。

## 末影人躲开投射物后，箭和三叉戟会按未造成伤害处理

末影人通常通过传送躲避投射物。新版将传送结果与伤害结果分开，箭和三叉戟据此决定反弹及命中后的效果。

### 差异出现的场景

箭或三叉戟碰撞未乘坐载具的末影人；或者末影人作为乘客，确实接受了投射物伤害。

### 版本变化

- Snapshot 9：末影人传送成功会被返回为伤害成功，箭和三叉戟又对末影人提前结束命中流程，跳过正常反弹。作为乘客而实际受伤的末影人也被该特判跳过后续命中效果。
- Snapshot 10：未乘坐载具的末影人躲避投射物时，无论传送是否成功都返回未造成伤害，箭会反弹，三叉戟也进入反向运动处理。作为乘客而实际受伤时，则正常处理插在身上的箭数、击退和命中后的附魔效果，燃烧箭也可以使其着火。

新版三叉戟只在伤害成功时播放实体命中声，因此无敌或以其他方式拒绝伤害的目标也不再触发该声音。药水引发末影人传送时，伤害返回值同样只取决于实际清水伤害。

## 非实体运算区块中的生物不再接受普通实体挤推

实体碰撞通过生物的可推动判定决定是否施加挤推。新版增加所在位置是否进行实体运算的条件，改变区块运算边界上的挤推行为。

### 差异出现的场景

生物所在区块仍已加载，但其位置不进行实体运算；相邻正在运算的实体与它发生碰撞。生物本身活着、非旁观且未在攀爬，也不属于始终运算的实体。

### 版本变化

- Snapshot 9：该生物仍被判定为可推动，邻近实体可以对它施加碰撞推力。
- Snapshot 10：该生物被判定为不可推动，不能再靠这项普通实体碰撞持续挤推。新增条件不限制始终运算的实体，也不改变活塞等其他外力的判定。

## 遮挡阳光的头盔损耗会应用耐久附魔

僵尸、骷髅等生物用头部装备遮挡阳光时会消耗装备耐久。新版让这项损耗经过正常的物品耐久处理。

### 差异出现的场景

会在阳光下燃烧的生物佩戴带有耐久附魔的可损坏头部装备，并处于触发阳光损耗的环境中。

### 版本变化

- Snapshot 9：直接给装备增加随机 0 或 1 点损耗，忽略耐久附魔的损耗调整。
- Snapshot 10：耐久附魔可以减少这项损耗，相同附魔装备通常能遮挡阳光更久。

## 装备损坏时立即移除原装备的属性与附魔效果

装备耗尽耐久后需要清理它提供的属性和位置型附魔效果。新版在销毁物品前保留副本，供同一次损坏处理使用。

### 差异出现的场景

生物或玩家的装备耗尽耐久、槽位中的该物品被移除，且原装备带有待清理的属性或位置型附魔效果。

### 版本变化

- Snapshot 9：先减少物品数量，再从装备槽读取待清理物品；槽位已经空了时，无法在这一步读到原装备的效果，可能残留到后续装备变化检查。
- Snapshot 10：使用损坏前的物品副本立即清理相应效果。

## 蝾螈、海豚与青蛙寻找水域时区分水源和流水

寻找水域和水边陆地的行为改用各生物独立的流体标签。默认标签只直接列出水源流体 `minecraft:water`，因此这次接口调整也改变默认行为。

### 差异出现的场景

蝾螈或海豚在陆地、流水附近寻找水域，或青蛙在流水及水源型含水方块附近寻找水边陆地。

### 版本变化

- Snapshot 9：蝾螈的目标是水方块，水源与流水均可接受，且在水中会停止这项寻找；海豚使用包含水源和流水的水标签。青蛙检查岸边下方是否为水方块，并会因身处水标签流体而跳过寻找。
- Snapshot 10：蝾螈只把含水源流体的液体方块作为入水目标，身处流水不再仅凭位于水中而停止寻找。海豚只把水源认作已到达或可返回的目标液体。青蛙改查岸边下方的流体：水源型含水方块也可满足条件，流水不再满足，身处流水也不会再按旧水标签条件直接跳过。

数据包可以分别修改这些标签，让三种生物接受不同的目标液体。

## 浮起与地面导航通过流体标签识别液体

一般生物浮起、骑乘时浮起及相关导航改为读取流体标签。地面导航向上寻找液面时，也开始检查方块中的流体。

### 差异出现的场景

可漂浮且使用地面导航的生物计算液面高度时，上方存在含水方块；或数据包需要修改生物浮起时接受的液体。

### 版本变化

- Snapshot 9：导航逐层检查水方块，遇到含水方块就结束向上的水面查找。相关浮起行为使用原有水条件，缺少本次新增的独立流体标签入口。
- Snapshot 10：导航逐层检查 `entity_floatable` 流体标签，默认水源、流水及含水方块中的水均可参与查询。数据包可通过对应标签修改一般浮起、骑乘浮起和相关导航接受的液体。

## 大型矿脉不再按原有高度区间硬性截断

大型铜、铁矿脉从噪声填充阶段移到地形材质规则中。新版保留高度边缘的密度渐弱，但移除了区间外直接拒绝的条件，并扩展了使用矿脉规则的内置噪声设置。

### 差异出现的场景

新生成地形中的位置超出原大型铜矿脉或铁矿脉高度区间，但矿脉噪声足够强；或者自定义维度使用内置 `caves`、`floating_islands` 噪声设置。

### 版本变化

- Snapshot 9：大型铜矿脉密度只在 `0 ≤ Y < 50` 计算，大型铁矿脉只在 `-60 ≤ Y < -8` 计算，区间外不生成。`caves` 和 `floating_islands` 的矿脉列表为空。
- Snapshot 10：不再按上述区间直接拒绝，区间外满足噪声条件的位置也能生成矿石、粗矿块及伴生岩石。`caves` 和 `floating_islands` 使用的主世界材质规则也加入大型铜、铁矿脉。

这些差异影响新生成地形，完整生成的旧区块不会重新布置矿脉。原有高度界限不能再作为矿脉分布的严格上下限。

### 差异出现的场景

世界目录迁移准备移动文件，但目标路径已经存在同名文件。

### 版本变化

- Snapshot 9：记录警告并跳过该文件，然后继续迁移。
- Snapshot 10：抛出文件已存在异常并中止升级，单人客户端显示升级中止提示，避免迁移继续后混用两处文件。

## 只读区块扫描不再创建空区域文件

区块区域文件现在区分只读访问与写入访问，只有写入才会创建尚不存在的文件。

### 差异出现的场景

读取或扫描某个区块，但它所在的 `.mca` 区域文件尚不存在，例如查找结构涉及只读扫描时。

### 版本变化

- Snapshot 9：打开区域存储时顺带创建空区域文件，即使扫描没有读到区块数据。
- Snapshot 10：直接按没有数据处理，不创建空文件；后续实际写入时才创建区域文件。

## 无玩家命令源运行游戏测试会触发异常

游戏测试命令输出返回位置时，需要读取命令源玩家的朝向。新版坐标输出遗漏无玩家检查，使部分命令和测试完成回调出现异常。

### 差异出现的场景

由服务器控制台、RCON 或命令方块执行 `/test locate` 并找到测试，或者运行一批游戏测试直至全部完成；命令源没有通过 `execute as` 切换为玩家。

### 版本变化

- Snapshot 9：输出返回位置前检查是否有玩家，没有玩家则跳过坐标输出。
- Snapshot 10：无玩家时仍读取玩家朝向，触发空指针异常。`/test locate` 在坐标输出时报命令异常；一批测试全部完成并输出汇总时也会触发。玩家本人执行或使用玩家作为执行者不受这项问题影响。

### 实际影响

测试完成回调由服务器游戏刻直接调用，调用链没有捕获上述异常。因此，无玩家命令源运行的一批测试在完成时可能导致服务器崩溃。

## 自定义地形数据包需要迁移噪声配置

新版重组噪声路由、密度函数与矿脉配置。这些变化既包含必填字段更名，也包含生成规则从噪声设置迁往材质规则。

### 差异出现的场景

直接加载使用旧噪声配置、旧密度函数类型或自定义矿脉列表的地形数据包。

### 版本变化

- Snapshot 9：噪声路由要求 `preliminary_surface_level`；插值网格由噪声设置的 `size_horizontal`、`size_vertical` 统一控制。支持 `cache_2d`、`cache_once`、`cache_all_in_cell`、`flat_cache` 及 `shifted_noise` 类型，并读取 `ore_veins` 列表。
- Snapshot 10：路由必填字段改为 `chunk_surface_level`；每个 `interpolated` 函数必须提供 `cell_size_xz`、`cell_size_y`，原全局大小字段被移除。四种旧缓存类型统一为 `cache`，`shifted_noise` 合并进 `noise` 的位移参数。矿脉改由材质规则中的 `ore_vein` 配置，噪声设置不再读取旧列表。

旧配置缺少新必填字段，或继续引用已移除的密度函数类型时，会加载失败。仅保留旧 `ore_veins` 字段也不会继续生成其中配置的矿脉。

## 命令可以直接计算数值提供器并写入 NBT

新增 `/compute` 命令和 `data modify` 的 `compute` 来源，让命令能够直接使用数值提供器。

### 差异出现的场景

命令需要在默认、方块或实体上下文计算数值，并把结果交给 `execute store` 或写入 NBT。

### 版本变化

- Snapshot 9：没有 `/compute` 及本次新增的 NBT `compute` 来源，不能通过这两个入口直接计算数值提供器。
- Snapshot 10：`/compute` 可以在上述上下文中计算，结果可供 `execute store` 使用；`data modify` 的修改操作可用 `compute` 来源直接写浮点数，或加 `integer` 写整数。

## 持续声音会刷新字幕，并调整同名声音的方向选择

声音字幕改为在持续声音播放期间更新通知，并重新选择多个同名声音中用于方向提示的来源。骑乘循环声音也会更新发声位置。

### 差异出现的场景

可更新的循环声音持续播放超过字幕显示时间，或可听范围内存在多个同名声音；骑乘声音随着所骑实体移动。

### 版本变化

- Snapshot 9：字幕仅依靠起播时的通知计时，持续声音仍在播放时也可能在约三秒后消失。同名声音优先选最近来源；骑乘声音的位置可能停留在原点。
- Snapshot 10：循环声音每 10 客户端刻刷新字幕通知，持续播放时字幕不会仅因最初通知经过三秒而消失。同名声音优先选择仍在可听范围内的最新来源，时间相同则选较远者；骑乘声音同时更新到实体位置。
