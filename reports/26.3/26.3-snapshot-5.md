# Minecraft 26.3 Snapshot 5 变更分析

- 上一个版本：`26.3-snapshot-4`
- 当前版本：`26.3-snapshot-5`

## 普通饰纹陶罐恢复四块红砖，旧格式陶罐补齐缺失的侧面

普通饰纹陶罐现在明确带有四面红砖装饰。这会改变陶罐被打碎时的材料掉落，也使直接取得的普通陶罐与用四块红砖合成的陶罐具有相同的装饰数据。

### 差异出现的场景

从创造模式物品栏或 `/give` 取得未额外指定装饰数据的饰纹陶罐，将其放置后用会打碎陶罐的工具破坏；另一种场景是生成试炼密室中没有纹样的陶罐。读取尚未执行陶罐装饰格式转换的旧存档时，还会涉及缺失侧面的转换。

### 版本变化

- Snapshot 4：默认物品的四面装饰为空，试炼密室中的普通陶罐也没有四面材料。打碎这类陶罐时，不会从其侧面掉出红砖。
- Snapshot 5：默认物品和上述结构中的陶罐都明确使用四块红砖。打碎时，每面掉出一块红砖，总计四块；物品提示也能列出四面的红砖。

用红砖正常合成的陶罐原本就记录了材料，本次主要影响直接取得的默认物品和对应的结构陶罐。

对于尚未执行陶罐装饰格式转换的旧存档，两版首次转换时也有区别：

- Snapshot 4：省略的 `sherds` 或不足四项的材料列表会留下空白侧面。
- Snapshot 5：缺失的侧面补成红砖，已有的有效纹样仍保留。

转换仍挂在原有的 4996 数据版本上，因此已由 Snapshot 4 转换并保存的空面方块不一定会再次执行这项修复。

## 弹射物忽略空气位置的方块命中，影响世界边界上的结算

弹射物在执行方块命中效果前，现在会重新读取命中位置；该位置是空气时，跳过整次命中效果。除了碰撞检测后方块状态发生变化的情况，这还直接影响世界边界产生的虚拟方块命中。

### 差异出现的场景

向世界边界投掷末影珍珠、鸡蛋等不会在边界反弹的弹射物，且边界命中位置实际为空气。普通实心方块命中不属于这一条件。

### 版本变化

- Snapshot 4：把边界交点当作方块命中，执行弹射物的落地效果。例如末影珍珠在这里结算传送，鸡蛋在这里破碎并进行生成小鸡的随机判定。
- Snapshot 5：空气检查使这些效果不再于边界交点触发，弹射物也不会因这次命中被消耗。移动检测仍把位置限制在边界内，后续运动或重力可以让它沿边界继续移动，直到实际命中方块或实体。

箭和鱼钩会先执行原有的边界反弹，因此不受这次空气检查阻止。若碰撞检测得到的普通方块命中在结算前已经变为空气，新版同样不会执行命中音效、落地游戏事件或该弹射物的其他命中后果。

## 幽匿斑块生成收紧扩散范围，远古城市尖啸体可以分布在不同高度

这一组变化作用于世界生成时的幽匿斑块，包括深暗之域和远古城市使用的斑块。生成时的扩散范围、停止条件及附加方块的放置方式都有变化。

### 差异出现的场景

用相同种子在两版中生成此前未生成的深暗之域或远古城市区域，尤其是斑块靠近台阶、不同高度的地面或扩散路径的末端时。

### 版本变化

- Snapshot 4：扩散能量移动之后，水平距离达到 15 格才被清除；找不到可移动位置时，可以留在原处继续处理。远古城市额外尝试放置的 1—3 个幽匿尖啸体只在起点同一高度、水平各轴正负 2 格内选位置。催发体要求下方方块拥有完整方块的碰撞形状。
- Snapshot 5：扩散能量只接受水平距离不超过 12 格的移动落点；没有可移动位置时立即耗尽。远古城市额外尖啸体的候选位置改为 X、Y、Z 三个方向都在正负 2 格内，因而可以落到高低不同的地面。催发体改为要求下方方块的上表面能够稳固支撑，允许部分碰撞形状并非整立方体、但上表面足够稳固的支撑方块。

尖啸体的额外放置仍要求候选位置为空气、下方上表面稳固，且生成的尖啸体可以召唤监守者。12 格限制约束的是扩散能量的移动位置，不能直接理解为所有幽匿脉络都严格截断在半径 12 格处。

### 实际影响

同一种子的新区域会出现不同的幽匿斑块边缘和催发体、尖啸体分布；已生成的区域不会因此重铺。这些扩散限制仅用于世界生成，击杀生物为幽匿催发体供能的农场不采用新的 12 格移动限制。

数据包直接使用 `minecraft:sculk_patch` 时，也不再由该特征读取 `catalyst_chance` 和 `extra_rare_growths` 来附加催发体或尖啸体。原版已改用组合特征单独放置它们；沿用旧特征配置的数据包需要相应拆分，才能保留原来的附加生成。

## 烈焰粉改用酿造专用的默认速度

烈焰粉作为酿造燃料时，通过数值提供器取得酿造速度倍率。新版把这一引用从烹饪默认速度改为酿造默认速度，影响分别定制这两个数值的数据包。

### 差异出现的场景

数据包令 `minecraft:cooking/speed_default` 与 `minecraft:brewing/speed_default` 返回不同倍率，酿造台燃料耗尽后消耗一份未额外修改燃料组件的烈焰粉。

### 版本变化

- Snapshot 4：从 `minecraft:cooking/speed_default` 取得倍率，用于这份烈焰粉支持的酿造。
- Snapshot 5：改从 `minecraft:brewing/speed_default` 取得倍率，同一配置下的酿造速度因而可能不同。

两版原版数据的默认倍率都是 1。倍率在酿造台消耗燃料物品时写入；已经装入的燃料不会因引用变化立即重新计算。

## 蜘蛛旁观滤镜出现编译失败，可触发客户端崩溃

旁观蜘蛛时启用的多重视野需要加载一组后处理着色器。新版原版着色器的输入、输出位置不一致，无法通过新的编译校验，进而触发资源包故障恢复。

### 差异出现的场景

以旁观模式进入蜘蛛视角，并启用其视觉效果。此问题来自原版着色器，无需安装自定义着色器。

### 版本变化

- Snapshot 4：着色器接口匹配，可以显示蜘蛛的多重视野。
- Snapshot 5：顶点着色器把 `scaledCoord` 输出到位置 1，片元着色器却从位置 2 读取；编译流程因输入缺少来源而拒绝加载。存在可清除的资源包时，客户端先清除资源包并重新加载；仅启用原版资源且已没有资源包可清除时，客户端会紧急保存并崩溃。

## 编辑已有服务器会刷新状态，但服务器资源包偏好不再保存

多人游戏列表会保存服务器地址、名称和资源包偏好。新版编辑保存时重置服务器状态查询，但遗漏了资源包偏好的复制，影响下一次连接采用的设置。

### 差异出现的场景

编辑多人游戏列表中的已有服务器，修改地址或“服务器资源包”选项后点击完成，再查看该条目、重新编辑或连接。新增服务器采用另一条保存路径，不属于这一偏好丢失的场景。

### 版本变化

- Snapshot 4：名称、地址和“服务器资源包”选项均保存到已有记录；原状态查询结果没有重置，改地址后可能继续显示旧地址的状态。
- Snapshot 5：保存名称、地址后重新查询状态，显示对应新地址；“服务器资源包”选项的修改没有复制回已有记录，再次编辑或连接时仍使用原先的偏好。

## 命令补全的同步异常不再向外传播

服务器会在可用的处理时机解析玩家的命令补全请求、同步生成候选项。新版在这一层捕获异常，使一次失败的补全不会继续触发外层的连接或任务异常处理。

### 差异出现的场景

玩家请求命令补全，服务器在解析命令或同步生成候选项时抛出异常。这里只涉及补全调用期间抛出的异常，不包括已返回的异步任务以后才发生的异常。

### 版本变化

- Snapshot 4：异常离开补全处理方法。若待处理请求是在连接更新中执行的，远程连接的外层处理会以“Internal server error”断开该玩家；同一路径上的本地内存连接则抛出崩溃报告异常。若请求在服务器调度任务中执行，异常交由该任务的外层处理。
- Snapshot 5：在补全处理层捕获异常并记录日志，不再因这次异常进入上述连接失败处理；服务器可以继续处理后续请求。失败的这次请求没有返回补全结果。

## 开启聊天延迟时，消息始终先进入队列

聊天延迟通过队列控制消息显示间隔。新版让启用延迟后的所有相关消息先入队，再由聊天更新取出，改变了间隔已结束或游戏暂停时的显示时机。

### 差异出现的场景

聊天延迟大于零，客户端收到玩家聊天或走同一队列的命令聊天；尤其是距离上一条消息已超过延迟间隔，或游戏正处于暂停状态时。普通系统消息走另一条处理路径，不在此列。

### 版本变化

- Snapshot 4：只有仍处于等待间隔内的新消息才入队；间隔已经结束时立即处理新消息，即使游戏正暂停。
- Snapshot 5：所有这类消息先入队，由未暂停时的聊天更新按间隔取出。暂停期间收到的消息不会绕过队列立即显示；没有暂停且间隔已结束时，消息最多等到下一次聊天更新才显示。

## 客户端按最后一次区块变化更新可见性

客户端会把一批区块和区段状态变化交给渲染器。新版记录变化时撤销相反通知，并在载入时补记非空区段，使可见性采用本批结束时的状态。

### 差异出现的场景

客户端向渲染器提交一批更新前，同一区块先卸载又重新载入，或同一区段在空与非空之间多次变化；重新载入的非空区段也可能仍有旧的空区段记录。

### 版本变化

- Snapshot 4：可以同时保留相反通知。渲染器固定先加后删，刚重新载入的区块可能仍被当作未载入；重新载入非空区段时也不会主动清除旧的空区段记录，可能导致部分地形未显示。
- Snapshot 5：记录变化时撤销相反通知，载入区块时同时记录空区段与非空区段。渲染可见性据此反映最终状态，改善快速移动、重载和密集方块变化时的地形显示。

## 资源包自定义着色器需要采用新的接口

新版改用 OpenGL、Vulkan 共用的着色器编译流程，同时调整导入语法和阶段接口。覆盖原版着色器的资源包若继续使用旧接口，相关渲染管线可能加载失败。

### 差异出现的场景

资源包包含自定义着色器，并使用 `#moj_import`、双引号相对导入、未指定位置的阶段输入输出，或旧的顶点索引及深度范围宏名称。

### 版本变化

- Snapshot 4：预处理器支持 `#moj_import`，双引号导入按着色器所在目录解析；原版着色器可使用没有显式位置的阶段输入输出和旧顶点索引名称，深度范围宏为 `B3D_DEPTH_IS_ZERO_TO_ONE`。
- Snapshot 5：不再处理 `#moj_import`，改用 `#include <命名空间:文件名>`，导入统一从 `shaders/include/` 查找。阶段输入输出使用显式 `layout(location = …)`，顶点与片元阶段按位置匹配，位置或类型不一致会被拒绝。原版使用 `gl_VertexIndex`，深度范围宏改为 `RENDERPEARL_DEPTH_IS_ZERO_TO_ONE`。

依赖旧相对路径的公共文件也需要按新版导入规则寻址。

## 僵尸类模型的游泳和持物姿态不再被最后的抬手动画覆盖

僵尸类模型需要把抬手动作与通用人形动画组合。新版调整组合顺序，并让溺尸使用自身的游泳动画，改变游泳和持物时的视觉姿态。

### 差异出现的场景

观察僵尸、僵尸村民、僵尸猪灵等模型游泳或持物，以及溺尸游泳、准备投掷三叉戟时的手臂姿态。

### 版本变化

- Snapshot 4：通用姿态完成后再次覆盖僵尸抬手动作，游泳及部分持物姿态可能被覆盖。溺尸还通过额外修改三叉戟手臂和攻击手臂角度作补偿。
- Snapshot 5：僵尸手臂动画在通用流程的攻击阶段执行，之后叠加蹲伏、手臂摆动和游泳。溺尸单独采用自身的游泳动画；准备投掷三叉戟的手臂不再被抬手动画重置，旧版的额外角度补偿被移除。

这些变化影响显示姿态，不改变投掷时机或攻击判定。
